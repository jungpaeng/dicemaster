## 변경 권한과 미션 복구

예약과 해제 모두 최신 정상으로 게시된 현재 선택 대상에서만 허용한다. 대기·실패·이전 값·게시 실패, 대상 없음·소멸·교체·새 문맥·실제 게임 데이터에서 빠진 대상은 변경하지 않는다. 예약 표시가 남았다는 이유로 오래된 대상의 검증을 우회하지 않는다.

새 확인 입력이나 선택된 행의 **포인터 누름 시점**에 원본 예약 슬롯·문맥·탭·변경 세대 스냅샷을 캡처한다. 해제 시 현재 표시로 동작을 다시 결정하거나 티켓을 새로 만들지 않는다. 슬롯과 세대가 달라지면 거부하므로 누르는 동안 소비·다른 예약 교체·같은 객체 재예약이 일어나도 반대 동작으로 바뀌지 않는다. 예약 조회 실패를 `예약 없음`으로 취급하지 않으며 회복 후에도 이전 티켓을 살리지 않는다. 실제 게임의 소비 알림과 예약 변경이 세대를 갱신한다. 최종 변경은 UI 모델·현재 게시·실제 게임 멤버십을 다시 확인하고 성공·거부·예외 후 실행 권한을 해제한다.

미션 활성 항목은 이번 예약이 직접 바꾼 관리자·사전 객체·키·현재 값이 그대로일 때만 원래 값으로 복원하거나 원래 없던 항목을 제거한다. 예약 전부터 같은 대상을 가리킨 정상 활성 항목은 삭제하지 않는다. 게임의 사전/값 교체·소비·새 문맥에서는 복구 기록을 버리며 게임이 반영한 상태를 되감지 않는다.

같은 문맥에서 마지막으로 명시 해제한 **원본 미션 대상**만 기존 위치 안내의 자동 지정에서 제외한다. 미션 안내 출력은 계속한다. 다음 명시적 미션 예약 또는 새 문맥에서 이 억제를 해제한다. 전체 미션을 끄거나 이후 게임 진행·판정을 막는 기능은 아니다. [세부 계약·검사·Windows 12단계](ISSUE-4-RESERVATION-TOGGLE.md)를 함께 따른다.

## 입력 보호와 기존 제약

새 버튼 에지·홀드 반복 방지·입력 소유권·버튼 해제·스틱/트리거 중립 대기와 재연결·모드 전환·Alt-Tab·닫기·주사위 왕복 보호를 유지한다. 다른 키/패드 조작·선택·탭·도구·새로고침·초점 상실·새 문맥은 진행 중 포인터 입력을 취소한다. 실제 게임에 입력이 중복 전달되지 않는지는 사용자 Windows 확인 대상이다.

패드 열기는 기존과 같이 같은 패드의 L3/R3 클릭이 겹치면 순서·300ms 제한 없이 한 번 여는 방식이다. `[DiceMaster].EnableGamepadLogOpen=true`의 **게임 창 초점·로그 닫힘**에서는 첫 클릭 중복 전달을 막기 위해 단독 L3/R3도 게임으로 보내지 않는다. 원래 클릭 기능이 필요하면 게임 종료 후 옵션을 `false`로 바꾸고 재시작하며 남은 누름은 해제 후 반환한다. 실제 게임의 버튼 바인딩이 미사용이라고 확정하지 않는다. 주사위 옵션과 독립적이며 게임 scheme·액션 맵을 강제 변경하지 않는다.

열린 뒤 전체 해제·중립을 기다린 다음 새 입력을 받는다. native 폴링의 1초 신선도 보호는 조합 유지 시간 제한과 구분한다. 게임의 XInput 폴링·차단 경로를 사용할 수 있을 때 지원하며 미지원 시 기존 Tab·마우스·키보드를 사용한다. `[DiceMaster].LogMenuToggleKey`(기본 Tab)를 유지한다. **Tab 진입의 기존 모드 전환·첫 패드 입력 소비 문제는 별도 미해결 경로**다.

모든 항목은 **사용자 확인 대기**다. DLL SHA-256, 해상도·배율·패드·Steam Input·게임/로더 환경과 항목 ID·재현 순서·BepInEx 로그를 기록한다.

2. 선택 없는 첫 A는 선택만 하고, 선택된 항목의 새 A / Enter / Space는 예약 → 해제 → 재예약을 각각 한 번만 수행하는지 확인한다. 홀드·해제로 반복하지 않아야 한다.

# PRD #6 — 자동 안내 범위·장소 준비 분리·중첩 조건 판정

2026-10-21 main에서 기준 HEAD `c262e64` 이후 구현한 후속 수정. 처음 준비·중첩 조건만 수정한 로컬 후보에 이어, 사용자가 확정한 지도 자동 안내 범위 제한도 함께 반영한다. 실제 게시 파일·검증 결과는 [alpha.12 기록](ISSUE-6-ALPHA12-RELEASE.md)을 기준으로 한다. 아래 이전 로컬 후보의 해시는 게시할 최종 파일의 해시가 아니다.

## 동작

- 지도 자동 안내는 현재 실행 가능한 기존 대기 임무와 1회성 증명·현재 조건·경로를 모두 확인한 항목만 발행한다. 일반 후속 인물 대화·미등록 임무 단계는 조건이 참이어도 명시적 상세에서만 제공한다. 도달성이 미확정인 1회성은 표식·증명 근거를 상세에 유지하되 자동 안내에서 제외한다.
- 자동 목록·최대 세 행·외 N개·패널 양성 색은 같은 표시 허용 기준으로 계산한다. 전체 임무 색인과 후속 NPC 조건 샘플은 상세 조회에서만 진행한다. 선택 화면의 경로 안내는 현재 메뉴의 실제 활성 버튼을 기준으로 유지하며 후속 발생을 보장하지 않는다.


- 선택 장소의 경로·효과 준비와 전체 임무 정의 색인의 준비를 구분한다. 전체 색인만 준비 중이고 자동 표시 대상이 없으면 빈 지도 패널을 숨긴다. `임무 정의 준비 중`과 읽기 실패·미확인 상태는 지도 로그 상세에 남긴다. 숨김은 전체 기회가 없다는 뜻이 아니다.
- 현재 주/부 대기 목록을 전체 색인보다 먼저 읽는다. 아직 색인하지 못했거나 색인 읽기가 실패해도 현재 대기 임무를 표시할 수 있다. 현재 `MainCheckData`의 교체는 정의 색인의 재구축 원인에서 제외한다. 실제 대기 단계는 계속 매 조회마다 새로 읽는다.
- 중첩 `ConditionResultData`를 수치 0/1로 읽을 때도 AND/OR의 부분 판정을 보존한다. `난수 AND 확정 거짓`은 거짓, `난수 OR 확정 참`은 참이다. 난수와 미지원 값은 추첨하지 않고 미확정으로 둔다. 수치 그룹 안의 미확정 값을 임의의 숫자로 대체하지 않는다.
- 선행 플래그 쓰기·대화 플래그 초기화 영향, 불명 콜백·누락 경로·깊이/작업 상한 보호는 유지한다. 이후 바뀔 수 있는 값의 현재 거짓만으로 미래 불가를 확정하지 않는다. 인물·플래그 예외 목록을 추가하지 않는다.

## 상세 진단과 설정

로그 → 도구 → 지도 안내에서 인물 대화의 상세를 열면 `현재 필수 조건 표본`을 읽을 수 있다. 원본 Condition/Switch 키, Switch의 `useCount`·횟수, 비교 연산과 현재 플래그 ID/값, 중첩 결과, 난수 미추첨·선행 쓰기 보호 사유를 표시한다. 최종 실행·이야기 전체의 완료를 보장하는 자료는 아니다.

진단은 명시적인 지도 상세 조회에서만 만든다. 한 조회에 최대 4개 인물 묶음, 표본 본문 최대 64행·행당 160자와 생략 표식, 기존 판정 작업/깊이 상한을 사용한다. 현재 값은 해당 표본 안에서만 읽고 캐시된 구문에 보관하지 않는다. 자동 오버레이·자동 로그·세이브·별도 파일에는 진단 값을 쓰지 않는다. 진단 표시 상한에 닿으면 생략을 밝힌다.

새 설정이나 단축키를 추가하지 않는다. `EnableMapGuide`와 기존 상위 `EnableOptionInfo`, 네 정보 기능의 기본 ON·OFF 정리 계약을 따른다. 정상 0.25초/실패 5초·숨김/OFF 조회 중단·warm Lua 로드/재분석 없음과 기존 패드 입력 소유권·해제/중립 보호를 유지한다.

## 구현과 독립 검증

`MapGuideSource`는 전역 색인 상태를 선택 장소의 진행 중 표시와 분리하고, 대기 목록 뒤에 제한된 색인 작업을 수행한다. 64단위 색인 예산을 무작정 늘리거나 모든 리소스를 일괄 로드하지 않는다. 관련 없는 정의 준비 속도와 해당 장소 표시 완료 시점을 분리한 수정이다. 선택 장소 자체의 최초 경로 로드 비용까지 없어졌다는 뜻은 아니다.

`PreviewConditions`는 수치 그룹과 중첩 조건을 재귀적으로 해석하고, 이미 감사한 구체 타입·능력치 변환·플래그 의존성을 검증한 뒤 안전한 기본값 읽기만 재사용한다. 게임 `GetValue/GetResult/Check/Execute`, RNG, 효과·예약·저장 호출을 하지 않는다. 일반 판정에는 진단 목록을 만들지 않는다.

- `MapInformationTests`: 서로 무관한 단계 1만 개에서 첫 조회의 빈 패널 숨김, 색인 중 대기 임무 표시, 실시간 주 임무 단계 교체 중 색인 완료·정의 재읽기 없음, 색인 실패 중 대기 임무 보존.
- `MapRouteTests`: AND/OR의 세 입력을 참/거짓/미확정으로 조합한 54개 구조에 대해 가능한 구체 참·거짓을 전수 대입한다. 이를 1·2단계 중첩 참조와 6개 비교 연산·0/1 상수에 대조한다. 확정된 중첩 값은 정확한 결과를 요구하고 미확정 수치 비교는 보수적인 Unknown을 허용한다. 선행 쓰기·순환·현재 값 갱신·횟수/RNG 불변도 확인한다.
- `MapGuideRouteIntegrationTests`: SHA를 확인한 실제 `center_001`과 후속 Lua에 명시적인 평면/중첩 조건 fixture를 연결한다. 불가 대화 자동 제외·상세 진단·warm 조회를 검사한다. 실제 직렬화된 `Center_001_001` 설정이나 사용자 세이브를 실행한 검사는 아니다.
- `PreviewIntegrationFixtures`: 새로 빌드한 실제 DLL의 조건/경로 IL을 연결해 중첩 `난수 AND false`, `난수 OR true`, 현재 값 갱신과 상세 진단을 검사한다. Unity/Windows 실행은 아니다.

공개 [도감 공략기](https://github.com/nhoecha/legend-of-mortal-guide)의 `graph.json`·`savemap.json`에서는 `center_001`의 단련 → `Center_001_001` 첫 분기 → `center_girl_03_01`과 `난수(0~100) <= 50 AND E12003 == 1 AND 현재 시점 <= 2년차 12월 하순`을 대조했다. 기준 게임은 `release_1.0.5000.13`이므로 현재 설치판의 정답 자료로 포함하거나 자동 안내의 예외 목록으로 사용하지 않는다. 그 자료는 설명 문자열이며 실제 `_useCount`·활성화 스위치·선행 변경까지 대체하지 못한다.

교차 검증의 원본 자료는 같은 설치판의 조건 트리·현재 필수 입력과 실제 선택 결과다. 실제 분기 관찰은 기존 `BranchObservationPatches`를 사용한다. 검증 시 #5 예약/강제 선택의 개입을 구분하고, 확률 후보가 이번에 선택되지 않았다는 사실만으로 오탐으로 세지 않는다.

## 실제 Windows 확인 — 모두 대기

- [ ] 이벤트가 없는 장소에서 전체 임무 색인만 준비 중인 동안 빈 오버레이가 남지 않는다. 지도 로그의 전역 준비 상태는 계속 구분된다.
- [ ] 이미 등록된 대기 임무가 색인 완료 전에도 보이고, 행동력·주 임무·대기 우선순위 안내가 유지된다.
- [ ] 우소매가 없는 연무장에서 지도 안내와 실제 진행을 대조한다. 문제가 남으면 해당 상세의 `Center_001_001`, `useCount`, 실제 플래그 값과 선행 변경 사유를 기록한다. `E12003`이라는 이름만으로 현재 설치판과의 동일성을 추정하지 않는다.
- [ ] 우소매가 있는 경우에도 난수 경로를 확정 발생으로 바꾸지 않는다. 사사형·소사매의 남은 이야기와 반복 활동 분류를 확인한다.
- [ ] Xbox/XInput으로 장소 선택 → L3/R3 겹침 → 해제/중립 → Y 도구 → 지도 안내 → 오른쪽 스틱 상세 → B 복귀를 확인한다. 기존 네 탭·예약·이벤트 팝업·주사위와 키보드·마우스·터치도 확인한다.
- [ ] 같은 지도에서 최초 로드·warm 갱신의 Unity 프레임/할당량, 정상 0.25초·실패 5초·숨김/OFF 중단을 관찰한다. 다른 장소·로드·OFF/ON 후 이전 조건 값이 남지 않고, 조회로 RNG·조건 횟수·세이브·능력치·아이템이 변하지 않는다.

새 후보 Windows 확인 전에는 #6 전체 완료나 이슈 종료로 처리하지 않는다.

# 지도 첫 대화의 고정 날짜 조회 — alpha.34

main의 기준 `8dd027264fc8a49f97ede68093f43c07e4666b78`에서 보완했다. [후보·검사·설치](ISSUE-6-ALPHA34-RELEASE.md)와 [실제 Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md)를 구분한다. 특정 인물·플래그 예외를 추가하지 않는다.

## 연단방 누락의 원인

사용자는 1년4월상순 지도에서 연단방 아이보리 마커가 없고, 방 안의 한담에는 이사형 대화 툴팁이 있으며, 한담 없이 업무만 진행해 지도로 돌아오면 마커가 생긴다고 보고했다. 남제자방 안내는 같은 지도에서 보였다.

제공받은 게임 복제본을 실행 없이 읽어 실제 `alchemy_001`과 조건 자료를 대조했다. 선택 해금은 `Condition("Talk_Brother2_00")`이며, 조건은 `Talk_Brother2_00 == 0 AND PlayerGameTime <= 第一年五月下旬`이다. 날짜 자산의 실제 값은1년5월하순이다. 파일 이름과 달리 저장된 날짜가 다를 수 있으므로 이름을 파싱해 날짜를 만들지 않는다. 업무 분기는 이 초회 대화 플래그를 바꾸지 않고, 한담 분기에서만 해당 플래그를1로 바꾼다.

alpha.33의 파일 reader는 모든 GameTimeData를 현재 가변 입력으로 취급했다. 플레이어의 현재 시각은 기존 player 소유자에서 연결되지만, 고정 기한 자산은 그 카탈로그에 없으므로 누락됐다. 선택 해금이 미확정이 되어 지도 자동 안내에서 제외됐다. Story 자료를 제공하거나 고정 기한 참조만 보충하면, 플래그·현재 날짜가 같아도 안내가 복구되는 것을 관리 코드에서 재현했다. 장소를 거친 뒤 표시되는 현상과 일치하는 원인이다. 사용자 Windows 세이브를 직접 실행했다는 의미는 아니다.

## 가변 시각과 정의의 분리

제공 복제본의 Mortal.Core/Story/Free 및 나머지 Mortal·Assembly-CSharp 코드를 읽어 GameTimeData 참조와 쓰기 경로를 확인했다. 검토한 Core의 변경 경로는 플레이어 `_gameTimeData`와 `_timeCollection`의 항목이다. 새 게임·불러오기·임무 시각 설정·시간 진행은 여기에 쓰고, Story의 환경 변경도 플레이어 현재 시각에 쓴다. StatValueReference와 GameDateTimeText의 다른 참조는 읽기다.

생성기는 검토한 소유자 구조에서 현재 시계1개와 GameTimeDataCollection의 저장 시각18개를 제외하고 나머지 고정 날짜37개의 파일/객체 ID를 인덱스에 기록한다. 인물·플래그·날짜 이름별 허용 목록이 아니다. 소유자 수·참조 타입·컬렉션 크기/끝 위치가 달라지면 새 프로필 생성부터 중단하고 재검토한다. 다른 게임 빌드까지 자동 지원한다고 추정하지 않는다.

DMD2 인덱스는158,218바이트, SHA-256 `a5c9242472caf46e0cac53f8b49a3102058927f2b495576edcd3b69ea86c1666`다. 기존7,131개 항목·8개 root와 같은6개 설치 지문에 고정 날짜의 위치 분류만 더했다. 게임의 날짜 값·조건 payload·Lua·대사·게임 DLL·세이브는 내장하지 않는다. [기존 지원 지문](ISSUE-6-FILE-DEFINITIONS.md#지원하는-설치-자료와-실패-처리)은 유지한다.

런타임의 우선순위는 다음과 같다.

1. 기존 정확한 타입/이름의 native 참조가 있으면 이를 사용한다. 이름 충돌의 null 참조를 파일로 우회하지 않는다.
2. 참조가 없고 DMD2에서 검토한 고정 날짜일 때만 설치 파일의 날짜를 내부 DisplayDefinition으로 읽는다.6개 파일의 SHA-256·크기 확인이 먼저이며, 날짜 범위·스키마·끝 위치·ID 타입·중복·개수 상한을 확인한다.
3. 현재 시각·임무 저장 시각·플래그·수량·실행 횟수 등은 파일 기본값을 현재 값으로 대신하지 않는다. 필요한 현재 참조가 없으면 미확정이다.

게임의 ScriptableObject나 GameTime을 생성·대입하지 않는다. 내부 날짜는 기존 안전한 reader의 ConvertToRounds 대응 계산에만 쓰며, 게임 Condition/Switch/Execute/Reset·Lua/RNG·세이브·효과를 실행하지 않는다. 파일 자료는 일반 경로 reader에만 제공하고 엄격 기회/1회성 증명에는 제공하지 않는다. 따라서 새 안내는 아이보리 배지이며 금색 기회의 증거가 되지 않는다.

## 수명·설정·성능

고정 날짜는 기존 작업 스레드의 일회 파일 검증/해석에 포함된다. 인덱스 증가는337바이트다. 정상 갱신마다 파일 검색·SHA 계산·날짜 파싱을 추가하지 않는다. 현재 날짜·초회 플래그를 포함한 실제 입력은 기존 ReadStamp로 검증하므로 완료·기한 경과를 즉시 반영한다. 미확정인 현재 시각을 고정 날짜로 대체하지 않는다.

정상0.25초/실패5초·협력식 준비5ms·Lua1개/8192작업·정상 웜 주기 Lua 재분석 없음·숨김/OFF 중단·로드/장면/소유자 변경의 정리·기존 캐시를 유지한다. 실패한 다른 후속 경로의 기존 재시도는 별개다. 설정 키·기본값·cfg·Xbox/XInput·키보드·마우스·터치·입력 소유권/해제/중립 보호는 바꾸지 않는다.

## 자동 검사와 한계

`FileCalendarCases`는 제공된 실제 설치 파일과 번체 Lua2,199개를 사용하고 현재 상태·Unity/게임 경계는 명시적 대체 객체를 사용한다. 고정 날짜 분류를 뺀 상태에서 연단방만 누락되는 이전 동작을 재현한 뒤, 같은 상태에 날짜 정의를 제공해 장소 미선택·미진입에서도 연단방/남제자방 안내를 확인한다. 기한 마지막 순·기한 경과·완료 후 제거·복구, 현재 시각 누락·참조 충돌·native 우선순위, 가변 시각19개 제외·잘못된 ID 타입·중복 거부, 엄격 증명 분리·정상 웜 자원 조회/재분석 없음을 검사한다.

전체 검사·제공 DLL 연결·고정 커밋 재빌드·배포 ZIP 검증 결과는 [릴리스 기록](ISSUE-6-ALPHA34-RELEASE.md)에 기록한다. 초기 검사에서 미사용 그룹을 root에서 찾는 잘못된 가정과, 현재 값 변경 후 다른 후속 경로의 자원 조회까지 금지한 과도한 검사를 수정했다. 최종 검사는 현재 입력이 같은 정상 주기의 무조회와 상태 변경 후 기존 준비/재시도 계약을 구분한다. 위 내용은 초기 실패에 대한 요약이며 최종 검사 로그는 로컬 artifacts에 보존한다.

실제 Windows/Unity/Harmony·사용자 세이브·물리 입력·FPS/GC는 실행하지 않았다. 특히 게임 완전 재실행 후1년4월상순 지도 저장 직행, 연단방 진입 전 마커/툴팁, 한담 완료·기한 경과 뒤 제거를 새 DLL로 확인해야 한다. #6 전체 완료/이슈 종료는 대기다.

# PRD #6 alpha.14 — 장소·선택지 옆 기회 표식

상태: main 구현·전체 자동 검사 21개 프로그램·실제 DLL 연결/읽기 전용 IL 검사 통과. 고정 커밋 재빌드·prerelease 게시는 준비 중이다. 새 DLL의 실제 Windows 확인과 #6 전체 완료는 대기다.

## 게임에서 달라지는 점

좌측 상단의 지도·선택 안내를 실제 장소·선택지 근처로 옮긴다. 현재 확인된 실행 기회가 있으면 붉은 점 `●`을 붙이고, 패드·키보드의 현재 선택 또는 움직인 마우스가 가리키는 항목 옆에 설명창 하나를 표시한다. 항목이 여러 개면 최대 세 행과 나머지 수를 보여준다. 가장자리에서는 좌우·위아래 중 가려짐이 적은 위치로 옮기고 화면 안으로 제한한다. 분기 알림은 기존 우측 상단 5초 표시를 유지한다.

붉은 점은 주의 표식이며 색 자체가 발생 확률이나 1회성 판정은 아니다. 이름·종류·상태를 함께 읽어 구분한다. `진행 가능`·`선택 후 진행 가능` 등의 확정 상태 문구는 기존 초록색을 유지한다. `진행 가능성 있음`은 확정 표식의 근거로 쓰지 않지만 실제 현재 선택의 상세 안내에는 남을 수 있다. 게임의 후속 이야기 실행을 보장하지 않는다.

| 화면 | 점의 허용 범위 | 설명·상세 |
| --- | --- | --- |
| 지도 전체 | 현재 실제 대기 목록 중 행동력·장소 활성·주/보조 우선순위를 통과한 항목. 이미 준비된 증명 1회성은 현재 조건·경로까지 새로 통과한 경우 | 원래 게임 포커스/호버 옆에 한 패널. 미선택 장소의 Lua를 새로 준비하지 않음 |
| 현재 선택 화면 | 실제 활성 선택지에 연결되고 현재 판정이 확정된 이야기 행 | 현재 선택 옆 짧은 경로. 불확실한 경로는 확률/발생 보장 없이 구분 |
| 로그 → 도구 → 지도 안내 | 자동 범위 밖의 미등록 단계·일반 후속 대화·전체 조건·효과·경로 | 기존 스크롤 상세와 현재 입력 표본 유지 |

표식이 없어도 전체 게임의 기회 없음이 아니다. 숨김·비활성·화면 밖·카메라 뒤·좌표 확인 실패·읽기 실패에서는 점을 표시하지 않는다. 기존 준비가 끝난 빈 장소는 패널도 숨긴다. 준비·실패 사유는 기존 상세에서 구분한다.

## 입력·설정

원래 장소·선택지에 포커스를 옮기면 마우스 없이 읽는다. 점과 설명은 `GUI.Label`이며 새 버튼·선택 대상·이벤트 소비·강제 포커스·클릭 동작이 없다. A/Enter/클릭은 원래 게임 동작이다. 터치도 원래 동작을 유지하며 새 길게 누르기/별도 터치 선택을 요구하지 않는다. 멈춘 마우스가 다른 곳에 있어도 패드/키보드 포커스 변경이 우선한다.

**L3/R3 겹침 → 해제·중립 → Y 도구 → 지도 안내 → ↑↓/왼쪽 스틱 항목 → 오른쪽 스틱 상세 → B 복귀**를 유지한다. 기존 네 탭·예약·이벤트 선택·주사위·XInput 입력 소유권과 해제/중립을 변경하지 않는다.

새 설정·단축키는 없다. 기존 기본 ON의 `EnableMapGuide`가 대기 임무 점과 현재 선택 안내, `EnableOneShotHints`가 증명 1회성 점/기존 태그를 제어한다. 관련 OFF 시 표식 스냅샷을 버리고 남은 기능의 현재 자료만 다시 읽는다. `EnableOptionInfo` 시작 시 상위 차단과 네 개별 설정의 저장 규칙은 그대로다. cfg 변경이 없으므로 업데이트는 DLL만 교체해 기존 cfg를 보존한다.

## 성능과 읽기 전용 경계

- 정상 0.25초·실패 5초로 하나의 지도 표식 배치를 읽는다. 실제 대기 목록을 최대 256개까지 한 번 열거해 장소별 첫 항목만 나눈다. 전체 임무 정의 색인은 열지 않는다. 행동력 자료는 배치 안에서 한 번 읽고 최대 256개 능력치 안에서 찾는다.
- 등록된 보이는 장소 최대 64개, 준비된 1회성 후보 최대 64개/현재 이벤트 판정 최대 16개, 약 5 ms 협력적 양보를 적용한다. 범위나 시간 한도 뒤의 장소·항목은 표시하지 않을 수 있다. 단일 동기 읽기나 실제 프레임 시간의 강제 상한은 아니다.
- 미선택 장소의 `GetSource`·경로 준비·효과/결과 파싱을 시작하지 않는다. 기존에 완성된 증명/정의만 재사용하고 현재 조건과 도달성은 매 조회 새로 읽는다. 일반 Lua/로드/장면/OFF 정리에서 이전 현재값·표식을 버린다.
- 렌더링은 등록된 실제 컨트롤·최대 16개 collider UI의 좌표만 읽는다. `FindObjectsOfTypeAll`·전체 씬 탐색·raycast·게임 판정·플래그 임시 변경을 하지 않는다. 실제 canvas/root camera 또는 FreeManager `_mainCamera`로 투영하고 확인 실패 시 숨긴다.
- 로그/팝업/현재 메뉴 뒤·비포커스·관련 기능 OFF에서는 자동 표식의 자료 조회를 멈춘다. 텍스트 측정은 내용·글자 크기·화면 변경 때만 하고 움직이는 좌표는 측정 없이 다시 배치한다.

게임 판정·RNG·세이브·능력치·아이템·선택 상태를 바꾸지 않는다. 기존 alpha.13의 제한된 완성 구문 공유·준비 양보를 유지한다. 기존 `지도 조회 성능` 표본은 **선택 장소 제공자만** 측정하며 새 전체 표식 배치/좌표/UI나 전체 프레임 비용을 포함하지 않는다. 실제 비교는 Windows 외부 프레임 측정을 병행해야 한다.

## 외부 비교에서 채택한 것과 제외한 것

- [조활시스템 MapIndicators.cs:16–62](https://github.com/Toufff/zhaohuo-system/blob/b6edf70a90f9cd7b84ca0ccbd6db0aa94ea4c8c2/src/ZhaoHuoSystem/MapIndicators.cs#L16-L62)는 준비된 지도 표식과 항목 옆 tooltip을 사용한다. [OptionHints.cs:54–80](https://github.com/Toufff/zhaohuo-system/blob/b6edf70a90f9cd7b84ca0ccbd6db0aa94ea4c8c2/src/ZhaoHuoSystem/OptionHints.cs#L54-L80)는 1회성 점과 짧은 요약을 붙인다. 기존 지도 전체 객체 탐색과 호버만의 조회 방식은 가져오지 않는다.
- 로컬 EventGuide 0.9.2의 [GuideMenus.cs:163](</Users/im-yongbeen/dev/jungpaeng/활협전 참고할 모드/LOM_EventGuide_0.9.2_test/source/EventGuide/GuideMenus.cs:163>)는 원래 버튼 근처 `!/?`와 native 선택/호버를 함께 쓰고, [GuidePlugin.cs:457](</Users/im-yongbeen/dev/jungpaeng/활협전 참고할 모드/LOM_EventGuide_0.9.2_test/source/EventGuide/GuidePlugin.cs:457>)은 화면 경계에 맞춰 설명 위치를 옮긴다. 같은 파일의 플래그 임시 쓰기·복원이나 실제 Check 호출은 DiceMaster의 읽기 전용 계약과 맞지 않아 제외한다. 두 모드의 독립 계보를 확정하지 않았으므로 독립 표 두 개로 세지 않는다.
- 독립 UI 도메인의 [Dear ImGui imgui.cpp:5015–5033](https://github.com/ocornut/imgui/blob/4be0b47ecc0edd535a40a79f6ceb6f1ac5936483/imgui.cpp#L5015-L5033)는 키보드/패드의 native 포커스와 마우스 tooltip 조건을 구분한다. 이 원칙을 적용하되 점의 색이나 배치 수치가 보편적 정답이라는 근거로 쓰지 않는다.

따라서 고정 좌측 상단 패널과 전면 미래 이야기 예측 대신, **얕은 현재 표식 + 포커스 옆 설명 하나 + 명시적 전체 상세**를 선택했다. 상호작용 방식의 근거는 중간 이상이며 붉은색·구체 위치·실제 프레임 성능의 우월성은 아직 Windows에서 검증해야 한다. 외부 구현의 코드를 복사하지 않았다.

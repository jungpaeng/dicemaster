# alpha.39 — 주사위 결과별 이야기 연결 안내

게시 준비 기록이다. 원래 `main`에서 구현했으며 별도 브랜치/worktree를 생성하지 않았다. alpha.38의 주사위 `진행 중` 패널·확정 결과 기록을 되돌린 `2db6a19`와 이번 결과별 안내를 함께 게시한다. **실제 Windows 확인과 PRD #6 전체 완료는 대기다.**

## 변경 사항

실제 열린 지원 주사위의 각 결과 행 옆에 두루마리 마커와 짧은 이야기 연결을 표시한다. 이전 선택지의 마커 유무와 관계없이 조회한다. 아이보리는 해당 결과를 가정한 연결 후보이며, 어두운 금색은 기존 기준대로 등록 임무/증명 1회성과 현재 경로를 모두 확인한 경우다. 미래 추가 판정·선택·상태 변경 이후의 이야기 발생을 보장하지 않는다.

alpha.38의 우측 상단 주사위 진행 알림은 제거했다. 기존 실제 이벤트·조건 분기의 5초 알림/최근 20건 기록은 유지한다. 주사위 확정 결과를 그 기록에 추가하지 않는다. 상세는 기존 로그 → 도구 → 지도 안내에서 결과별로 읽는다.

원래 효과·임계값·주사위 조작을 유지한다. TMP 표시 공간이 부족하면 새 요약만 생략하며 마커/상세 조회는 남긴다. 새 설정·입력·탭은 없다. `EnableMapGuide`와 `EnableOneShotHints`를 따르고 `EnableBranchNotices`와 독립적이다. 정상 0.25초/실패 5초·숨김/OFF 조회 중단·현재 화면의 제한된 준비/캐시·읽기 전용과 기존 패드 입력 보호를 유지한다.

현재 자동 연결은 관찰한 원문/`ExecuteRoll`의 키·원본 결과 배열이 하나의 호출 위치를 식별한 경우만 지원한다. 중복 서명·동적/미지원 문법·레거시 ShowTimer·다른 모드가 임의 생성한 화면을 추측해 표시하지 않는다. [설계·설정·성능 상한·한계](ISSUE-6-DICE-RESULT-GUIDANCE.md).

## 자동 검사와 파일

고정 참조 16개와 사용자 게임 복제본 DLL 16개를 각각 연결한 전체 22개 검사 프로그램을 통과하고 같은 모드 DLL을 생성했다. 빌드 입력 319개·생산 소스/리소스 128개를 기록했고 참조·입력 불변을 확인했다. 릴리스 검증기 자체 검사 20개와 ZIP 두 경로/CRC/내부 바이트 대조를 통과했다. cfg는 이전 버전과 같다.

주사위 원문 288파일/402호출 형태를 색인하고 결과 격리·거짓 AND 조건 제외·서명 중복 차단·일반 지도 가정 격리·등록 임무/예약·설정/가림/불러오기·글자 폭과 임계값·수동 배지/입력 보존을 검사했다. 1,000회 웜 경로 재조회는 새 파싱/준비 작업이 없고 1,000회 변경 없는 표시에는 재측정·요약 중복이 없다. 이는 실제 Windows/Unity/Harmony·사용자 세이브·물리 패드·FPS 검증이 아니다.

게시 전 고정 커밋 재빌드와 검토 후보 대조를 추가 수행한다. 기록은 `artifacts/releases/v1.0.7-alpha.39/`, 기존 검토 후보/복제본 연결은 `artifacts/issue-6/dice-route-guide/`에 보관한다.

## 설치와 Windows 확인

활협전용 BepInEx 모드 베이스가 필요하다. 게임을 종료하고 DLL/cfg를 백업한 뒤 새 ZIP의 `plugins/DiceMaster/DiceMaster.dll`만 교체하여 기존 cfg를 보존한다. 최초 설치는 ZIP의 `config`·`plugins`를 BepInEx 아래에 넣는다. 자동 Source code 압축은 설치용이 아니다. 문제 시 게임 종료 후 백업 DLL/cfg를 복구한다. 게임 원문·DLL/자산은 배포하지 않는다.

새 후보로 굴리기 전 결과별 요약/마커, 실제 연결, 긴 효과·임계값과 여러 해상도, 창 가림/설정/불러오기, 기존 주사위·로그·예약·팝업·패드 조작과 최초 지연/FPS를 확인해야 한다. [Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md#주사위-결과별-안내--로컬-후보-확인-대기).

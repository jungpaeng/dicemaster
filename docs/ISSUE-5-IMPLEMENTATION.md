# PRD #5 — 이번 행동의 이벤트 선택 팝업 구현 기록

상태: **v1.0.6-alpha.3 준비 중 — 전체 로그 터치·팝업 행 재클릭 진행 보완**. 최신 `origin/main`을 기준으로 구현하며 검사·고정 소스·게시 결과는 [alpha.3 배포 안내](ISSUE-5-ALPHA3-RELEASE.md)에 실제 확인 후 기록한다. 아래 동작·입력 절은 현재 alpha.3 후보 안내이며 마지막 로컬 검증 절은 alpha.1 당시 기록이다. [PRD #5](https://github.com/jungpaeng/dicemaster/issues/5)의 새 이벤트 실행 방식은 사용자 확인 전까지 완료로 취급하거나 이슈를 닫지 않는다. [이번 후보 Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md)를 별도로 사용한다.

alpha.2는 2026-10-20 01:02:17 KST에 고정 소스·태그 `e71020020b1b7f1938f22ff4a60d046c8bace839`의 재빌드·14개 검사·공개 다운로드 검증을 마치고 게시했다. 이후 사용자는 팝업 터치 행 선택 성공과 전체 로그 터치 실패를 보고했다. 당시 검사·파일·게시와 제한된 사용자 확인 범위는 [alpha.2 배포 안내](ISSUE-5-ALPHA2-RELEASE.md)에 보존한다.

최초 alpha.1은 2026-10-20 00:32:06 KST에 고정 커밋 `9c257b76b8a551022b6ea606c35b91e870c4a654`의 재빌드·14개 검사·공개 다운로드 검증을 마치고 게시했다. 당시 조작과 파일·검사 결과는 [alpha.1 배포 안내](ISSUE-5-ALPHA1-RELEASE.md)에 보존한다.

## 구현 시작 기준

2026-10-20 Asia/Seoul의 이 대화에서 사용자가 **“v1.0.5에서 Windows 확인 완료”**라고 확인했다. PRD #4의 안정화 배포본 v1.0.5를 선행 기준으로 사용한다. v1.0.5의 소스·태그 커밋은 `8886309e2a7248fa13544f81546e3c4795ff9611`, 이번 작업 시작 HEAD는 `40813f9`다. [기존 정식 배포 기록의 후속 확인](ISSUE-4-STABLE-RELEASE.md#2026-10-20-사용자-후속-확인)을 따른다.

이 확인에는 게임·로더 버전, 패드 모델, Steam Input 구성, 해상도·배율, 개별 시나리오나 설치 DLL 해시가 제공되지 않았다. 그 세부 환경을 추정하지 않으며, 기존 확인을 이번 팝업·결과 직접 지정·조건 무시 기능의 Windows 확인으로 재사용하지 않는다. PRD #4 당시의 게시·검사·해시는 역사 기록으로 보존한다.

## 사용자 동작과 설정

기존 로그는 정보를 읽는 화면이다. 로그를 닫아 게임 행동·대화 선택지를 조작한 뒤, **지원하는 실제 이벤트 판정 직전**에 좌측 하단의 작은 팝업이 나타난다. 팝업은 현재 행동의 실제 후보 이름·발동 상태와 선택 항목의 짧은 조건 설명을 표시한다. 초기 선택은 `무작위로 진행`이며 정상 발동 가능한 후보를 앞에, 각 그룹 안에서는 원래 후보 순서대로 둔다. 초점은 현재 판정의 대상 ID로 유지한다.

| 선택 | 동작 |
| --- | --- |
| 이 이벤트로 진행 | 현재 후보의 소속·결과 ID와 발동 자격을 확정 직전에 다시 검증한 뒤 해당 결과를 직접 반환한다. |
| 조건 무시하고 이번만 진행 | 미충족·가중치 0·난수/분석 미지원으로 미확인인 현재 후보를 명시적으로 지정한다. 대상과 결과 자체를 읽을 수 있는 경우에만 허용한다. |
| 무작위로 진행 | 결과를 지정하지 않고 이번 대기를 끝내 원래 게임의 조건·가중치·난수 판정으로 진행한다. |

조건 무시는 **이번 판정의 발동 자격 검사**에만 적용한다. 능력치·호감도·스토리 플래그를 선행 수정하지 않는다. 지정 이벤트의 정상 보상·수치 변경·대화·내부 분기는 게임이 처리하며 내부의 모든 이야기 조건까지 통과시키는 기능은 아니다. 사전 예약·다음 행동 반복·지난 선택 반복과 현재 행동 밖의 임의 이벤트 실행은 제공하지 않는다.

전체 후보가 정확히 하나이고 대상·결과를 읽을 수 있으며 정상 발동 가능하다고 확인되면 팝업을 생략하고 원래 게임을 진행한다. 하나라도 미충족·가중치 0·판정 미확인이면 팝업을 제공한다. 복수 후보 중 가능한 항목이 하나뿐이어도 나머지를 숨기거나 자동 선택하지 않는다. 후보가 없거나 실행 경로·후보군을 읽지 못하면 대기를 만들거나 유지하지 않고 원래 판정으로 넘긴다.

새 영구 설정은 기존 BepInEx `[DiceMaster]`의 `EnableEventSelectionPopup: bool`이며 최초 기본값은 `true`다. 로그 **도구 → 이벤트 선택 팝업 사용: ON/OFF**에서 마우스·패드로 변경하며 기존 `ConfigElement`의 cfg 저장 경로를 사용한다. 별도 설정 파일·원격 플래그·계정·세이브 형식은 추가하지 않는다.

- ON이고 기존 상위 `EnableOptionInfo`가 유효하게 켜져 있을 때만 새 판정 대기를 시작한다.
- `EnableOptionInfo=false`로 시작하면 팝업 저장값을 바꾸지 않고 해당 후킹·대기를 비활성화한다. 상위 옵션을 켜는 기존 재시작 계약은 유지한다.
- 설정 누락의 최초 기본 ON과 설정 조회 실패를 구분한다. 조회·평가 실패는 해당 판정에서 대기 없이 원래 진행으로 복구하며 BepInEx에 진단한다.
- 미확정 대기 중 OFF로 바꾸면 선택을 취소하고 다음 Lua 재개에서 원래 판정을 한 번 진행한다. 화면만 숨기고 대기를 남기지 않는다. 다시 ON은 다음 새 판정부터 적용한다.

## 실제 실행 경계와 지원 범위

구현 전 기존 읽기 전용 게임 참조의 메타데이터·IL에서 `CheckPointManager.Position`과 `PositionResultData.GetResult`의 **동기 반환** 및 Lua 코루틴 호출 경계를 확인했다. 동기 `Position` 자체를 화면 대기로 막지 않고, 지원되는 Lua 호출 표현식 바로 앞에 코루틴 yield 경계를 둔다. 실제 Windows 게임에서 같은 경로가 실행되는지는 별도 확인 대상이다.

| 경로 | 이번 구현 |
| --- | --- |
| 로드된 Lua의 직접 호출 `checkpointmanager.Position("문자열 리터럴")` | 구문 분석으로 해당 호출만 감싼다. 실제 실행 중인 비메인 Lua 코루틴·현재 게임 manager 객체·스크립트/호출 위치/문맥 토큰이 맞을 때만 대기한다. |
| 감싼 실제 호출이 대기를 통과한 뒤의 `Position` → `GetResult` | 같은 현재 후보군·결과 식별자·판정 인스턴스를 검증하고 정상/조건 무시 지정 결과를 한 번 반환한다. 나머지 게임 진행은 원래 호출이 처리한다. |
| 미리보기에서 발견한 호출·마우스 위치·큰 로그 관련 목록 | 조회 전용이다. 실행 토큰이나 사전 지정 요청을 만들지 않는다. |
| 변수 인수·별칭·콜론 메서드·동적 호출·일반 C# 동기 호출·메인 Lua 실행 | 선택 대기를 만들지 않고 원래 게임으로 넘긴다. 모든 이벤트 호출을 지원한다고 주장하지 않는다. |
| 별도 코루틴의 동시 판정, 안전한 삽입/콜백 바인딩 불가, 지원 구문/크기 한도 밖 | 원래 경로로 넘긴다. 다른 실제 판정의 대기나 토큰을 공유하지 않는다. |

Lua의 주석·문자열에서 추출한 이름만으로 실행 중인 후보라고 판단하지 않는다. 변환 시에도 실행하지 않으며, 콜백이 실제 호출 위치에 도달하고 현재 manager가 일치해야 후보군을 얻는다. 기존 선택지 분석 파서를 통째로 대체하거나 게임 DLL·게임 소스를 배포에 추가하지 않는다.

큰 로그의 이벤트 예약 버튼과 `TargetEvent`의 **99999 가중치 보정·예약 상태·실행 요청**을 제거했다. 새 결과 직접 지정과 옛 가중치 예약을 함께 적용하지 않는다. **미션 조건 통과 예약·해제의 기존 소속 검증·수명은 유지**하고 주사위 임의 정수·음수·0 자동과 기존 패드 조정도 유지한다.

## 조회 상태와 큰 로그

발동 자격은 `EventEligibilitySnapshot`의 구조화된 상태와 원인으로 게시한다. `정상 발동 가능`, `발동 불가 · 조건 미충족`, `발동 불가 · 최종 가중치 0`, `판정 미확인`을 한국어 텍스트로 구분한다. 난수·분석 미지원의 미확인과 실제 조회 실패는 다르다. 대상/결과 조회 실패·오래된 값·소속 불일치에서는 강제도 허용하지 않는다.

정상 확정은 안전한 읽기 전용 평가로 현재 조건·가중치를 다시 검증한다. 조건이 바뀌면 안내하고 같은 유효 행동에서 다시 선택하게 한다. 임의로 다른 이벤트·조건 무시·무작위로 바꾸지 않는다. 후보군이 사라지거나 시스템이 판정을 유지할 수 없으면 원래 경로로 복구한다.

기존 네 탭과 현재 스크립트에 연결된 관련 목록·전체 설명을 유지한다. **이벤트 탭에만** 이름·표시 이름·원본 식별자·설명 검색, 가능 항목 우선 정렬과 `발동 가능한 항목만 보기`를 제공한다. 필터는 최초 전체 보기이며 도구에서도 패드로 바꾸고 검색을 지울 수 있다. 물리 키보드로 검색하며 화면 검색 자판은 추가하지 않는다. 조건·미션·선택지 탭에는 검색을 복원하지 않는다. 이벤트 행의 A·재클릭은 사전 실행이나 예약을 만들지 않는다.

검색·필터·선택·스크롤과 팝업 초점은 실행 중 메모리 상태다. 선택이 필터 밖으로 나가거나 대상이 교체되면 이전 확인 권한을 취소한다. 표시색·번역 제목·확률 문자열을 역파싱하지 않고, 표시용 난수 샘플을 발동 자격 근거로 쓰지 않는다. 이전 정상 설명은 읽을 수 있어도 현재 발동 가능의 근거로 표시하거나 가능 필터에 넣지 않는다.

## 입력과 화면 전환

| 입력 | 작은 팝업 |
| --- | --- |
| 십자키·왼쪽 스틱 위아래 / 키보드 위아래 | 항목 이동·선택 행 스크롤 추적 |
| A / Enter / Shift+Enter | 표시된 기본 진행으로 확인. 정상 후보는 일반 진행, 미충족·가중치 0·미확인 후보는 명시 조건 무시, 무작위 행은 원래 판정 진행 |
| X | 팝업 확정 동작 없음 |
| B / Esc | 선택을 폐기하고 무작위 진행 |
| 마우스·터치 | 처음 누른 행은 선택만 한다. 선택된 행을 새로 누르고 같은 행에서 떼면 표시된 일반/명시 조건 무시/무작위로 확정한다. 진행 버튼 또는 무작위 버튼도 클릭·터치할 수 있다. |
| 기존 로그 열기 키(기본 Tab) | 행동 대기를 유지하고 팝업을 감춘 채 큰 로그 표시. 닫으면 같은 유효 문맥의 팝업 복귀 |

로그를 닫는 B는 돌아온 팝업의 무작위 진행으로 재사용하지 않는다. 로그의 탭·검색·스크롤과 팝업 초점을 별도로 유지한다. 로그 열기 키와 이미 제공하던 같은 패드 **L3/R3 클릭 겹침 열기**는 유지하며 이번 기능용 새 조합은 추가하지 않는다.

확인 버튼은 정상 후보에서 `이 이벤트로 진행 [A/Enter]`, 미충족·가중치 0·미확인 후보에서 `조건 무시하고 이번만 진행 [A/Enter]`을 표시한다. 대상/결과 읽기 실패는 차단한다. 일반 진행의 확인 권한을 받은 뒤 자격이 바뀌면 요청을 거부하고 새로 표시된 진행 방식을 다시 확인하게 하며 조건 무시로 자동 전환하지 않는다.

공통 버튼은 `GUILayoutUtility.GetRect`로 실제 영역을 확보하고 `GUI.Button`을 호출한다. 이벤트 검색 칸도 `GUI.TextField` 호출 전에 영역을 확보해 이벤트 소비 뒤 임시 영역을 읽는 문제를 피한다. 버튼 누름을 Unity가 소비한 뒤 `GetLastRect`로 영역을 읽던 순서를 제거한다. alpha.3은 실제/effective 누름·해제에서만 포인터 기록을 만들거나 끝내며 `rawType`만 입력인 화면 갱신·무시된 단계는 실행에 사용하지 않는다. 소비된 `Used`와 원래 입력 종류는 정리에 사용한다. 별도 터치 단계는 버튼 호출 안에서 마우스 단계로 전달해 Unity의 버튼 영역·스크롤 잘림·누름 소유권을 유지한다. 실제 Windows native 창의 전체 이벤트 전달은 관찰하지 않았으므로 사용자 증상의 원인을 한 창 필터로 확정하지 않는다.

팝업의 행 재클릭은 누름 시점에 이미 선택된 행에서만 확정 권한을 얻는다. 첫 선택 클릭은 실행하지 않으며 토큰·대상 객체·결과·일반/조건 무시 방식을 해제 때 다시 대조한다. 일반 진행의 자격이 바뀌거나 읽기가 실패하면 차단한다. 팝업은 새 프레임의 입력 중립 대기, 포인터로 전환하는 입력, 게임 입력 모드 변화에서 같은 유효 문맥의 누름·해제를 보존한다. 입력 모드 변화에서는 이미 대기 중인 확정을 폐기하고 새 확인을 받아야 한다. Alt-Tab·초점·문맥·대상·연결·소유자 등 안전 경계에서는 포인터 누름도 취소한다. 실제 Windows 트랙패드 클릭·마우스 에뮬레이션 터치와 별도 터치 이벤트의 결과는 자동 대역 검사와 별도로 확인한다.

팝업·큰 로그·주사위·게임 중 한 화면만 입력을 소유한다. 공유 native XInput 인스턴스를 재사용하며 모든 슬롯/채널 차단과 소유자 고정을 확장한다. 게임 선택지를 확정한 A와 팝업 A/B가 다음 화면에서 다시 작동하지 않도록 전체 버튼 해제·양쪽 스틱/트리거 중립을 거쳐 새 입력을 받는다. 안전 경계와 모드 변화의 패드·키보드 확정은 취소하고 중립을 기다린다.

읽을 수 있는 게임 입력 모드를 우선하고 불명 상태에서는 기존 양쪽 지원을 유지한다. 조회를 위해 게임 모드·커서 모드·액션 맵을 강제 변경하지 않는다. Windows Xbox/XInput이 확인 대상이며 Steam Input은 사용자가 실제로 확인한 구성만 기록한다. native 차단 경로를 확인하지 못하면 위험한 패드 확정을 막고 키보드·마우스 복구 경로를 제공한다. 다른 OS·모든 패드 구성이 확인된 것은 아니다.

## 갱신·수명·진단

큰 로그는 열린 현재 탭, 팝업은 실제로 보이는 현재 행동만 조회한다. 정상 주기 **0.25초**, 실제 읽기 실패 항목은 **5초** 재시도와 항목 실패 격리를 유지한다. 로그와 팝업이 모두 숨겨져 있으면 표시용 현재값 조회·자동 재시도는 0회다. 팝업을 숨겨 큰 로그를 읽을 때도 행동 대기는 유지하지만 숨은 팝업의 표시용 조회는 하지 않는다.

표시·검색·정렬·필터는 게시 캐시와 안전한 읽기 전용 평가를 사용한다. 원본 `GetRate/GetResult/Check/Execute` 체인을 표시 때문에 호출하지 않으며 게임 RNG·조건 카운터·예약·세이브를 변경하지 않는다. 정상 주기에는 전체 Lua를 재분석하지 않는다. 확정 직전의 검증은 표시 갱신과 별도 경계다.

토큰은 manager·후보군/결과 ID·Lua 문맥/판정 인스턴스에 묶는다. 로드·새 게임·씬/실행 문맥 변경·대상 소멸은 이전 토큰과 코루틴 권한을 폐기한다. 이전 흐름을 새 장면에서 재개하지 않는다. 정상·조건 무시·무작위·OFF·실패 복구에서 원래 호출과 결과 소비가 중복되지 않게 하며, 일부 효과가 이미 적용된 뒤 다른 결과로 재시도하지 않는다.

기존 BepInEx 로그의 `EventSelection` 접두사로 `wait`, `consumed`, `completed`, `release`, `invalidated`, `failure`, `recovered`를 남긴다. 필요한 판정 token·후보군/대상/결과 ID·일반/조건 무시/무작위 구분·복구 사유를 연결하고 같은 실패는 경계별 최초와 복구를 기록한다. 매 프레임 로그·전체 Lua·세이브·검색 원문·원격 지표를 수집하지 않는다.

## 최초 alpha.1 빌드·검사·후보와 복구 기록

기존 `net48` 전체 소스 프로젝트·고정 읽기 전용 게임 참조를 사용한다. 개발 명령은 다음과 같다.

```sh
python3 build/build-source.py --references '<읽기 전용 참조 루트>' --output-dir artifacts/issue-5/candidate
```

후보 생성 경로는 `artifacts/issue-5/candidate/`다. 최종 빌드·자동 검사·DLL/설정/ZIP 해시는 해당 경로의 `build-manifest.json`과 빌드 로그를 기준으로 별도 기록한다. 매니페스트의 `source_sha256`·`build_input_sha256`는 이 로컬 입력의 바이트 식별값이다. **00:21 KST 로컬 후보 생성 당시에는 새 고정 소스 커밋이 없었다.** 아래 로컬 입력 검증과 이후 prerelease의 고정 커밋 재빌드·공개 다운로드 검증은 별도 기록이며, 게시 결과는 [배포 안내](ISSUE-5-ALPHA1-RELEASE.md)를 따른다.

자동 검사는 실제 후보 DLL 경계와 renderer/model/controller 소스 및 명시적 게임/Unity/native 대역을 구분한다. 관리 코드 대역에서 측정한 시간·할당량은 측정 환경과 함께 기록하며 실제 Unity/Windows 프레임 성능이나 고정 ms 합격선으로 바꾸지 않는다. 사용자 Windows 확인은 아직 실행하지 않았으며 [이번 후보 확인표](ISSUE-5-WINDOWS-VALIDATION.md)에 남긴다.

설치 ZIP은 기존처럼 `plugins/DiceMaster/DiceMaster.dll`과 `config/DiceMaster.cfg` **두 파일만** 포함한다. 게임 소스·게임 DLL·새 세이브 데이터는 포함하지 않는다. 적용 시 게임을 종료하고 기존 DLL/cfg를 백업한 뒤 **DLL만 교체해 cfg를 보존**한다. 최초 실행 시 빠진 새 옵션은 기본 ON으로 추가된다. 문제 시 게임을 종료하고 백업한 이전 DLL을 복원한다. 필요할 때만 백업 cfg를 복원하며, **DLL 복원은 이미 진행·저장한 게임 상태를 되돌리지 않는다.**

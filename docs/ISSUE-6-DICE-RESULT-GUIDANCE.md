# 주사위 결과별 이야기 연결 안내 — alpha.39

## alpha.40 후속 수정 — 최초 활성화

alpha.39의 최초 주사위 화면 누락을 보완했다. `ExecuteRoll` 호출 인자를 대기 보관하고 실제 `UpdateOptions` 완료 후 현재 활성 소유자·문맥·원본 결과 행 전체를 대조해 결합한다. 초기 `MenuDialog.Awake → Clear`는 해당 초기화 범위에서만 대기를 보존한다. 실제 Clear/OnDisable/문맥 변경/초기화 실패는 취소하며 오래된 완료 통지로 복구하지 않는다. 기존 위쪽 주사위 패널을 다시 추가하지 않는다.

## alpha.38 되돌림과 이번 범위

사용자가 지적한 alpha.38의 우측 상단 `주사위 판정 / 진행 중`과 주사위 확정 결과 기록은 의도한 기능과 달랐다. 로컬 커밋 `2db6a19`에서 alpha.38 구현·게시 기록 커밋을 되돌리고 alpha.37의 기존 실제 분기 기록을 복원했다. 이미 게시된 alpha.38 태그·릴리스·설치 DLL은 이 소스 되돌림으로 바뀌지 않는다. 새 후보를 설치해야 이번 동작을 확인할 수 있다.

목적은 **어떤 주사위 결과가 어떤 이야기/선택 경로로 이어지는지, 굴리기 전에 결과 행에서 읽는 것**이다. 마커를 보고 들어왔는지와 관계없이 게임이 실제로 연 지원 주사위 화면을 조회한다. 이전 선택의 마커 근거를 따로 넘겨 강조하거나 전체 미래 이벤트를 탐색하지 않는다.

## 화면과 상세

- 결과 행 옆의 아이보리 두루마리는 해당 결과를 가정한 **이야기 연결 후보**다. 이후 추가 판정·상태 변경·사용자 선택까지의 발생 보장은 아니다.
- 어두운 금색 두루마리는 **이미 등록된 대기 임무와 확인된 현재 경로**, 또는 **안전한 1회성 증명과 확인된 현재 경로**가 있는 경우다. 미확정 조건·완료/잠김·불완전한 경로는 이 근거로 쓰지 않는다. 기존 일회 예약이 있으면 자연 실행 경로에 대한 검은 기회 표시는 보류한다. 주사위 결과 자체를 고르거나 보장한다는 뜻도 아니다.
- 결과 이름과 기존 효과 뒤에 `인물/주제 · 연결 후보` 또는 `해당 결과 시 진행 가능`이라는 짧은 요약을 붙인다. 표시할 수 있는 근거는 결과마다 최대 한 개다. 조회 중에는 해당 결과 행 옆에 준비 스피너가 나타날 수 있고, 준비가 끝난 빈 결과·지원하지 않는 연결에는 표시하지 않는다.
- 현재 TMP 글자 폭과 임계값 열을 피할 공간을 측정한다. 요약을 단계적으로 줄여도 안 맞으면 기존 효과 글자를 보존하고 새 요약은 생략한다. 이때 마커와 상세 로그로 확인한다. 실제 해상도·폰트·다른 모드 조합의 배치는 Windows 확인 대상이다.
- 상세는 기존 **로그 → 도구 → 지도 안내**에 `결과 1`, `결과 2` 등의 행과 `주사위 연결 자료`로 제공한다. 스크립트·실제 이야기 키·경로·현재 판정·해석 한계를 읽을 수 있다. 로그 네 탭과 기존 패드 탐색을 그대로 이용하며 다섯 번째 탭이나 새 입력을 추가하지 않는다.

결과 버튼은 게임이 원래 `interactable=false`로 만드는 상태를 유지한다. 마커 때문에 클릭·패드 포커스 대상을 만들지 않는다. 호버 없이도 짧은 요약을 읽고, 자세한 내용은 로그에서 조회한다. 숫자 입력·음수 지정·자동 굴림 복귀·기존 패드 LB 조정·해제/중립 보호는 기존 코드가 맡는다.

## 설정과 수명

새 설정 키는 없다. 기존 네 설정의 기본 ON과 상위 `EnableOptionInfo`의 재시작 적용을 유지한다. 패키지 cfg 바이트는 변경하지 않았다.

| 설정 | 이번 주사위 화면에서의 역할 |
| --- | --- |
| `EnableMapGuide` | 현재 결과별 일반 이야기 연결 후보·등록 대기 임무 안내 |
| `EnableOneShotHints` | 안전한 1회성 증명과 현재 경로를 확인한 결과 안내 |
| `EnableBranchNotices` | 기존 실제 실행 분기의 5초 알림·최근 20건. 주사위 안내와 독립적 |
| `EnableShopEffectInfo` | 기존 상점 사용·학습 효과. 이번 변경과 독립적 |

지도/1회성이 모두 OFF면 주사위 경로 조회도 멈춘다. 로그·팝업·다른 창에 가려지거나 앱 포커스를 잃으면 자동 표시를 숨기고 자신의 요약만 복원한다. 숨긴 동안 자동 조회를 진행하지 않는다. 현재 주사위를 닫거나 세이브 불러오기·장면/게임 문맥이 바뀌면 화면 소유자·행·경로를 버려 이전 표시가 재사용되지 않게 한다. 상세 로그를 명시적으로 조회하는 경우만 숨겨진 자동 화면과 독립적으로 읽는다.

## 원본 연결과 안전 경계

`ChoiceStoryPatches`에서 기존 #5 Lua 계측 전의 원문을 보관한다. `DiceMenuDialog.ExecuteRoll`의 원래 인자와 현재 native 결과 행을 수동적으로 관찰하고, **원문 스크립트 + 판정 키 + 순서가 같은 원본 결과 문자열 배열**이 하나의 호출 위치를 식별할 때만 연결한다. 표시 번역/이름만으로 연결하지 않는다.

`DiceRouteIndex`는 제한된 리터럴 테이블 → `ExecuteRoll` → `ResultSelection` → 숫자 동등 비교 형태만 색인한다. 동일 서명이 둘 이상이면 어느 위치인지 추측하지 않는다. 동적 결과·미지원 제어 흐름·API 덮어쓰기·손상된 원문도 자동 표시는 보류한다. 제공된 코퍼스의 402개 호출 형태를 색인했다는 것은 모든 호출을 유일하게 식별하거나 모든 후속 이야기를 표시한다는 뜻이 아니다.

가정한 결과값은 해당 결과 분기 전용 `MapRouteDefinitions.DiceArm`에만 넣는다. 일반 지도/선택지 생성자는 이 값을 받지 않는다. 그 이후에는 기존 해금·현재 조건·반복 활동 분리·완료 판정으로 경로를 거른다. `미확정 난수 AND false`는 표시 근거가 될 수 없다. 결과 분기 이전의 임의 지역변수 등 지원하지 않는 조건식도 긍정 근거로 쓰지 않는다. 실제 인물·플래그 예외 목록은 추가하지 않았다.

실제 주사위 실행/Continue·체크포인트 판정·RNG·세이브·능력치·아이템을 조회 코드가 호출하지 않는다. 원래 코루틴을 교체하지 않고 게임의 결과 선택·예약을 실행하거나 소비하지 않는다. 렌더링용 TMP 글자의 자기 요약만 붙이고 원본 키·임계값·폰트·레이아웃·버튼 활성 상태는 쓰지 않는다.

현재 자동 연결은 원문과 `ExecuteRoll`을 관찰한 화면에 한정한다. 제공된 Lua에서 사용하지 않은 레거시 `ShowTimer`, 다른 모드가 생성한 화면, 원문/서명이 없는 화면까지 지원한다고 주장하지 않는다. 이 경우 다른 결과에 잘못 붙이는 대신 안내를 보류한다.

## 성능 계약

정상 **0.25초**, 읽기 실패 **5초** 재시도를 유지한다. 현재 열린 주사위의 결과만 준비하며, 한 번 준비한 원문 구문·결과 분기 그래프는 해당 문맥에서 재사용한다. 표시할 결과가 없다는 서명 판정도 반복하지 않는다. 변할 수 있는 현재 조건은 새 주기에 읽으므로 이미 뜬 마커를 영구 고정하지 않는다.

- 원문 최대 524,288자/131,072토큰, 최대 호출 32곳/결과 16개, 색인 총 작업 상한 1,048,576.
- 화면 전체가 기존 5ms 준비 슬라이스를 공유하며 색인은 최대 262,144 작업, 의미 경로는 최대 8,192 작업/결과당 최대 2,048 작업으로 나눠 다음 조회에서 이어 간다. 결과마다 독립 5ms를 부여하지 않는다.
- 결과별 그래프는 최대 스크립트 8개·문맥 64개·항목 128개·깊이 4·총 작업 262,144. 현재 경로/조건/종류 조회에도 화면 전체 상한을 둔다. 차가운 1회성 증명은 한 조회에 최대 한 건이다.
- 변경 없는 1,000회 그래프 재조회에서 새 파싱/준비 작업이 없고, 1,000회 표시에서 새 폭 측정·요약 중복 추가가 없는 것을 자동 검사한다.

5ms는 준비 루프의 양보 기준이며 외부 자료/증명/텍스트 측정·Unity 렌더링까지 포함한 프레임 시간의 하드 상한이 아니다. 실제 FPS·GC·Harmony 조합은 Windows에서 확인해야 한다. 주기를 늘렸을 때 효과가 입증된 상태가 아니므로 이번에는 0.25초를 늘리지 않았다.

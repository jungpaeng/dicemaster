## 공통 표시 기준

당문 장소 지도와 청성·공동 유학을 포함한 실제 행동/선택 메뉴의 붉은 점은 아래 두 경우만 허용한다. 일반 인물 대화의 조건이 맞는다는 이유만으로 붙이던 선택 메뉴의 점을 제거한다.

| 항목 | 붉은 점 | 설명 |
| --- | --- | --- |
| 실제 등록된 대기 임무 + 해당 선택의 현재 실행 연결 확인 | 표시 | 실제 대기 목록과 시작 스크립트 연결을 각각 확인 |
| 안전하게 증명한 1회성 + 현재 조건·해당 선택의 도달 경로 확인 | 표시 | 활성 조건을 끄는 확정 결과와 현재 조건·가중치·경로를 각각 확인 |
| 일반/반복 인물 대화의 연결·현재 조건 충족 | 표시하지 않음 | 현재 포커스의 이야기·필요한 선택 경로와 초록 상태 문구는 유지 |
| 조건 미충족·선행 상태 변경·자료 누락·불명·분석 중 | 표시하지 않음 | 인식한 경로·표식 사유는 지도 로그 상세에서 조회 |

붉은 점은 원래 항목 옆 수동 표시이며 별도 클릭/선택 대상이 아니다. 패드·키보드의 현재 선택 또는 마우스 호버 옆에 설명창 하나를 띄우고 원래 A/Enter/클릭/터치 조작을 유지한다. 초록 `진행 가능`은 조건 상태이므로 일반 대화에도 남을 수 있으며, 붉은 점과 별도로 판정한다. 정보 조회는 실제 이벤트/RNG 결과를 선택하거나 게임을 진행시키지 않는다.

## 당문·유학의 실행 구조 차이와 지원 범위

당문의 PositionController 경로는 기존 행동력·장소 활성·주/보조 임무의 native 우선순위 확인을 유지한다. 유학의 SectionFree01/SectionFree02는 Lua choose 메뉴이므로 당문의 위치나 임무 우선순위를 그대로 대입하지 않는다.

선택 메뉴의 대기 임무 표식은 게임의 **이미 존재하는 MissionManagerData 인스턴스**에서 현재 MainMissionStart/MainCheckData 또는 ActiveSubMissions만 읽는다. 해당 실제 메뉴 선택에서 같은 시작 스크립트로 가는 확정된 literal SetNextScript/SetCurrentStoryScript → 인접 Init 실행 연결이 있어야 한다. 단순 등록·문자열 이름 일치·현재 임무 단계의 존재만으로 점을 붙이지 않는다. ChangeScene은 대기 조건을 다시 평가하므로, 이후 발생할 임무를 현재 등록만으로 보장하지 않는다. 새 임무를 활성화하거나 등록/예약하지 않는다. 인접 Init 직전에 확정된 시작 대상만 별도 메타데이터로 보존하며, Init 뒤 이야기·이벤트의 현재 도달성은 기존처럼 미확정으로 유지한다. 이 메타데이터를 이유로 일반 이야기의 진행 가능을 올리지 않는다.

1회성은 기존 OneShotProof·EventEligibility의 읽기 전용 판정을 재사용한다. 같은 이벤트 풀이라도 **현재 선택에 속한 경로**만 판정해 다른 선택의 참 조건을 빌려오지 않는다. 이름이 같은 메뉴 위치가 여러 개이거나 해당 경로에 상태 쓰기·미지원 호출·난수/미확정 판정이 있으면 양성으로 올리지 않는다. 원래 버튼의 행동력/공헌도 등 interactable 상태도 함께 확인한다.

**모든 유학 이벤트를 탐지하는 구현은 아니다.** 원본 section_01_free_start_02·section_02_free_start_02와 후속 자료를 SHA-256으로 대조한 관리 코드 회귀에서는 화면 준비·행동 소비·후속 판정의 불확실성 때문에 양성 점을 만들지 않는 것을 확인했다. 알려진 변경을 무시해 점을 늘리지 않는다. 현재 연결을 안전하게 증명하지 못한 유학 항목은 점 없이 상세의 `기회 표식 판정`·인식된 경로/사유로 남는다. 표시가 없어도 게임 전체에 기회가 없다는 뜻이 아니다. 실제 게임 설정 그래프·세이브·물리 UI 검증은 아직 남아 있다.

## 설정과 성능

새 설정·단축키·cfg 변경은 없다. 기본 ON의 EnableMapGuide는 지도/선택 메뉴의 대기 임무 점과 일반 이야기·경로 설명을, EnableOneShotHints는 증명 1회성 점과 기존 태그를 제어한다. 지도 안내 OFF/1회성 ON에서도 실제 메뉴의 1회성 조회는 독립적으로 유지한다. 관련 OFF 시 메뉴 스냅샷·현재 그래프를 정리하고 남은 기능만 새로 읽는다. 상위 EnableOptionInfo의 시작 시 차단·네 설정 저장 규칙과 분기/상점 기능은 유지한다.

- 기존 정상 0.25초·실패 5초·숨김/비포커스/OFF 조회 중단·로그 상세의 기존 갱신 소유권을 유지한다.
- 현재 메뉴 경로 엔진과 완성 구문 캐시를 재사용한다. 임무의 전체 정의 색인이나 미선택 장소의 새 Lua 분석을 시작하지 않는다.
- 선택별 이벤트/실행 연결 색인은 최대 64개 셀마다 양보하고 이어서 재개한다. 완료된 색인은 정상 갱신에서 다시 만들지 않는다. 대기 목록은 배치당 최대 256개 한 번, 후보 최대 64개·현재 이벤트 16개·새로 시작하는 짧은 결과 증명 1개와 약 5 ms 협력적 양보를 적용한다. 강제 프레임 시간 상한은 아니다.
- 현재 조건값·대기 멤버십은 매번 새로 읽고 문맥/로드/장면/OFF에 과거 표식을 버린다. 읽기 실패의 이전 양성은 점으로 재사용하지 않는다. 정상 주기마다 Lua를 재분석하거나 전체 효과 설명을 만들지 않는다.
- 실행 연결 메타데이터를 추가했지만 실제 Init/Position/Condition/Check·RNG·세이브·능력치·아이템·플래그 쓰기는 호출하지 않는다. 특정 문파·인물·플래그 예외 목록을 추가하지 않는다.

기존 지도 조회 성능 표본은 선택 장소 제공자만 측정한다. 선택 메뉴·좌표/UI·전체 프레임의 비용은 Windows에서 별도로 측정해야 한다.

## 자동 검사와 설치 후보

전체 21개 프로그램, 빌드 입력 261개·소스/리소스 107개·고정 참조 16개, 실제 DLL 연결·읽기 전용 IL을 통과했다. 선택 메뉴 2,424개·실제 DLL 경로/분석 통합 2,236개·런타임 연결 4,418개·UI 5,335개 검사를 포함한다. 검증 도구 자체 20개 검사와 git diff --check도 통과했다. 새 관리 코드 회귀는 일반 대화의 초록 문구/점 분리, 실제 대기 등록·해제·실행 연결, 같은 풀의 서로 다른 선택 조건, 증명 1회성의 현재 완료 플래그, native 버튼 비활성·독립 OFF, 100회 warm Lua/전체 효과 분석 없음, 원본 유학 두 메뉴의 불확실성 유지와 상세 사유를 포함한다. 실제 DLL 연결·읽기 전용 IL과 기존 전체 회귀도 검사한다.

# 지도·선택 화면의 이야기 툴팁과 이어 읽기

2026-10-22 원래 작업 폴더의 main에서 구현한 **alpha.26 후보**다. 사용자의 커밋·prerelease 지시에 따라 고정 커밋 재빌드와 새 게시를 진행한다. 공개 alpha.25 파일은 보존하며 새 Windows 확인과 #6 전체 완료는 대기다.

## 표시 기준

사용자 지시에 따라 지도에서도 추가 주제 선택 없는 초회 인사를 안내한다. 지도와 선택 화면이 MapRoutePath.ReadGuidance의 해금·완료·반복 활동·현재 필수 조건 필터를 공유한다. 실제 활성 버튼을 관찰한 선택 화면은 그 버튼 다음 선택부터 해금을 확인하고, 지도는 장소 진입 전이므로 첫 선택을 포함해 확인한다. 지도 진입 쓰기·행동력·장소 활성·대기 임무 우선순위 보호는 유지한다.

표시 대상이 되는 초회 인사나 해금된 후속 이야기 경로를 선택 장소 옆에 최대 하나 안내한다. 일반 경로만으로 기회 마커·기회 수·Available을 추가하지 않는다. 마커는 기존 실제 등록 대기 임무 또는 엄격한 1회성 증명과 현재 도달성 기준을 유지한다. 미선택 장소는 새 경로 분석을 시작하지 않는다.

잠긴/해금 미확정 주제, 완료 인사, 반복 활동의 고정 반응, 완료 근거가 없는 진입 대화는 자동 툴팁에서 제외한다. 내부 이야기의 미확정은 발생 보증으로 바꾸지 않는다. 인물·조건 키·플래그 예외 목록은 없다.

## 누락 원인과 수정

alpha.25의 지도는 매번 StoryEntries의 처음부터 32개 경로만 검사했다. 제외될 경로도 한도를 소비했고 다음 조회도 처음부터 시작해 뒤쪽 경로는 영구적으로 확인하지 못할 수 있었다. SHA를 확인한 room_001 원문과 합성 직렬화 조건을 연결한 재현에서는 같은 후속 주제가 선택 화면 29번째에 있어 보였지만 지도 34번째여서 빠졌다. 이는 사용자의 색종이 번역/세이브 내부 키를 직접 읽은 검증은 아니다.

현재는 정의 준비 과정에서 보존된 이야기·경로 쌍을 append-only 목록에 등록한다. 선택 장소의 색인은 조회당 최대 64개 새 메타데이터만 읽고, 이미 읽은 정의는 다시 수집·정렬하지 않는다. 같은 이야기 항목에 나중에 추가된 경로도 목록에 들어온다. 경로 수는 기존 이야기 항목/항목별 경로 상한에 제한된다.

현재 조건 조회는 기존 32경로/32조건·분류 예산에서 이어 읽는다. 조회 커서를 다음 갱신까지 보관해 앞쪽의 잠긴 항목 때문에 뒤쪽이 굶지 않게 한다. 남은 조건 예산이 부족해 경로를 다 확인하지 못하면 다음 조회의 새 예산으로 먼저 재시도한다. 전체 예산을 넘는 경로는 그 순회에서 건너뛰어 다른 경로를 막지 않는다. 알려지지 않은 조건을 참으로 바꾸거나 판정 상한을 높이지 않는다.

## 무엇을 재사용하는가

기존에도 지도는 유효 경로 하나를 찾으면 반환했고 완성된 Lua 구문/정의를 재사용했다. 이번에는 직전에 표시한 **경로 정의의 참조**를 먼저 검사한다. 여전히 유효하면 즉시 반환하므로 앞선 실패 후보를 다시 읽지 않는다. 유효하지 않으면 툴팁에서 즉시 제거하고 이어 읽는다. 한 경로를 안내하는 목적에 맞는 최적화이며 모든 이야기를 열거한 결과가 아니다.

선택 화면은 조건 상태가 더 확실한 후보와 추가 이야기 수를 고르는 기존 동작을 유지한다. 그 결과를 바꾸면서 첫 발견에서 임의로 중단하지 않는다. 이번 성공 경로 우선 단축의 측정 대상은 경로 하나를 안내하는 지도 제공자다.

해금/완료/횟수/플래그 값과 true/false 결과는 다음 갱신에 캐시하지 않는다. 과거 false도 순회 후 다시 읽어 새 해금을 발견한다. 완료·잠김·조건 자료 누락/복구는 현재 조회에서 반영하며 문맥·소스 교체/OFF/로드/장면의 정의 정리 때 커서와 참조도 버린다. 기존 조회 내부 조건 메모화와 가상 초기화 읽기는 유지한다. 게임 조건·Lua·RNG·카운터·플래그 초기화를 실행하지 않는다.

기존 8192작업·약5ms 협력적 양보·조회당 자원/풀 각1회·누적 분석 상한을 유지한다. 정상0.25초/실패5초·숨김/OFF 조회 중단·정상 주기 Lua 재분석 없음과 기존 입력 소유권/해제/중립은 유지한다. 단일 동기 작업이나 Unity 전체 프레임의 강제5ms 상한은 아니다.

## 반복 조회 측정

호스트 .NET8에서 생산 지도 제공자와 합성 직렬화 조건을 사용했다. 합법적인 작은 메뉴 여러 개에 28개 이야기를 두고 26번째만 열었다. 정의 캐시는 양쪽 모두 동일하게 재사용하고, 이전 성공 경로/커서만 유지하거나 매번 잊는 방식을 비교했다. 양쪽의 측정용 reflection 비용도 동일하며 워밍업 뒤 순서를 바꿔 각300회씩 세 번 측정했다.

| 지표 | 매번 처음부터 | 이전 성공 경로 먼저 재검사 |
| --- | ---: | ---: |
| 300회 조회 CPU 시간 중앙값 | 35.822875ms | 5.598083ms |
| 조회당 할당 중앙값 | 47098B | 11640B |
| 조회당 현재 플래그 읽기 | 26회 | 1회 |
| 측정 중 Lua 자원 읽기 | 0회 | 0회 |

이 표본에서 CPU 약84%, 할당 약75%를 줄였지만 버전 전체/실제 게임/FPS 개선율은 아니다. 현재 값을 전혀 읽지 않는 영구 결과 캐시는 완료·재해금 전환에서 틀리므로 채택하지 않았다. 정의 참조 색인에 필요한 보존 메모리는 추가된다. 정상0.25초 간격은 유지한다.

재현: MapGuideRouteIntegrationTests.dll --map-guidance-benchmark. 코드 tests/MapGuideRouteIntegrationTests/SelectedStoryScanCases.cs, 원자료 artifacts/issue-6/map-story-scan/benchmark.json. 성능은 테스트 합격 임계값으로 사용하지 않는다.

## 검사와 새 Windows 확인

새 회귀는 앞의32개 뒤 유효 경로의 발견, 커서 순환 후 새 해금, 성공 경로의 현재 값 재확인·완료/잠김 즉시 제거·자료 누락/복구, 소스 교체, 초회 인사와 완료 제외, 마커 미부여, 정의 색인/작업/읽기 상한을 검사한다. SHA 원본 room_001·talk_brother4를 합성 조건과 연결해 초회 인사에서 완료 후 후속 주제로 넘어가는 지도 공급자도 확인한다. 단일 큰 선택 메뉴의 기존16분기 상한을 늘리지 않는다. 실제 후보 DLL에서 지도/선택 화면 모두 공통 필터를 호출하는지도 검사한다.

게임 종료 후 DLL만 교체해 기존 cfg를 보존한다. 기본 cfg와 설정 도움말은 설명만 갱신하며 키·섹션·기본값은 같다. 실제 Windows에서는 초회 전/완료 후·색종이 등 해금된 주제·잠김/반복 대련만 남은 상태, 표시까지의 지연/완료 뒤 제거, 패드·포인터·창 가림과 최초/warm 프레임/할당을 확인해야 한다. 이전 후보의 부분 확인을 새 DLL 통과로 승계하지 않는다.

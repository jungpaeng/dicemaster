## 사용자에게 달라진 점

- 이벤트 판정에 더해 지원하는 대화 중 `checkpointmanager.Switch` 판정도 직전에 선택 팝업을 표시한다. 강릉 포위전의 휴식 이후 `Ch_3_6_4_002`처럼 조건 탭에만 나타나던 분기를 고르고 결과 요약·상세와 분기 조건을 읽을 수 있다.
- 조건 탭 상단의 **조건 분기 선택 팝업: ON/OFF**, 이벤트 탭 상단의 **이벤트 선택 팝업: ON/OFF**에서 종류별로 켜고 끈다. 빈 목록에서도 사용할 수 있고 로그 도구에도 두 설정을 제공한다. 클릭·터치·A/Enter로 바꾸고 저장한다. 목록 맨 위의 ↑로 설정에 접근하고 ↓로 목록에 돌아온다.
- 이벤트 검색창·발동 가능한 항목만 보기와 관련 도구를 제거한다. 전체 목록과 가능한 항목 우선 정렬은 유지한다.
- alpha.10의 참조 기반 조건명 처리와 전용 모의 검사를 alpha.9 방식으로 되돌린다. 새 회상에도 내부 ID가 남는다는 사용자 보고에 따른 원복이며 `Ch_3_6_4_3_001` 표시 문제를 해결했다고 주장하지 않는다. [alpha.10 후속 보고·원복 범위](https://github.com/jungpaeng/dicemaster/blob/main/docs/ISSUE-5-ALPHA10-RELEASE.md#2026-10-20-사용자-후속-보고와-원복).

기존 이벤트 팝업의 첫 클릭·터치 선택 후 같은 행 재클릭·터치 확인, 결과 효과색·굵은 제목·불가 후보의 회색 표시, 하단 텍스트 안내와 중복 실행 방지를 유지한다. 이벤트 사전 예약은 제공하지 않고 미션 예약·해제와 주사위 조정은 유지한다.

## 팝업의 조작과 판정 의미

| 입력 | 동작 |
| --- | --- |
| 첫 클릭·터치 | 해당 행 선택만 수행 |
| 선택한 행을 새로 눌렀다 같은 행에서 떼기 | 표시된 일반 진행 또는 명시적인 조건 무시를 한 번 요청 |
| ↑↓·왼쪽 스틱 | 후보 이동 |
| A / Enter / Shift+Enter | 선택한 후보를 표시된 방식으로 확인. 미선택이면 진행하지 않음 |
| B / Escape | 조건 분기는 원래 조건·난수 판정, 이벤트는 원래 무작위 추첨으로 한 번 진행 |
| 휠·오른쪽 스틱 | 선택 결과·조건 상세 스크롤 |

하단은 안내 텍스트이며 실행 버튼이 없다. 클릭·터치로 실행하는 곳은 목록뿐이고 터치 전용 원래 판정 UI는 없다. 정상 후보는 일반 진행, 미충족·난수/미지원 판정 등 읽기 가능한 후보는 **조건 무시하고 이번만 진행**으로 구분한다. 대상·결과를 읽을 수 없으면 두 방식 모두 실행하지 않는다. 일반 진행을 요청한 뒤 자격이 바뀌면 조건 무시로 자동 전환하지 않고 새 상태를 보고 다시 확인한다.

직접 지정한 Switch는 **해당 Switch 자체 실행 횟수만 한 번 증가**시키고, 원래 검사의 조건·난수·중첩 조건 평가는 건너뛴다. 이어서 선택한 Lua 분기의 대사·효과를 실행한다. 능력치·호감도·스토리 플래그를 미리 바꾸거나 모든 후속 분기를 통과시키는 기능은 아니다. 직접 지정은 원래 난수 소비 순서를 보존하지 않는다. B/Esc·설정 OFF는 원래 검사를 그대로 한 번 실행한다.

팝업은 실제 분기 지점에서 열린다. 행동 선택 직후가 아니라 대화가 진행된 뒤 후속 판정에서 나타날 수 있다. `checkpointmanager.Position` 이벤트 팝업과 `Switch` 팝업은 같은 모달 소유권·입력/문맥 검증을 사용한다. 문맥·대상·실행 횟수가 바뀌면 이전 요청을 적용하지 않는다.

## 설정·설치·업데이트와 복구

Windows용 활협전과 **BepInEx가 포함된 활협전용 모드 베이스**가 필요하다.

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 백업한다.
2. 위 설치 ZIP을 받는다. GitHub 자동 `Source code` 압축 파일은 설치용이 아니다.
3. 업데이트는 **`plugins/DiceMaster/DiceMaster.dll`만 교체**해 기존 cfg를 보존한다. 최초 설치는 ZIP의 `config`·`plugins`를 기존 BepInEx 아래에 넣는다.
4. 문제 시 게임 종료 후 백업 DLL과 필요한 cfg를 복원한다. DLL 복원으로 이미 진행·저장한 게임 상태가 되돌아가지는 않는다.

새 `EnableSwitchSelectionPopup=true`는 실행 시 기존 cfg에 추가된다. 기존 `EnableEventSelectionPopup=true`와 사용자 저장값은 유지한다. 두 기능 모두 `EnableOptionInfo`가 켜져 있어야 한다. 해당 설정 OFF는 그 종류의 미확정 대기·접수 요청을 취소하고 원래 판정으로 진행하며 다른 종류의 저장값은 유지한다.

alpha.9로 돌아가면 기존 이벤트 선택 팝업과 입력 구조를 사용하며 새 Switch 팝업·탭 상단 설정은 제공하지 않는다. 조건명은 이번 버전과 같은 기존 객체 이름 중심의 표시를 사용한다. 이미 공개된 alpha.10 Release·태그·자산은 변경하지 않는다.

ZIP은 다음 두 파일만 포함하고 게임 소스·게임 DLL은 배포하지 않는다.

```text
config/DiceMaster.cfg
plugins/DiceMaster/DiceMaster.dll
```

## 지원 범위와 알려진 제한

지원하는 Switch는 비메인 Lua 코루틴의 직접 문자열 리터럴 호출을 지역 변수에 대입하고, 바로 뒤에서 그 변수를 정수와 동등 비교하는 `if/elseif/else` 형식이다. 해당 호출 지점의 Lua 본문과 실제 Switch 설정을 함께 확인하고 처리할 결과가 둘 이상일 때만 선택을 제공한다. 별칭·변수/동적 인수·복합 분기식·호출과 분기 사이의 다른 문장·메인 Lua·직접 C# 동기 호출은 지원하지 않는다. 해석 범위·작업량 한계를 넘으면 대기 없이 원래 게임으로 진행한다. 기존 이벤트 팝업도 지원하는 직접 리터럴 `checkpointmanager.Position` 경로에만 표시한다.

분기별 결과 설명은 해당 호출 지점의 본문을 기존 정적 분석기로 읽는다. 결과 요약·상세의 효과색을 보존하고 후속·중첩 불확실성을 표시하지만 미래의 모든 대사·조건·난수 결과를 확정하지 않는다. 회상·조건 설명에 내부 ID가 남을 수 있으며 확인하지 않은 ID를 특정 능력치로 고정 치환하지 않는다.

Xbox/XInput 패드, 마우스·트랙패드, 마우스로 인식되는 모니터 터치와 별도 터치 이벤트의 실제 장치별 결과는 자동 검사와 구분해 [Windows 확인표](https://github.com/jungpaeng/dicemaster/blob/main/docs/ISSUE-5-WINDOWS-VALIDATION.md)에 기록한다. 이번 새 DLL의 사용자 확인 전에는 이슈 #5를 완료로 닫지 않는다.

## Windows에서 우선 확인할 항목

아래는 시험 순서이며 아직 통과한 것으로 기록하지 않는다. 시험 DLL의 SHA-256·게임/로더 버전·장치를 [확인표](https://github.com/jungpaeng/dicemaster/blob/main/docs/ISSUE-5-WINDOWS-VALIDATION.md)에 먼저 남긴다.

1. 조건 탭의 팝업을 ON으로 하고 강릉 포위전의 **할 일 없이 그늘에서 쉰다**를 선택한 뒤 대화를 진행한다. 지원하는 Switch 직전 팝업이 뜨고 바둑 장면·만남 주사위 경로의 요약·상세가 구분되는지 확인한다.
2. 첫 터치로 선택하고 같은 행의 바로 다음 터치 또는 패드 A로 한 번 진행하는지 확인한다. 일반 진행·명시 조건 무시를 구분하고 중복 대사·효과가 없는지 기록한다.
3. 다시 해당 상황에서 B/Esc가 원래 조건·난수 판정을 한 번 실행하는지 확인한다. 조건 팝업을 OFF로 했을 때도 팝업 없이 원래 진행하는지 비교한다.
4. 조건·이벤트 탭의 설정을 서로 다르게 저장하고 재시작 뒤 유지되는지 확인한다. 빈 목록, 목록 위 ↑→설정 A→↓목록, 터치 뒤 패드 전환을 시험한다.
5. 기존 Position 이벤트 팝업·미션 예약·주사위 조정과 전체 로그의 탭·목록·도구 터치를 회귀 확인한다. 이벤트 검색창·가능한 항목만 보기 UI가 없는지 확인한다.

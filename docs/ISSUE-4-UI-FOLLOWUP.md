# PRD #4 UI 후속 수정 — Windows 재검증 대기

2026-10-19 KST. 사용자가 Windows의 `v1.0.5-alpha.1`에서 **UI가 너무 작음**, **목록·상세의 스크롤 영역이 너무 낮음**, **패드로 바꾼 포커스를 스크롤이 따라가지 않음**을 보고했다. 해당 세 항목은 alpha.1의 실제 실패 보고다. 이전 자동 검사 통과나 prerelease 게시는 이 실패를 해소한 근거가 아니다.

이번 변경은 위 보고를 수정한 뒤 사용자의 commit·prerelease 지시에 따라 [v1.0.5-alpha.2](ISSUE-4-ALPHA2-RELEASE.md)로 게시한 후보다. 기존에 공개한 alpha.1 자산은 수정하거나 덮어쓰지 않는다. 이 문서의 Windows 항목은 사용자 재검증 전까지 미확인이고, 이슈 #4는 미완료다. 에이전트는 게임을 설치하거나 실행하지 않았다.

## 원인과 변경

| 사용자 보고 | 확인한 코드 원인 | 이번 변경 |
| --- | --- | --- |
| 창과 글자가 작음 | 화면 해상도와 무관한 `750×750`, `14px` 기본값. 설정한 글자도 창 너비·높이의 계산식으로 다시 축소 | 기본값을 화면 높이에 맞춰 확대. 본문은 설정한 `12~64px`를 그대로 사용 |
| 목록·상세가 좁은 높이만 사용 | 스크롤 영역의 최소 높이·자동 배치에 의존. 별도 계산한 `contentHeight`는 실제 배치 높이를 정하지 않음 | 제목·탭·상태·검색·하단 안내를 뺀 나머지 사각형을 본문에 배정. 목록·상세·카드·도구·검색 자판에 명시적 뷰포트 높이 적용 |
| 포커스가 화면 밖으로 이동 | 선택 추종에 실제 뷰포트 대신 창 높이에서 추정한 `contentHeight` 사용 | `EndScrollView` 다음에 측정한 뷰포트와 콘텐츠 기준의 선택 행 좌표로 표시 범위를 계산 |
| 창을 제목에서만 끌 수 있음 | PRD #4에서 전체 창의 `GUI.DragWindow()`를 제목 높이의 사각형으로 제한 | 기존과 같이 창 전체를 드래그 영역으로 복원하고 안내 문구 수정. 컨트롤이 입력을 먼저 처리하도록 마지막에 호출 |

화면 배율은 PRD에 고정된 [조활 시스템 ToolWindow](https://github.com/Toufff/zhaohuo-system/blob/b6edf70a90f9cd7b84ca0ccbd6db0aa94ea4c8c2/src/ZhaoHuoSystem/ToolWindow.cs)와 [UiScale](https://github.com/Toufff/zhaohuo-system/blob/b6edf70a90f9cd7b84ca0ccbd6db0aa94ea4c8c2/src/ZhaoHuoSystem/Palette.cs)의 원칙을 참고했다. 참조의 창은 `900×620`, 본문 글자는 `16px`이고 화면 높이를 1080으로 나눈 배율을 적용한다. DiceMaster는 여러 카드 비교와 상세 읽기에 더 넓은 기본 공간을 배정한다.

| 화면 해상도 | 새 기본 창 크기(반올림 표시) | 새 기본 본문 글자 |
| --- | --- | --- |
| 1920×1080 | 1200×860 | 20px |
| 2560×1440 | 1600×1147 | 27px |
| 3840×2160 | 2400×1720 | 40px |

배율은 `clamp(화면 높이 / 1080, 0.85, 4)`이며 글자는 `round(20 × 배율)`을 사용한다. 화면보다 큰 창은 화면 안으로 제한한다. 탭·검색·하단 안내 등의 조작 영역은 본문과 별도의 읽을 수 있는 글자 크기를 사용한다. 큰 본문 글자나 작은 창으로 공간이 부족하면 상태·상세 조작 안내·검색을 스크롤 본문으로 옮기고 고정 하단 안내를 짧게 표시한다. 본문 글자를 몰래 줄이지 않으며 도구의 크기 조정·기본값 복구도 계속 탐색할 수 있게 한다.

배치에 쓰는 스타일의 `margin`을 0으로 고정해 게임 GUI 스킨의 여백이 높이 계산에 추가되지 않게 했다. 수평 스크롤바는 사용하지 않아 선택 행 하단을 가리지 않게 한다. 펼친 카드가 화면보다 길면 카드 헤더를 따라가고, 본문은 오른쪽 스틱이나 마우스로 읽는다. 상세의 예약 버튼은 별도 조작 글자와 실제 상세 너비로 문구 높이를 측정하여, 작은 창에서도 예약 안내가 잘리지 않도록 상세 스크롤 높이에서 차감한다.

창 이동은 선행 완료 커밋 `102cafe`의 `DicePlugin.DrawLogWindow` 마지막 `GUI.DragWindow()`와 같은 전체 영역 동작을 복원한다. [Unity의 컨트롤 우선 규약](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/GUI.DragWindow.html)에 따라 제목·본문 라벨·빈 공간을 끌어 이동하고, 버튼·검색 입력란·스크롤바가 먼저 입력을 소비하거나 마우스를 포착하면 해당 조작을 우선한다. 새 카드 헤더·목록 행은 버튼이므로 선택·펼침을 우선한다. 관리 코드 검사 대역의 `GUI.DragWindow`는 무동작이므로 실제 창 이동과 Unity의 마우스 포착 성공은 자동 검사 결과에 포함하지 않는다.

## 기존 설정과 스크롤 보존

저장은 기존 BepInEx 설정의 `LogWindowX`, `LogWindowY`, `LogWindowWidth`, `LogWindowHeight`, `LogFontSize`를 그대로 사용한다. 새 영구 설정 키는 추가하지 않는다.

- `(X=20, Y=20, 너비=750, 높이=750, 글자=14)`인 수정되지 않은 alpha.1 기본값을 새 화면 배율 기본값으로 바꾼다.
- 패키지 기준 튜플 `(20, 20, 1200, 860, 20)`도 현재 화면에 맞는 기본값으로 취급한다. 기본값과 정확히 같은 값으로 수동 지정한 경우는 구분할 수 없다.
- 그 밖의 사용자 지정 위치·크기·글자는 물리 픽셀 값으로 유지한다. 기존에 창을 이동하거나 글자만 바꾼 경우 자동 이행 대상이 아니므로 **도구 → 창 위치·크기·글자 기본값 복구**로 새 기본값을 적용할 수 있다.
- 마우스 스크롤바·휠·오른쪽 스틱으로 직접 스크롤한 뒤에는 자동 갱신이 선택 행으로 강제 복귀시키지 않는다. 방향 탐색으로 선택을 바꾸면 선택 행 따라가기를 재개한다. 검색·선택·펼침·스크롤은 실행 중 상태이며 새 문맥에서는 기존 선택·실행 포커스를 취소한다.

## 자동 검사와 확인 범위

실제 렌더러·모델·검색 자판 소스를 사용하는 관리 코드 검사에 서로 다른 행 좌표, 실제 전달 뷰포트 높이, 긴 카드, 목록 재정렬, 창·글자 크기 변경, 수동 스크롤 후 탐색 재개 검사를 추가했다. 레이아웃 대역은 호출한 높이·영역과 콘텐츠 좌표를 기록하는 검사 장치이며 실제 Unity의 글꼴·줄바꿈·클리핑·마우스 포착·XInput을 실행하지 않는다. 최종 전체 빌드·검사 수치와 후보 해시는 아래 후보 기록을 따른다.

실제 Windows 게임에서 아직 확인하지 않은 범위는 한국어 글자 가독성, 실제 목록·상세의 남은 높이 사용, 패드 선택 추종, 마우스 스크롤바, 작은 창·큰 글자에서의 복구, 입력 중복과 모드 전환이다. 자동 검사 결과를 실게임 성공으로 표시하지 않는다.

## Windows 재검증

게임 종료 후 현재 DLL과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업하고, 이번 후보의 **DLL만 교체**해 기존 설정을 보존한다. 후보 DLL의 SHA-256을 확인하고 해상도·창 모드·화면 배율·패드/Steam Input 구성을 결과와 함께 기록한다. 실패 시 게임을 종료한 뒤 백업 DLL과 필요하면 설정을 복구한다.

1. **크기·글자:** Tab 또는 기존 설정 열기 키로 창을 연다. 수정되지 않은 alpha.1 기본값의 이행과 1080p/1440p/4K 중 사용 환경의 가독성을 확인한다. 사용자 지정 설정은 유지되는지 확인하고 도구의 기본값 복구도 조작한다. 재시작 후 위치·크기·글자가 기억되는지 확인한다.
2. **남은 영역 사용:** 네 탭에서 긴 카드, 항목이 많은 목록, 긴 상세를 연다. 창 높이를 늘린 만큼 본문이 늘고 목록·상세가 하단까지 사용하는지 확인한다. 작은 창과 큰 본문 글자(32·64px)에서도 잘린 안내를 스크롤로 읽을 수 있고 도구·검색·예약·닫기·기본값 복구에 접근할 수 있는지 확인한다.
3. **포커스·스크롤:** 패드 위·아래로 목록의 첫 항목부터 마지막까지 왕복한다. 긴 카드를 펼친 뒤 다음·이전 카드 헤더가 보이는지 확인한다. 자동 갱신·재정렬·창 축소·글자 확대 중 선택 행이 유지되는지 확인한다. 마우스 스크롤바·휠·오른쪽 스틱으로 다른 위치를 읽는 동안 강제로 되돌아가지 않고, 다음 방향 탐색 때 선택 추종이 재개되는지 확인한다.
4. **창 전체 드래그:** 제목·상태·본문 라벨·빈 공간에서 각각 끌어 창이 움직이는지 확인한다. 목록 선택·카드 펼침·예약 버튼·검색 입력란의 커서/선택·스크롤바 드래그에서는 의도치 않게 창이 움직이거나 다른 버튼이 작동하지 않는지 확인한다. 이동 후 마우스를 놓고 재시작했을 때 위치가 저장되는지, 화면 경계에서 창이 화면 안에 남는지 확인한다. 네 탭·도구·검색 자판에서도 반복한다.

추가로 검색 지우기·한국어 패드 자판·새로고침·이벤트/미션 예약, 대상 소멸과 새 문맥, 버튼 홀드 상태 닫기, 게임 입력 모드 전환·재연결·Alt-Tab·주사위 왕복을 기존 [Windows 검증표](ISSUE-4-WINDOWS-VALIDATION.md)에 따라 회귀 확인한다. 탐색 입력이 게임의 대화 진행·취소·주사위 조정·예약 실행으로 중복 전달되면 실패로 기록한다.

ZIP은 CRC 정상인 **설정+새 DLL 두 파일**이며, 압축 내부 바이트가 현재 설정과 새 DLL에 정확히 일치한다.

```powershell
Get-FileHash .\DiceMaster-source-candidate.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

첫 명령은 다운로드/복사한 ZIP에, 두 번째 명령은 ZIP을 푼 폴더에서 실행한다. 기존 설치에는 DLL만 교체하여 사용자 설정을 보존한다. ZIP의 설정 전체 교체는 새 설치용이다. 공개 alpha.1의 로컬 보관 DLL/ZIP 해시는 종전과 일치한다. 위 로컬 후보 생성 시에는 공개 자산을 변경하지 않았다. 이후 사용자가 alpha.2 prerelease 게시를 지시하여 2026-10-19 04:13:07 KST에 새 버전 자산으로 게시했다. 인증 없는 공개 페이지·ZIP 다운로드와 내부 두 파일·CRC·해시를 확인했고 기존 15개 Release·태그·자산과 Latest 정식 v1.0.4를 보존했다.

**남은 완료 조건:** 사용자가 실제 Windows 게임에서 위 UI 항목과 기존 입력 회귀를 재검증해야 한다. 자동 검사와 후보 생성만으로 이슈 #4 또는 전체 패드 지원을 완료 처리하지 않는다.

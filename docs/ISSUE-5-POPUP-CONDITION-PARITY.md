# 조건·이벤트 팝업의 조건과 판정 표시 통일

상태: **v1.0.6-alpha.15 배포 준비 중 · 전체 후보 검사 통과 · 고정 재빌드·공개 파일 검증 대기 · 실제 Windows·장치 확인 대기**. alpha.14의 팝업 로그 전환과 조건 분기 표시를 유지하고 이벤트의 정보량과 두 팝업의 상태 표현을 맞춘다. [배포·파일 기록](ISSUE-5-ALPHA15-RELEASE.md) · [Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md#alpha15-팝업-조건요약판정-통일-확인표).

## 사용자에게 보여주는 정보

두 목록은 **굵은 제목·결과 요약·조건 요약의 고정 세 줄**이다. 선택 전후 행 높이·좌표를 유지하고 긴 조건은 한 줄로 줄인다. 선택 상세는 **필요한 짧은 판정 이유 → 전체 조건 → 예상 결과** 순서다. 정상 상태 문구를 반복하지 않고 조건식을 짧은 이유와 상세에 두 번 펼치지 않는다. 조건은 문자 그대로, 기존 결과 설명은 효과색을 보존해 표시한다.

| 상태 | 표시 | 기존 실행 권한 |
| --- | --- | --- |
| 충족·일반 진행 | 기본색과 조건 요약 | 일반 진행 |
| 확정 미충족·가중치 0·앞 분기 우선 | 제목·조건 회색과 짧은 이유 | 결과를 읽을 수 있으면 명시 조건 무시 |
| 난수·미지원 계산·앞 분기 미확정 | 기본색과 `?`·사유 | 결과를 읽을 수 있으면 명시 조건 무시 |
| 실제 대상·결과/판정 자료 확인 실패 | `!`·사유 | 일반·조건 무시 차단 |

이벤트는 **전체 활성 조건·기본 가중치·조건별 가중치 증감·최종 가중치**를 읽는다. 이전 미충족 비교 최대 세 개 요약으로 전체 조건을 대체하지 않는다. 가중치를 확률 `%`로 바꾸지 않는다. Switch는 앞 분기 우선순위와 기본 분기의 성립 조건, 횟수 모드의 이번 실행 횟수 비교를 보존한다. 두 종류가 서로 다른 게임 판정을 사용한다는 점은 유지하며 동일한 알고리즘으로 취급하지 않는다.

난수 참조는 **범위·원래 식·미확정**으로 설명한다. 난수 여러 개의 합산·곱셈 등은 원래 식을 보존하며 계산하지 않은 합성 범위를 만들어 내지 않는다. 표시용 예시 난수, 게임 `GetValue`/`Check` 호출이나 실제 RNG 소비를 설명에 사용하지 않는다. 현재 값을 엄격하게 확인할 수 없는 위치에는 미확인 사유를 남긴다.

설명은 지원하는 정적·표시 평가 범위이며 모든 미래 효과를 확정하지 않는다. 순환·깊이·표시 한도와 지원하지 않는 계산은 해당 위치에 표시한다. 조건 이름은 유한한 시간·능력치 번역과 직접 지역화 조회만 사용한다. 기존 이름 도우미의 GetFlag/DevNote 표현식 확장은 순환할 수 있어 팝업에서 호출하지 않으며 실패 시 원본 이름·ID를 남긴다. 내부 ID 문제의 해결이나 alpha.10의 원복한 참조명 처리를 다시 적용한 것으로 안내하지 않는다.

## 판정과 표시의 책임

- [EventEligibility.cs](../src/DiceMaster/EventSelection/EventEligibility.cs): 엄격한 읽기로 이벤트 상태를 먼저 판단하고 별도로 조건 설명을 만든다. 표시 실패가 확인된 상태·가중치·실행 가능성을 덮어쓰지 않도록 분리한다.
- [EventEligibilitySnapshot.cs](../src/DiceMaster/EventSelection/EventEligibilitySnapshot.cs): 상태·사유·실행 결과 사용 가능 여부와 짧은 `Summary`·전체 `Detail`을 함께 전달한다. 기존 생성 경로는 전체 상세가 없으면 요약을 사용한다.
- [PopupConditionText.cs](../src/DiceMaster/EventSelection/PopupConditionText.cs): 조건의 이름·논리/비교 연산·중첩값·가중치를 표시한다. 난수는 범위와 미확정으로 남기고 표시 실패·지원 밖·순환·한도를 설명한다. 설명 문자열로 실행 여부를 결정하지 않는다.
- [EventSelectionRuntime.Switch.cs](../src/DiceMaster/EventSelection/EventSelectionRuntime.Switch.cs): 기존 조건·횟수·분기 우선순위를 판단하고 같은 설명기를 사용한다. 앞 분기의 미확정·실패와 해당 분기의 확정 미충족을 구분한다.
- [EventSelectionRuntime.cs](../src/DiceMaster/EventSelection/EventSelectionRuntime.cs): 후보에 요약과 전체 조건 상세를 전달한다. 실행 가능 여부와 원래/명시 조건 무시 요청 검증은 기존 경계를 사용한다.
- [EventPopupRenderer.cs](../src/DiceMaster/LogUI/EventPopupRenderer.cs): 동일한 목록·상세 배치와 상태색을 사용한다. `?`/`!`는 표시를 보완하며 문자열을 실행 권한으로 해석하지 않는다. 대상·결과를 확인할 수 없으면 별도 실패 표시를 보장한다.

결과 정적 분석 설명을 읽지 못한 것과 실제 실행 대상·결과 식별자를 확인하지 못한 것을 구분한다. 전자의 형식화 실패는 이미 확인한 일반/명시 조건 무시를 제거하지 않으며 후자는 기존 실행 차단을 유지한다. 표시용 코드가 조건·능력치·호감도·Switch 횟수·난수 상태를 바꾸지 않는다.

첫 클릭·터치는 선택, 선택된 같은 행의 새 누름·해제나 A/Enter는 현재 표시된 방식으로 한 번 요청한다. 하단 원래 판정 안내는 텍스트이고 B/Esc를 사용한다. 팝업 로그 열기와 로그의 입력 우선권·판정/예약 소비 보류·닫은 뒤 해제/중립, 오래된 대상·진행 방식 거부를 유지한다. 예약 소비·팝업 지원 Lua 형식·cfg 기본값을 바꾸지 않는다.

## 검사와 남은 확인

전체 소스 후보의 14개 검사 프로그램을 통과했다. 전체 결과·입력 수·DLL/cfg/ZIP 크기·해시는 [alpha.15 배포 기록](ISSUE-5-ALPHA15-RELEASE.md)의 같은 최종 후보 기준이다.

| 검사 | 현재 결과·확인 범위 |
| --- | --- |
| EventPopupTests 전체 후보 | 2,069개 검사 통과. 두 종류의 정상·미충족·난수·미지원·읽기 실패, 같은 좌표의 다음 터치 일반/명시 조건 무시/차단, 효과색·문자 경계·미확인 표시·설명 중복 방지와 4개 해상도×3개 글자 크기의 긴 조건/결과·로그 열기 배치 |
| RealGameApiTests 전체 후보 | 관리 동작 3,988개·메타데이터 계약 1,250개 단언 통과. 실제 제공 API와 설명·난수 비소비·표시 오류·안전한 이름 조회 경계 |
| 전체 소스 후보·고정 커밋 재빌드 | 후보 14개 통과. 고정 커밋 재빌드·동일 입력·파일 대조는 다음 단계에서 기록 |
| 공개 파일 대조 | 미게시. 게시 후 익명 다운로드·CRC·두 파일·바이트·해시 확인 필요 |
| 실제 Windows·물리 장치 | 미실행. 트랙패드·마우스 인식 터치·별도 터치·XInput과 실제 게임 표시를 별도로 확인 |

제공된 게임 API·실제 MoonSharp·관리 Unity 대체 경계의 통과를 실제 Windows 화면과 물리 입력의 확인으로 확대하지 않는다. 이전 버전 확인은 해당 파일의 당시 기록이며 새 DLL의 통과를 대신하지 않는다.

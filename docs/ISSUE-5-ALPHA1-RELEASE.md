## v1.0.5 이후 변경

큰 로그에서 이벤트를 미리 예약하고 가중치를 `99999`로 높이던 방식 대신, **지원하는 실제 이벤트 판정 직전**에 현재 행동의 결과를 고르는 좌측 하단 팝업을 표시한다. 큰 로그의 이벤트 탭은 조회 전용이며 사전 실행 요청이나 이벤트 예약을 만들지 않는다. **미션 조건 통과 예약·해제와 주사위 임의 정수·음수·0 자동·기존 패드 조정은 유지**한다.

| 선택 | 이번 판정의 동작 |
| --- | --- |
| 이 이벤트로 진행 | 현재 후보의 소속·결과 ID·발동 자격을 확정 직전에 다시 확인하고 선택한 결과를 직접 적용한다. 조건이 바뀌면 안내하고 같은 유효 행동에서 다시 선택한다. |
| 조건 무시하고 이번만 진행 | 조건 미충족·최종 가중치 0·난수/분석 미지원으로 미확인인 현재 후보를 명시적으로 선택한다. 대상과 결과 자체를 읽을 수 있을 때만 허용한다. |
| 무작위로 진행 | 결과를 지정하지 않고 원래 게임의 조건·가중치·난수 판정으로 한 번 진행한다. |

조건 무시는 이번 판정의 발동 자격에만 적용한다. 능력치·호감도·스토리 플래그를 미리 수정하지 않는다. 선택 이벤트의 보상·수치 변경·대화·내부 분기는 게임이 처리하며 내부의 모든 이야기 조건까지 통과시키는 기능은 아니다. 대상/결과 읽기 실패·오래된 값·소속 불일치·대상 소멸에서는 일반·조건 무시 모두 거부한다.

후보가 없거나 안전한 실행 경로·후보군을 읽지 못하면 대기 없이 원래 게임으로 진행한다. 전체 후보가 정확히 하나이며 정상 발동 가능으로 확인되면 팝업을 생략한다. 하나라도 미충족·가중치 0·미확인이면 팝업을 표시하며, 복수 후보 중 가능한 항목이 하나뿐이어도 나머지를 유지한다. 새 행동의 기본 초점은 무작위이고 정상 발동 가능한 후보를 앞에 표시한다.

## 설정·큰 로그·입력

`[DiceMaster].EnableEventSelectionPopup=true`가 최초 기본값이다. 큰 로그 **도구 → 이벤트 선택 팝업 사용: ON/OFF**에서 마우스·패드로 변경하면 기존 cfg 저장 경로에 저장한다. 미확정 대기 중 OFF로 바꾸면 선택을 폐기하고 원래 판정을 한 번 진행한다. 다시 ON은 다음 새 판정부터 적용한다.

기존 상위 `EnableOptionInfo=false`로 시작하면 팝업 저장값은 보존하고 후킹·대기를 비활성화한다. 상위 옵션을 켜는 기존 재시작 계약을 유지한다. 설정 누락의 최초 기본 ON과 설정 조회·평가 실패를 구분하며 실패 시 대기를 남기지 않고 원래 진행으로 복구한다.

큰 로그의 **이벤트 탭에만** 발동 상태·짧은 원인, 이름/표시 이름·원본 ID·설명 검색, 가능 우선 정렬과 `발동 가능한 항목만 보기`를 제공한다. 조건·미션·선택지 탭에는 검색을 복원하지 않는다. 도구에서 패드로 필터를 바꾸고 검색을 지울 수 있으며 화면 검색 자판은 추가하지 않는다. 검색·필터·선택·스크롤과 팝업 초점은 실행 중 메모리 상태다.

| 입력 | 작은 이벤트 팝업 |
| --- | --- |
| 십자키·왼쪽 스틱 ↑↓ / 키보드 ↑↓ | 항목 이동·선택 행 추적 |
| A / Enter | 선택 이벤트 일반 진행, 무작위 행이면 원래 판정 진행 |
| X / Shift+Enter | 선택 후보를 명시적으로 이번만 조건 무시 |
| B / Esc | 선택을 폐기하고 무작위 진행 |
| 마우스 | 행을 선택해 설명을 읽고 일반·조건 무시·무작위 버튼으로 확정 |
| 기존 로그 열기 키(기본 Tab) | 행동 대기를 유지하고 큰 로그로 전환. 닫으면 같은 유효 팝업으로 복귀 |

같은 패드의 기존 L3/R3 클릭 겹침 열기도 유지하며 새 패드 조합은 추가하지 않는다. 로그를 닫는 B를 돌아온 팝업의 무작위 진행으로 재사용하지 않는다. 팝업·큰 로그·주사위·게임 중 한 화면만 공유 native XInput을 소유하고, 전체 버튼 해제·양쪽 스틱/트리거 중립 뒤 새 입력을 받는다. 게임 선택지 A와 팝업 A/X/B의 다음 화면 재사용을 막고 Alt-Tab·초점·모드·연결·소유자 변화 시 미확정 입력을 취소한다.

기존 `EnableGamepadLogOpen=true`의 게임 초점·로그 닫힘 구간에서는 단독 L3/R3도 로그 열기용으로 예약한다. 원래 클릭 기능이 필요하면 옵션을 끄고 남은 누름을 해제한다. 게임의 scheme·액션 맵을 강제 변경하지 않으며 native 차단 경로 미확인 시 위험한 패드 확정을 제한하고 키보드·마우스 경로를 제공한다. 실제 Windows Xbox/XInput·Steam Input의 구체 구성별 동작과 기존 Tab 진입의 모드/첫 입력 문제는 사용자 확인 대상이다. [패드 안내](GAMEPAD.md)를 함께 따른다.

## 지원하는 실제 판정 경로

이번 팝업은 로드된 Lua의 **직접 리터럴 점 호출 `checkpointmanager.Position("문자열 리터럴")`**에 한정한다. 실제 실행 중인 비메인 Lua 코루틴·현재 게임의 실제 manager 객체·스크립트 호출 위치·문맥 토큰이 일치할 때 호출 직전 yield 대기를 만들고, 이어지는 같은 판정의 `Position` → `GetResult`에서 선택한 결과를 한 번 반환한다. 미리보기나 큰 로그 목록을 읽는 것만으로 대기를 만들지 않는다.

변수/동적 인수·별칭·콜론 메서드·메인 Lua·직접 C# 동기 호출, 별도 코루틴의 동시 판정이나 안전한 삽입/바인딩 불가 경로는 원래 게임으로 넘긴다. 모든 이벤트 호출에 팝업이 표시되는 것은 아니다. 실제 Windows 게임에서 지원 경로가 실행되는지는 별도 확인해야 한다.

표시·검색·정렬·필터는 게시 캐시와 안전한 읽기 전용 평가를 사용하고 원본 판정 체인·게임 RNG·조건 카운터·예약·세이브를 변경하지 않는다. 보이는 현재 로그 탭/팝업의 정상 갱신은 0.25초, 읽기 실패 재시도는 5초이며 모두 숨기면 표시용 현재값 조회와 자동 재시도는 0회다. 로드·새 게임·씬/문맥 변경·대상 소멸 시 오래된 토큰·코루틴을 폐기하고 이전 흐름을 새 장면에서 재개하지 않는다. [구현 당시 상세 기록](ISSUE-5-IMPLEMENTATION.md)에 경계와 진단을 남겼다.

## 검토 후보와 검증 상태

2026-10-20의 로컬 전체 소스 빌드와 Git/기존 모드 DLL 없는 격리 소스 재빌드가 통과했다. 입력 165개·모드 소스/리소스 69개를 기록했고 컴파일 오류 0개·기존 경고 7개다. 두 빌드의 DLL·cfg·ZIP은 동일 바이트이며 외부 참조 불변, 설치 ZIP CRC·정확히 두 파일·내부 바이트를 확인했다.

| --- | ---: | --- |

**14개 자동 검사 프로그램이 로컬 빌드와 격리 소스 재빌드에서 통과**했다. 기존 갱신·수명·미션·실제 참조 API·패드·번역·미리보기·로그 UI·로그 열기 검사 12개와 새 `EventSelectionRuntimeTests` 17개 시나리오·86개 단언, `EventPopupTests` 87개 검사를 포함한다. 실제 후보 DLL 연결 78개·UI/입력 2,584개 검사도 통과했다.

관리 코드의 Unity/게임/native 대역과 실제 참조의 MoonSharp 검사를 구분한다. 자동 결과는 실제 게임·물리 장치·화면 배치·Unity 글꼴/터치·Windows 성능 확인을 대신하지 않는다. MoonSharp의 .NET 8 검사 환경은 Unity Resources 없는 초기화 경고 뒤 fallback으로 통과했으며 게임 오류나 Windows 성공의 근거로 쓰지 않는다.

게시에는 실제 소스 커밋을 확정한 뒤 `verify-preview-release.py --scope prd5`로 고정 커밋 전체 재빌드·14개 검사·검토 후보 바이트 일치를 다시 확인한다. 태그·prerelease 상태·공개 페이지와 인증 없는 설치 ZIP 검증 결과는 완료 후 기록하고 영수증은 `artifacts/releases/v1.0.6-alpha.1/`에 보존한다. 준비 시점의 로컬 결과를 아직 실행하지 않은 고정 커밋·공개 다운로드 결과로 표현하지 않는다.

## 적용·복구

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. 게시 후 Assets의 **`DiceMaster-v1.0.6-alpha.1.zip`**을 임시 폴더에 푼다. GitHub 자동 `Source code` 압축 파일과 구분하고 위 SHA-256을 확인한다.
3. **`plugins/DiceMaster/DiceMaster.dll`만** `BepInEx/plugins/DiceMaster/DiceMaster.dll`로 교체해 기존 cfg를 보존한다. 최초 실행 시 빠진 새 설정은 기본 ON으로 추가된다.
4. 문제 시 게임을 종료하고 백업한 이전 DLL을 복원한다. cfg는 필요한 경우에만 백업으로 복원한다. v1.0.5로 복구하면 이벤트 목록의 기존 일회 가중치 예약 방식으로 돌아간다.

```powershell
Get-FileHash .\DiceMaster-v1.0.6-alpha.1.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

ZIP에는 `plugins/DiceMaster/DiceMaster.dll`과 `config/DiceMaster.cfg` 두 파일만 포함한다. 게임 소스·게임 DLL·새 세이브 파일은 배포하지 않는다. **DLL 복원은 이미 진행·저장한 게임 상태를 되돌리지 않는다.** [이번 Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md)에 시험 DLL 해시·환경·일반/조건 무시/무작위 결과·화면 전환·입력 중립·기존 미션/주사위 회귀와 복구 결과를 기록한다.

## alpha.6 — 인물 대화·증명된 1회성만 안내

alpha.5의 `MapStoryEntry`는 선택 뒤 지원된 `say`와 리터럴 대사 참조를 발견하면 발행됐다. 남제자방의 휴식 뒤 `room_001_break_option`과 `room_work_101`·`room_work_301`도 안내·독백을 이 형식으로 표시하므로, 기본 반복 활동에 첫 진입 조건이 붙는 문제가 생겼다.

새 후보는 모든 대사의 존재를 사용자에게 안내할 이야기로 취급하지 않는다. 지도·선택 안내의 이야기 범위는 기존 엄격 증명에 통과한 원본 1회성 또는 같은 지원 경로에서 **원본의 명시적인 플레이어 이외 화자와 실제 발화가 연결된 인물 대화**로 제한한다. `talk` 아이콘/원문 종류·`D_`/`N_` 같은 키 접두사·파일명만으로 대화 상대나 1회성을 추정하지 않는다. 플레이어 독백·기본 휴식 설명·화자 미확정은 인물 대화 양성이 아니다. 임무와 기존 원본 1회성 표시는 유지한다.

휴식 선택을 탐색에서 잘라내지 않는다. 기존 한도와 캐시 안에서 후속 연결을 계속 읽고, 그 뒤에 확인되는 특수 인물 대화·증명된 1회성을 안내 대상으로 남긴다. 나레이션 후 실제 인물 발화가 오는 경우도 첫 대사 키만으로 제외하지 않는다. 표시하는 선택 경로와 현재 조건은 해당 분류 근거가 있는 경로에서 가져오며, 진입·대화·플래그 변경 뒤 발생을 보장하지 않는다. 같은 선택 구간·경로 안의 여러 발화는 한 연결로 유지하고 처음 확인한 비플레이어 화자를 대표 근거로 쓴다. 이는 등장인물 전체 목록이 아니며, 서로 다른 분기의 화자 근거·조건은 섞지 않는다. 미분류나 표시 없음은 반복 가능·대화 없음·전체 기회 없음의 증명이 아니다.

기존 `EnableMapGuide`와 1회성 설정·로그 조회·키보드/마우스/터치/패드 입력 소유권을 유지한다. 분류를 위해 게임의 대사·조건·RNG를 실행하거나 세이브·능력치·아이템을 바꾸지 않는다. 자동 화면에 전체 효과 분석을 추가하지 않고 정상 0.25초/실패 5초·숨김/OFF 조회 0·정상 주기 Lua 재분석 없음 계약을 유지한다. 전체 소스 후보의 21개 검사 결과·파일 해시는 [후보 기록](ISSUE-6-ALPHA6-RELEASE.md)을 따른다. 고정 커밋 재빌드·게시·공개 파일 대조도 통과했다. Windows·물리 패드·화면/성능 확인 및 #6 완료는 대기다.

## alpha.5 공개 기록 — 이야기·선택 경로

사용자의 후속 승인에 따라 지도 첫 진입의 현재 조건, 현재 선택 항목 뒤의 이야기와 필요한 선택 순서를 안내하도록 구현했다. 일반 후속 스크립트와 스크립트 안의 이야기는 기존 임무·Position 결과와 다른 근거로 구분하며, 구조화된 선택 순서는 현재 도달 보장과 별도로 다룬다. 기존 `main`에서만 작업하고 `.agents/`·`skills-lock.json`을 보존한다. 초기 구현의 별도 작업 트리 기록은 당시 이력이다.

원본 등록에 연결된 경로를 발견해도 대화·대기·시각 처리·Switch/플래그 변경 뒤의 진행을 확정하지 않는다. 선택지의 원래 번호·라벨·출처를 순서대로 보존하고 화면 표시 문자열과 식별 근거를 분리한다. 단순 등록의 교체/취소·동적 대상·선택지 비활성·불완전/상한 상태를 유지하며, 표시를 위해 Lua나 게임 조건을 실행하지 않는다. 현재 선택은 게임의 기존 콜백을 관찰하고 GUI는 캐시된 문자열만 읽는다.

지도 첫 선택의 현재값은 `진입 조건 충족 (현재)`·`진입 조건 미충족 (현재)`·`선택 화면에서 확인`으로 안내하고, 미완성·읽기 실패·생략 자료만으로 음성을 확정하지 않는다. 관련 이야기는 선택 뒤 실제 리터럴 대사 참조를 확인한 현재/후속 구간이며 단순 메뉴·유틸리티는 제외한다. 기존 클릭 우선순위·장소/행동 보호를 적용하고 자동 조회는 16개 묶음·32개 게이트와 최대 세 표시 행으로 제한한다.

선택 화면은 게임의 현재 패드 선택에 맞는 캐시 행으로 짧은 연결 경로 한 개를 표시하며 전체 경로는 기존 지도 안내 도구에 발행한다. 완전한 연결은 `외 N개`를 알리고, 준비·부분/실패 자료는 발견된 `경로 후보`와 확인 필요 상태만 보여준다. 실제 같은 원문의 원본 노드가 여럿이면 특정 자동 경로를 붙이지 않는다. 원본 스크립트·choose 위치·번호·원문 라벨을 분리하고 동일 라벨의 출처가 모호하면 확인 필요로 남긴다. 지도·선택 패널은 중립색을 사용한다. `EnableMapGuide`가 둘을 함께 제어하며 기존 네 bool 외 새 설정은 추가하지 않는다.

최종 지원 범위·자동 검사·파일 식별·게시 결과는 [alpha.5 후보 기록](ISSUE-6-ALPHA5-RELEASE.md)에 확정했으며 새 Windows 확인은 별도로 대기한다. 현재 아래 기존 후보의 수치와 과거 Windows 관찰을 alpha.5 통과로 승계하지 않는다. 네 개별 설정·상위 시작 시 적용·OFF 정리, 0.25초/5초·숨김 0·정상 Lua 재분석 없음, 실제 분기 5초/20건과 기존 이벤트 선택·예약·주사위·입력 소유권 계약은 유지한다.

## 표시와 기존 로그 동선

게임 자동 화면에는 이름·종류·상태만 표시한다. 지도는 현재 장소 옆, 선택지·이벤트 팝업은 해당 항목 옆, 상점은 기존 설명 영역, 분기는 우측 상단에 표시한다. 기존 글자 크기·해상도와 화면 가장자리/열린 로그 겹침 조정을 공유하고 새 배치 설정·단축키·전용 입력 패널을 추가하지 않는다. 한국어 상태와 원문/ID 대체를 제공한다.

기존 로그 도구에 `지도 안내 조회`·`분기 기록 조회`·`상점 효과 조회`를 추가한다. 기존 Tab/설정 키 또는 같은 패드 L3/R3 겹침으로 열고 Y에서 도구에 진입한다. 새 조회는 ↑↓·왼쪽 스틱 목록 이동, 오른쪽 스틱 상세 스크롤, B/Esc 도구 복귀, LB/RB 기존 네 탭 이동을 사용한다. 정보 행은 실행·예약 target/ticket을 갖지 않고 선택만으로 게임이 진행되지 않는다. 기존 클릭·터치와 단일 XInput·다중 슬롯 소유권·해제/중립 보호를 유지한다.

지도 후보는 가능·불가·불명 순으로 정렬하며 같은 상태 안에서는 원래 순서를 유지한다. 불명은 진행 가능 수에 포함하지 않는다. 일부 후보 실패는 다른 후보를 숨기지 않고 같은 대상의 마지막 정상 값에만 이전 값 상태를 붙인다. 장소·대상·데이터 소속이 바뀌면 이전 결과를 폐기한다.

1회성은 **실행 후 현재 활성 조건이 꺼진다는 국소적인 증명**이다. 미래에 다시 활성화될 가능성을 부정하거나 영구적으로 놓치는 유일한 기회를 뜻하지 않는다. 실제 제공 `NormalOptionButton`에는 현재 interactable만 있고 원래 활성 조건 참조가 없다. 선택지 내용 갱신 콜백은 캐시된 표식을 표시하지만 기본 선택지의 1회성 판정은 **확인 불가**다. 비활성·미독을 근거로 양성 판정을 만들지 않는다. 양성 1회성은 지도·실제 이벤트 팝업에서 명시 활성 조건과 무조건 확정 상수 SetFlag 결과가 연결되는 경우 지원한다. 단순히 표식이 없다는 이유로 반복 가능으로 안내하지 않는다.

상점의 책 조건은 묶음 간 AND·묶음 내 OR이며 빈 OR 묶음은 false다. 학습 소모의 AND/첫 양수 OR 선택·중앙 50 방향 변화·무공 25 단위와 비급 등급 게이트·최소/최대 제한을 읽기 전용의 지역 계산으로 해석한다. 선행 소모나 효과가 불명이라 후속 수치를 확정할 수 없으면 확인 불가다. 학습점이 실제로 얼마나 들어오는지·언제 다음 레벨에 도달하는지·후속 이벤트의 최종 효과는 예측하지 않는다.

소모품은 등록된 ItemEffect의 능력치 종류·값을 상세에 제공한다. 전달 참조에서 이 자료의 실제 사용 실행 경로를 확인하지 못했으므로 배열이 읽힌 사실만으로 현재 실제 적용 변화가 확인됐다고 주장하지 않는다. 정상 빈 배열은 확인된 효과 없음, 미지원·자료 부재·읽기 실패는 각각 구분한다.

## 읽기 전용·성능·실패 계약

- 표시를 위해 게임 GetRate/GetResult/Check/Execute 체인을 실행하지 않는다. FreePositionData.GetActiveConditionResult/GetDialog는 실제 ConditionResultData.Execute와 횟수 증가를 포함하므로 사용하지 않는다.
- 구매·아이템 사용·Book.Learn·학습 소모·능력치 Apply·조건 카운터·RNG·예약·세이브를 변경하지 않는다. 실제 분기 관찰만 원래 실행 뒤 발생하며 원래 반환값과 예외를 유지한다.
- 정상 0.25초·실패 5초, 자동·상세 모두 숨김 또는 OFF의 표시용 조회 0을 유지한다. 현재 문맥만 읽으며 정의·Lua 결과 분석은 기존 캐시를 재사용하고 정상 주기 재분석을 하지 않는다. GUI는 게시 문자열을 읽는다.
- 데이터 대기·현재 대상 없음/빈 목록·확인 불가·첫 읽기 실패·같은 문맥의 이전 값을 구분한다. 오래된 콜백·ID/소속 교체·로드·장면 뒤 다른 대상에 이전 결과를 붙이지 않는다.
- 기존 BepInEx 진단에 기능·원래 대상 ID·최초 실패/복구를 기록하며 전체 스크립트·세이브·프레임별 로그·원격 분석·별도 이력 파일을 만들지 않는다.
- 비용/할당량의 합성 검사와 실제 Windows Unity 프레임 관찰은 별도다. 미측정 Windows 성능이나 고정 ms 합격선을 주장하지 않는다.

분기 알림은 최신 실제 결과 1건을 5초 표시하고 새 결과가 오면 교체해 5초를 다시 시작한다. 실제 실행마다 별도 토큰으로 최신순 최대 20건을 메모리에 보관한다. 같은 실행의 중복 전달만 제거하며 같은 제목의 별도 실행을 합치지 않는다. **저장·로드·장면 전환·기능 OFF**는 알림·기록·진행 중 관찰을 초기화한다. 재실행·ON에서 과거 결과를 복원·재생하지 않는다.

## 설정·OFF·복구

기존 `[DiceMaster]` cfg에 `EnableMapGuide`, `EnableOneShotHints`, `EnableBranchNotices`, `EnableShopEffectInfo`를 모두 기본 true로 추가한다. 기존 cfg 저장값·로그 키·배치·글자를 보존한다. 도구 변경은 각 기능에 즉시 적용·저장하고 다른 개별 값을 바꾸지 않는다. OFF는 해당 표시·수집·스냅샷을 정리하며 분기는 기록도 지운다. ON은 현재 유효 문맥부터 읽는다. 최초 키 누락의 기본값과 읽기 실패를 구분하고 유효하게 읽지 못하면 해당 기능만 비활성화한다.

`EnableOptionInfo=false`로 시작하면 네 저장값을 유지하면서 모두 비활성화한다. 상위 옵션은 시작 시 적용하는 기존 재시작 계약을 따른다. 새 영구 데이터는 cfg 네 bool뿐이며 세이브 형식·조회 선택·스크롤·분기 이력 파일을 추가하지 않는다. 업데이트는 DLL만 교체하고 문제가 있으면 게임 종료 후 백업 DLL/필요 cfg 또는 확인된 정식 v1.0.6으로 복구한다. DLL 복원은 이미 저장한 게임 진행을 되돌리지 않는다.

## 자동 검사와 남은 확인

전체 소스 net48 빌드·기존 회귀·실제 DLL 연결·cfg/ZIP 검증의 최종 결과와 파일 식별값은 [후보 기록](ISSUE-6-CANDIDATE.md)의 확정 영수증으로 관리한다. 준비 당시 #5 기준선의 기존 검사와 새 #6 후보 검사를 섞지 않는다. 독립 상점 검사는 실제 provider/patch/RefreshEngine 소스를 링크하고 명시적 Unity/Harmony/게임 대역, 전달 DLL의 메타데이터·금지 실행 호출을 검사한다.

**실제 Windows·물리 Xbox/XInput·터치·UI 가독성·비용/할당량과 사용자 확인은 미실행**이다. [새 확인표](ISSUE-6-WINDOWS-VALIDATION.md)를 후보 파일 해시와 함께 기록하기 전까지 PRD #6 전체 완료·이슈 종료·전체 패드 지원 완료로 처리하지 않는다. #5의 사용자 포괄 확인을 새 기능의 검증으로 승계하지 않는다.

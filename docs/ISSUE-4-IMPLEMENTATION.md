## 화면·데이터 연결

`LiveLog.LogBridge`가 현재 문맥·탭·`DisplayRow.Id`와 원본 식별자·제목/실제 선택지 문장·설명·읽음/분석 상태·조회 상태·예약 대상을 `LogUI.LogModel`에 게시한다. 기존 튜플 게시 경계는 이전 검사/비교용으로 유지한다. 렌더러는 제목·색상·행 순번에서 ID나 분석 의미를 복원하지 않는다. 검색·요약은 이미 게시된 값만 읽는다.

선택지·조건은 복수 펼침 카드, 이벤트·미션은 검색 목록과 상세다. 정상/대기/실패/이전 값 및 검색 밖 오류 개수를 현재 탭에서 표시한다. 조회·분석기·0.25초 정상 갱신·5초 실패 재시도·숨김/비활성 탭 조회 없음 계약은 기존 엔진에 남긴다. 검색으로 Lua 재분석이나 숨은 탭 평가를 추가하지 않는다.

탭별 검색·선택·펼침·스크롤은 메모리에만 둔다. 같은 문맥의 제목/색/순번 변경에 선택 ID를 유지한다. 대상 소멸·검색 제외·새 Lua/로드/새 게임/씬에서는 상세와 실행 초점을 취소한다. 예약은 입력 시작과 적용 시 문맥·ID·대상 객체와 최신 조회 성공을 확인한다. 다른 항목으로 자동 대체하지 않는다.

버튼은 `이벤트 우선 예약`, `미션 조건 통과 예약`이다. 기존 가중치/조건 통과 예약의 의미를 유지하며 즉시 실행·발생을 보장하지 않는다. 예약 안내는 실제 `OptionInfoPatch.TargetEvent/TargetMission`을 읽는다. 새 예약 취소 기능이나 별도 예약 상태 원본은 만들지 않는다. 기존 실제 미션 예약의 수명은 유지하고 새 문맥의 UI 실행 티켓은 무효화한다.

## 입력과 접근성

열기 키는 기존 `[DiceMaster].LogMenuToggleKey` / 기본 Tab이다. 패드 열기 조합은 추가하지 않는다. 활성 `PlayerInputController`와 연결된 `PlayerInput`의 활성/장치 상태 및 실제 `currentControlScheme` 문자열을 검증해 읽는다. 내부 scheme이 null/불명일 때 `ControlSchemeType` getter 0만으로 키보드·마우스 모드라고 판단하지 않는다. 모드 조회는 게임 이벤트·모드·커서를 변경하지 않는다.

| 입력 | 동작 |
| --- | --- |
| LB/RB | 이전/다음 탭 |
| 십자키·왼쪽 스틱 상하 | 항목 또는 컨트롤 이동 |
| 좌우 | 목록·카드와 상세 영역 이동 |
| A | 현재 초점의 펼침/진입/컨트롤 작동 |
| 오른쪽 스틱 | 본문 스크롤 |
| Y | 도구 영역 |
| B | 도구에서 복귀, 상세에서 목록, 목록에서 닫기 |
| X | 누를 때 한 번 수동 새로고침 |

검색·지우기·새로고침·위치/크기/글자 크기·소유자 재선택·예약·닫기를 패드로 접근한다. 로컬 화면 키보드는 한글 자모 조합 및 영문/숫자/ID 문자 입력·지우기·확정·취소를 제공한다. 외부 서비스·OS 키 입력 에뮬레이션은 없다. 이는 Windows 한글 글꼴·IME·패드 조작감의 실증 결과가 아니며 최종 접근성은 사용자 검증 전까지 미확인이다.

입력 소유권은 공유 XInput 한 인스턴스에서 `로그 > 주사위 조절 > 게임` 순이다. 로그 중 게임에 전달되는 모든 슬롯의 버튼·양쪽 스틱·트리거를 차단한다. 소유자 패드는 고정하며 도구에서 명시적으로 재선택한다. 닫기/모드 변화/포커스 상실/재연결 뒤 버튼 해제·스틱 중립·트리거 해제를 기다린다. 게임이 실제 후킹된 XInput 경로를 최근 사용했음을 확인하지 못하면 위험한 탐색 입력을 실행하지 않는다. 주사위 조정 설정을 꺼도 로그 입력은 독립 동작한다.

Steam Input의 XInput 출력 구성과 키보드·마우스 변환은 별도 경로다. 미확인 Steam Input 구성·모든 패드·운영체제를 지원 완료로 표시하지 않는다. 실제 게임 액션 입력 중복, 모드 전환, Alt-Tab, 재연결, 다중 패드, 주사위 왕복은 Windows 필수 확인 항목이다.

보조 `GameActionGate`는 실제 수신 `Unity.InputSystem.dll` 1.5.1의 `InputActionState.CallActionListeners` 서명과 phase를 검증해 Started/Performed 콜백을 차단한다. Canceled는 해제 정리에 전달하며 실제 게임 버튼/탐색의 performed-only 구독도 정적 검사한다. 창 닫기 뒤 키/마우스 해제까지 콜백 차단을 유지한다. **키보드·마우스의 직접 상태 폴링은 이 콜백 경계 밖**이므로 실제 게임/다른 모드와의 중복 입력 검증이 필요하다. XInput 패드는 이와 별개로 원본 상태 자체를 필터링한다. 연결 실패는 기존 로그에 1회 안내한다.

## 설정·복구

기존 BepInEx `[DiceMaster]`에 아래 값만 추가한다. 기존 키와 기본값은 유지한다.

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `LogWindowX`, `LogWindowY` | 20, 20 | 창 위치(화면 픽셀) |
| `LogWindowWidth`, `LogWindowHeight` | 750, 750 | 창 크기(화면 픽셀) |
| `LogFontSize` | 14 | 글자 크기 |

너비는 `min(540, 화면 너비)`~화면 너비, 높이는 `min(440, 화면 높이)`~화면 높이로 보정한다. 위치는 0~화면에서 창을 뺀 범위다. NaN/무한대는 위치20·크기750 기본값을 적용한 뒤 화면에 맞춘다. 희망 글자 크기는12~28이고 기본14다. 작은 창에서는 `min(희망 크기, max(10, floor(min(창 너비/28, 창 높이/32))))`로 표시 크기를 줄여 조작 영역을 확보하며 희망 크기만 저장한다. 레이아웃 저장은 0.5초 간격으로 제한하고 도구 조작·마우스 해제 때 즉시 반영한다. 검색·선택·펼침·스크롤·실행 초점은 설정에 저장하지 않는다. 이전 DLL로 복구 시 추가 UI 설정 키는 사용하지 않으며 기존 세이브 형식은 유지한다.

## 진단·미확인 경계

기존 BepInEx 로그에서 같은 경계의 실패 최초와 복구를 구분한다. 패킷/프레임마다 로그를 남기지 않고 전체 Lua·검색 입력·세이브 원문을 수집하지 않는다. 문제 제보에는 후보 DLL SHA-256, 게임/로더/패드/Steam Input/해상도, 탭·항목 ID, 실패 순서와 해당 최초 실패/복구 로그가 필요하다.

Windows에서 아직 확인하지 않은 항목은 [검증표](ISSUE-4-WINDOWS-VALIDATION.md)에 모두 미실행으로 남긴다. 사용자 본인이 실제 게임에서 패드 탐색·스크롤·버튼 동작을 확인하기 전에는 이슈 #4나 기능을 완료로 처리하지 않는다. 최초 로컬 구현 이후 별도로 승인된 prerelease의 고정 커밋·게시 검증은 [게시 기록](ISSUE-4-ALPHA1-RELEASE.md)을 따른다.

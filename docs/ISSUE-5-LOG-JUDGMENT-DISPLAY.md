# 로그와 팝업의 조건·이벤트 판정 표시 공유

상태: **2026-10-20 22:00:13 KST v1.0.6-alpha.16 prerelease 게시 완료 · 실제 Windows·장치 확인 대기**. alpha.15의 팝업 판정을 로그의 이벤트 목록과 조건 상세에도 적용한다. 소스·주석 태그는 `e2fa8163a5565a571eca2d7d5c51d8d05b75bae1`이며 후보·고정 소스에서 각각 14개 검사와 동일 입력·파일 바이트를 확인하고 익명 공개 파일을 대조했다. [배포·검증 기록](ISSUE-5-ALPHA16-RELEASE.md) · [Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md#alpha16-로그-판정회색-표시-확인표).

## 표시할 대상과 시간 기준

이벤트 목록 제목·선택 상세의 조건, 조건 상세의 개별 분기 제목·전체 조건을 판정에 따라 표시한다. 조건 목록은 기존 체크포인트당 한 행이며 부모 제목을 미충족 회색으로 바꾸지 않는다. 각 체크포인트에는 여러 분기와 기본 분기가 있어 한 분기의 미충족을 체크포인트 전체의 미발동으로 해석할 수 없기 때문이다.

로그창은 실행 이력이나 과거 실제 판정의 저장소가 아니다. 현재 Lua에서 정적으로 찾은 대상에 대해 **마지막 정상 조회 시점의 현재 상태**를 보여준다. `RefreshEngine.Tick`은 열린 현재 탭을 약 0.25초 주기로 갱신하고 실패는 재시도한다. Lua·게임 문맥 교체에서는 이전 게시와 실행 권한을 초기화한다. 실제 실행 당시 판정·실제 난수값의 기록을 이 변경에서 새로 만들거나 복원하지 않는다.

Switch 횟수 모드는 현재 `_count`에 1을 더한 다음 실행 횟수를 비교하며 원래의 정수 오버플로 의미도 유지한다. 앞에서 처음 충족한 분기가 우선하고 이후 분기와 기본 분기는 앞 분기의 충족·미확정·실패를 함께 반영한다. 표시를 위해 `_count`를 쓰거나 조건의 `Execute`를 호출하지 않는다.

| 판정·신선도 | 로그 표시 | 예약·팝업 실행과의 관계 |
| --- | --- | --- |
| 정상 게시·충족 | 기본색 | 기존 예약과 일반 진행 의미 유지 |
| 정상 게시·확정 미충족/가중치 0/앞 분기 우선 | 제목·조건 회색과 이유 | 회색이어도 최신 대상·결과가 읽히면 기존 예약 가능. 팝업은 기존 명시 조건 무시 |
| 정상 게시·난수/미지원/앞 분기 미확정 | 기본색과 `?`·사유 | 미충족으로 단정하지 않음. 기존 읽기 가능한 예약/명시 조건 무시 유지 |
| 실제 대상/결과 또는 판정 자료 조회 실패 | `!` 또는 기존 읽기 실패·판정 미확인 안내 | 읽기 실패는 확정 미충족과 다름. 조건 상세는 체크포인트 전체의 마지막 정상 설명을 보존하는 실패 경계를 유지 |
| 대기·갱신 실패·게시 실패 | 이전 설명은 읽되 기존 회색 제거·판정 미확인/이전 값 | 오래된 판정으로 예약을 변경하거나 현재 발동 여부를 단정하지 않음 |

`State != Eligible`나 `IsAvailableEvent == false`를 회색 기준으로 사용하지 않는다. 두 식에는 난수·미지원·실패·이전 값까지 포함되므로 확정 미충족과 미확정을 섞기 때문이다. 정상 게시·정상 조회·읽기 가능한 판정이며 `State == Ineligible`인 경우만 회색이다. 예약 가능 여부와 버튼 활성화는 별도 기존 경계를 사용한다.

| [LogModel.cs](../src/DiceMaster/LogUI/LogModel.cs) | `LogConditionBranch.Eligibility`를 구조화 상태로 전달. 기존 생성 경로·분기 ID/예약 대상·읽기 가능한 이전 설명 유지 |

| [LogRenderer.cs](../src/DiceMaster/LogUI/LogRenderer.cs) | 정상 게시·정상 조회와 확정 미충족을 조합해 제목/조건 회색 적용. 기존 제목 인라인 색이 회색을 덮지 않게 처리하고 결과 효과색·선택 화살표·예약 표시·터치 ID 유지 |

공통 평가에 실행 문맥·Lua 재개·후보 선택·예약 소비를 옮기지 않는다. 로그는 조회 스냅샷만 받아 색을 고르고 팝업 런타임은 기존 경계에서 실제 요청을 검증한다. 설명 형식화 실패만으로 이미 확인한 판정을 미충족이나 실행 불가로 바꾸지 않는다. 색·지역화 텍스트·화면 줄 수에서 판정·분기·예약 대상을 복원하지 않는다.

이벤트 상세는 **조건 상세 → 예상 결과**로 나눈다. 전체 조건은 `EventEligibility.Detail`을 문자 그대로 표시하고 결과 설명은 기존 효과색을 보존한다. 조건 상세의 분기 설명은 `PopupConditionText` 계열의 전체 식을 사용해 표시용 예시 난수에 따른 빨강/초록과 엄격한 회색 판정이 충돌하지 않게 한다. 현재 조건명에 남는 내부 ID의 원인을 해결하거나 원복한 참조 기반 조건명 처리를 재도입하지 않는다.

## 검사와 남은 확인

최종 전체 소스 후보의 RealGameApiTests에서 **관리 동작 4,265개·메타데이터 계약 1,266개 단언**을 통과했다. 실제 `ConditionResultItem`·비교·그룹·값 참조의 관리 IL을 사용하고 Switch 컨테이너·횟수 필드와 Unity 경계만 명시적인 테스트 대체물로 구성한다. Windows·Unity 네이티브 실행이 아니다.

후보·고정 재빌드·게시 영수증은 [alpha.16 배포 기록](ISSUE-5-ALPHA16-RELEASE.md)에 구분한다. 고정 소스 문서의 준비 문구와 고정 검사 영수증의 `published=false`는 게시 전 검사 시점이며, 게시 결과 보충은 별도 문서 커밋으로 남긴다.

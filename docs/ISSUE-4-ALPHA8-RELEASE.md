# DiceMaster v1.0.5-alpha.8 — 이벤트·미션 목록에서 바로 예약

이벤트·미션은 **선택된 목록 항목에서 새 A 입력으로 바로 기존 예약**을 설정한다. 상세의 예약 버튼과 진입 단계를 없애고 포커스를 목록에 유지한다. 사용자의 커밋·prerelease 지시에 따라 이 후보를 고정 커밋에서 재빌드·검증하고 게시한다. 실제 게시 시각·커밋·공개 다운로드 검증 결과는 확인 후 아래에 기록한다.

실제 Windows 게임은 에이전트가 설치하거나 실행하지 않았다. 패드 탐색·스크롤·버튼·터치와 주요 회귀는 사용자 확인 대기이며 [이슈 #4](https://github.com/jungpaeng/dicemaster/issues/4)를 완료 처리하지 않는다. 이전 버전의 Windows 확인을 이번 DLL에 승계하지 않는다.

## alpha.7 이후 변경

| 변경 | 동작 |
| --- | --- |
| 목록에서 바로 예약 | 선택된 이벤트·미션에 새 A / Enter / Space를 누르면 한 번 예약한다. 선택이 없으면 첫 입력은 첫 항목을 선택하기만 한다. |
| 마우스·터치 | 다른 항목을 누르면 선택한다. 이미 선택된 항목을 다시 누르고 같은 항목에서 떼면 예약한다. |
| 읽기 전용 상세 | 예약 버튼·상세 포커스를 제거한다. 그 공간을 본문에 사용하며 오른쪽 스틱으로 읽는다. |
| 예약 상태 | `활성화 (예약 중)` / `비활성화 (예약 없음)`과 `예약 가능` / `예약 불가 · 이유`를 분리한다. 실제 예약이 소비되면 표시도 바뀐다. |
| 이동·복귀 | ↑↓는 항상 목록 이동, ←/→는 상세 진입 없이 소비한다. B / Escape는 목록에서 바로 닫고 도구에서는 목록으로 복귀한다. |

A는 기존 예약을 설정하며 취소 토글이 아니다. `이벤트 우선 예약`은 다음 해당 판정의 가중치 예약이고 `미션 조건 통과 예약`은 기존 조건 통과 예약이다. 즉시 발생·즉시 실행·행동 재개를 보장하지 않는다.

선택지의 읽기 전용 본문, 조건의 목록/분기 설명, 한국어 표시·읽음 상태·자동 갱신·필요할 때만 보이는 스크롤바, 창·글자 설정 저장·전체 창 드래그·검색 없는 네 탭과 주사위 조정을 유지한다. 새 설정 키가 없어 **기존 cfg를 보존하고 DLL만 교체**한다.

## 입력 보호와 유지되는 제약

새 확인 입력에만 임시 실행 권한을 부여하고 성공·거부·예외 후 해제한다. 마우스·터치는 누름 시점의 원본 대상·문맥 티켓을 사용하며 해제 시 새로 만들지 않는다. 다른 키/패드 조작·선택·탭·도구·새로고침·새 문맥·초점 상실은 진행 중 누름을 취소한다. 자동 갱신의 유효 선택은 유지하지만 대상 소멸·같은 ID 객체 교체·게시 실패·오래된 티켓은 예약하지 않으며 회복만으로 예약하지 않는다.

기존 입력 소유권과 홀드 반복 방지, 버튼 해제·스틱/트리거 중립 대기, 재연결·모드 전환·Alt-Tab·닫기·주사위 왕복 보호는 유지한다. 실제 게임에 대화·취소·주사위 조정·예약이 중복 전달되는지는 아래 Windows 확인 대상이다.

패드 열기는 alpha.7과 동일하다. 같은 패드에서 L3 또는 R3를 누른 채 반대쪽을 추가해 겹치면 순서·300ms 제한 없이 한 번 연다. 전체 해제·중립을 기다린 뒤 새 탐색 입력을 받는다. `[DiceMaster].EnableGamepadLogOpen=true`의 **게임 창 초점·로그 닫힘**에서는 첫 클릭 중복 방지를 위해 단독 L3/R3도 게임에 보내지 않는다. 원래 클릭 기능이 필요하면 옵션을 `false`로 바꾸고 재시작하며 남은 입력 해제 후 반환한다. 게임의 직렬화된 바인딩 자료가 없어 미사용 버튼이라고 확정하지 않는다. 주사위 옵션과 독립적이고 게임 scheme·액션 맵을 강제 변경하지 않는다.

기존 `[DiceMaster].LogMenuToggleKey`(기본 Tab)를 유지한다. **Tab 진입의 기존 모드 전환·첫 패드 입력 소비 문제는 별도 미해결 경로**다. 패드 겹침 열기는 진입 의도를 전달해 같은 첫 입력 손실을 피하는 기존 경로를 유지한다. 실제 지원·확인된 XInput 경로에서 사용하고 미지원 시 Tab·마우스·키보드를 사용한다. native 폴링 1초 신선도 보호는 조합 유지 시간 제한과 구분한다.

## 적용·복구

1. 게임을 종료하고 기존 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. **설치 자산 `DiceMaster-v1.0.5-alpha.8.zip`**을 임시 폴더에 푼다. GitHub 자동 `Source code` 압축 파일과 구분하고 위 SHA-256을 확인한다.
3. ZIP의 **`plugins/DiceMaster/DiceMaster.dll`만** `BepInEx/plugins/DiceMaster/DiceMaster.dll`로 교체한다. 기존 cfg를 보존한다.
4. 문제 시 게임 종료 후 백업 DLL과 필요한 cfg를 복원한다. [alpha.7 설치·해시](ISSUE-4-ALPHA7-RELEASE.md)로 복구하면 이전 상세 예약 버튼 방식으로 돌아간다.

## Windows 확인

모든 항목은 **사용자 확인 대기·실제 게임 미확인**이다. DLL SHA-256, 해상도·배율·패드·Steam Input·게임/로더 환경과 항목 ID·재현 순서·BepInEx 로그를 기록한다.

1. cfg 보존 설치·재시작, L3/R3 겹침 열기와 해제·중립 후 첫 새 방향/A가 동작하는지 확인한다.
2. 선택 없는 첫 A는 선택만 하고, 선택된 항목의 새 A/Enter/Space는 한 번 예약하는지 확인한다. 누른 채 유지·해제로 반복 예약하지 않아야 한다.
3. 첫 클릭·터치는 선택만 하고 선택된 행 재클릭·터치는 예약하는지, 누르는 중 대상/문맥·탭·도구·키/패드 전환 후 해제가 예약하지 않는지 확인한다.
4. 상세 버튼·포커스가 없고 ↑↓는 목록 이동·선택 추적, 오른쪽 스틱은 상세 스크롤이며 B는 바로 닫는지 확인한다. 도구 B는 목록 복귀다.
5. 실제 예약 전/후·소비 후 활성 상태와 예약 가능/불가 사유, 대기·실패·이전 값·게시 실패/회복·대상 소멸/교체·최하단 비활성 안내 행을 확인한다.
6. 홀드로 닫기·재연결·모드 전환·Alt-Tab·주사위 왕복 후 남은 입력이 게임 대화·취소·주사위·예약에 중복 전달되지 않는지 확인한다.
7. 짧고 긴 네 탭·조건 분기·읽음 표시·한국어 번역·창/글자 설정·필요한 스크롤바와 cfg 저장을 확인한다. [상세 12단계](ISSUE-4-LIST-RESERVATION.md#windows-확인표)를 따른다.

공개 게시·자동 검사 통과만으로 기능이나 이슈 #4를 완료하지 않는다. 기존 Release·태그·자산과 Latest 정식 v1.0.4, 이슈 #2 closed·#4 open을 유지한다.

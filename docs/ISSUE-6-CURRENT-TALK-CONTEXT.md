## 보고와 재현의 범위

사용자는 alpha.27 재로드 후 지도에서 사사형 초회 인사가 보인다고 확인했지만, 사사형 하위 ‘안색’·‘색종이’ 같은 주제는 지도에서 빠지고 방 안 사사형 포커스에서는 표시된다고 보고했다. 재로드가 해결한 정확한 원인이나 실제 세이브의 직렬화 조건 전체를 확보한 것은 아니다.

원문 room_001은 사사형 선택 뒤 초회 분기를 읽고 ResetTalkFlag를 거쳐 talk_brother4의 조건부 주제 메뉴로 이동한다. 이전 PreviewConditions는 마지막으로 컴파일된 환경의 약한 참조만 사용했다. 관련 없는 환경의 로드 관찰이 이 참조를 지우거나 자료 관찰을 잃으면 초회 인사에는 필요 없는 초기화 근거가 후속 주제에서만 누락된다. 원문 Lua+합성 조건에서 ‘초회 표시 → 초회 완료 후 후속 누락 → 초기화 자료 재관찰 후 표시’를 재현했다. 이것은 사용자 Windows 세이브 원인의 확정이 아니다.

## 구현과 안전 경계

현재 CheckPointManager와 같은 어셈블리의 LuaManager 기존 Instance backing field와 실제 직렬화 _luaEnvironment를 매 조건 Reader에서 읽는다. LuaManager getter, InitEnvironment, Lua 표현식/함수 실행이나 Unity 오브젝트 검색을 하지 않는다. 이미 존재하는 MoonSharp 테이블의 RawGet으로 checkpointmanager와 statmodifymanager를 읽고 정확한 타입과 현재 CheckPointManager 객체 일치를 확인한다. 실제 StatModifyManager._talkOptionFlag의 1,024개 한도 목록과 FlagData._default를 읽어 조회별 가상 초기화 값을 사용한다. 실제 State를 임시 변경·복원하지 않는다.

현재 소유자가 존재하지만 환경/등록/목록이 누락·손상되거나 다른 체크포인트 문맥에 속하면 이전 관찰로 우회하지 않는다. 기존 관찰 대체 경로도 관찰 당시 체크포인트와 raw 현재 등록을 매번 확인한다. 로드/장면·모드 종료·지도 안내와 1회성 표시 모두 OFF 때 관찰 참조를 정리한다. 현재 소유자와 환경이 준비되면 다음 조회에서 자료를 다시 읽으므로 추가 Lua 컴파일 관찰이나 게임 재로드가 필요하지 않다. 경로 발견 자체는 기존 준비·순회 예산과 완료 상태를 계속 따른다.

이야기 조건·선택지 해금은 별도로 확인하며 미확정을 해금으로 승격하지 않는다. 우소매 부재 같은 확정 거짓, 잠긴 미래 선택지, 완료 초회/주제, 반복 활동의 고정 반응을 계속 제외한다. 지도 툴팁은 확인된 경로 최대1개이며 초회 인사가 선택되어 있는 동안 모든 후속 주제를 나열하지 않는다. 일반 경로는 기회 마커/개수·진행 가능 판정을 만들지 않는다. 등록된 대기 임무·증명1회성의 기존 현재 도달 조건과 행동력·장소 활성·임무 우선순위를 유지한다.

상세 로그는 공통 조건 표본이 미확정이어도 독립적인 ‘대화 초기화 자료: 확인/미확인 · 현재 게임 Lua 연결’ 진단을 제공한다. 이 진단은 명시적 상세 조회에서만 구성하고 자동 툴팁에 내부 분석 문구를 추가하지 않는다.

## 성능

기존 정의 캐시·조회 내부 메모화·32경로/조건·분류·64셀 색인·8,192작업·약5ms 협력 양보와 누적 상한을 유지한다. 정상0.25초/실패5초·숨김/OFF 조회 중단·warm Lua 재읽기/재분석 없음은 변경하지 않는다. 읽기 결과나 가상 값을 갱신 사이에 저장하지 않는다.

호스트 .NET8에서 alpha.27 고정 소스와 현재 제공자의 동일한 초기화 의존 2단계 유효 경로를 비교했다. 각 사전100회 뒤 300조회×6회이며 alpha.27을 먼저 측정한 순서 고정 표본이다. 합성 게임/Unity 상태이며 Windows·실제 Lua/게임 프레임·전체 버전 FPS 비교가 아니다.

| 후보 | 300회 CPU 중앙값(ms) | 조회 p95 중앙값(ms) | 관찰 최대(ms) | 조회당 할당(B) |
| --- | ---: | ---: | ---: | ---: |
| alpha.27 | 3.949042 | 0.014104 | 0.026084 | 9840.0 |
| alpha.28 후보 | 4.235604 | 0.014687 | 0.064000 | 10144.0 |

현재 연결 검증의 CPU·할당 비용이 조금 늘었다. 모든 round의 warm Lua 자원 재읽기/구문 재분석·실제 플래그 쓰기와 게임 조건 실행은0이다. 이 제한된 표본은 갱신 간격을 늘릴 근거를 주지 않아0.25초를 유지한다. 실제 최초 준비 지연·프레임·GC와 현재 환경 확보 성공 여부는 Windows 확인 대기다. 측정 스크립트/원자료는 artifacts/issue-6/current-talk-context/benchmark.py·benchmark.json에 보존한다. 초기 측정 프로젝트 배치 오류 로그는 별도 남겼으며 최종 측정은 격리된 프로젝트로 성공했다.

## 검사·설치·남은 확인

지도/활성 선택지/실제 후보 DLL IL에서 관찰 손실·GC·현재 환경의 늦은 초기화와 복구, 다른 체크포인트/잘못된 raw 등록·손상/누락 목록과 이전 자료 우회 차단, 현재 기본값 변경·잠김·진입/임무 보호·읽기 전용을 검사한다. SHA 원문 room_001→talk_brother4→조건부 주제 경로에서 관찰을 잃어도 지도에 표시하고, 연결 복구 시 Lua 자원 재읽기/구문 재분석 없이 다시 찾는지 확인한다. 실제 세이브 대신 명시적인 합성 직렬화 조건을 사용한다.

전체 자동 검사·고정 소스 재빌드·설치 파일 해시와 게시 영수증은 [alpha.28 기록](ISSUE-6-ALPHA28-RELEASE.md)으로 확정한다. 게임 종료 후 DLL만 교체해 기존 cfg를 보존한다. [새 Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md#alpha28--현재-게임-lua-연결후속-주제-확인-대기)에서 지도 남제자방/방 안 사사형과 실제 해금된 안색·색종이 주제, 완료/잠김·반복 대련·로드/창·입력/성능을 비교한다. #6 전체 완료·종료로 처리하지 않는다.

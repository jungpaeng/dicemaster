## 표시 의미와 범위

| 표시 | 의미 | 판정·우선순위 |
| --- | --- | --- |
| 기존 어두운 바탕·금색 두루마리 | 현재 확인한 기회 | 실제 등록 대기 임무의 실행 연결 또는 증명1회성+현재 조건/도달 경로. 기존 Opportunity 유지 |
| 새 아이보리 바탕·갈색 두루마리 | 현재 대화/경로 안내 있음 | 기존 자동 툴팁과 같은 해금·완료·반복 활동 판독을 통과한 경로. Guidance만 설정하며 기회 수/Opportunity를 늘리지 않음 |
| 배지 없음 | 현재 표시 근거가 없거나 아직 준비/검증되지 않음 | 게임 전체에 이벤트/대화가 없다는 뜻은 아님 |

같은 항목에 둘 다 있으면 어두운 금색 하나를 표시한다. 밝은 배지로 이벤트 발생·1회성·최종 실행을 보장하지 않는다. 조건을 안전하게 거짓으로 확인한 경우와 잠김/해금 미확정·완료·고정 반복 활동을 이전처럼 제외한다. 특정 인물/플래그 예외 목록은 없다.

지도에서는 실제로 등록되고 보이는 장소 최대64개를 확인한다. 선택 장소를 먼저 처리하고 미선택 장소를 순환 준비한다. 현재 안내 가능한 초회 인사/후속 주제 경로를 찾으면 밝은 핀과 짧은 연결선을 붙인다. 일반 경로는 장소당 현재 확인한 하나를 안내한다. 당문이라는 이름에 제한하지 않으며 기존 PositionController 화면에 적용한다.

선택 메뉴에서는 실제 현재 메뉴가 만든 활성 선택지의 기존 안내 결과를 사용한다. 방 안 인물 선택·실제 대화 주제·유학 행동 메뉴도 같은 방식이며 숨김/비활성/다른 메뉴 버튼은 제외한다. 포커스 전에도 배지가 보이고 패드/키보드 원래 포커스 또는 움직인 마우스 호버 옆에 툴팁 하나를 표시한다. A/Enter/클릭/터치는 게임의 원래 동작이며 새 입력 대상·포커스 이동·입력 소비는 없다. 이전 Xbox/XInput·소유권/해제/중립 보호와 창 가림을 유지한다.

## 구현과 성능 경계

- `InformationRow.Guidance`와 `HasBadge`로 기회와 안내를 구분한다. 렌더러의 배지·호버·툴팁 회피 크기에 같은 기준을 사용한다. 기존 두루마리는 그대로 두고 `StoryGuideBadge` RGBA/라이선스 SVG를 추가한다. 64×64 이미지 두 개는 각각 최초 Repaint에 한 번 업로드하고 재사용하며 종료 시 해제한다. 지도/메뉴 기존 크기·배치를 유지한다.
- `InformationRuntime`의 지도/선택/표식 갱신을 `BeginScheduledReads`/`EndScheduledReads`의 try/finally로 묶는다. 지도 선택/배경 장소는 하나의 준비 슬라이스를 공유한다. 한 갱신에서 새 route 준비 최대8192작업·Lua 리소스1회/풀1회이며 작업이 발생한 준비 슬롯을 다른 장소가 다시 쓰지 않는다. 선택 장소가 준비 중이면 먼저 소비한다.
- 약5ms 시간 예산은 협력식 양보다. 이미 시작한 고정 작업·네이티브 I/O·JIT를 중간 취소하는 하드 마감이 아니다. 배경 장소마다 예산을 새로 주지 않는다. 배경은 총64경로/해금128/분류128/신규 색인128, 한 장소당32경로/신규64셀 안에서 커서를 이어 읽는다. 알려진 유효 정의를 먼저 재검사하고 새 장소를 round-robin으로 준비한다.
- 직전 유효 경로는 정의 참조만 저장한다. 현재 값/완료/해금의 참·거짓을 다음 갱신으로 캐시하지 않는다. 매 게시 때 다시 확인한 것만 배지로 공개하고 오류·시간/검사 상한으로 확인하지 못한 이전 양성을 재사용하지 않는다. 무거운 경로가 많은 화면에서는 일부 배지가 늦거나 간헐적으로 생략될 수 있다.
- 장소별로 큰 조건 정의 목록을 반복 검색하는 병목을 측정했다. `DefinitionScope`에서 같은 갱신의 이름→정의 객체 색인만 공유한다. 실제 상태·조건 판정·진입 가상 값은 장소별 새 Reader에 격리한다. 목록 참조/길이가 바뀌면 색인을 무효화하고 갱신 끝에 모든 이름/설정/정의 참조를 지운다. 최대4개 빈 사전의 할당 용량만 재사용한다.
- 정상0.25초/실패5초, 숨김/다른 창/두 기능 OFF 조회 중단, 정상 주기 Lua 재읽기/재분석 없음 계약을 유지한다. 정보 조회는 Lua 실행·게임 판정/RNG·세이브·조건·능력치·아이템·행동력을 변경하지 않는다.
- `EnableMapGuide`가 밝은 배지·경로·배경 준비를 함께 제어한다. OFF면 새 배경 준비를 하지 않고 `EnableOneShotHints`의 기존 기능은 독립적으로 유지한다. 키/기본값/저장 값은 그대로이며 패키지 cfg 설명 주석만 변경했다. DLL 교체 시 기존 cfg를 보존한다.

## 재현 가능한 측정

`tools/benchmark-guidance-markers.py`와 `tools/Benchmarks/GuidanceMarkers.cs`를 추가했다. .NET8 SDK가 PATH에 있는 상태에서 아래 두 명령을 실행한다. 기준 소스는 Git archive로 임시 폴더에서 읽기만 하며 브랜치/worktree를 만들지 않는다.

```sh
python3 tools/benchmark-guidance-markers.py
python3 tools/benchmark-guidance-markers.py --baseline c850006
```

macOS arm64 / .NET8.0.32 / SDK8.0.426의 **관리 코드·합성 게임/Unity 경계** 측정이다. 각 장소는 서로 다른 짧은 조건부 대화 정의를 가지며 컨트롤러는 실제 Unity의 소유를 흉내 내 강하게 유지한다. 조건 목록 앞에 무관한 정의0/4096개를 넣는다. 300회 준비/워밍 뒤 200회 query의 p95/스레드 할당을 읽었다. 입력·Unity 렌더·실제 Lua·FPS 측정은 아니다. JIT/티어링·실행 순서·동시 빌드의 영향이 있는 단일 표본으로 장소 수와 시간이 단조 비례한다고 해석하지 않는다.

모든 warm 표본에서 표시 수가 각각8/32/64로 유지되고 새 Lua 읽기는0이었다. 최초 화면당 리소스 총 읽기는 장소 수와 같고 한 갱신 최대1회였다. 선택 장소+배경을 함께 읽는 측정에서도 warm 전체 표시와 읽기0을 유지했다(각 경우 p95 약0.10–1.78ms, 할당67,528–455,487 B/회). 4096개 정의·32장소에서 기준은 선택 장소 하나만 조회하면서 약477KB/회, 새 구현은 전체32장소를 재확인하면서 약235KB/회였다. 기본 정의 목록의 같은32장소에서는 약24KB→235KB로 추가 비용이 생긴다. 기능 증가에 따른 메모리/CPU 비용이 사라진 것은 아니다.

0.25초 기준 전체 표시까지 이 짧은 합성 입력은 8장소 약2–3초, 32장소8초, 64장소16초다. 실제 긴 Lua·후속 경로/자원 대기에서는 더 걸릴 수 있다. 첫 번째 JIT를 포함한 query 최대는 새 구현 약11–13ms로5ms를 넘었다. 이번 자료로 프레임 무영향이나 단단한5ms 보장을 주장하지 않는다. 0.5초로 늘리면 초기 순환과 상태 변화 반영이 더 늦어지므로 이번에는0.25초를 유지했다. 주기 변경 효과를 새로 측정했다는 주장은 하지 않는다.

세부 측정 JSON/빌드 로그는 `artifacts/issue-6/guidance-badges/{final,baseline}-benchmark.json` 및 동일 접두사의 `-build.log`에 있다. 조건 색인 공유 전의 보조 탐색에서는 큰 목록의 warm 조회가 약5.6ms에 도달하고32장소 중11개만 남는 것을 관찰해 색인 공유/빈 버퍼 재사용을 적용했다. 초반에 컨트롤러 소유를 빠뜨린 탐색 결과는 무효이며 최종 표·재현 도구에 사용하지 않는다.

## 자동 검사·후보

실제 고정 참조 DLL16개를 연결한 소스 빌드와 전체21개 검사 프로그램이 통과했다. 입력291개·프로덕션 소스/리소스117개의 SHA-256을 기록하고 빌드 중 입력 불변을 확인했다. 기존 컴파일 경고7개·오류0개다. 설치 ZIP은 정확한 두 경로·CRC·새 DLL/cfg 바이트 일치로 검증했다. 실제 Windows 실행은 하지 않았다.

- 실제 provider+route+조건 Reader 통합3,669개: 미선택8장소 순환·공유8192작업/리소스 한도·현재 잠금 제거/재해금·행동 부족·금색 우선·창 밖/빈 장소·대상별 실패 격리·Guide OFF/읽기 전용·메타데이터 공유의 장소별 값 격리를 포함한다.
- 실제 선택 안내7,719개, GUI/입력 경계5,454개, 실제 DLL 연결/스케줄/설정/읽기 전용5,892개, route6,884개, 기존 패드262,831개를 포함한다. 이미지 두 개 업로드/해제·한 이미지 실패 격리·미포커스 마커와 단일 툴팁을 검사했다. 조건/원문/API/상점/분기·이벤트 팝업/예약/로그/주사위 회귀도 전체 검사에 포함한다.

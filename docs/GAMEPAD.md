## v1.0.6-alpha.4 — 로그 탭 터치·팝업 두 번째 터치 보완

alpha.3에서 사용자는 이벤트 탭의 목록 선택·다른 탭 이동과 팝업의 첫 터치 선택은 확인했지만, 다른 탭의 터치 실패와 선택 후 두 번 더 터치해야 실행되는 문제를 보고했다. 이번 후보는 로그의 포커스 해제를 필요한 경계에서만 한 번 처리하고 포인터 조작 중에는 미룬다. 팝업은 첫 터치 뒤 늦은 입력 전환 처리가 다음 터치를 버리지 않도록 수정한다.

조작은 **첫 클릭·터치 선택 → 두 번째 클릭·터치 진행**이며 진행 버튼과 A/Enter/Shift+Enter도 유지한다. B/Escape는 무작위다. 대상·결과·일반/조건 무시 방식이 달라진 누름은 취소하고 초점·문맥·연결·소유자 경계와 화면 전환의 해제·중립 보호를 유지한다. 새 키·패드 조합·설정은 없다.

현재 alpha.4는 회귀 검사·고정 재빌드·게시 검증 준비 단계다. 결과는 [alpha.4 배포 기록](ISSUE-5-ALPHA4-RELEASE.md)에 확정 후 기록하며 새 DLL의 실제 Windows·장치 확인은 대기다. [Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md). 아래 alpha.3의 게시 당시 검사·확인 대기는 당시 이력이다.

## alpha.6 — 패드로 로그 열기

같은 XInput 패드의 **한쪽 스틱 클릭을 누른 채 0.3초가 되기 전에 다른 쪽도 눌러 겹치면 로그를 여는 기능**을 추가합니다. L3+R3 동시 입력도 가능하며 한쪽을 뗀 뒤 반대쪽만 누르는 연속 클릭은 조합이 아닙니다. 조합은 열기 전용이며 열린 로그를 다시 닫지 않습니다. 닫기는 기존 B 순서(예약 버튼→목록→닫기, 도구→이전 영역)와 기존 설정 키를 사용합니다. `[DiceMaster].EnableGamepadLogOpen`의 기본값은 `true`이며 `EnableGamepadAdjustment`·`EnableDiceController`와 독립적으로 동작합니다. 초기 PRD의 패드 열기 제외 조건은 이번 사용자 후속 지시로 대체하며 아래 과거 기록은 당시 계약으로 보존합니다.

| 입력·설정 | 새 패드 열기 계약 |
| --- | --- |
| 같은 패드의 L3+R3, 첫쪽을 누른 채 300ms 미만에 겹침 | 전체 해제·중립 뒤 새 조합으로 로그 열기 |
| 조합 홀드·창이 이미 열림 | 추가 열기·닫기·예약 없음. 해제·중립 뒤 새 탐색 입력 사용 |
| 기본 Tab·사용자 지정 `LogMenuToggleKey` | 기존 열기·닫기 유지 |
| `EnableGamepadLogOpen=false` | 패드 열기와 닫힌 로그의 L3/R3 예약 해제. 남아 있는 누름은 해제 후 반환 |
| 주사위 패드 조정 끔 | 로그 열기 옵션이 켜져 있으면 별도로 사용 가능 |

**옵션 켜짐·게임 창 초점·로그 닫힘**에서는 첫 클릭의 게임 중복 전달을 막기 위해 L3와 R3를 단독으로 눌러도 게임에 보내지 않습니다. 따라서 게임의 원래 L3/R3 기능을 제한합니다. 옵션을 끄면 이 예약을 해제하지만 열린 로그의 기존 전체 입력 차단은 유지합니다. 게임의 직렬화된 바인딩 자료가 없어 L3/R3가 미사용인지 확정할 수 없으므로 실제 Windows의 게임·Steam Input 조합에서 확인합니다.

초기화·상태 재설정으로 전체 해제·중립 대기를 거는 구간에는 다른 버튼·양쪽 스틱·트리거의 남은 입력도 게임에 전달하지 않습니다. 그 중립 확인을 마친 뒤, 로그가 닫혀 있고 조합을 완성하지 않은 평상시에는 L3/R3를 제외한 게임 입력을 유지합니다.

입력 소유자는 한 패드로 고정하며 서로 다른 패드의 클릭을 합치지 않습니다. 게임의 실제 XInput 차단 경로를 확인한 환경에서만 패드 열기를 사용하고 기본 Tab·마우스·키보드는 대안으로 유지합니다. 게임 scheme·액션 맵을 쓰지 않고, 패드 열기의 의도를 로그 내부에 전달해 KM로 읽히거나 scheme이 자동 변경되어도 해제·중립 후 첫 새 탐색 입력을 추가로 소비하지 않도록 합니다. 단순 마우스 이동·호버는 이 패드 진입을 취소하지 않으며 실제 클릭·터치·휠·탐색 키는 기존 전환 보호를 적용합니다. 초점·차단 준비·연결을 잃거나 닫으면 패드 진입 의도를 취소합니다. Tab 진입의 기존 모드 전환 문제는 이번 변경의 별도 미해결 경로입니다.

[설정·후보 SHA-256·적용과 Windows 확인표](ISSUE-4-PAD-OPEN.md)에 기록했습니다. 2026-10-19 06:14:54 KST에 `artifacts/issue-4/pad-open/`의 후보를 생성했고 **전체 12개 검사 프로그램**이 통과했습니다. 새 패드 열기 통합 993개 단언·28개 시나리오, UI·입력 2,720개와 실제 DLL 연결 47개를 포함하며 ZIP의 CRC·두 파일·해시와 입력 153개 일치를 확인했습니다. 관리 대역 검사는 실제 Windows·native 게임 동작의 확인을 대신하지 않습니다. 이 로컬 후보를 검증한 뒤 위 alpha.6으로 게시했습니다. 게임 설치·실행과 이슈 완료는 수행하지 않았으며 실제 Windows 확인은 대기입니다.

## 직전 로컬 후보 — 조건의 분기 후보 구분

조건 탭의 오른쪽 설명은 **분기 1·분기 2·그 외** 블록으로 나눕니다. 순서 안내와 첫 분기·후속 분기·그 외의 검사 맥락을 표시하며 본문은 항상 공개합니다. 블록은 읽기 전용이라 별도의 초점·선택·접기·예약 단계가 없습니다. ↑↓는 왼쪽 체크포인트 선택, 오른쪽 스틱은 오른쪽 전체 설명 스크롤이며 A·→로 동작 없는 상세에 진입하지 않습니다. B 닫기·Y 도구·X 새로고침과 기존 탭 조작은 유지합니다.

조건 안의 여러 비교식과 서로 다른 분기 후보는 구조화된 게시 정보로 구분합니다. 실패 중에는 이전 정상 묶음을 함께 표시하고 회복 시 전체 묶음을 바꿉니다. 읽음 표시는 실제 분기 선택이나 조건 충족을 뜻하지 않습니다. [변경·후보·적용과 Windows 확인표](ISSUE-4-CONDITION-BLOCKS.md)를 따릅니다. 후보는 `artifacts/issue-4/condition-blocks/`에 생성했으며 전체 11개 검사 프로그램·UI/입력 2,720개·실제 DLL 연결 43개·통합 203개 단언을 통과했습니다. ZIP·빌드 입력과 파일별 SHA-256을 확인해 후보 문서에 기록했습니다. 실제 Windows 확인과 이슈 완료는 별도이며 이번에 커밋·prerelease를 발행하지 않습니다.

패드 모드에서 로그를 연 직후 첫 입력이 소비되는 증상은 이번 조건 화면 후보에서도 **미해결**입니다. [입력 진단](../artifacts/issue-4/mode-entry-diagnosis/diagnosis.md)을 별도로 보존하며 자동 검사 통과가 이 증상이나 실제 기기 전환을 해결했다는 뜻은 아닙니다.

## 직전 로컬 후보 — 선택지 읽기와 필요한 스크롤바

선택지 탭은 모든 문장·효과를 읽는 화면입니다. 헤더와 본문은 일반 텍스트로 표시하며 선택·접기·펼침·예약 포커스를 만들지 않습니다. 항목 사이의 간격은 `max(8px, 글자 크기 × 0.6)`이며 기본 20px 글자에서는 12px입니다. 조건·이벤트·미션은 기존 목록 선택과 유효 예약 컨트롤 진입을 유지합니다.

| B | 예약 버튼→목록, 도구→이전 영역, 목록·선택지 본문→닫기 |
| 물리 키보드 방향키·Enter/Space·Escape·Y·X | 대응하는 탐색·확인·복귀·도구·새로고침. 문자 검색은 제공하지 않음 |

선택지는 전체 문장·효과를 이어서 공개하며 A·헤더는 선택만 바꿉니다. 좌우는 접기나 별도 상세 진입을 만들지 않습니다. 조건은 체크포인트 목록에 포커스를 두고 오른쪽 스틱으로 설명을 읽습니다. 읽기 전용 설명에는 진입하지 않습니다. 이벤트·미션에서는 유효한 예약 버튼이 있을 때 A·→로 바로 포커스를 옮기고, 진입 입력과 구분된 다음 새 A로 예약합니다. 버튼 포커스에서 ←·B는 목록으로 돌아갑니다. 대기·실패·대상 없음·게시 실패의 버튼은 진입할 수 없습니다.

미션 안내 행만 있으면 A·→로 선택하거나 상세에 진입하지 않고 오른쪽 스틱으로 목록을 읽습니다. 일반 항목과 섞였으면 마지막 선택 가능 항목에서 ↓를 더 눌러 선택을 유지한 채 아래 안내 행을 스크롤합니다. ↑는 이전 일반 항목으로 이동하며 선택 추종을 재개합니다. 마우스 휠·스크롤바·터치 스크롤로도 안내와 원본 ID를 읽을 수 있습니다.

비활성 기준은 Bridge가 게시한 `IsStatusOnly`입니다. 실제 값이 있는 미션의 대기·이전 값/실패 행이나 예약 대상이 없는 선택지·조건은 선택해 읽을 수 있습니다. `미션 정보`는 실제 미션 이름이 아닌 상태 안내 제목이며 `설명 조회 대기`만으로 미완료·조건 미충족을 뜻하지 않습니다. 선택한 행이 안내 행으로 바뀌면 선택·예약 초점을 취소하며 정상 회복만으로 다시 선택하지 않습니다. 열린 활성 탭의 대기·실패 재조회는 기존 5초 간격이고 X로 다시 확인할 수 있습니다.

도구는 **17개**입니다. 새로고침, 글자·창 크기·위치 조절과 기본값 복구, 패드 소유자 재선택, 선택지/이벤트 빠른 탭 이동, 이전 영역 복귀, 닫기를 유지합니다. 검색 문자 입력과 검색 지우기만 제거합니다. 위치·크기·글자는 기존 cfg에 저장하고 선택·스크롤은 실행 중에만 유지합니다.

게임 모드를 읽는 경로는 계속 읽기 전용이며 유효한 모드를 우선하고 불명일 때 양쪽 입력을 지원합니다. 열린 로그와 활성 게임 창에서만 커서를 임시로 해제·표시하고 닫기·초점 상실·비활성화·종료 시 복원합니다. 물리 키보드 명령은 터치·마우스 이동과 겹쳐도 다음 Update에서 초점이 지워지지 않도록 처리합니다. 실제 모드·커서·터치 동작은 Windows 기기에서 확인해야 합니다.

입력 소유권 `로그 > 주사위 조절 > 게임`, 패드 버튼·스틱·트리거와 남은 터치의 해제·중립 대기, 원래 문맥·컨트롤 ID·대상·티켓 검증을 유지합니다. `이벤트 우선 예약`과 `미션 조건 통과 예약`은 즉시 실행을 보장하지 않습니다. 성공한 예약의 같은 유효 버튼은 포커스를 유지하되 이전 티켓은 폐기합니다. 대상 소멸·새 문맥·게시 실패는 이전 실행 권한을 취소합니다.

보조 게임 액션 차단은 Started/Performed 콜백을 대상으로 하며 Canceled는 정리에 전달합니다. 직접 상태를 폴링하는 게임·다른 모드의 경로는 이 차단 범위 밖입니다. 실제 Unity/Harmony/native 적용, 터치스크린과 Steam Input 구성은 미확인입니다. 자동 검사와 로컬 후보 생성으로 전체 패드 지원이나 이슈 완료를 선언하지 않습니다.

## 이전 후보와 공개 버전의 기록

이 절의 검색·화면 자판·펼침 및 검사 설명은 각 후보 작성 당시의 동작입니다. 관련 상세 문서와 해시는 보존하며 현재 조작은 문서 상단의 패드 열기와 최신 후속 안내를 따릅니다. [검색 제거 후보](ISSUE-4-NO-SEARCH.md)의 전체 행 표시·17개 도구 변경도 함께 유지합니다.

현재 터치 복구 로컬 후보는 패드 모드에서도 로그를 터치·마우스로 조작할 수 있도록, 로그가 열리고 게임 창에 초점이 있는 동안 커서를 임시로 해제·표시합니다. 닫기·초점 상실·비활성화·종료 시 이전 또는 관찰된 게임 커서 요청을 복원합니다. 입력 모드 변화만으로 진행 중 클릭·검색을 지우지 않으며 패드의 기존 입력은 해제·중립까지 소비합니다. 문맥·대상·연결·포커스의 안전 경계는 계속 취소합니다. [원인 경로·후보·터치 Windows 확인](ISSUE-4-TOUCH-INPUT.md)을 따릅니다.

현재 탭별 로컬 후보는 선택지의 모든 본문을 항상 공개합니다. ↑↓는 항목 이동, A·마우스 헤더는 선택, 오른쪽 스틱은 전체 본문, B는 닫기입니다. 좌우는 내용을 숨기거나 별도 상세로 전환하지 않습니다. 조건은 검색 가능한 목록/설명이며 포커스는 목록에 유지합니다. ↑↓ 항목 이동·오른쪽 스틱 상세 스크롤·B 닫기를 사용합니다. 이벤트·미션은 활성 예약 버튼이 있을 때 A·→로 버튼을 바로 선택하고 다음 새 A로 예약합니다. 상세 제목은 조작 포커스가 아니며 비활성 버튼이나 동작이 없는 상세로 진입하지 않습니다. [최신 포커스·보호·후보](ISSUE-4-ACTION-FOCUS.md)와 [탭 구성 근거](ISSUE-4-TAB-LAYOUT.md)를 따릅니다.

현재 로컬 후속은 기본 창을 처음 표시하는 화면의 약 60%×70%로 적용합니다. 초기 임시 해상도가 설정을 축소해 덮어쓰는 경로를 보호하며 패드 도구의 기본값 복구도 같은 크기를 사용합니다. 기존 카드·입력 소유권은 유지합니다. [원인·후보와 Windows 확인](ISSUE-4-VIEWPORT-DEFAULTS.md)을 따르며 공개 alpha.4의 기록과 구분합니다.

선택지·조건에서 → 펼치기/← 현재 카드 접기, 펼친 상태의 ↑↓ 항목 이동을 지원합니다. A는 펼침을 전환하고 B는 상세→목록→닫기의 기존 복귀 순서를 유지합니다. 이벤트·미션 상세의 ↑↓ 본문/예약 버튼 이동은 유지합니다. [창 확대·미션 목록 잘림·상태 안내와 Windows 검증](ISSUE-4-CARD-NAVIGATION.md)을 따르며 사용자 지시로 [alpha.4 prerelease](ISSUE-4-ALPHA4-RELEASE.md)를 2026-10-19 04:46:13 KST에 게시했습니다. 고정 커밋 재빌드·공개 다운로드를 검증했으며 실제 Windows 확인은 대기 중입니다.

alpha.2의 작은 빈 창 실패를 고정 크기 창 호출로 수정한 [alpha.3](ISSUE-4-ALPHA3-RELEASE.md)을 게시했습니다. [원인·검사 보강·설정 복구·Windows 재검증](ISSUE-4-WINDOW-SIZE-REGRESSION.md)을 따르며 기존 패드 매핑과 입력 소유권은 유지합니다. 실제 Windows 표시·탐색 성공은 재검증 대기입니다.

alpha.1의 사용자 보고에 따른 [UI 크기·본문 높이·포커스 스크롤 후속 수정](ISSUE-4-UI-FOLLOWUP.md)은 사용자 지시에 따라 [v1.0.5-alpha.2 prerelease](ISSUE-4-ALPHA2-RELEASE.md)로 게시했습니다. 1080p 기본 1200×860/본문20px을 화면 높이에 맞춰 확대하며 본문 글자는12~64px을 그대로 표시합니다. 기본 배치 이행·사용자 지정 보존, 실제 뷰포트 추적과 수동 읽기 유지, 큰 글자·작은 창에서의 복구를 추가했습니다. 후속 후보의 실제 Windows 확인은 대기 중이며 아래 기존 alpha.1 검증/게시와 구분합니다.

현재 소스는 [PRD #2 완료](ISSUE-2-COMPLETION.md) 뒤 로그 UI·패드 탐색과 alpha.2 UI 후속을 구현한 prerelease 후보입니다. [구현/자동 검사/후보 해시](ISSUE-4-IMPLEMENTATION.md)와 [사용자 Windows 검증표](ISSUE-4-WINDOWS-VALIDATION.md)를 함께 봅니다. 실제 Windows 확인 전이며 정식 배포나 전체 패드 접근성 완료로 처리하지 않습니다. 최초 alpha.1의 구현 기록과 현재 alpha.2 검증·해시를 구분합니다.

로그는 기존 `[DiceMaster].LogMenuToggleKey`(기본 Tab)로 엽니다. 패드 열기 조합은 없습니다. LB/RB 탭, 십자키·왼쪽 스틱 이동, A 선택/컨트롤 진입/작동, 오른쪽 스틱 본문 스크롤, Y 도구, X 누를 때 한 번 새로고침, B 도구→이전 영역/예약 버튼→목록/목록→닫기입니다. 도구에서 검색 문자 입력·지우기·창 위치/크기/글자 크기·패드 소유자 재선택·닫기에 접근합니다. 검색 자판은 초성→중성→종성 조합으로 한글 입력, 영문/숫자/원본 ID, 지우기/확정/취소를 제공합니다. Windows 한글 글꼴·가독성·물리 IME·패드 입력감은 실제 확인이 남아 있습니다.

유효한 게임의 `PlayerInput.currentControlScheme`을 우선합니다. `ControlSchemeType`이 0이어도 내부 scheme이 null/불명·비활성·연결 미준비이면 정상 키보드·마우스 모드로 확정하지 않고 양쪽 입력을 지원합니다. 차단 때문에 게임 모드 갱신이 멈춘 경우 물리 패드의 전환 입력을 먼저 소비하고 중립 후 새 입력을 받습니다. 모드 조회를 위해 게임 모드 이벤트·커서·액션 맵을 강제로 바꾸지 않습니다. 열린 로그의 임시 커서 접근은 위 터치 복구 수명에 한정하며 게임 모드는 변경하지 않습니다.

하나의 네이티브 XInput 인스턴스가 `로그 > 주사위 조절 > 게임` 소유권을 적용합니다. 열린 로그와 활성 게임 창에서는 모든 슬롯의 버튼·양쪽 스틱·트리거를 게임에서 차단하고 고정 소유자의 원본 입력만 탐색에 사용합니다. 다른 패드는 소유권을 자동 탈취하지 않으며 도구에서 명시적으로 바꿉니다. 닫기/전환/Alt-Tab/재연결/새 문맥 후 버튼 해제·스틱 중립·트리거 해제까지 소비합니다. 후킹 경로의 실제 게임 호출을 최근 확인하지 못하면 위험한 패드 동작을 중지하고 기존 키·마우스 복구 경로를 안내합니다. 주사위 조정 설정과 로그 탐색은 독립입니다.

보조 `GameActionGate`는 실제 `InputActionState.CallActionListeners` 경계를 검증하고 로그 중 Started/Performed 콜백을 막아 게임의 키보드·마우스/패드 액션 중복을 줄입니다. Canceled는 해제 정리에 전달하고 닫힌 뒤 키/마우스·남은 터치 해제를 기다립니다. 게임 모드나 액션 맵을 끄지 않습니다. **게임/다른 모드가 키보드·마우스 값을 직접 폴링하는 경로는 이 콜백 차단 밖**입니다. 해당 경로·Steam Input의 키보드/마우스 변환·실제 native/Harmony 적용 여부는 Windows 검증 대상이며 완전 차단을 자동 검사만으로 보장하지 않습니다. XInput 패드는 별도 네이티브 상태 필터를 거칩니다.

이벤트/미션은 목록의 A·→ 입력으로 예약 버튼에 포커스를 주며, 그 진입 입력은 예약하지 않습니다. 다음 새 A만 예약하고 홀드 반복은 소비합니다. 예약 성공 뒤 같은 유효한 버튼의 포커스는 유지하되 이전 티켓은 폐기합니다. `이벤트 우선 예약`은 다음 해당 판정 가중치 예약, `미션 조건 통과 예약`은 기존 조건 통과 예약이며 즉시 실행/발생을 보장하지 않습니다. 대기/실패/이전 값·오래된 문맥·대상은 예약할 수 없고 해당 버튼으로 진입하지 않습니다. 실제 예약 필드의 소비 상태를 표시하고 별도 예약 취소 기능은 추가하지 않습니다.

아래 주사위 설명에서 A/X·오른쪽 스틱·트리거 보존은 **로그가 닫힌 주사위 조정**에 해당합니다.

Windows에서 Xbox/XInput 패드로 주사위 수치를 조정합니다. 주사위 입력창이 활성화되고 게임 창에 포커스가 있을 때만 적용됩니다.

| 조작 | 동작 |
|---|---|
| LB를 누른 채 십자키/왼쪽 스틱 좌우 | −1 / +1 |
| LB를 누른 채 십자키/왼쪽 스틱 아래·위 | −10 / +10 |
| LB+B | 자동 주사위(0)로 복귀 |
| LB 놓기 | 조정 종료, 설정값 유지 |

방향키를 누르거나 왼쪽 스틱을 기울인 채 유지하면 0.35초 뒤부터 0.08초 간격으로 반복합니다. 0은 자동 모드입니다. 패드에서도 음수와 100을 넘는 양수를 지정할 수 있습니다. 좌우는 ±1, 상하는 ±10을 그대로 적용하므로 1에서 왼쪽은 0, 아래는 −9가 됩니다. 0에서 계속 감소하면 음수로 내려갑니다. 정수 범위를 벗어나는 경우에만 최솟값·최댓값에서 멈춥니다. 주사위 창을 다시 열면 기존 동작대로 0으로 초기화됩니다.

왼쪽 스틱은 충분히 기울여야 입력을 시작하고, 중앙 부근의 작은 흔들림은 무시합니다. 대각선은 더 크게 기울인 축을 따르며, 십자키와 스틱을 함께 쓰면 십자키를 우선합니다.

스틱 방향은 절댓값이 16,000 이상이면 새 입력으로 판단하고, 같은 방향을 유지할 때는 10,000 이상이면 유지합니다. 두 축이 모두 ±8,000 안으로 들어오면 중앙으로 판단합니다. 두 축의 절댓값이 같으면 가로 방향을 선택합니다.

A·X와 오른쪽 스틱·트리거는 원래 입력을 유지하며 키 입력 에뮬레이션은 없습니다. 조정 중에는 XInput에서 조정용 버튼과 왼쪽 스틱 입력을 제외합니다. LB를 먼저 놓아도 B·방향키는 해당 버튼을 놓을 때까지, 왼쪽 스틱은 중앙으로 돌아올 때까지 제외하여 뒤늦은 게임 입력을 방지합니다.

## 설정

`config/DiceMaster.cfg`의 `[DiceMaster]`에 있는 `EnableGamepadAdjustment`로 켜고 끕니다. 기본값은 `true`입니다. `EnableDiceController = false`이면 패드 조정도 비활성화됩니다.

## 입력 처리

- XInputGetState와 XInput 1.3/1.4의 StateEx(ordinal 100)를 지원합니다.
- Windows 게임 프로세스 안에서만 입력을 필터링합니다. 다른 프로그램이나 시스템의 패드 설정은 변경하지 않습니다.
- 게임이 실제로 이 XInput 경로를 읽는 것이 확인된 경우에만 수치를 변경합니다. 다른 입력 경로를 사용하는 환경에서는 대기 안내를 표시하며 원래 수치를 유지합니다.
- MinHook 1.3.4의 x86/x64 라이브러리를 DiceMaster.dll 리소스에 내장합니다. 실행 시 BepInEx 캐시의 `DiceMaster/Gamepad/<해시>`에 해당 비트 수의 라이브러리를 추출합니다. 별도의 BepInEx 플러그인 설치는 필요하지 않습니다.
- 플러그인 종료 시 후킹을 해제합니다. 이미 실행 중인 콜백의 원본 호출이 끝날 수 있도록 라이브러리·트램펄린은 프로세스 종료까지 유지합니다.

자동 검사는 입력 로직과 DLL 구조를 대상으로 합니다. Windows 네이티브 후킹, 게임 안에서의 숫자 반영과 UI 위치, Steam Input 호환성은 실제 게임에서 별도로 확인하고 릴리스 설명에 검사 범위를 기록합니다.

## 소스와 빌드

패드 소스는 `src/DiceMaster/Gamepad/`에서 전체 모드와 같은 프로젝트로 관리합니다. 주 프로젝트가 다음 두 파일을 한 번씩 컴파일하며 기준 DLL에서 추출한 중복 구현은 포함하지 않습니다.

- `PadController.cs`: 수치 조정, 스틱 방향·중립 판정, 반복 입력, 버튼·스틱 입력 필터, 표시 상태.
- `NativeXInput.cs`: Windows XInput 연결과 MinHook 관리.
- `tests/GamepadTests`: 모든 65,536개 버튼 조합, A/X 보존, 버튼 해제 순서, 연결 해제, 스틱의 경계값·입력 차단, 반복 입력, 0 및 정수 경계와 네이티브 구조체 크기를 검사합니다.

루트 솔루션과 .NET 8 SDK로 전체 C# 소스를 빌드합니다. 자동 검사를 포함한 새 후보는 다음 명령으로 `artifacts/source-candidate/`에 생성합니다. 전체 참조·복원·호환성 검사는 [전체 소스 빌드 안내](SOURCE-BUILD.md)를 따릅니다.

```sh
python3 build/build-source.py --references '<읽기 전용 참조 루트>'
```

보존한 `tools/LegacyPatch/GamepadInjector/`는 같은 패드 소스를 링크하여 기존 DLL에 Update·OnGUI·주사위 창 초기화·설정·종료 지점을 연결하는 비교·복구 도구입니다. 기존 명령은 새 소스 프로젝트와 별도입니다. 기본 입력은 고정 Git 커밋에서 재생성·해시 확인한 alpha.3 DLL이고 기본 출력은 `artifacts/legacy-candidate/gamepad/DiceMaster.dll`이므로 기준을 덮어쓰지 않습니다. 다른 후보 위치에는 `--output`을 지정합니다.

```sh
python3 tools/LegacyPatch/build-gamepad.py --output artifacts/legacy-local/DiceMaster.dll
```

이미 기능이 들어 있는 DLL에서도 패드 코드를 교체하며, 다른 기능과 번역은 유지합니다. 일반 빌드 산출물과 중간 파일은 `artifacts/`에 모으고 Git에서 제외합니다. 예전 `development/releases/` 기록은 과거 검증 증거로 보존합니다.

# PRD #4 후속: 탭 성격에 맞춘 선택지·조건 화면

2026-10-19 KST. 사용자가 접기·펼침을 없애거나 목록·상세로 나누는 방식을 탭 성격에 맞게 판단해 구현하도록 요청했다.
이번 후속 지시는 원래 PRD #4의 선택지·조건 접기 카드 요구를 대체한다. 기존 네 탭은 유지한다.
선택지는 본문을 항상 공개하는 비교 카드, 조건은 체크포인트 목록·상세로 구성한다. 이벤트·미션은 기존 구성을 유지한다.
이 기록은 로컬 후보이며 prerelease 게시·게임 설치나 실행·이슈 #4 완료를 의미하지 않는다.
후속 사용자 지시에 따른 [상세 조작 포커스 변경](ISSUE-4-ACTION-FOCUS.md)이 아래 진입 매핑을 대체한다. 최신 조건 탭은 목록 포커스를 유지하고 오른쪽 스틱으로 설명을 읽으며, 이벤트·미션은 활성 예약 버튼에 직접 진입한다. 아래 후보·해시는 탭 구성 수정 당시 기록이다.

## 화면 결정과 데이터 근거

| 탭 | 화면 | 선택 이유 |
| --- | --- | --- |
| 선택지 | 전체 폭의 연속 카드, 접기 없음 | 서로 다른 선택지 문장과 효과를 오가며 비교하기 쉽도록 전체 본문 제공 |
| 조건 | 왼쪽 체크포인트 목록·오른쪽 전체 상세 | 체크포인트를 찾고 그 안의 조건 전체를 함께 읽도록 구성 |
| 이벤트·미션 | 기존 검색 목록·상세·예약 | 기존 탐색과 예약 의미·검증 경로 유지 |

선택지는 `LuaParser.ExtractOptionActionsFromLua`가 발견한 선택지 ID별 효과 분석이다. `LogBridge`는
실제 선택지 문장·전체 설명·읽음·분석·조회 상태를 게시한다. 문장이 없으면 기존 제목·식별자를 사용한다.
분석 범위는 현재 Lua의 발견 항목이다. 현재 게임에 동시에 표시된 `choose` 그룹이나 항목 가시성을 보장하는 정보는 없다.
항목 수가 항상 적다는 전제나 실제 게임의 평균·최대 개수 추정으로 이 결정을 설명하지 않는다.

조건은 현재 Lua에서 발견한 고유 `checkpointmanager.Switch` 키마다 한 행이다. `DataHelper.ParseSwitchCheckpoint`는
그 체크포인트에 속한 조건 항목 전체를 설명으로 묶는다. 한 상세 안에서 모든 조건을 읽도록 본문을 보존한다.
분기 라벨의 읽음 표시는 연결된 이야기의 열람 상태이며, 설명에 표시되는 현재 조건 비교 결과와 다르다.
조건의 분기 읽음·읽음 정보 없음·조회 상태를 유지하며 제목·색·순번에서 새 상태를 추정하지 않는다.

## 선택지: 항상 본문 공개

- 각 카드에 실제 문장, 상태, 원본 ID와 전체 설명을 처음부터 표시한다. 긴 본문은 스크롤로 읽는다.
- 접기·펼침 아이콘과 동작을 제거한다. 제목 클릭은 현재 항목 선택만 바꾸며 본문을 숨기지 않는다.
- 위·아래는 항목 선택을 옮기고 제목이 화면 밖이면 스크롤이 따라간다.
- A는 항목 선택만 수행한다. 좌·우는 본문을 숨기거나 별도 상세 영역으로 이동하지 않는다.
- 오른쪽 스틱은 선택지 전체 본문 영역을 스크롤한다. 수동 읽기 중의 기존 스크롤 소유권 규칙은 유지한다.
- 본문 영역에서 B는 창을 닫는다. Y로 연 도구에서는 B로 이전 영역에 돌아간다.

여러 선택지 설명을 함께 제공하지만 한 화면에 모든 설명이 동시에 들어간다는 의미는 아니다.
UI 모델의 `Expanded` 집합과 `ToggleExpanded` API 및 관련 게시·초기화 상태를 제거했다.
다른 분석 기능의 확장·추적 상태는 이 UI 접기 상태와 별개이며 변경하지 않는다.

## 조건: 목록과 읽기 전용 상세

- 왼쪽 목록에서 체크포인트를 선택하고 오른쪽에서 전체 조건 설명·분기 읽음·원본 ID를 확인한다.
- 검색은 이미 게시된 한국어 제목·식별자·설명만 사용한다. 검색 때문에 게임 조회나 Lua 분석을 추가하지 않는다.
- 위·아래는 목록과 상세 모두에서 체크포인트를 이동한다. 오른쪽 또는 A로 상세에 진입한다.
- 상세에서 왼쪽 또는 B는 목록으로 돌아간다. 목록에서 B는 창을 닫는다.
- 목록과 상세는 독립적인 스크롤을 유지한다. 오른쪽 스틱은 상세 본문을 읽는다.
- 같은 항목의 정상 자동 게시에서는 선택과 상세 스크롤을 유지한다. 목록 배치가 바뀌면 선택 제목을 따라가며, 수동 목록 읽기는 새 탐색까지 유지한다. 다른 항목을 고르면 상세는 처음부터 읽는다.
- 검색 제외·항목 소멸·새 문맥에서는 이전 상세와 실행 초점을 취소하며 다른 항목을 자동으로 고르지 않는다.

조건은 읽기 전용이므로 예약 버튼·예약 안내를 표시하지 않는다. 예약 지원 탭을 이벤트·미션으로 명시해
화면·입력·실행 경로를 보호한다. 단순히 “이벤트가 아니면 미션”으로 처리해 조건에 미션 문구를 붙이지 않는다.
선택지·조건은 유효한 예약 대상을 게시하지 않으며 이벤트·미션의 대상과 타입 의미를 섞지 않는다.

## 이벤트·미션과 공통 입력

이벤트 우선 예약과 미션 조건 통과 예약은 즉시 발생·실행을 보장하지 않는 기존 기능이다.
상세 진입·예약 버튼 초점·예약 작동의 새 입력 요구와 문맥·ID·대상·최신 조회/게시 성공 검증을 유지한다.
대기·실패·이전 값의 예약 차단, 소비된 실제 예약 필드를 반영하는 표시도 유지한다.
LB/RB 탭, Y 도구, X 수동 새로고침, 검색 자판, 기존 로그 열기 키와 입력 소유권·해제 대기 계약은 그대로다.

## 함께 포함하는 초기화·설정 수정

이번 작업 트리에는 [첫 표시 초기화·화면 비율 기본값 수정](ISSUE-4-VIEWPORT-DEFAULTS.md)도 포함한다.
초기 `Awake` 해상도로 작은 배치를 저장하지 않도록 첫 유효 표시까지 계산·보정을 미루고,
새 기본 창은 화면 너비 약 60%·높이 약 70%로 정한다. 본문은 1080p 기준 20px의 높이 배율을 유지한다.
사용자 지정 픽셀 배치·글자 설정은 보존하며 도구 기본값 복구로 새 배치를 적용할 수 있다.
기존 미커밋 변경과 다른 세션의 파일은 보존한다. 이전 `viewport-defaults` 후보 기록은 당시 결과로 남기며 새 후보 해시와 섞지 않는다.

실제 게임 확인은 유지보수자가 수행한다. [기존 Windows 검증표](ISSUE-4-WINDOWS-VALIDATION.md)와 함께 확인한다.

적용 전 게임을 종료하고 DLL과 cfg를 백업한다. 후보 DLL을 교체하되 기존 cfg는 유지할 수 있다.
새 배치는 도구 기본값 복구 또는 [다섯 배치 키 동기화](ISSUE-4-VIEWPORT-DEFAULTS.md)로 적용하며 전체 설정을 불필요하게 덮어쓰지 않는다.
문제가 있으면 게임 종료 후 백업 DLL을 복원하고 배치까지 되돌릴 때는 백업 cfg도 복원한다. 세이브 형식은 바꾸지 않는다.
수신 게임 DLL은 읽기 전용 참조이며 저장소·배포물에 넣지 않는다. 에이전트는 실제 게임을 실행하지 않는다.

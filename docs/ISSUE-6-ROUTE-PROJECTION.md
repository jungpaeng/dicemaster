## 표시 범위

현재 활성 선택지에서 이어지는 주제의 해금을 안전하게 확인하면 상위 선택지에도 `경로 후보: 사사형 → 주제 · 사사형 대화 · 진행 가능성 있음`으로 안내한다. 지도에서는 **선택한 장소**의 두 단계 이상 선택 경로를 최대 한 개 추가한다. 예를 들어 남제자방을 고른 상태에서 `사사형 → 해금된 주제`를 읽는다. 주제의 한국어 이름은 게임 자료로 해석하며 특정 인물·플래그 예외 목록을 두지 않는다.

표시한 모든 후속 선택지의 해금은 확인해야 한다. 내부 이야기의 미확정 분기는 발생 보증으로 바꾸지 않는다. 잠김·해금 미확정·완료 인사·확인된 반복 활동의 고정 반응은 제외한다. 지도 단일 선택의 일반 대화 전체를 새로 표시하는 변경은 아니다. 준비된 경로가 없으면 기존 빈 지도 패널 숨김을 유지한다.

**이 경로 안내만으로 금색 두루마리 마커를 붙이지 않는다.** 기존 실제 대기 임무·1회성 증명·현재 도달 가능성·임무 우선순위 기준은 별도의 기존 읽기로 판정한다. 미선택 장소 마커 조회는 이 경로 수집을 호출하지 않고 Lua 준비를 새로 시작하지 않는다. 지도 행동력·장소 활성·행동 진행·주/대기 임무 우선순위 때문에 기본 활동에 진입하지 못하면 그 기본 활동의 경로도 표시하지 않는다.

## 원인과 읽기 경계

원본 `room_001`은 `statmodifymanager.ResetTalkFlag()` 뒤 `talk_brother4` 메뉴를 연다. 제공된 게임의 `StatModifyManager.ResetTalkFlag → FlagCollectionData.ResetData → FlagData.ResetData`는 해당 목록의 각 `State`를 직렬화된 `_default`로 바꾼다. 기존 표시는 이 읽기를 무조건 미확정으로 마스킹해 바깥 사사형에서는 숨고 실제 열린 안쪽 주제에서만 안내되는 경우가 있었다.

`PreviewConditions.CreateRouteReader`는 이미 로드된 Lua 환경의 정확한 raw 등록에서 관찰한 관리자의 대화 플래그 목록과 **실제 int `_default` 필드**만 읽는다. 기본값을 0으로 가정하지 않는다. 해당 조건을 읽는 시점에만 조회 안의 가상 값으로 사용하며 게임 `State`·Lua·조건·Switch·RNG·ResetData를 실행하거나 쓰지 않는다. 이전에 캡처한 조건을 뒤의 초기화로 다시 해석하지 않는다. 다른 명시적 플래그 쓰기·불명 호출·누락/교체된 자료·상한은 기존 미확정 처리를 유지한다. 추가 쓰기의 순서를 추정해 초기화 값으로 덮지 않는다.

지도는 `FreePositionData._conditionFlags`의 쓰기 대상만 32개 한도에서 읽는다. 그 조건이나 Setup/Execute를 실행하지 않는다. 의존하는 플래그는 미확정이고, 다른 플래그만 쓰는 것으로 확인되면 해당 경로를 계속 읽는다. 뒤의 알려진 대화 초기화가 같은 플래그를 덮는 경우에는 그 이후 기본값을 읽을 수 있다. 진입 배열/대상이 잘못됐거나 한도를 넘으면 경로 안내를 보류한다. 진입 시 행동 소비의 영향을 받을 행동력 조건도 미확정으로 남긴다.

현재 값·가상 값·목록 색인은 한 번의 예정된 조회가 끝나면 버린다. 장기 구문/정의 캐시에 현재 값은 저장하지 않는다. 상세의 `후속 경로 가상 조회`와 기본값 진단은 실제 현재 상태와 구분한다. 가상 조회를 기회 마커 읽기에 적용하지 않는다.

## 준비와 비용

선택 번호가 리터럴로 정해진 `if/elseif`는 새 대안이 아니다. 동일 작업을 그대로 이어 처리해 불필요한 환경 복사와 누적 문맥 소비를 줄였다. 게임 조건은 이 최적화로 계산하지 않는다. 원본 사사형 재현에서 기존 문맥 한도에 막히던 주제 연결을 같은 한도 안에서 수집한다. 지역 변수의 가림/복원·나중 등록 우선 규칙을 유지한다.

현재 원문의 메뉴 범위가 닫히고 표시할 경로의 각 후속 해금이 확인되면 다른 후속 작업의 완료까지 기다리지 않는다. 루트 중복 메뉴·생략 본문·동적 원문·상한은 여전히 먼저 표시할 유일성 근거가 아니다. 지도도 현재 루트의 미처리 작업 수를 추적하되 기존 지도 작업 큐 순서는 바꾸지 않는다. 경로 발견 범위가 늘었으므로 전체 준비가 소비하는 총 자원/작업량은 예전의 잘린 탐색보다 늘 수 있다. 첫 유효 표시와 전체 탐색 종료를 따로 측정해야 한다.

각 조회의 기존 8192 작업·약 5ms 양보·자원/풀 각 1회와 누적 작업/문맥/깊이 한도는 유지한다. 새 분석기를 병렬로 돌리거나 한도를 늘리지 않는다. 현재 값 조회에는 기존 32개 경로/조건·16384 읽기 작업 한도를 적용한다. 같은 조회 안에서는 직렬화된 조건 목록을 앞에서부터 거듭 훑지 않고 이미 읽은 접두 색인과 동일 조건 노드 결과를 재사용한다. 임무/1회성 기본 읽기는 별도이며 이 추가 색인을 만들지 않는다.

선택 장소의 경로 준비는 `EnableMapGuide`에 속한다. 따라서 **1회성 OFF여도 지도 안내 ON이면 선택한 장소의 경로 Lua를 예정된 예산 안에서 준비할 수 있다.** 실제 대기 임무가 클릭을 차지하면 1회성 OFF의 임무 우선 빠른 조회를 유지한다. 미선택 마커·숨김/OFF의 조회 중단과 정상 주기 Lua 재분석 없음은 유지한다.

## 갱신 간격 비교

호스트 .NET 8에서 생산 Reader/공급자·합성 직렬화 조건으로 측정했다. Windows·Unity 렌더링·실제 세이브·FPS 측정이 아니다. 비교 원본은 기존 엄격 Reader이며 기능이 다른 alpha.24 전체 런타임과의 프레임 비교가 아니다.

256개 조건 정의에서 뒤쪽 32개를 읽는 동일 결과 실험을 순서를 바꿔 각 150회씩 3회 실행했다. 평균은 기존 목록 탐색 **2.371ms → 0.254ms**, 약 **89% 감소**였다. 대신 조회당 할당은 약 **36KB → 61KB**로 늘었다. 이는 조회 안의 색인에 따른 교환이다. 모든 경로/조건/기기에서 같은 비율을 보장하지 않는다.

별도로 공급자를 준비시킨 후 각 간격을 3회, 90초·60fps의 가상 스케줄로 비교했다. 생산 RefreshEngine의 시계만 비례 조절하고 공급자의 실제 시간/실패 재시도 시계는 유지했다. 자원 읽기는 각 실행 1회였다.

| 정상 간격 | 조회 수 | 첫 경로 표시 | 잠김 전환 뒤 제거 지연 | 조회 CPU 합계 중앙값/90초 |
| --- | ---: | ---: | ---: | ---: |
| 0.25초 | 361 | 0.25초 | 0.117초 | 6.353ms |
| 0.5초 | 181 | 0.5초 | 0.367초 | 3.185ms |
| 1초 | 91 | 1초 | 0.867초 | 1.659ms |

**정상 0.25초·실패 5초를 유지한다.** 0.5초는 이 표본의 조회 수와 CPU 합계를 약 절반으로 줄였으나, 90초 동안 절약한 CPU는 약 3ms였고 첫 표시/해금 변경 반영은 늦어졌다. 최초의 여러 단계 준비에서는 더 늦어질 수 있다. 실게임에서 이득이 확인되지 않은 상태에서 반응성을 낮출 근거로 충분하지 않다. 향후 Windows 자료에서 반복 조회가 병목이면 준비/포커스 변경은 즉시 처리하고 안정된 상태만 늦추는 방식을 별도로 검증할 수 있다.

재현: `ChoiceStoryTests.dll --projection-benchmark`. 코드 `tests/ChoiceStoryTests/ProjectionBenchmark.cs`, 원자료 `artifacts/issue-6/route-reset-projection/projection-benchmark.json`. 성능 수치를 테스트 통과 임계값으로 사용하지 않는다.

## 검증과 설치

`ResetProjectionCases`는 기본값/비영 기본값·현재 값 유지·선행 캡처·추가 쓰기·미확정 자료·잠김 전환·준비 중 조기 표시·정상 캐시를 검사한다. SHA를 확인한 원본 `room_001 → talk_brother4 → talk_brother4_option_00_01`을 합성 조건과 연결해 실제 원문 캡처 후킹·완료 인사 제외·해금 주제 공개·다른 준비 작업 대기 중 공개·다시 잠겼을 때 제거·매 조회 예산을 함께 검사한다. 검사에서 부여한 주제 이름을 실제 ‘색종이’ 번역/사용자 세이브와 동일하다고 주장하지 않는다.

지도 통합 검사는 상위 경로·마커 부재·잠긴 조건·진입 쓰기/분리된 쓰기/후속 초기화·누락된 진입 자료·행동력·대기 임무 우선·정상 캐시를 검사한다. 실제 DLL의 Reader 진입점/기본값/쓰기 마스크/거짓 AND/진단과 기존 입력·로그·주사위·상점·분기·팝업 검사도 실행한다. [Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md#alpha25--후속-경로-확인-대기).

로컬 후보는 `artifacts/issue-6/route-reset-projection/candidate/`의 DLL·설치 ZIP·build-manifest.json·build.log다. 최종 파일 식별값과 전체 검사 결과는 아래 검증 기록을 따른다. 게임 종료 후 백업하고 DLL만 교체해 기존 cfg를 보존한다. 새 설정/키 변경은 없다. 새 후보의 실제 Windows·물리 입력·화면 가림·첫/반복 프레임 확인 전 #6을 완료하거나 종료하지 않는다.


## 최종 로컬 검증 기록

전체 소스 빌드의 **21개 검사 프로그램**과 실제 후보 DLL 연결·기존 입력/정보 후킹·설치 ZIP의 두 경로/CRC/내부 DLL·cfg 바이트 검증을 통과했다. 280개 빌드 입력·113개 소스/리소스·16개 제공 참조를 대조했다. 후보 생성 후 현재 전체 빌드 입력 지문을 다시 확인했다. 선택 안내 원본/합성 조건 7,650개, 지도 통합 3,356개, 경로 분석 6,884개 단언이 포함되며 전체 결과는 build-manifest.json과 build.log에 보존한다.

설정은 상위 EnableOptionInfo·개별 EnableMapGuide/EnableOneShotHints를 유지한다. 정상 .25초/실패 5초와 OFF/숨김 조회 중단은 변경하지 않았다. 경로만을 근거로 분기 기록·세이브·상태를 추가 저장하지 않는다. 기존 지도 성능 진단의 경로 현재값 횟수는 이벤트 경로 표본 수이며 신규 대화의 모든 조건 읽기 횟수를 뜻하지 않는다. 공급자 시간·실게임 프레임/할당량은 함께 확인해야 한다.

이 절은 커밋·게시 전의 로컬 검증 기록이다. 후속 고정 소스 재빌드와 게시·공개 다운로드 결과는 [alpha.25 후보·게시 기록](ISSUE-6-ALPHA25-RELEASE.md)에 구분한다. 새 Windows/물리 입력/실제 프레임 확인과 #6 전체 완료는 대기다.

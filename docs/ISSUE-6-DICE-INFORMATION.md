# 주사위 판정 안내와 확정 결과 기록 — alpha.38

## 범위와 사용자 표시

마커가 있던 선택지뿐 아니라 마커 없는 선택·자동 진행에서 실제 열린 DiceMenuDialog를 대상으로 한다. 현재 게임의 ExecuteRoll과 legacy ShowTimer를 관찰한다. 우측 상단의 기존 분기 알림 자리에 판정 이름·연결을 확인한 진입 선택·진행 중 상태를 표시하며, 현재 주사위가 우선한다. 로그/팝업/게임 창 가림·앱 포커스 상실·주사위 소유자 변경은 표시를 숨긴다.

진입 선택은 실제 표준 메뉴 Button.Press에서 해당 메뉴의 활성·조작 가능한 버튼과 표시 이름을 확인하고 원래 호출이 성공했을 때만 연결한다. 포커스/마우스 호버를 누른 선택으로 취급하지 않는다. 새 메뉴·실제 Lua 로드에서 미소비 맥락을 버리고 다음 주사위가 한 번 소비한다. 다른 스크립트로 넘어가 연결을 확정하지 못하면 주사위 정보만 제공한다. 이벤트 이름이나 미래 결과를 추측해 만들지 않는다.

진행 확정 뒤의 결과는 기존 5초 알림과 로그 → 도구 → 분기 기록에서 조회한다. 실제 이벤트/조건/주사위를 합쳐 최근20건을 실행 메모리에 보관하며, 새 실제 결과가 이전 알림보다 우선한다. 저장하지 않는다. 결과별 미래 대화/효과 예측, 모든 후속 이야기 분석, DiceOption에 흰/검은 마커를 붙이는 기능은 이번 범위에 포함하지 않는다.

## 실제 게임 근거와 확정 시점

제공받은 Mortal.Story.DiceMenuDialog.ExecuteRoll(string[],int,string)은 options와 checkName을 받아 원래 UI에 결과 이름을 채운다. Roll은 RNG와 CheckPointManager.Dice를 실행하고 _resultSelection에 실제 번호를 남긴다. DiceOption은 _sourceText에서 원래 항목/범위를 읽고 _normalText에 결과 이름을 표시한다. DiceHeader._front에는 실제로 표시한 판정명이 있다.

원문 Lua에는 Setup을 위한 초기 Dice 호출, 실제 Roll·재굴림의 Dice 호출이 구분돼 있다. CheckPointManager.Dice나 DiceResultData.Execute만 관찰하면 아직 채택하지 않은 계산을 기록할 수 있다. Execute는 _count도 변경하므로 정보 조회를 위해 다시 실행해서는 안 된다.

두 원래 주사위 코루틴은 진행 입력을 기다린 뒤 Clear→화면 닫기→후속 콜백을 수행한다. 관찰 중인 정확한 코루틴의 MoveNext 안에서 같은 소유자의 _triggerNextInput이 참인 Clear에만 상태를 잡고, 그 Clear의 finalizer가 원래 예외 없이 끝났을 때 결과를 기록한다. UI 이름/원래 항목은 Clear 전에 복사해 둔다. 외부 Clear·취소·초기 계산·재굴림 중간 값·원래 Clear 실패는 확정 기록이 아니다. 정상 확정 뒤 후속 Lua 콜백이 실패해도 이미 확인한 주사위 결과를 다른 결과로 바꾸지 않으며 그 원래 예외를 보존한다.

MenuDialog.Clear의 StopAllCoroutines가 자기 정리 중 Dispose를 일으키는 관리 경계도 검사한다. 원래 MoveNext/Current/yield 객체/Reset/예외를 위임하고 Dispose를 전달하며 입력, 주사위 값, 원래 게임 판정 결과를 덮어쓰지 않는다. 실제 Unity 코루틴 취소·정리 순서와 다른 모드의 Harmony 조합은 Windows 확인이 필요하다.

## 데이터·설정·성능·실패

- 게임이 이미 표시한 텍스트·판정 키·확정 결과 번호만 읽는다. GetStoryText, 주사위 판정/실행 함수, RNG, 세이브/능력치/아이템, 전체 이벤트/Lua 검색을 새로 실행하지 않는다. 자동 표시는 이름·종류·상태이며 원래 결과 항목과 상세는 기존 로그에서 읽는다.
- 기존 EnableBranchNotices와 상위 EnableOptionInfo를 따른다. 지도/1회성 설정이 모두 OFF여도 동작하고 새 키/탭/cfg 변경은 없다. 기존 저장/불러오기/새 게임/장면/기록 초기화와 분기 OFF에서 현재 맥락·기록을 정리한다. OFF 전에 시작한 코루틴은 ON 후 기록으로 재생하지 않는다.
- 기존 정상0.25초/실패5초·Lua 정의 캐시·숨김 조회 중단 계약을 바꾸지 않는다. 새 폴링은 없다. 원래 주사위의 진행 경계에서 UI 자료만 복사하고, 정상 그리기와 기록 상세는 복사본을 재사용한다. 결과64개·메뉴 버튼256개·표시 변형12개·문자열4096자 읽기 상한을 둔다. 추가 씬 탐색이나 입력 리스너는 없다.
- 제목·진입 선택·결과명은 자동 표시에서 짧게 줄이고 화면/글꼴/내용 변경 때만 크기를 측정한다. 작은 화면에서는 줄 단위 요약/생략 후에도 맞지 않으면 숨기며, 완료 결과의 전체 이름은 기록 상세에 남긴다.
- 읽기 실패는 기존 진단에 남기고 이전 UI 이름을 현재 값처럼 유지하지 않는다. 소유자 표시와 실제 확정 번호만 별도로 확인되면 이름 미확인/결과 번호로 기록한다. 연결 미확인·읽기 실패를 가짜 대화명이나 이벤트 부재로 바꾸지 않는다. 새 후킹 실패는 기존 분기 기록을 끄지 않고 진단에 남긴다.

## 검사와 한계

실제 생산 소스의 관찰/기록/표시 코드로 마커 없는/자동 진행·legacy timer·실제 버튼과 호버 구분·재굴림·확정 1회·취소/외부 clear/clear 실패·자기 정리 Dispose·원래 yield/반환/예외/Dispose 보존·OFF/ON/문맥·5초/20건·데이터 실패·긴 이름/작은 화면·가림을 검사한다.1,000회 웜 안내는 같은 행과 측정 결과를 재사용하며 원천 샘플을 다시 읽지 않는다. 실제 DLL IL 검사는 판정/RNG/입력 쓰기·자료 재검색 호출이 없는지 확인하고 실제 제공 DLL의 Button.Press/주사위 코루틴/필드 서명을 대조한다.

고정 참조와 제공받은 게임 복제본 DLL 연결의 전체21개 검사를 각각 통과했다. 이는 관리 경계/메타데이터 검사이며 실제 Windows/Unity/Harmony·사용자 세이브·물리 입력·FPS 검사를 대신하지 않는다. [후보·게시·파일](ISSUE-6-ALPHA38-RELEASE.md) · [Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md).

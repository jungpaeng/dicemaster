# PRD #4 후속: 상세 제목 대신 조작 버튼에 초점

2026-10-19 KST. 사용자는 이벤트·미션 상세의 제목에 초점을 둘 필요 없이 내부 조작 항목으로 바로 이동하도록 요청했다.
조건에도 같은 원칙을 적용하며, 작동 가능한 항목이 없거나 비활성 상태라면 상세 초점 진입을 막는다.
화면의 설명을 읽는 것과 실제 조작 버튼에 초점을 주는 것을 구분한다. 상세 제목·본문은 초점 없이도 표시하고 스크롤한다.
이번 기록은 로컬 후보이며 실제 Windows 게임 확인·prerelease 게시·이슈 #4 완료를 뜻하지 않는다.
기존 구현은 선택 항목이 있으면 버튼의 활성 여부와 무관하게 상세 영역으로 진입할 수 있었다. 이번에 명시적인 진입 조건을 추가했다.
후속 [패드 모드 터치 복구](ISSUE-4-TOUCH-INPUT.md)는 이 포커스 규칙을 포함한다. 아래 해시와 검사는 조작 포커스 수정 당시 후보의 기록이다.

## 바뀐 초점 규칙

| 탭·상태 | A·오른쪽으로 상세 진입 | 읽기·복귀 |
| --- | --- | --- |
| 선택지 | 별도 상세 초점 없음, 본문 항상 공개 | ↑↓ 항목 선택, 오른쪽 스틱 본문, B 닫기 |
| 조건 | 조작 항목이 없어 진입하지 않음 | ↑↓ 체크포인트 선택, 오른쪽 스틱 상세 본문, B 닫기 |
| 이벤트·미션의 유효한 예약 버튼 | 제목을 건너뛰고 예약 버튼에 바로 초점 | 오른쪽 스틱 본문, 왼쪽·B 목록 |
| 대상 없음·대기·실패·게시 실패 등 비활성 버튼 | 진입하지 않고 목록에 유지 | ↑↓ 항목 선택, 본문 읽기·새로고침·도구 사용 가능 |

모든 `상세`·`조건 상세` 제목은 일반 라벨이며 `▶` 초점 표시를 붙이지 않는다.
예약 버튼이 실제로 초점을 가질 때 그 버튼에 표시한다. 제목이나 본문을 가상의 조작 항목으로 두지 않는다.
조건의 오른쪽 상세는 계속 보이지만 A·오른쪽으로 빈 조작 영역에 들어가지 않는다.
따라서 조건에서는 B 한 번으로 로그를 닫으며, 앞선 후보의 조건 상세 진입·단계별 복귀 동작은 이번 요청으로 대체한다.

## 진입·활성화와 예약 보호

렌더러의 `CanFocusDetailControl`은 예약 지원 탭, 선택 대상 존재, `CanReserve`, 게시 실패 없음이 모두 참일 때만 성립한다.
`EnterDetail`은 이 조건을 확인한 뒤 유효한 예약 버튼에 초점과 실행 권한을 준다. 실패하면 목록에 남는다.
이 진입 판단은 게시된 상태 기준이며 실제 예약 직전에는 기존 `LogBridge.TryReserve`가 문맥·항목·실제 대상을 다시 검증한다.

- 목록에서 A·오른쪽은 **버튼에 초점만** 준다. 그 입력으로 예약까지 실행하지 않는다.
- 예약하려면 버튼을 놓은 뒤 별도의 새 A 입력이 필요하다. 키보드의 확정 키도 같은 새 입력 규칙을 따른다.
- 현재 상세의 조작 항목은 예약 버튼 하나다. 위·아래·오른쪽을 다시 눌러도 이 버튼을 유지한다.
- 위·아래·오른쪽으로 제목에 이동하거나 무효화된 실행 권한을 자동으로 다시 부여하지 않는다.
- 이벤트는 다음 해당 판정의 가중치를 높이는 우선 예약, 미션은 조건 통과 예약이라는 기존 의미를 유지한다.
- 초점 이동·예약 성공을 즉시 이벤트 발생·미션 실행·행동 재개의 보장으로 설명하지 않는다.

선택이 없을 때 A의 기존 첫 항목 선택 동작은 유지한다. 대상 선택·버튼 초점·예약은 필요한 별도 입력을 거친다.

## 비활성화·복구와 도구 복귀

버튼이 대기·실패·대상 소멸·게시 실패 등으로 사용할 수 없으면 처음부터 상세 초점에 진입하지 않는다.
이미 진입한 뒤 사용할 수 없게 되거나 실행 권한이 취소되면 목록으로 돌아가 진행 중 확인을 취소한다.
패드 입력도 취소하고 기존 버튼 해제·스틱 중립 대기를 적용해 같은 입력이 다른 대상이나 게임으로 넘어가지 않게 한다.
조회가 정상으로 회복됐다는 이유만으로 상세 초점에 자동 진입하거나 이전 확인 입력을 되살리지 않는다.
사용자가 목록에서 다시 A·오른쪽으로 유효한 버튼을 명시적으로 고른다.

Y로 도구를 연 뒤 B 또는 **이전 영역으로 돌아가기**를 선택할 때도 같은 진입 조건을 재확인한다.
이전에 예약 버튼을 보고 있었더라도 현재 대상이 비활성이면 목록으로 돌아간다. 조건은 항상 목록으로 복귀한다.
도구·검색 자판의 기존 복귀 단계와 검색 확정·취소 동작은 유지한다.

## 예약 뒤 초점과 마우스·키보드

`TryReserve`가 성공하고 기존 실행 티켓의 문맥·항목·대상이 계속 유효할 때만 같은 예약 버튼의 초점을 유지한다.
이때도 이전 티켓 버전은 폐기한다. 다음 예약은 버튼 해제 뒤의 새 입력으로 새 티켓을 만들어야 한다.
예약 실패나 대상 변경 시에는 목록으로 돌아가며 이전 초점으로 다른 항목을 작동시키지 않는다.

패드는 기존 A의 누름 전환, 키보드는 `heldKeys`를 사용한다. A·Enter·Space를 누른 채 두어도 반복 예약하지 않는다.
마우스 예약은 누르기 시작한 문맥·안정적인 컨트롤 ID·대상의 확인을 해제 시점까지 유지한다.
도구·닫기 등의 마우스 누름과 검색 편집은 실행 권한을 의도적으로 취소한다. 다만 누름→해제나 편집이 끝나기 전에
초점을 강제로 초기화해 진행 중인 클릭·닫기·검색 조작이 사라지지 않도록 보호한다.
이 보호를 예약 권한의 자동 복구로 사용하지 않으며, 실제 예약은 기존 티켓 검증을 통과해야 한다.
검색어가 선택 행을 제외해도 동일 문맥에서의 연속 편집은 유지하고 선택·예약 권한만 취소한다. 외부 게시나 새 문맥의 대상 소멸은 기존 취소 경로를 따른다.
검색 종료 Enter·KeypadEnter·Escape도 해제까지 눌린 키로 기억해 반복 입력이 목록 선택이나 닫기로 전달되지 않도록 한다.

## 함께 포함한 로컬 변경

선택지 본문 상시 공개·조건 좌우 배치는 [탭 구성 기록](ISSUE-4-TAB-LAYOUT.md)의 화면 구성을 유지한다.
단, 상세 초점과 조건의 A·오른쪽·B 계약은 위 최신 규칙을 따른다.
[첫 표시 지연 초기화와 화면 너비 60%·높이 70% 기본 배치](ISSUE-4-VIEWPORT-DEFAULTS.md)도 작업 트리에 함께 포함한다.
이전 후보의 해시·검사·미확인 기록은 당시 결과로 보존하며 이번 후보의 성공 증거로 바꾸어 쓰지 않는다.
다른 세션의 미커밋 변경과 기존 파일은 보존한다. 수신 게임 DLL은 읽기 전용 참조이며 설치 ZIP에 추가하지 않는다.

실제 게임 검증은 유지보수자가 수행한다. 아래 항목은 아직 확인 대기다.

적용 전 게임을 종료하고 현재 DLL과 cfg를 백업한다. 후보 DLL만 교체하며 기존 cfg는 유지할 수 있다.
새 기본 배치를 원하면 도구의 기본값 복구를 사용한다. 전체 cfg를 불필요하게 덮어쓰지 않는다.
문제 시 게임 종료 후 백업 DLL을 복원하고, 창 설정까지 되돌릴 때는 백업 cfg도 복원한다. 세이브 형식은 변경하지 않는다.

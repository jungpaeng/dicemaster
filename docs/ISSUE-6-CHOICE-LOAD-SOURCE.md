# 선택 안내 — 실행용 변환 전 원문 보존

<!-- alpha23-publication -->
전체 소스 빌드의 21개 검사 프로그램·275개 입력·112개 소스/리소스·16개 고정 참조·실제 후보 DLL 연결·설치 ZIP의 두 경로/CRC/내부 바이트 검증을 통과했다. 고정 커밋 재빌드·게시·공개 다운로드는 후속 기록한다. **새 DLL의 실제 Windows·Unity 화면·물리 입력·FPS 확인과 #6 전체 완료는 대기다.**
<!-- /alpha23-publication -->

## 확인한 증상과 원인

사용자는 alpha.22에서 초회 인사가 늦게 나타나 미표시로 생각했다고 정정했다. 초회 대화를 본 뒤에도 툴팁이 남으며, 상세의 표시 근거는 `room_001 · D_Room_001_001`, 현재 조건 진단은 미확정, 수집 경로는 20개·직접 우선 배치는 1개라고 보고했다. 이는 후속 대련이 아니라 초회 인사를 표시한 자료이며, 수집 경로가 32개보다 적어 alpha.22의 상한 우선 배치만으로 해결할 수 없다.

실제 로드 경계에서 `EventExecutionPatches.LuaLoadPatch.Prefix`는 #5의 실행 직전 선택을 위해 `EventLuaGate.Instrument`로 원래 Switch/Position 호출을 콜백·함수 래퍼로 변환한다. 기존 `ChoiceStoryPatches.ScriptLoaded.Finalizer`는 이 **변환된 luaString 인수**를 이야기 정의로 전달했다. 단순 원문 Switch를 읽는 조건기에는 호출 래퍼가 미지원 식이 되어 완료 조건·원문 화면 준비 경계가 손실된다. 범용 미확정 분기로 남은 초회 대사가 다시 가능성 툴팁이 되고, 원문에서 좁힐 수 있었던 후속 경로도 더 준비하게 된다.

원본 `room_001` SHA-256은 `106d054c345c97060b627bf0dac03dcb8046de38eed03397598f08a58e44be10`이다. 원문을 실제 #5 변환기에 넣고 완료 횟수 1의 합성 직렬화 설정으로 읽으면 같은 대사 ID·미확정·잔존을 재현한다. 변환 전 원문은 같은 설정에서 완료 인사를 제거한다. 사용자 세이브의 실제 Switch 설정·횟수·전체 플래그를 직접 읽은 것은 아니므로 세이브의 모든 조건이 검증됐다고 해석하지 않는다.

## 수정과 보존

동일 LoadLuaFunction 호출의 `HarmonyPriority.First` Prefix에서 원문과 friendlyName을 호출별 상태에 보관하고, `Priority.Last` Finalizer에서 성공 결과·예외 없음·표시 보호 밖임을 확인한 뒤 그 원문만 `ObserveScript`에 전달한다. 실행용 luaString을 역변환/삭제하거나 전역 마지막 문자열에서 가져오지 않는다. #5 변환기는 기존대로 실행 입력을 만들고 실제 선택·예약·분기 관찰 경로는 유지한다. 실패/결과 없음/보호된 호출은 새 원문을 게시하지 않으며 예외를 그대로 반환한다.

특정 인물·조건 키·완료 목록 예외가 아니다. 기존 직접 경로 우선 배치, 완료/활동/후속 해금 판정, 대기 임무와 증명 1회성 마커 기준을 유지한다. 새 설정이나 cfg 변경은 없다. 상위 EnableOptionInfo·개별 EnableMapGuide/EnableOneShotHints와 OFF/숨김 중단, .25초 정상/5초 실패·기존 경로/읽기 예산·정상 주기 Lua 재분석 없음 계약을 보존한다. 게임 판정·RNG·횟수·플래그·세이브·능력치·아이템을 변경하지 않는다.

## 자동 검사와 지연 한계

`ChoiceLoadCases.cs`는 생산 코드의 원문 캡처 Prefix·성공 Finalizer와 실제 #5 변환기를 호출 순서에 맞게 연결한다. 실행 입력 유지·호출별 원문 참조·초회 남음/완료 전환·패드 포커스·실패/결과 없음/표시 보호·중첩 실패·정상 캐시/횟수 무변경을 검사한다. `EntryDialogueCases.cs`는 SHA를 확인한 실제 room 원문을 변환해 **이전 잘못된 경계의 잔존**부터 재현한 뒤 수정된 후킹 경계에서 미완료 보존·완료/반복 제외를 확인한다. 실제 DLL의 Harmony 우선순위·상태 인수·게임 API 연결은 InformationRuntimeTests에서도 검사한다. 이 순서 검사 자체는 Harmony를 사용자 게임에 설치하거나 Lua를 실행한 결과가 아니다.

읽기 전용 별도 조사에서는 같은 합성 설정의 원문이 6개 자원·10회 갱신 후, 변환문이 18개 자원·27회 갱신 후 처음 툴팁을 만들었다. 정상 .25초 간격으로 환산하면 2.5초와 6.75초이며 Windows 실측이나 FPS 개선 수치가 아니다. 수정은 불필요한 변환문 분석과 그 불확실성이 늘리는 준비를 제거한다. **전체 후속 경로/메뉴 유일성 준비를 기다리는 구조는 남아 있으므로 모든 장소의 즉시 표시를 보장하지 않는다.** 최초 준비·다시 진입·완료 후 제거 시간을 새 Windows 후보에서 따로 확인한다.

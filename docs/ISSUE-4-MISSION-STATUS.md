# PRD #4 후속: 미션 상태 안내 행 배치와 선택 제한

2026-10-19 KST. 사용자가 미션 탭의 `미션 정보 / 설명 조회 대기`처럼 값 없는 상태 안내 행을
목록 최하단에 배치하고 비활성화하도록 요청했다. 아래는 기존 변경을 보존한 로컬 후보의 검사 기록이다.
이후 사용자 승인에 따라 [alpha.5 prerelease](ISSUE-4-ALPHA5-RELEASE.md)에 함께 포함한다. 에이전트는 게임을 설치하거나 실행하지 않으며 이슈 #4 완료는 사용자 확인을 기다린다.

## 구분과 표시

실제 게시 경계인 `LogBridge`가 **미션 탭이며 게시 값이 null인 행에만** `IsStatusOnly = true`를 지정한다.
모델은 일반 행을 먼저, 상태 안내 행을 마지막에 배치하고 각 그룹 안의 원래 순서를 유지한다.
제목이 `미션 정보`인지, 예약 대상이 null인지, 조회 상태가 대기인지로 분류를 추측하지 않는다.
상태 안내 행도 삭제·필터링하지 않는다. 비활성 목록에서 조회 상태·원본 ID를 읽고 상단 상태 요약에도 포함한다.
선택하지 않아도 대기의 의미와 재조회 방법을 읽을 수 있도록, 목록의 첫 대기 안내 행 앞에 기존 설명을 한 번 표시한다.
안내 행만 있을 때 오른쪽 영역은 선택 가능한 항목이 없음을 알리고 목록 안내·새로고침을 안내한다.

| 행의 성격 | 선택·상세 읽기 | 예약 |
| --- | --- | --- |
| 미션 값 없는 상태 안내 행 | 모든 입력에서 선택 거부, 목록에서 상태·원본 ID 읽기 | 불가 |
| 실제 값 있는 대기·실패·이전 값 미션 | 선택 가능, 보존된 설명과 상태 읽기 | 현재 불가. 정상 복구 후 현재 대상 재검증 필요 |
| 읽기 전용 선택지·조건 | 기존 선택·전체 본문/설명 읽기 유지 | 예약 기능 없음 |
| 정상 이벤트·미션 | 기존 선택·상세 읽기 유지 | 활성 버튼 진입 뒤 별도 새 입력으로 기존 예약 |

모델의 안내 행 선택 거부는 기존 정상 선택·목록/상세 스크롤·유효 예약 티켓을 바꾸지 않는다.
별도 포인터 입력 전환이 기존 패드 실행 권한을 취소하는 입력 소유권 보호는 유지한다.
존재하지 않는 ID, 대상 소멸·교체와 새 문맥의 기존 취소 계약은 유지한다.
선택 중인 일반 행이 안내 행으로 바뀌면 선택·실행 초점·이전 티켓을 취소한다.
후속 조회가 정상으로 회복되어도 자동 선택하거나 이전 예약 권한을 되살리지 않는다.

## 상태 문구의 의미

`미션 정보`는 값 없는 게시 행에 붙이는 상태 안내 제목이며 실제 미션 이름이나 별도 분석 상태가 아니다.
`설명 조회 대기`는 기존 데이터 미준비 상태의 UI 문구다. 현재 미션 단계 키가 없거나 설명 조회에 필요한 자료를
얻지 못한 경우 등이 포함되므로 게임 로딩 중·미션 미완료·조건 미충족으로 단정할 수 없다.
현재 단계가 없는 상태도 기존 대기 계약에 포함되어 계속 표시될 수 있으며 개별 행의 원인을 문구만으로 확정하지 않는다.
구조화된 효과 분석의 `분석 대기`와도 별개다. 이번 변경은 조회·분석 백엔드의 상태 분류를 바꾸지 않는다.

기존 준비 완료 이후 대기·실패 행은 로그를 연 활성 탭에서 5초 간격으로 재조회하고 X/새로고침으로 다시 확인한다.
Lua 문맥 자체가 준비되지 않은 경우에는 기존 준비 경계를 기다리며 새로고침으로 강제 준비하지 않는다.
실제 값이 있는 대기·실패 행은 읽을 수 있지만, 정상 최신 값이 아니면 예약 버튼은 진입·작동할 수 없다.

## 패드·키보드·포인터로 읽기

- ↑↓/왼쪽 스틱은 안내 행을 건너뛰고 선택 가능한 항목 사이를 이동한다. A도 안내 행을 선택하지 않는다.
- 선택이 없으면 오른쪽 스틱은 목록을 스크롤한다. 안내 행만 있는 목록도 끝까지 읽을 수 있다.
- 일반 항목을 선택했으면 오른쪽 스틱은 기존처럼 오른쪽 상세를 스크롤한다.
- 일반 항목과 안내 행이 섞인 목록의 마지막 선택 가능 항목에서 ↓를 더 누르면 선택을 유지한 채 아래 안내를 스크롤한다.
- 이 상태에서 ↑는 이전 일반 항목으로 이동하고 선택 항목을 따라가는 스크롤을 재개한다.
- 마우스·터치의 안내 행 누름도 선택을 바꾸지 않는다. 휠·스크롤바·터치 스크롤로 목록의 안내·원본 ID를 읽는다.

로그 열기는 기존 `[DiceMaster].LogMenuToggleKey`이며 기본값은 Tab이다. 패드 열기 조합은 추가하지 않는다.
검색 없는 네 탭과 도구 17개, 일반 키보드 탐색, 터치·커서 복원, 예약 시 현재 문맥·대상·티켓 검증을 유지한다.
`이벤트 우선 예약`·`미션 조건 통과 예약`은 즉시 발생을 보장하지 않는다. 진입 입력 뒤 별도 새 확인 입력이 필요하다.
모드 전환·재연결·Alt-Tab·새 문맥·닫기 뒤 해제/중립 대기와 `로그 > 주사위 조절 > 게임` 입력 소유권도 유지한다.
위치·크기·글자는 기존 cfg에 저장하고 선택·두 스크롤은 실행 중에만 유지한다. 설정 키는 추가하지 않는다.

## 적용과 복구

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. 최종 후보 ZIP을 임시 폴더에 풀어 아래 명령으로 해시를 확인한다. 기존 설정 유지 시 **DLL만** 플러그인 경로에 교체한다.
3. Tab 또는 기존 열기 키로 로그를 열어 미션 목록과 네 탭·도구를 확인한다. cfg 전체 교체는 새 설치용이며 이번 변경에 필요하지 않다.
4. 문제가 있으면 게임 종료 후 백업 DLL을 복원한다. 배치 설정까지 되돌리려면 백업 cfg도 복원한다. 세이브 형식은 바꾸지 않는다.

```powershell
Get-FileHash .\DiceMaster-source-candidate.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

실제 패드 탐색·스크롤·버튼과 주요 회귀를 사용자가 확인하기 전까지 전체 지원이나 이슈 #4 완료를 선언하지 않는다.

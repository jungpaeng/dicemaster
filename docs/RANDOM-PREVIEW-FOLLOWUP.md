# 이슈 #1 후속 구현 — 난수 조건 미리보기 (alpha.2 게시)

[PRD #1](https://github.com/jungpaeng/dicemaster/issues/1) · [현재 검증 기록](ISSUE-1-VALIDATION.md) · [실제 게임 API 분석](REAL-GAME-API-FINDINGS.md)

기록일: 2026-10-18. 사용자가 난수 표시 문제 수정과 새 prerelease 발행을 명시적으로 승인하여 **[v1.0.3-alpha.2 prerelease](https://github.com/jungpaeng/dicemaster/releases/tag/v1.0.3-alpha.2) 게시와 익명 공개 다운로드 검증을 마쳤습니다.** 최종 macOS 패드→로그 왕복·반복 패치·직접 패드 검사를 통과했고 2026-10-18 21:52:10 KST에 게시했습니다. 전체 기능 완료 기록은 아닙니다. Windows 게임 실행은 새로 승인되지 않았으며 실행하거나 요청하지 않습니다. 기능·이슈 완료와 정식 Release는 계속 보류합니다.

게시된 `v1.0.3-alpha.1`의 코드·DLL·ZIP에는 이 개선안이 없습니다. alpha.1의 난수 실패 정책·배포 커밋·해시·검사 결과는 이력으로 보존하며 alpha.2의 결과로 승계하지 않습니다.

## 소스에 반영한 표시 동작

`v1.0.3-alpha.1`의 `SafeDisplayEvaluation`은 난수 참조에서 `RandomDisplayValueException`을 발생시켜 행의 `읽기 실패` 또는 `갱신 실패 · 이전 값`으로 연결합니다. 난수 결과가 아직 결정되지 않았다는 사실과 실제 조회 오류를 구분하는 것이 이번 변경입니다.

| 상황 | alpha.2 표시 |
|---|---|
| `1~100의 난수 ≥ 50`, 범위를 안전하게 해석할 수 있음 | `난수 1~100 · 실행 시 판정` — 비교식도 함께 유지 |
| 범위·비교는 표시할 수 있지만 확률의 근거가 부족함 | 범위와 판정 미정만 표시하고 확률은 생략 |
| 복합·종속·미지원 형태로 안전한 미리보기가 불가능함 | `난수 조건 · 미리보기 미지원` |
| 필드 조회·자료 파싱 등 실제 오류 | 기존 대기/읽기 실패/이전 값 상태를 유지 |

판정 미정과 미지원은 거짓·0·정상 빈 목록으로 변환하지 않습니다. 성공/실패로 오해할 수 있는 판정 색상을 사용하지 않고 한국어 문구로 구분합니다. 같은 행에서 표시할 수 있는 고정 설명과 확정값은 가능한 범위에서 유지합니다.

## 구현 계약

- 미리보기에서는 실제 게임 RNG를 호출하거나 샘플을 만들지 않습니다. RNG 상태 저장·복원에 의존하지 않습니다.
- 원본 `GetValue/GetResult/Check/Execute` 사슬을 우회 호출하지 않으며 `ConditionResultData._count`, 실행 예약, 대화 기록과 게임 상태를 변경하지 않습니다.
- 실행 때 나올 난수의 값이나 실제 판정 결과를 미리 확정한다고 보장하지 않습니다.
- 난수 판정 미정·미지원 자체는 일반 조회 오류의 5초 재시도나 오류 로그 대상으로 취급하지 않는 표시 경로를 연결했습니다. 실제 조회 오류의 재시도·복구 정책은 보존합니다.
- Lua·로드 문맥이 바뀌면 이전 범위·확률·판정 표현도 제거합니다. 문맥 차단 중 미리보기 조회를 시작하지 않습니다.

## 범위와 확률의 허용 경계

실제 게임 IL의 난수 분기는 `Random.Range(_randomMin, unchecked(_randomMax + 1))`을 호출하며 이 종류에는 `_negative`를 적용하지 않습니다. Unity 2020.3의 [정수 Random.Range 문서](https://docs.unity3d.com/2020.3/Documentation/ScriptReference/Random.Range.html)는 상한 제외와 대략 균등한 분포, 같은 인수·역순 인수의 별도 처리를 설명합니다. 이는 native 게임 실행 검증과 구분합니다.

첫 구현 범위는 일반적인 정수 구간을 안전하게 읽는 형태로 제한합니다. `_randomMax + 1`의 32비트 overflow, 역순 구간, 해석할 수 없는 변환·재귀·종속 구조는 정상적인 닫힌 구간으로 임의 보정하지 않습니다. 그 형태를 검증하여 지원하기 전에는 전용 미지원 표시를 사용합니다. `_negative`도 모든 종류에 일괄 적용하지 않고 현재 실제 API 분석의 종류별 의미를 유지합니다.

범위·판정 미정 표시를 우선하며, 확률은 별도 근거와 검사를 갖춘 제한된 형태에만 구현합니다. 초기 허용 범위는 **난수 평가 한 번과 확정된 정수 상수의 단일 비교**입니다. 예를 들어 이산 균등 모델에서 `R ∈ {1,…,100}`, `R ≥ 50`을 만족하는 값은 51개이므로 모델상 비율은 `51/100`입니다. 표시 문구는 `균등 정수 기준 이론 확률`로 구분하며 실제 native 난수의 정확한 분포나 다음 실행 결과를 측정한 수치로 쓰지 않습니다. 분포 근거·표시 의미를 충족하지 못하면 확률을 생략합니다.

실제 API는 `RandomPreview.Group/Compare/EventRate/ContainsRandomCondition`, 결과 모델은 `PreviewValue/PreviewComparison`, 설명 경로는 `PreviewFormatting`입니다. formatter 문구는 `난수 L~U · 실행 시 판정`, `난수 조건 · 미리보기 미지원`, `균등 정수 기준 이론 확률 N/D`입니다. 경우의 수 분수는 `51/100`처럼 약분하지 않은 정수 비율이며, 한 값 구간도 임의 bool 판정으로 바꾸지 않습니다.

초기 지원은 `Sum` 안의 직접 난수 참조 1개와 `L ≤ U < int.MaxValue` 범위입니다. 이론 확률은 그 난수 한쪽과 `Sum` 안의 직접 정수 상수 1개인 다른 쪽의 단일 비교만 대상으로 하며 여섯 연산자·좌우 순서를 다룹니다. 중첩·여러 개·중복 난수 참조, Max/Min/Multiply의 난수, 역순·상한 overflow 구간에는 확률을 출력하지 않습니다. 이 API·formatter와 설명 경계를 연결했고 전체 파이프라인에서 검사했습니다. 최종 파일의 패드→로그 왕복·해시를 아래 기록으로 식별하며 게시 커밋·익명 공개 다운로드도 검증했습니다.

확률을 제공할 때는 다음 조건을 모두 확인해야 합니다.

- 난수 평가 횟수와 비교 구조를 정확히 식별하고 지원 목록에 포함합니다. 같은 객체를 두 번 참조했다고 같은 추첨 결과가 된다고 가정하지 않습니다.
- 피연산자 순서와 여섯 비교 연산자, 경계 포함 여부를 보존합니다. 범위 크기·임계값의 ±1·경우의 수는 64비트 이상의 안전한 산술로 계산합니다.
- 복합 AND/OR, 여러 난수, 의존 관계, 중첩 집계, overflow가 가능한 산술, 미지원 변환에는 독립성·균등성·단순 확률 곱셈을 가정하지 않습니다.
- 조건 통과 확률을 이벤트 발동 확률이나 `PositionEventData.GetRate()`의 확정 반환값처럼 표시하지 않습니다. 현재 값에 의존하는 확장에는 계산 시점도 구분해야 합니다.
- 지원 여부나 근거가 불명확하면 범위·판정 미정 또는 전용 미지원 표시로 제한하고 추정 확률을 출력하지 않습니다.

## 코드 경계와 구현 상태

alpha.1의 `SafeEvaluationHooks` 설명용 wrapper는 `int`/`bool`을 반환합니다. 여기에 임의의 숫자나 `false`를 대입하면 기존 문자열·색상·이벤트 확률 계산이 잘못된 확정값을 만들 수 있습니다. 따라서 확정값, 난수 범위, 판정 미정, 미지원, 실제 오류를 구분하는 표시용 결과 모델과 설명 formatter 경로가 필요합니다. `PreviewValue`·`PreviewComparison`과 `RandomPreview`가 표현을 구분하고 `PreviewFormatting`이 조건·이벤트 설명에 연결합니다. 기존 primitive int/bool `SafeDisplayEvaluation` API는 난수 예외 정책을 유지하지만 새 설명 경로는 구조화된 결과를 읽습니다. 범위·판정 미정·미지원이 조회 실패 재시도 상태로 들어가지 않습니다.

구현 대상은 `SafeDisplayEvaluation`, `SafeEvaluationHooks`, 기존 `DataHelper`·이벤트 설명 호출, `LogBridge`·`RefreshEngine`의 상태 전달입니다. 로그뿐 아니라 게임 선택지 옆 요약과 내러티브 설명에서도 같은 의미를 유지해야 합니다. 원본 게임 진행 API를 이 표시 모델로 대체하지 않습니다.

보호된 로그 표시 경계에서 실제 조회 오류는 예외로 항목 엔진에 전달되어 기존 5초 재시도·이전 값 정책을 유지합니다. 보호 깊이 0의 게임 내러티브 설명 경계는 오류를 `읽기 실패` 텍스트로 바꾸고 같은 오류 로그를 억제하며 복구를 기록해 설명 오류가 원래 게임 진행 호출로 전파되지 않게 했습니다. 이벤트 설명은 진입한 보호 깊이를 캡처하고 `finally`에서 원래 값으로 복원합니다.

활성 조건이 false여서 확정 확률 0인 이벤트에서는 읽을 필요가 없는 null 확률 배열·항목·조건을 기존 의미대로 0/skip 처리합니다. 활성/판정 미정 경로의 실제 잘못된 자료는 정상 난수 미정으로 숨기지 않습니다.

## 후속 수용 기준

- [ ] 정상 범위와 비교식을 RNG 호출 없이 표시하고 판정을 실행 시점으로 남긴다.
- [ ] 미지원 난수 형태가 일반 조회 오류와 구분되며 다른 정상 행의 표시를 막지 않는다.
- [ ] 지원한 단일 비교의 경우의 수를 작은 정수 구간의 완전 열거와 대조한다. 여섯 연산자·좌우 반전·음수·한 값 구간·임계값 밖·최대/최소 정수 경계를 포함한다.
- [ ] 중복 참조·복합 조건·여러 난수·종속성·중첩 그룹·역순 구간·`max + 1` overflow를 지원 근거 없이 확률로 축약하지 않는다.
- [ ] 자동·수동·재시도·탭 전환·요약·내러티브 설명 전후의 RNG 호출 수, 조건 실행 카운터, 실행 예약과 대화 기록을 보존한다. 대역 검사는 실제 게임 확인과 구분한다.
- [ ] 실제 조회 실패의 이전 값·5초 재시도·복구 로그와 새 문맥 차단을 회귀 검사한다. 난수 상태를 성공/실패의 확정 색상이나 이전의 확정값으로 오인시키지 않는다.
- [ ] 현재 탭 스케줄·공유 파서 캐시·기존 설정·주사위·패드·번역 계약을 보존한다.

위 항목은 전체 수용 기준입니다. 관리 코드·경계 대역 자동 검사를 통과했어도 실제 게임 실행을 포함한 전체 완료로 체크하지 않습니다. 최종 패드→로그·직접 패드·파일 해시를 확인했으며 게시 커밋·익명 공개 다운로드 검증까지 마쳤습니다. 기존 prerelease의 자동 검사 통과 수·DLL 해시를 이 개선안의 검증 결과로 승계하지 않습니다. 최종 소스·DLL·반복 패치·패드 검사와 새 prerelease의 두 파일 ZIP·다운로드 검증 결과를 별도로 기록한 뒤 게시합니다. prerelease 재발행은 승인되었으며 Windows 실행은 승인되지 않았습니다. 실제 게임 API·native·리소스·Windows·성능의 기존 미검증 범위와 정식 완료 조건은 유지합니다.

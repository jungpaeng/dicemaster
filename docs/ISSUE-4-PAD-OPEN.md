# PRD #4 후속: 양쪽 스틱 클릭으로 로그 열기

2026-10-19 KST. 사용자가 양쪽 스틱 클릭으로 로그를 여는 기능을 후속 승인했다. 초기 PRD의 **패드로 열지 않는다**는 조건은 이 새 지시로 대체한다.
기존 [조건 분기 후보](ISSUE-4-CONDITION-BLOCKS.md), [읽기 화면 후보](ISSUE-4-READING-LAYOUT.md)와 공개 alpha.5는 각각의 당시 파일·검사·계약으로 보존한다.
2026-10-19 06:14:54 KST에 로컬 후보를 생성하고 전체 소스 빌드·12개 검사 프로그램을 통과했다. 파일별 SHA-256과 적용·복구·Windows 확인표는 아래에 기록한다.
실제 Windows 게임 확인은 대기 중이며 게임 설치·실행·커밋·공개 게시·이슈 완료는 수행하지 않는다.

## 열기와 설정

같은 XInput 패드에서 **한쪽 스틱 클릭을 누른 채 0.3초가 되기 전에 다른 쪽도 눌러 겹치면** 닫힌 로그를 연다. L3+R3를 동시에 눌러도 된다. 스틱을 기울이는 동작과 스틱 클릭을 구분한다.
판정 간격은 **300ms 미만**이며 정확히 300ms 이상이면 거부한다. 첫쪽을 뗀 뒤 반대쪽만 누르는 연속 클릭은 조합이 아니다.
기존 `[DiceMaster].LogMenuToggleKey`와 기본 Tab을 유지한다. 새 조합은 **열기 전용**이며 열린 창을 다시 닫거나 예약을 실행하지 않는다.
닫기는 기존 B 복귀·닫기 순서와 설정 키·화면의 닫기 버튼을 사용한다.

```ini
[DiceMaster]
EnableGamepadLogOpen = true
```

기본값은 `true`이며 `EnableGamepadAdjustment`·`EnableDiceController`와 독립적이다. 주사위 패드 조정을 꺼도 로그 열기 옵션은 사용할 수 있다.
기존 cfg를 보존한 채 새 DLL을 적용하면 새 키를 기본값으로 바인딩한다. 끄려면 같은 `[DiceMaster]` 섹션에서 `EnableGamepadLogOpen=false`로 설정한다.
중복 섹션이나 같은 이름의 키를 추가하지 않는다. 일반 설정 로드 계약에 따라 게임 종료 후 수정하고 재시작한다.

## 단독 스틱 클릭을 예약하는 제약

첫 번째 스틱 클릭을 이미 게임에 보낸 뒤 두 번째 클릭에서만 차단하면 게임의 기능과 로그 열기가 함께 작동할 수 있다.
이를 막기 위해 **옵션 켜짐·게임 창 초점·로그 닫힘** 동안 L3와 R3 두 클릭을 로그 열기용으로 예약한다.
조합을 완성하지 않고 **한쪽만 눌러도 게임으로 전달하지 않는다.** 초기화·상태 재설정의 해제·중립 확인을 마친 평상시에는 나머지 게임 입력을 기존 경로로 전달한다.

이 예약은 원래 게임의 L3/R3 기능을 제한한다. 게임의 직렬화된 입력 바인딩 자료가 없어 두 클릭이 미사용이라고 확정할 수 없다.
게임의 두 클릭 기능이 필요하면 옵션을 끈다. 비활성화 때 클릭 누름이 남아 있으면 해제 후 게임으로 반환해 늦은 누름이 게임 동작으로 새지 않게 한다.
옵션을 꺼도 열린 로그의 기존 전체 패드 입력 차단과 해제·중립 보호는 유지한다.
초기화·상태 재설정으로 native 해제·중립 대기를 거는 구간에는 L3/R3뿐 아니라 다른 버튼·양쪽 스틱·트리거의 남은 입력도 함께 소비한다.

## 새 입력·소유권·모드 계약

- 같은 패드의 두 클릭만 조합한다. 서로 다른 패드의 한쪽 클릭을 합치거나 다른 패드가 열린 로그의 소유자를 임의로 탈취하지 않는다.
- 전체 버튼 해제·양쪽 스틱 중립·트리거 해제를 확인한 뒤 새 조합을 기다린다. 시작 때 이미 누른 클릭, 닫기 직후 홀드, Alt-Tab·연결 복구의 남은 입력으로 자동으로 열지 않는다.
- 조합이 창을 연 뒤에도 클릭·스틱·트리거를 해제·중립으로 돌린 다음 새 탐색 입력을 받는다. 조합 홀드가 탭 이동·스크롤·예약·닫기로 이어지지 않는다.
- 게임의 실제 XInput 폴링·차단 경로가 확인된 경우에만 패드 열기를 사용한다. 실패·미지원·미확인 경로에서는 기본 Tab·마우스·키보드로 접근한다. Windows의 Xbox/XInput을 기준으로 하며 다른 OS나 Steam Input의 모든 변환을 보장하지 않는다.
- 게임의 입력 scheme·모드 이벤트·액션 맵은 변경하지 않는다. 패드로 열었다는 의도를 로그 내부에 전달해 Gamepad·KM·불명으로 읽히거나 scheme이 자동 변경되어도 해제·중립 뒤 첫 새 패드 탐색 입력을 전환용으로 다시 소비하지 않도록 한다.
- 패드 열기 의도는 단순 마우스 이동·호버로 취소하지 않는다. 실제 클릭·터치·휠·탐색 키 조작에는 기존 입력 전환·해제·중립 보호를 적용한다. 초점·입력 차단 준비·연결을 잃거나 창을 닫으면 이 진입 의도를 취소한다.

패드로 여는 경로와 Tab으로 여는 경로를 구분한다. **Tab 진입에서 게임 모드가 KM로 바뀌거나 첫 패드 입력이 소비되는 기존 증상은 이번 조합 추가만으로 해결했다고 처리하지 않는다.**
[이전 입력 진단](../artifacts/issue-4/mode-entry-diagnosis/diagnosis.md)을 보존하며 해당 경로는 별도로 확인한다. 패드 모드의 터치·커서 접근도 유지한다.

## 적용과 복구

1. 게임 종료 후 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. 생성·검증한 후보 ZIP을 임시 폴더에 풀고 **DLL만 교체**해 기존 cfg를 보존한다. ZIP의 cfg 전체를 덮어쓸 필요는 없다.
3. 시작 후 패드를 완전히 해제·중립으로 두고 양쪽 스틱 클릭으로 연다. 새 키의 기본값은 `true`다. Tab도 계속 사용할 수 있다.
4. 스틱 클릭 기능을 원래 게임에 사용하려면 종료 후 `EnableGamepadLogOpen=false`로 바꾸고 재시작한다.
5. 문제 시 종료 후 백업 DLL·필요한 cfg를 복원한다. 공개 alpha.5 또는 직전 로컬 후보로 복구하면 이번 패드 열기 기능은 제공하지 않는다.

```powershell
Get-FileHash .\DiceMaster-source-candidate.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

## 참고 자료와 적용 한계

- [Unity PlayerInput 공식 문서](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.6/api/UnityEngine.InputSystem.PlayerInput.html)는 입력 장치 활동에 따른 제어 체계 자동 전환을 설명한다. 이는 일반 API 동작의 참고이며 실제 게임에서 Tab 단독 입력이 모드를 바꿨다는 원인 증거는 아니다. 이번 후보는 게임의 제어 체계를 직접 변경하지 않는다.
- [Microsoft Xbox Accessibility Guideline 107](https://learn.microsoft.com/en-in/xbox/accessibility/xbox-accessibility-guidelines/107)은 빠른 반복·동시 입력이 접근 부담을 만들 수 있어 대안을 제공하도록 권고한다. 이번 조합은 사용자가 승인한 선택 기능이며 기존 단일 설정 키·Tab과 비활성화 옵션을 유지한다. 이 사실만으로 해당 접근성 지침 전체를 충족했다고 주장하지 않는다.

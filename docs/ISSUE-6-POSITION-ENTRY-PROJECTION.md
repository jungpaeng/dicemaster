2026-10-22 원래 작업 폴더의 main에서 구현한 alpha.27이다. 사용자 지시에 따라 커밋·고정 소스 재빌드·새 prerelease를 완료했다. 새 Windows·화면·물리 입력·FPS 확인과 PRD #6 전체 완료는 대기다.

## 관찰과 원인

사용자는 alpha.26에서 남제자방 안 사사형 선택지의 초회/후속 주제 툴팁은 보이지만 지도에서 남제자방에 포커스를 두면 보이지 않는다고 확인했다. 지도 상세의 표본은 Condition Talk_Brother4, 현재 플래그0과 비교0=1 미충족, 행동4/필요1이었다. 자료 상태 행은 없었다. 이는 실제 사용자가 전달한 현재 값이며 진입 뒤 실측값이나 해당 세이브의 전체 직렬화 자료를 받은 기록은 아니다.

제공 게임 DLL의 PositionController.OnPositionClick은 행동력·임무 우선순위를 거친 일반 활동에서 SetConditionFlag를 호출한 뒤 기본 Lua를 정한다. PositionConditionFlagItem.Execute는 _condition.Check 결과를 한 번 구하고, 그 그룹의 PositionFlagItem.Setup이 _trueState 또는 _falseState를 순서대로 대입한다. alpha.26은 쓰기 대상만 마스킹해 미확정으로 처리했으므로 지금0이지만 진입 후1이 되는 해금을 확인할 수 없었다. 공유 이야기 필터를 사용해도 실제 활성 버튼을 본 선택 화면과 진입 전 지도는 같은 결과가 아니었다.

제공 LOM_EventGuide0.9.4의 GuideMeet.cs:258-279는 클릭 시 플래그 순서를 반영한다. GuideMenus.cs:317-345는 실제 FlagData.State를 임시 변경·복원하고 Check도 호출한다. 처리 순서는 참고하되 이 방식은 복사하지 않는다. 조활시스템0.3.33(b6edf70a90f9cd7b84ca0ccbd6db0aa94ea4c8c2)의 MapOverview/GameAdapter는 임무·풀1회성 중심이며 이 일반 인물 대화의 진입 예측을 완료한 근거가 아니다. 외부 모드/게임 DLL을 설치 ZIP에 넣지 않는다.

## 구현과 안전 경계

PreviewConditions.Reader.ProjectPositionEntry가 그 조회에만 속한 Snapshot.entryValues에 가상 값을 보관한다. 실제 필드·프로퍼티를 쓰지 않고 Check/Execute/Setup·Lua·RNG를 호출하지 않는다. strict 현재 판독기와 기회/1회성 증명 판독기는 이 가상 값을 받지 않는다.

1. 전체 그룹·대상·true/false 정수 필드의 구조를 먼저 확인한다. 잘못된 뒷부분이 있으면 앞의 성공 값도 사용하지 않는다.
2. 기존 읽기 전용 조건 판독기로 그룹 조건을 한 번 해석한다. 같은 그룹의 모든 대입은 그 결과를 사용한다.
3. true/false를 확인하면 대응 정수를 가상 값에 넣는다. 미확정이면 그 대상을 미확정으로 남긴다. 양쪽 대입값이 같으면 난수를 뽑지 않고도 그 값은 확인한다.
4. 뒤 그룹은 앞 그룹의 가상 값을 읽는다. 아직 쓰지 않은 플래그는 현재 값을 읽고, 같은 대상의 후속 대입은 앞 값을 덮는다. 다음 갱신에서는 모두 새로 읽는다.

난수 AND 확정 false/OR 확정 true의 부분 판정은 보존한다. 누락 자료·미지원/난수 결과를 임의의 해금으로 바꾸지 않는다. 판독 중 구조 오류가 발생하면 동일 true/false 값이어도 전체 진입 예측을 사용하지 않는다. 동명의 특정 인물·플래그 예외 목록은 없다.

진입 플래그는 행동력 소비 전에 처리되므로 그 조건은 소비 전 행동력을 읽는다. 이후 Lua의 행동력 조건은 기존처럼 미확정이며 능력치 변화/리스너를 임의로 예측하지 않는다. 가상 플래그의 영향을 받는 파생 능력치의 원래 getter도 가상 값을 볼 수 없으므로 해당 의존은 보류한다. 후속 Lua의 명시 쓰기/불명 효과 마스크와 확인된 대화 초기화 기본값의 기존 순서는 유지한다. 초기화 자료가 없으면 그에 의존하는 후속 주제는 계속 보류한다.

선택한 지도 장소의 경로 툴팁에만 적용한다. 기존 장소 활성·행동 진행·행동력·주/대기 임무 우선순위, 해금·완료·반복 활동 필터와 초회/후속 경로 최대1개·이어 읽기를 유지한다. 일반 경로로 마커·Available·기회 수를 늘리지 않으며 미선택 마커는 경로 분석을 시작하지 않는다.

## 로그·설정·입력

명시적 지도 상세는 기존 ‘현재 조건 진단’과 새 ‘진입 후 가상 조건 진단’을 나란히 제공한다. 진입 조건과 가상 플래그 값도 제한된 표본에 표시한다. 연구 행의 현재 값 미충족과 진입 후 경로의 표시를 구분하며 실제 상태가 바뀌었다는 뜻이 아니다. 자동 화면은 기존 이름·종류·상태/경로 요약을 유지한다.

EnableMapGuide에 속하며 새 키·기본값·cfg 변경은 없다. 상위 시작 시 적용·개별 OFF 정리와 정상0.25초/실패5초·숨김/OFF 중단·정상 주기 Lua 재분석 없음 계약은 유지한다. 패드/키보드 포커스와 마우스 호버로 읽으며 A/Enter/클릭/터치·입력 소유권/해제/중립·창 가림은 유지한다.

## 예산과 성능

기존32그룹/총32대상 한도를 유지한다. 진입 조건 판독에 2,048단계 하위 상한을 추가하며 기존 조건 Snapshot 전체16,384단계 안에서 소비한다. 기존 경로 준비8,192작업·협력적 약5ms 양보·자원/풀 읽기 각1회, 경로32개/현재 조건·분류 예산과 누적 상한은 늘리지 않는다. 진입 조건 해석은 새로 필요한 현재값 작업이며 비용이0이라는 뜻은 아니다. 전용 한도 예외를 상위까지 전달해 한도 도달 후 남은 모든 피연산자에서 예외를 반복하지 않는다. Unity 프레임 전체의 강제5ms 상한은 아니다.

호스트 .NET8의 생산 지도 제공자와 합성 조건에서 같은 유효 경로를 안내하도록 하여 진입 그룹0/1/32개를 비교했다. 순서를 바꿔 각300회×3회, 사전100회 warm 뒤 측정했다. 각 경우의 현재 상태는 실제/가상 결과가 같도록 구성한 대역이며 alpha.26 전체와의 비교나 Windows/FPS 결과가 아니다.

## 자동 검사 범위와 설치

현재0/진입후1, false/unknown 전환, 동일 true/false 대상, 한 그룹1회 판독·그룹 간 순서·미확정 덮기, 부분 AND/OR, 행동 소비 전후, 파생 getter 보호, 손상된 뒷부분·32개/2,048단계 상한과 복구, 현재 판독/마커 분리, warm 캐시 및 임시 변경까지 검출하는 State 쓰기 횟수를 검사한다. SHA 원본 room_001·talk_brother4에 사용자가 보고한0=1 조건과 명시적인 합성 진입 대입을 연결해 초회→완료→해금 후속 주제를 검사한다. 실제 세이브의 전체 진입 설정을 복제한 검사는 아니다.

전달 후보 DLL의 실제 IL에서도0→1 예측·false/unknown/같은 대상값·진단·누락 자료를 실행한다. 게임 참조의 필드 타입과 진입 Setup의 실제 쓰기를 고정 메타데이터에 대조하며, 생산 판독기에는 게임 evaluator/setup·플래그 setter·반사 쓰기·게임 필드 쓰기가 없음을 검사한다. 실제 Lua/Windows/물리 입력을 실행한 검사는 아니다.

전체21개 검사 프로그램·283개 빌드 입력·113개 소스/리소스·16개 제공 참조, 실제 후보 DLL 연결·설치 ZIP의 두 경로/CRC/DLL/cfg 바이트 대조를 통과했다. 배포 검증기 자체 회귀20개도 통과했다. 초기에는 한도 초과 표본 크기, 새 진단 대역 메서드, IL 대역의 숫자 타입 기본값을 수정했고 각 실패 로그를 별도 보존한 뒤 전체 검사를 다시 통과했다. 최종 고정 커밋 재빌드·게시·공개 파일 검증은 [alpha.27 게시 기록](ISSUE-6-ALPHA27-RELEASE.md)을 따른다.

게임 종료 후 DLL/cfg를 백업하고 새 설치 ZIP의 plugins/DiceMaster/DiceMaster.dll만 교체해 기존 cfg를 보존한다. [새 Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md#alpha27--진입-플래그-가상-조회-확인-대기)에 남제자방 초회/해금 주제/완료·잠김·반복 대련과 입력/성능을 구분한다. #6 전체 완료나 이슈 종료로 처리하지 않는다.

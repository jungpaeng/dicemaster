## 증상과 원인

난수와 인물 부재를 AND로 묶은 조건 자체는 이미 거짓으로 계산했다. 그러나 선택 안내가 그 결과를 읽기 전에 선행 플래그 변경 또는 전체 경로의 미완성을 이유로 미확정 처리하여 표식 없이 `우소매 대화 · 진행 가능성 있음`을 남길 수 있었다. 표시 인물은 첫 경로에서, 진행 가능 여부는 여러 경로의 합집합에서 가져와 다른 인물의 참 조건을 우소매 이름에 붙이는 문제도 있었다. 진행 불가 상태도 자동 툴팁에 그대로 남았다.

기존 원본 연무장 Lua 검사는 확정된 양성으로 바뀌지 않는지만 확인하고 `진행 가능성 있음`을 허용했다. 수정 전 조사에서 원본 `center_001`·후속 두 스크립트의 SHA를 대조하고 인물 부재를 나타내는 합성 AND 조건을 연결하여 증상을 재현했다. 이는 실제 설치판의 직렬화된 조건 설정이나 사용자 세이브를 실행한 결과가 아니다.

## 수정

- 실제 메뉴와 원문 노드를 유일하게 연결하고, 선행 게임 상태 쓰기가 없는 닫힌 루트 메뉴임을 확인한 경우에만 기존 지도의 현재 필수 조건 투영을 재사용한다. 이 투영은 거짓을 확인하는 데만 쓰며 진행 가능으로 승격하지 않는다.
- 연결 경로의 공통 AND 필수 조건은 기존 64셀 색인 예산 안에서 정의로 준비한다. 정상 갱신에는 캐시된 식의 현재 값만 읽는다. 원본 연무장의 56개 연결처럼 경로가 많아도 공통 거짓을 확인할 수 있고, 32개 개별 경로 조회 상한은 늘리지 않는다. 우회 경로가 있으면 공통 거짓을 상속하지 않는다.
- 개별 경로의 거짓을 먼저 제외한 뒤 같은 조건 상태의 경로에서 인물·선택 경로·상태·추가 이야기 수를 함께 고른다. 같은 상태 안에서는 기존처럼 후속 선택을 보여주는 경로를 우선한다. 조회 상한 때문에 전체 수를 확인하지 못하면 정확한 추가 개수를 표시하지 않는다.
- 진행 불가로 확인된 대화는 자동 행·힌트·포커스 툴팁에서 제외한다. 명시적 상세 조회에는 불가 사유와 연결 경로를 보존하고 AutoText를 비워 패드 포커스·이동한 포인터로 빈 설명창이 되살아나지 않게 한다. 실제 게임 선택지는 비활성화하거나 변경하지 않는다.
- 조건에 영향을 주는 선행 쓰기·임의 콜백, 이미 저장한 조건 뒤의 변경, 원문 중복, 미조회 경로는 보수적으로 구분한다. 닫힌 루트 메뉴로 확인하지 못한 기존 메뉴의 예전 조건을 현재 값으로 재해석하지 않는다. 인물·플래그 예외 목록을 추가하지 않는다.

등록된 대기 임무·엄격한 1회성의 기회 표식 판정과 개별 설정은 유지한다. 일반 대화 경로만으로 표식을 부여하지 않는다. 게임 Condition/Switch/Check/Execute·RNG·플래그·능력치·아이템·세이브에 쓰거나 실제 선택을 실행하지 않는다. 0.25초/실패 5초·숨김/OFF 조회 중단·정상 주기 Lua 로드/재분석 없음·기존 입력 소유권/해제/중립 보호를 유지한다.

## 설치와 실제 Windows 확인

새 공개 후보를 설치할 때 게임을 종료하고 ZIP의 plugins/DiceMaster/DiceMaster.dll만 교체하여 기존 BepInEx/config/DiceMaster.cfg를 보존한다. 새 설정 키나 저장 데이터 변경은 없다. 현재 후보에는 앞선 배지 크기·게임 창 가림 변경도 포함된다.

[새 Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md)를 사용한다. 우소매 부재/존재, 남은 다른 인물 대화, 패드·포인터와 로그 상세, 배지 가림/크기, 실제 최초·반복 프레임을 확인해야 한다. 공개 배포와 실제 Windows 확인·#6 전체 완료는 별도 상태다.

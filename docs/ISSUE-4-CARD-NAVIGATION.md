# PRD #4 후속: 카드 탐색·기본 배치·미션 목록과 상태 안내

2026-10-19 KST. 사용자 Windows 피드백의 네 요청을 반영하는 로컬 후보 기록이다.
선택지·조건의 방향키 탐색, 기본 창 크기, 미션 목록 잘림, 상태 문구를 다룬다.
이전 후보와 공개본의 이력은 [구현 기록](ISSUE-4-IMPLEMENTATION.md)을 따른다.
로컬 구현 시점에는 게시하지 않았다. 사용자 후속 지시에 따라 고정 커밋 재빌드·11개 검사·공개 다운로드 검증을 거쳐 2026-10-19 04:46:13 KST에 [alpha.4 prerelease](ISSUE-4-ALPHA4-RELEASE.md)를 게시했다. 태그 소스는 `2bb45aa75b3c863f91d70bf1d78fd413c9a6a45d`이며 아래 로컬 후보와 DLL·설정·ZIP 바이트가 같다. 실제 Windows 확인 전에는 이슈를 완료하지 않는다.

## 카드 탐색

- 선택지·조건에서 오른쪽은 현재 카드를 펼치고 왼쪽은 현재 카드만 접는다.
- 카드를 펼친 상태에서도 위·아래로 다른 항목을 선택한다. 다른 카드의 펼침 상태는 유지한다.
- A는 선택한 카드의 펼침·접기를 전환한다. 선택이 없으면 첫 입력은 항목 선택에만 사용한다.
- 오른쪽 스틱으로 본문을 스크롤하며, 항목 이동 시 현재 카드의 제목을 따라 스크롤한다.
- 펼친 카드 영역에서도 자동 갱신으로 앞 카드 길이·순서가 바뀌면 선택 제목을 따라간다. 사용자의 수동 스크롤은 다음 항목 이동 전까지 유지한다.
- B는 펼친 카드 영역에서 목록으로 먼저 돌아가고 목록에서 창을 닫는다. 복귀 시 다른 펼침을 지우지 않는다.
- 도구에서는 B로 이전 영역에 돌아간다. 검색 자판에서는 입력을 취소하고 도구로 돌아간다.
- 키보드 방향키와 패드가 같은 탐색 경로를 사용하며 홀드·문맥 변경의 기존 입력 무효화 규칙을 유지한다.
- 이벤트·미션 상세의 위·아래는 본문/예약 버튼 이동이다. 기존 예약의 의미와 별도 새 입력 요구는 유지한다.

## 새 기본 배치와 기존 설정

1080p 기준 기본 창은 1280×960픽셀, 본문은 20픽셀이다. 새 기본값은 화면 높이에 비례한다.
배율은 `화면 높이 / 1080`을 0.85~4로 제한하며 창은 화면 안으로 보정한다.

| 화면 | 새 기본 창 크기 | 기본 본문 크기 |
| --- | --- | --- |
| 1920×1080 | 1280×960 | 20 |
| 2560×1440 | 약 1707×1280 | 27 |
| 3840×2160 | 2560×1920 | 40 |

이전 기본 배치와 위치·너비·높이·글자 크기가 모두 일치하는 설정만 새 기본값으로 이행한다.
대상은 750×750/14, 1200×860/20 등의 기본값과 현재 해상도로 배율을 적용했던 이전 기본 배치다.
비교 허용 오차는 각 좌표·크기에서 0.01픽셀 미만으로, 설정 직렬화의 소수점 왕복 오차만 허용한다.
사용자가 이동·조절한 배치나 글자 크기, 540×440 같은 작은 창 설정은 자동으로 확대하지 않는다.
기존 사용자는 도구의 **창 위치·크기·글자 기본값 복구**로 현재 화면의 새 기본값을 적용할 수 있다.
창·글자 설정은 기존 BepInEx 설정에 저장한다. 검색·선택·펼침·스크롤은 실행 중 상태다.

## 미션 목록 잘림과 상태의 뜻

목록은 제목과 상태를 하나의 버튼에 표시한다. [Unity 2020.3의 줄바꿈 크기 계산](https://github.com/Unity-Technologies/UnityCsReference/blob/2020.3/Modules/IMGUI/LayoutEntry.cs#L255)에서 기존 `MinHeight`는
최대 높이도 강제할 수 있어, 좁은 열의 긴 제목·상태가 필요한 높이를 얻지 못하는 경로가 있었다.
이제 스크롤바를 제외한 실제 열 너비에서 `GUIStyle.CalcHeight`로 행 높이를 계산하고 너비·높이를 명시한다.
일반 버튼의 불필요한 `MinHeight`와 스킨에서 상속한 고정 너비·높이도 제거한다.
관리 코드 경계의 분석·대역 검사와 실제 Windows Unity/native 표시 결과는 구분한다. 후자는 확인 대기다.

- 이벤트·미션은 이야기 읽음 상태를 연결하지 않으므로 `Unknown`의 **읽음 불명** 배지만 생략한다.
- 명시적인 `Read`/`Unread`는 계속 **읽음/미독**으로 표시한다. 선택지·조건의 `Unknown`은 **읽음 정보 없음**이다.
- 이는 미션 완료 여부를 새로 판정하는 변경이 아니다. 기존 게시 모델은 `NoStory`와 읽음 정보 미제공을 모두
  `Unknown`으로 전달하며, 이번에는 백엔드에 두 경우를 구분하는 새 상태를 추가하지 않는다.
- 조회의 `Waiting`은 화면에서 **설명 조회 대기**로 표시한다. 분석기의 **분석 대기**와 다른 상태다.
- 미션 상세에는 현재 단계가 없거나 필요한 자료를 얻지 못했을 가능성과 재조회·새로고침 방법을 안내한다.
- 대기 표시는 미션 미완료·조건 미충족을 뜻하지 않는다. 개별 행의 실제 원인은 해당 진단 없이 단정할 수 없다.

기존 `LogBridge.ValidateMissionStage`는 빈 `CurrentKey`도 대기로 분류한다. 게임의 `GetByKey`는 빈 키를
정상적인 단계 없음으로 처리하므로, 대기를 항상 로딩 중이라고 해석하면 안 된다. 이번에는 조회 계약을 바꾸지 않는다.
정상 문맥에서 대기·실패 행은 열린 현재 탭에서 5초 간격으로 재조회하고 수동 새로고침은 대기 시간을 건너뛴다.
정상 행은 0.25초 주기이며 닫힌 창·비활성 탭은 조회하지 않는다. 새 문맥 준비 전의 전체 대기는 별도 경로다.

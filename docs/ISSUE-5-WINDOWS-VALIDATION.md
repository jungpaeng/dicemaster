# PRD #5 — 실제 Windows 확인표

상태: **v1.0.6-alpha.10 게시 · 새 DLL의 모든 항목 미실행 · 사용자 확인 대기**. 설치 파일·해시·게시 상태는 [alpha.10 배포 기록](ISSUE-5-ALPHA10-RELEASE.md)을 따른다. alpha.9 이후 실제 능력치 참조에 따른 공통 조건 이름 표시를 보완하며 팝업·입력 조작·설정은 유지한다. 이전 자동 검사·사용자 보고를 새 DLL의 실행 결과로 승계하지 않는다. [구현·지원 범위](ISSUE-5-IMPLEMENTATION.md)를 먼저 대조한다.

alpha.10 시험 파일은 [DiceMaster-v1.0.6-alpha.10.zip](https://github.com/jungpaeng/dicemaster/releases/download/v1.0.6-alpha.10/DiceMaster-v1.0.6-alpha.10.zip)이며 소스·태그는 `df627348e3aa099a087389642d04f7ac4b0a845c`, DLL은 621,056바이트·SHA-256 `c2a413032c23e532083143c1bccc4292f62d837caf83e35ac9a27d7de6d8a1c1`이다. 전체 후보·고정 커밋 재빌드에서 각각 14개 검사 프로그램을 통과했고 2026-10-20 04:15:46 KST 게시 후 익명 공개 ZIP의 CRC·두 파일·바이트·해시를 대조했다. 아래 alpha.9 공개 파일·검사 기록은 당시 이력이다.

## 판정·설정·복구

각 항목에 실제 관찰 결과와 재현 순서·관련 token/ID·BepInEx `EventSelection` 로그를 남긴다. 미실행을 통과로 바꾸지 않는다.

- [ ] **미실행** — 최초 설정 누락은 `EnableEventSelectionPopup=true`; ON 저장·재시작 뒤 유지. OFF는 새 팝업과 선택 대기를 생략한다.
- [ ] **미실행** — `EnableOptionInfo=false`로 시작하면 팝업 저장값은 보존하고 표시·대기는 비활성. 상위 옵션을 켜는 재시작 계약을 확인한다.
- [ ] **미실행** — 미확정 대기 중 큰 로그 도구에서 OFF로 바꾸면 숨은 대기가 남지 않고 원래 판정이 한 번 진행된다. 이후 ON은 다음 판정부터 적용한다.
- [ ] **미실행** — 유효한 설정 읽기/평가 실패는 최초 기본값과 구분해 진단하고 대기 없이 원래 게임으로 진행한다. 안전하게 재현할 수 없는 실패는 미실행과 사유를 기록한다.
- [ ] **미실행** — 실제 게임 선택지 → 지원하는 Lua 직접 리터럴 `Position` 코루틴 → 판정 직전 팝업을 확인한다. 미리보기·관련 이벤트 조회·다른 분기만으로 대기하지 않는다.
- [ ] **미실행** — 별칭·변수/동적 인수·메인 Lua·직접 C# 동기 경로 등 지원 밖 호출은 원래 판정으로 진행한다. 확인한 경로만 기록한다.
- [ ] **미실행** — 후보 0개·군/경로 조회 실패는 원래 진행. 전체 정상 후보 1개는 팝업 생략. 하나라도 미충족·가중치 0·미확인이면 팝업 표시. 복수 후보 중 가능 1개여도 나머지를 유지한다.

- [ ] **미실행** — 조건 미충족·최종 가중치 0·난수/미지원으로 미확인인 읽기 가능한 후보를 각각 명시 강제 지정한다. 선행 능력치·호감도·스토리 플래그 수정 없이 한 번 진행하며 정상 효과·대화·내부 분기는 유지한다.

- [ ] **미실행** — 무작위는 지정 없이 원래 조건·가중치·난수로 한 번 진행한다. 연속/중첩 판정·동일 프레임 중복 확정·오래된 콜백에서 결과가 중복 적용되지 않는다.

## 화면·입력 소유권

- [ ] **미실행** — 큰 로그를 자동으로 열지 않고 좌측 하단 작은 팝업을 표시한다. 초기 후보는 미선택이고 무작위 목록 항목이 없다. 선택 전 A/Enter는 진행하지 않으며 ↑↓·왼쪽 스틱의 첫 탐색은 첫 후보부터 시작한다. 가능 후보 우선·그룹 내 원래 순서·선택 후 대상 ID별 초점을 유지한다.
- [ ] **미실행** — 굵은 이벤트 제목·결과 요약과 선택 상세의 조건 설명, B/Escape 무작위 안내를 읽을 수 있다. 긴 한국어·긴 목록·큰 로그 글자·해상도/배율 변경에서 현재 행·조건·하단 안내가 잘리지 않고 스크롤로 접근된다.
- [ ] **미실행** — 패드 ↑↓·왼쪽 스틱 이동/추적과 A 확인을 시험한다. 정상 후보는 `[A / Enter] 이 이벤트로 진행`, 미충족·가중치 0·판정 미확인 후보는 `[A / Enter] 조건 무시하고 이번만 진행`을 표시하고 한 번 진행한다. X는 확정하지 않으며 B는 무작위다. 키보드 Enter와 Shift+Enter가 같은 확인인지, Esc가 원래 판정으로 한 번 진행하는지도 대조한다.
- [ ] **미실행** — 하단에 선택 이벤트·무작위 실행 버튼이 없고 선택 상태에 맞춘 A/Enter 진행·B/Esc 무작위 텍스트가 보이는지 확인한다. 안내를 클릭·터치해도 실행하지 않는다. 후보를 선택하지 않았을 때도 B/Escape는 원래 판정으로 한 번 진행하고 A/Enter는 진행하지 않는다. 터치 전용 무작위 UI는 제공하지 않는다.
- [ ] **미실행** — 일반 진행을 누른 뒤 확정 직전에 자격이 바뀌면 조건 무시로 바뀌지 않고 안내 후 재선택을 요구한다. 대상·결과 읽기 실패는 A/Enter와 행 재클릭·터치 모두 차단한다.
- [ ] **미실행** — 트랙패드 클릭으로 큰 로그의 네 탭·목록 항목·도구 버튼을 선택하고 이벤트 검색 칸의 클릭·초점·물리 키보드 입력을 확인한다. 팝업은 다른 행의 첫 클릭으로 선택만 하고, 선택된 행의 새 클릭으로 일반 진행·명시 조건 무시를 한 번 확정한다. 실행을 요청하는 클릭 영역은 목록뿐이며 하단 안내를 눌러도 실행하지 않는다. Enter 입력을 요구하지 않는다. 누름과 해제가 서로 다른 프레임이어도 한 번만 동작하고 다른 행/창 밖에서 떼면 확정하지 않는다.
- [ ] **미실행** — 마우스로 인식되는 모니터 터치로 전체 로그의 네 탭 각각에서 목록 선택·다른 탭 이동·도구 버튼이 실제 동작하고 이벤트 검색 칸에 초점을 둘 수 있는지 확인한다. 특히 이벤트 탭에서 나간 뒤 선택지·조건·미션 탭에서도 연속 조작되는지 확인한다. 팝업은 첫 터치로 선택하고 바로 다음 두 번째 터치로 일반 진행·명시 조건 무시를 한 번 확정하며 세 번째 터치를 요구하지 않는다. 패드 모드에서 첫 터치로 넘어올 때와 누른 동안 입력 모드가 바뀔 때 유효한 선택을 유지한다. 실제 장치와 인식 방식을 기록한다.
- [ ] **미실행** — 별도 터치 이벤트가 지원되는 장치가 있으면 전체 로그 탭·목록·도구와 팝업 행 재터치의 같은 조작·취소·중복 실행 방지를 별도로 확인한다. 마우스 에뮬레이션 터치 결과를 이 경로의 성공으로 기록하지 않으며 해당 장치가 없으면 미실행으로 둔다.
- [ ] **미실행** — 선택된 팝업 행을 누른 뒤 같은 ID의 대상 객체·결과·판정 문맥이나 일반/조건 무시 방식이 바뀌면 해제해도 실행하지 않는다. 특히 일반 진행이 불가능해져도 조건 무시로 자동 전환하지 않고 새 상태를 보고 새 클릭·터치를 요구한다.
- [ ] **미실행** — 행 재터치로 접수한 뒤 Lua 재개 전에 후보 설명이 갱신돼도 접수한 후보·결과를 다른 결과로 바꾸지 않는다. 같은 ID의 실제 대상 객체·결과가 바뀌면 이전 요청을 거부하고 새 표시를 보고 다시 선택하게 하며 일반 진행을 조건 무시로 자동 승격하지 않는다.
- [ ] **미실행** — 기존 `LogMenuToggleKey`로 팝업을 감추고 큰 로그를 읽어도 실제 행동은 계속 대기한다. 로그를 닫으면 같은 유효 문맥·초점으로 돌아오며 B 닫기를 팝업 무작위로 재사용하지 않는다.
- [ ] **미실행** — 큰 로그의 탭·검색·필터·선택·스크롤과 팝업 초점이 따로 유지된다. 이벤트의 이름/표시 이름·원본 ID·설명 검색, 가능만 필터·전체 설명과 도구의 패드 필터/검색 지우기를 확인한다. 다른 탭에는 검색이 없다.
- [ ] **미실행** — 큰 로그에서 도구를 열면 도구만 선택 표시하고 이전 목록 탭이 동시에 강조되지 않는다. 터치 뒤 물리 패드를 다시 쓸 때 도구 화면·현재 선택·스크롤은 유지하고 이전 확인·클릭 권한과 검색 입력 커서는 취소한다. 버튼 해제·스틱/트리거 중립 뒤 새 조작을 받으며 실제 초점·문맥 변경·닫힘 등 안전 경계의 초기화도 따로 확인한다.
- [ ] **미실행** — 자동 입력 모드 변경이나 실제 포인터 전환은 같은 유효 누름을 보존한다. 팝업의 첫 터치 선택과 두 번째 터치 진행이 유지되며 물리 패드 재획득은 이전 클릭 권한을 취소하는지 확인한다. 선택 행 재터치로 요청을 접수한 뒤 자동 모드 관측이 늦게 와도 실제 결과가 한 번 실행되는지 확인하고 실제 게임/입력 모드·재개 로그를 기록한다.
- [ ] **미실행** — 팝업 목록의 정상 발동 가능/발동 불가 상태 행과 반복 클릭·터치 안내가 없고 굵은 제목·결과 요약의 두 줄로 유지된다. 선택 전후 행 높이·좌표와 첫 선택 후 같은 위치 재터치 진행, A/Enter·B/Escape를 확인한다. 예상 결과와 발동 조건을 구분하고 서로 다른 실제 결과 ID의 설명이 섞이지 않는다.
- [ ] **미실행** — 결과 요약·상세에 기존 로그의 효과색이 유지되고 색 태그가 말줄임 길이나 줄 수를 늘리지 않는다. 긴 색 설명·이모지·큰 글자에서 잘린 색이 다음 행으로 번지지 않고, 제목·발동 조건의 태그처럼 보이는 문자열이 실제 서식으로 해석되지 않는다. 제목은 렌더러가 굵게 표시하고 굵은 폭으로 말줄임해 긴 `Section_...:이벤트_이름`이 영역을 넘지 않는다. 색이 없던 아이템·플래그 등은 기존 본문색을 유지한다.
- [ ] **미실행** — 조건 미충족·가중치 0·판정 미확인·읽기 불가 후보의 제목은 회색이며 선택 화살표와 결과 효과색은 유지된다. 회색 후보 첫 터치 선택과 읽기 가능한 후보의 두 번째 터치/A 명시 조건 무시를 확인하고 실제 대상·결과 읽기 불가는 실행을 차단한다.
- [ ] **미실행** — 선택 결과·발동 조건을 목록과 별도로 휠·오른쪽 스틱으로 끝까지 읽고 ↑↓는 후보 이동을 유지한다. 준비 중·미지원·읽기 실패·확인된 효과 없음을 구분하며 설명 분석 실패만으로 일반 진행·조건 무시 가능 여부가 바뀌지 않는다. 큰 글자·긴 설명·작은 화면과 결과/대상 변경 후 상세 스크롤 초기화도 확인한다.
- [ ] **미실행** — 게임 선택지 A를 누른 채 팝업 진입, 팝업 A/B를 누른 채 게임·대화·주사위 복귀에서 입력이 재사용되지 않는다. 전체 버튼 해제·스틱/트리거 중립 뒤 새 입력만 받는다.
- [ ] **미실행** — Alt-Tab·문맥/대상 교체·패드 분리/재연결·여러 슬롯·소유자 재선택에서 미확정 포인터 누름을 취소한다. 단순 포인터 전환·입력 모드 변화는 같은 유효 누름을 보존하며 자동 입력 모드 관측만으로 이미 접수된 유효 확정을 폐기하지 않는다. 실제 안전 경계는 접수된 확정도 취소하고 한 화면만 조작한다. 길게 누르기·동시 입력·새 확인과 해제/중립도 확인한다.
- [ ] **미실행** — 실제 native XInput 차단 경로를 확인한다. 미확인/실패 시 위험한 패드 확정을 막고 키보드·마우스로 복구한다. Steam Input은 시험한 구성만 기록한다.
- [ ] **미실행** — 기존 같은 패드 L3/R3 클릭 겹침 열기·설정 키·Tab과 로그 LB/RB·Y 도구·X 새로고침·B 닫기를 회귀 확인한다. 이번 기능용 새 패드 조합이 없다.

## 순수 조회·기존 기능·배포

- [ ] **미실행** — 표시·검색·정렬·필터 전후 게임 RNG·조건 카운터·예약·세이브가 바뀌지 않는다. 보이는 현재 탭/행동의 0.25초 갱신·실패 5초 재시도·항목 실패 격리·정상 주기 Lua 재분석 없음과 모두 숨김 조회 0을 구분한다.
- [ ] **미실행** — 이벤트 예약 UI·`TargetEvent` 99999 보정이 없고 로그에서 사전 요청을 만들지 않는다. 미션 조건 통과 예약·해제·소속 검증·수명과 기존 한국어/선택지 분석·읽음·대화 기록을 유지한다.
- [ ] **미실행** — 주사위 임의 정수·음수·0 자동, 기존 Xbox/XInput 조정과 로그/팝업/주사위 왕복을 확인한다.
- [ ] **미실행** — 시험 DLL·cfg·두 파일 ZIP·매니페스트 해시를 대조한다. 게임 소스·게임 DLL·새 UI 이력/세이브 파일을 배포하지 않는다.
- [ ] **미실행** — 게임 종료 후 이전 DLL만 복원해 이전 모드 동작으로 돌아간다. 필요한 경우에만 백업 cfg를 복원한다. DLL 복원이 이미 진행·저장한 게임 상태까지 되돌리는 것은 아니다.

자동 검사·관리 코드 시간/할당량 측정과 실제 Unity/Windows 프레임 관찰을 별도 기록한다. 확인하지 않은 다른 운영체제·모든 패드·모든 Steam Input 구성을 지원 완료로 표시하지 않는다. **이번 후보의 사용자 확인 전에는 PRD #5를 완료로 닫지 않는다.**

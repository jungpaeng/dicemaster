# PRD #5 — 실제 Windows 확인표

**v1.0.6-alpha.12의 새 DLL은 실제 Windows·장치 확인 대기**다. 조건·이벤트 일회 예약과 조건 팝업 신규 기본값 OFF를 확인한다. 아래 첫 확인표는 이번 변경을 위한 것으로 아직 실제 Windows에서 실행하지 않았다. 전체 현재 소스 후보 빌드·14개 검사 프로그램과 설치 ZIP·188개 입력 해시 대조를 통과했다. 이번 DLL은 634,368바이트·SHA-256 `7db4b6dbffd3ed4f4441002fa7c868d5d66db234942395178de5cf4ad6fc802f`이며 실제 게임 확인과 구분한다. [alpha.12 배포 기록](ISSUE-5-ALPHA12-RELEASE.md) · [예약 설계·검증 범위](ISSUE-5-CHECKPOINT-RESERVATIONS.md). 공개 alpha.11의 파일·기본값·검증 기록은 다음 절에 당시 상태로 보존한다.

## alpha.12 예약·기본값 변경 확인표

시험 전에 alpha.12 DLL의 SHA-256·소스 식별값·게임/BepInEx/Windows 버전·장치/Steam Input·해상도를 기록한다. 공개 alpha.11의 해시나 기존 Windows 확인을 이번 DLL에 대신 사용하지 않는다.

- [ ] **미실행** — 새 cfg 및 Switch 키가 없는 기존 cfg는 `EnableSwitchSelectionPopup=false`로 시작한다. 이미 `true`/`false`가 저장된 cfg는 그 값을 유지하며 조건 탭 상단에서 바꾸고 재시작하면 유지된다. 이벤트 기본값은 `true`다.
- [ ] **미실행** — 조건 탭에서 분기 1·분기 2·그 외가 각각 독립된 행으로 표시된다. 선택 행의 조건 설명·횟수 비교와 앞에서 처음 만족한 분기를 사용하는 공통 안내를 읽고 다른 분기의 설명이 섞이지 않는지 확인한다.
- [ ] **미실행** — 조건·이벤트에서 첫 터치는 선택만, 바로 다음 같은 행 터치는 예약/해제 한 번으로 동작한다. 패드 A·키보드 Enter도 확인하고, 미선택 확인은 첫 행 선택만 수행하며 `(예약 중)` 표시가 현재 예약과 일치하는지 기록한다.
- [ ] **미실행** — 조건과 이벤트에 각각 하나씩 동시에 예약하고 미션 예약도 유지한다. 같은 탭의 다른 행 예약은 그 탭의 이전 예약만 교체한다. 눌렀다 다른 행/창 밖에서 떼기·문맥/대상/예약 교체·패드 재획득에서는 오래된 누름이 적용되지 않는지 확인한다.
- [ ] **미실행** — 큰 로그에서 예약해도 현재 이벤트가 즉시 실행되거나 멈춘 행동이 재개되지 않는다. 로그를 닫고 진행해 다음 일치 체크포인트에서만 한 번 적용되며 다른 판정은 예약을 소비하지 않는지 확인한다.
- [ ] **미실행** — 조건/이벤트 각각 팝업 OFF와 ON에서 유효 예약이 우선한다. 같은 팝업이 기다릴 때 큰 로그에서 예약한 뒤 닫고 흐름이 재개되면 재선택 없이 한 번 적용하며 다른 대기 중 판정의 초점은 빼앗지 않는지 확인한다.
- [ ] **미실행** — 수동 예약은 원래 조건·가중치·난수 판정을 건너뛰지만 능력치·호감도·조건 데이터를 사전에 바꾸지 않는다. Switch 자체 횟수는 한 번 증가하고 선택 결과 이후 게임의 대사·효과는 한 번 실행되는지 기록한다.
- [ ] **미실행** — 일반 이야기/Lua 교체 뒤에도 같은 유효 예약은 유지되고, 로드·새 게임 등 실제 실행 전환에서는 해제된다. 게임을 종료하고 재시작해 예약이 cfg·세이브에서 복원되지 않는지 확인한다.
- [ ] **미실행** — 대상·소속·결과·접두사·Switch 모드/횟수가 바뀌면 오래된 예약을 다른 결과에 적용하지 않고 폐기한다. 읽기 실패·이전 값·구조 불일치 행은 예약을 변경할 수 없다. 안전하게 재현할 수 없는 경우 미실행과 사유를 남긴다.
- [ ] **미실행** — 상위 `EnableOptionInfo=false`에서는 팝업·예약이 적용되지 않는다. 종류별 팝업 설정을 바꾸어도 다른 설정·유효 예약이 지워지지 않으며 예약이 없으면 기존 팝업 ON/OFF와 B/Esc 원래 판정을 유지한다.
- [ ] **미실행** — 실제 확인 가능한 지원 밖 Lua·메인 Lua·직접 C# 호출은 유효 예약이 있으면 다음 일치 호출에서 소비하고 없으면 원래 판정으로 진행한다. 팝업 자체의 지원 범위가 넓어진 것으로 기록하지 않는다.
- [ ] **미실행** — 기존 미션 예약·해제·주사위 조정·큰 로그의 탭/목록/도구 터치·팝업의 첫 선택/다음 터치 진행을 회귀 확인한다. 해제는 이미 진행한 결과를 되돌리지 않음을 확인한다.

## alpha.11 조건 분기·탭별 설정 확인표

- [ ] **미실행** — 기존 cfg를 유지해 DLL만 교체하고 새 `EnableSwitchSelectionPopup=true`가 추가되는지 확인한다. 조건·이벤트 탭 상단의 ON/OFF를 서로 다르게 저장하고 재시작 뒤 각각 유지되는지 확인한다.
- [ ] **미실행** — 조건·이벤트 목록이 비어 있어도 해당 설정 버튼이 보이고 클릭·터치·A/Enter로 동작한다. 목록 맨 위 ↑로 설정 이동·↓로 목록 복귀, 터치로 설정 선택 뒤 패드 해제·중립 후 A와 목록 탐색을 확인한다. 이전 목록 탭과 도구의 동시 강조가 없는지도 확인한다.
- [ ] **미실행** — 강릉 포위전의 **할 일 없이 그늘에서 쉰다**를 선택하고 대화를 진행해 `Ch_3_6_4_002`의 실제 Switch 직전 팝업이 뜨는지 확인한다. 바둑 장면·만남 주사위 경로의 결과 요약·상세가 해당 행과 일치하고 다른 분기의 설명이 섞이지 않는지 기록한다.
- [ ] **미실행** — 첫 터치로 선택하고 바로 다음 같은 행 터치 또는 패드 A로 한 번 진행한다. 표시된 일반 진행과 명시 조건 무시를 구분하며 세 번째 터치·중복 대사·중복 효과가 없는지 확인한다.
- [ ] **미실행** — 직접 지정은 해당 Switch 실행 횟수만 한 번 증가시키고 원래 조건·난수·중첩 조건 평가는 건너뛰며 선택한 Lua 분기의 후속 대사·효과를 실행한다. 저장·후속 재진입에서 실행 횟수 의미가 유지되는지 관찰한다. 조회만으로 실행 횟수·RNG·게임 상태가 바뀌지 않는지도 확인한다.
- [ ] **미실행** — B/Esc는 원래 Switch 조건·난수 검사를 한 번 실행한다. 해당 종류의 설정 OFF도 숨은 대기 없이 원래 진행하며 다른 종류의 팝업은 유지한다. 미확정 대기·접수 후 OFF와 재시작을 구분해 기록한다.
- [ ] **미실행** — 실행 횟수·대상·조건·Lua 문맥이 바뀌면 이전 요청을 적용하지 않고 새 상태를 다시 선택하게 한다. 로드·씬 전환·입력 소유자 변경과 중복 확인에서도 이전 분기를 새 흐름에 적용하지 않는다.
- [ ] **미실행** — 별칭·동적 인수·복합 비교·호출 뒤 중간 문장·메인 Lua·직접 C# 등 지원 밖 경로는 팝업 대기 없이 원래 게임으로 진행한다. 실제 확인한 경로만 기록한다.
- [ ] **미실행** — 이벤트 검색창·가능한 항목만 보기·관련 도구가 없고 전체 이벤트 목록·가능한 항목 우선 정렬을 유지한다. 기존 이벤트 팝업·미션 예약·주사위 조정과 전체 로그 탭·목록·도구 터치를 회귀 확인한다.
- [ ] **미실행** — 회상·조건 표시가 기존 객체 이름 중심의 alpha.9 방식이며 내부 ID가 남을 수 있음을 확인한다. alpha.10 원복이 해당 ID 문제를 해결한 것으로 기록하지 않는다.

## alpha.10 게시 당시 조건 이름 표시 확인표

아래는 원복한 기능의 당시 확인표다. 사용자 보고로 해당 ID 표시 문제의 지속은 확인했지만 실제 참조 값·설치 파일 해시와 각 항목 전체의 대조는 완료하지 않았다. 현재 소스의 확인 완료 항목으로 사용하지 않는다.

- [ ] **미실행** — 게임 기본 회상 화면에 DiceMaster가 남긴 조건 로그에서 실제 참조 능력치와 표시명을 대조한다. `Ch_3_6_4_3_001`이 학문인지 다른 값인지 먼저 확인하고 이름을 추정하지 않는다.
- [ ] **미실행** — 학문 외 능력치와 합산·곱셈·최댓값·최솟값의 복합식 표시가 실제 조건과 일치하는지 확인한다.
- [ ] **미실행** — 참조·번역을 읽지 못한 경우 기존 객체 이름이 표시되는 한계를 확인한다. 이 경로는 능력치명 확인 완료로 취급하지 않는다.

## alpha.11 당시 판정·설정·복구

각 항목에 실제 관찰 결과와 재현 순서·관련 token/ID·BepInEx `EventSelection` 로그를 남긴다. 미실행을 통과로 바꾸지 않는다. 아래 기존 이벤트 체크리스트의 가능한 후보 우선 정렬·단일 정상 후보 팝업 생략·“이 이벤트”·“무작위” 문구는 `Position` 이벤트 팝업 기준이다. `Switch` 팝업은 Lua의 분기 순서를 유지하며 B/Esc로 원래 조건·난수 판정을 실행한다. Switch의 후보·설정·조작은 위 alpha.11 별도 확인표를 기준으로 확인한다.

- [ ] **미실행** — 최초 설정 누락은 `EnableEventSelectionPopup=true`·`EnableSwitchSelectionPopup=true`; 각 ON/OFF 저장·재시작 뒤 유지. OFF는 새 팝업과 선택 대기를 생략한다.
- [ ] **미실행** — `EnableOptionInfo=false`로 시작하면 팝업 저장값은 보존하고 표시·대기는 비활성. 상위 옵션을 켜는 재시작 계약을 확인한다.
- [ ] **미실행** — 미확정 대기 중 큰 로그 도구에서 OFF로 바꾸면 숨은 대기가 남지 않고 원래 판정이 한 번 진행된다. 이후 ON은 다음 판정부터 적용한다.
- [ ] **미실행** — 유효한 설정 읽기/평가 실패는 최초 기본값과 구분해 진단하고 대기 없이 원래 게임으로 진행한다. 안전하게 재현할 수 없는 실패는 미실행과 사유를 기록한다.

## alpha.11 당시 화면·입력 소유권

- [ ] **미실행** — 큰 로그를 자동으로 열지 않고 좌측 하단 작은 팝업을 표시한다. 초기 후보는 미선택이고 무작위 목록 항목이 없다. 선택 전 A/Enter는 진행하지 않으며 ↑↓·왼쪽 스틱의 첫 탐색은 첫 후보부터 시작한다. 가능 후보 우선·그룹 내 원래 순서·선택 후 대상 ID별 초점을 유지한다.

- [ ] **미실행** — 큰 로그의 탭·팝업 설정·선택·스크롤과 팝업 초점이 따로 유지된다. 이벤트 검색·가능한 항목만 보기와 관련 도구가 없고 전체 이벤트 목록·가능 우선 정렬·전체 설명이 유지되는지 확인한다.
- [ ] **미실행** — 큰 로그에서 도구를 열면 도구만 선택 표시하고 이전 목록 탭이 동시에 강조되지 않는다. 터치 뒤 물리 패드를 다시 쓸 때 도구 화면·현재 선택·스크롤은 유지하고 이전 확인·클릭 권한은 취소한다. 버튼 해제·스틱/트리거 중립 뒤 새 조작을 받으며 실제 초점·문맥 변경·닫힘 등 안전 경계의 초기화도 따로 확인한다.
- [ ] **미실행** — 자동 입력 모드 변경이나 실제 포인터 전환은 같은 유효 누름을 보존한다. 팝업의 첫 터치 선택과 두 번째 터치 진행이 유지되며 물리 패드 재획득은 이전 클릭 권한을 취소하는지 확인한다. 선택 행 재터치로 요청을 접수한 뒤 자동 모드 관측이 늦게 와도 실제 결과가 한 번 실행되는지 확인하고 실제 게임/입력 모드·재개 로그를 기록한다.
- [ ] **미실행** — 팝업 목록의 정상 발동 가능/발동 불가 상태 행과 반복 클릭·터치 안내가 없고 굵은 제목·결과 요약의 두 줄로 유지된다. 선택 전후 행 높이·좌표와 첫 선택 후 같은 위치 재터치 진행, A/Enter·B/Escape를 확인한다. 예상 결과와 발동 조건을 구분하고 서로 다른 실제 결과 ID의 설명이 섞이지 않는다.
- [ ] **미실행** — 결과 요약·상세에 기존 로그의 효과색이 유지되고 색 태그가 말줄임 길이나 줄 수를 늘리지 않는다. 긴 색 설명·이모지·큰 글자에서 잘린 색이 다음 행으로 번지지 않고, 제목·발동 조건의 태그처럼 보이는 문자열이 실제 서식으로 해석되지 않는다. 제목은 렌더러가 굵게 표시하고 굵은 폭으로 말줄임해 긴 `Section_...:이벤트_이름`이 영역을 넘지 않는다. 색이 없던 아이템·플래그 등은 기존 본문색을 유지한다.
- [ ] **미실행** — 조건 미충족·가중치 0·판정 미확인·읽기 불가 후보의 제목은 회색이며 선택 화살표와 결과 효과색은 유지된다. 회색 후보 첫 터치 선택과 읽기 가능한 후보의 두 번째 터치/A 명시 조건 무시를 확인하고 실제 대상·결과 읽기 불가는 실행을 차단한다.
- [ ] **미실행** — 선택 결과·발동 조건을 목록과 별도로 휠·오른쪽 스틱으로 끝까지 읽고 ↑↓는 후보 이동을 유지한다. 준비 중·미지원·읽기 실패·확인된 효과 없음을 구분하며 설명 분석 실패만으로 일반 진행·조건 무시 가능 여부가 바뀌지 않는다. 큰 글자·긴 설명·작은 화면과 결과/대상 변경 후 상세 스크롤 초기화도 확인한다.
- [ ] **미실행** — 게임 선택지 A를 누른 채 팝업 진입, 팝업 A/B를 누른 채 게임·대화·주사위 복귀에서 입력이 재사용되지 않는다. 전체 버튼 해제·스틱/트리거 중립 뒤 새 입력만 받는다.
- [ ] **미실행** — Alt-Tab·문맥/대상 교체·패드 분리/재연결·여러 슬롯·소유자 재선택에서 미확정 포인터 누름을 취소한다. 단순 포인터 전환·입력 모드 변화는 같은 유효 누름을 보존하며 자동 입력 모드 관측만으로 이미 접수된 유효 확정을 폐기하지 않는다. 실제 안전 경계는 접수된 확정도 취소하고 한 화면만 조작한다. 길게 누르기·동시 입력·새 확인과 해제/중립도 확인한다.
- [ ] **미실행** — 실제 native XInput 차단 경로를 확인한다. 미확인/실패 시 위험한 패드 확정을 막고 키보드·마우스로 복구한다. Steam Input은 시험한 구성만 기록한다.
- [ ] **미실행** — 기존 같은 패드 L3/R3 클릭 겹침 열기·설정 키·Tab과 로그 LB/RB·Y 도구·X 새로고침·B 닫기를 회귀 확인한다. 이번 기능용 새 패드 조합이 없다.

## alpha.11 당시 순수 조회·기존 기능·배포

- [ ] **미실행** — 표시·정렬·팝업 설정 조회 전후 게임 RNG·조건 카운터·예약·세이브가 바뀌지 않는다. 보이는 현재 탭/행동의 0.25초 갱신·실패 5초 재시도·항목 실패 격리·정상 주기 Lua 재분석 없음과 모두 숨김 조회 0을 구분한다.
- [ ] **미실행** — 이벤트 예약 UI·`TargetEvent` 99999 보정이 없고 로그에서 사전 요청을 만들지 않는다. 미션 조건 통과 예약·해제·소속 검증·수명과 기존 한국어/선택지 분석·읽음·대화 기록을 유지한다.
- [ ] **미실행** — 주사위 임의 정수·음수·0 자동, 기존 Xbox/XInput 조정과 로그/팝업/주사위 왕복을 확인한다.
- [ ] **미실행** — 시험 DLL·cfg·두 파일 ZIP·매니페스트 해시를 대조한다. 게임 소스·게임 DLL·새 UI 이력/세이브 파일을 배포하지 않는다.
- [ ] **미실행** — 게임 종료 후 이전 DLL만 복원해 이전 모드 동작으로 돌아간다. 필요한 경우에만 백업 cfg를 복원한다. DLL 복원이 이미 진행·저장한 게임 상태까지 되돌리는 것은 아니다.

자동 검사·관리 코드 시간/할당량 측정과 실제 Unity/Windows 프레임 관찰을 별도 기록한다. 확인하지 않은 다른 운영체제·모든 패드·모든 Steam Input 구성을 지원 완료로 표시하지 않는다. **이번 후보의 사용자 확인 전에는 PRD #5를 완료로 닫지 않는다.**

# PRD #4 후속: 조건 탭의 분기 후보 블록

2026-10-19 KST. 조건 탭의 여러 분기 후보가 공백과 이어진 설명만으로 구분되지 않는다는 사용자 보고에 따라, 체크포인트의 실제 분기 구조를 별도 읽기 전용 블록으로 표시한다.
이전 [읽기 화면 후보](ISSUE-4-READING-LAYOUT.md)와 [공개 alpha.5](ISSUE-4-ALPHA5-RELEASE.md)의 산출물·검사는 당시 기록으로 보존한다.
이번은 로컬 후속이며 커밋·prerelease 게시·이슈 완료는 포함하지 않는다. 게임을 설치하거나 실행하지 않는다.

## 표시와 조작

조건 탭의 왼쪽 목록에서 체크포인트를 선택하면 오른쪽 상세에 다음 구조로 표시한다. 아래는 배치를 설명하는 예시다.

```text
위에서부터 검사하며, 처음 만족한 분기로 진행합니다.

분기 1
이 조건을 만족하면
    원래 첫 분기의 조건 설명

분기 2
앞 분기가 모두 불충족일 때 검사
    원래 둘째 분기의 조건 설명

그 외 (분기 3)
위 분기가 모두 불충족일 때
```

서로 다른 분기 후보의 경계를 제목·맥락·블록 간격으로 드러낸다. 한 분기 안의 여러 비교식은 같은 블록에 남긴다.
분기 본문은 항상 공개하며 블록을 선택하거나 접는 단계는 추가하지 않는다. ↑↓는 왼쪽 체크포인트 선택, 오른쪽 스틱·휠·터치는 오른쪽 상세를 읽는 데 사용한다.
조건 상세에는 실행할 버튼이 없으므로 A·→로 진입하는 초점을 만들지 않는다. B 닫기·Y 도구·X 새로고침·LB/RB 탭과 입력 해제·중립 보호를 유지한다.

읽음·미독은 스토리 열람 정보다. 조건 충족이나 실제로 선택된 분기라는 뜻으로 바꾸지 않는다.
이번 화면은 분기 설명을 읽기 쉽게 나누며 실제 게임 판정을 실행하거나 선택 결과를 보장하지 않는다. `|`·AND/OR의 의미나 기존 복합 조건 계산은 변경하지 않는다.

## 실제 데이터 경계

- `DataHelper.DescribeSwitchCheckpoint`는 게임의 각 `ConditionResultItem`을 **한 분기 후보**로 캡처한다. 각 항목의 `ExtractConditions`는 한 번만 평가한다.
- `LogConditionBranch`는 제목·검사 맥락·조건 설명을 보관한다. `LogConditionDetails`는 순서 안내·분기 목록·호환 문자열 설명을 보관하고 분기 목록을 복사해 읽기 전용으로 만든다.
- `LogBridge`는 구조를 `Value`와 `LogItem.ConditionDetails`로 전달한다. 번역·지역화 때도 새 구조를 복사하며 문자열의 공백·줄바꿈·연산자·색상·읽음 배지에서 분기 경계를 추측하지 않는다.
- 기존 `ParseSwitchCheckpoint`는 같은 캡처의 호환 문자열 설명을 반환한다. 새 GUI용 정보를 만들기 위해 조건이나 모드 난수를 다시 조회하지 않는다.

조회가 실패하면 성공한 앞부분만 새로 붙이지 않고 **마지막 정상 분기 묶음 전체**와 실패 상태를 보존한다.
회복 시 새 묶음 전체로 바꾸며 같은 유효 체크포인트의 선택·직접 읽던 스크롤을 유지한다. 새 Lua 문맥에서는 이전 상세와 선택을 비운다.
체크포인트 원본이 없어지면 이전 분기 상세를 새 값처럼 남기지 않는다. 새 문맥에서 목록 항목 자체가 사라지면 기존 선택도 취소한다.

## 빈 값과 실행 횟수 분기

실행 횟수로 분기하는 `_useCount` 경로에서는 사용하지 않는 조건식을 읽거나 실행 횟수를 늘려 결과를 알아내지 않는다.
분기 목록 대신 **이 체크포인트는 조건식 대신 실행 횟수를 기준으로 분기합니다.**라는 중립 안내를 사용한다.

실제 분기 후보 안에 등록된 비교식이 없으면 **등록된 조건이 없어 이 분기는 충족되지 않습니다.**로 표시한다. 빈 묶음을 무조건 충족으로 설명하지 않는다.
전체 분기 목록이 유효한 빈 목록이면 `그 외 (분기 1)`만 표시한다. 외부 목록이 없는 기존 성공 빈 설명 계약은 유지한다.
잘못된 내부 항목은 정상 빈 값으로 숨기지 않고 기존 읽기 실패·마지막 정상 값 보호를 따른다.

자동 검사에는 실제 새 DLL의 helper → Bridge → 모델 연결, 복합 조건과 분기 경계, 한 번의 값 캡처, 정상 갱신·실패·회복·소멸·새 문맥을 포함한다.
해당 검사에서 게임 데이터·Unity·번역 경계는 명시적인 관리 대역이다. 실제 Unity의 줄바꿈·스크롤바·한글 배치와 native 패드·터치 결과는 별도로 확인한다. 긴 영문 ID도 실제 게임의 작은 창·큰 글자에서 확인한다.
패드 모드에서 로그를 연 직후 첫 입력이 소비되는 증상은 [별도 진단](../artifacts/issue-4/mode-entry-diagnosis/diagnosis.md) 상태로 남아 있다. 이번 조건 상세 변경으로 입력 모드 전환 문제까지 해결했다고 처리하지 않는다.
이번 빌드 결과와 검사 수·파일 해시는 이전 후보의 숫자나 해시와 구분한다. 검사 도구의 복제 허용 목록에도 새 분기 DTO 두 타입을 포함해 실제 후보의 게시 모델을 사용했다. 게임 DLL·소스는 설치 ZIP에 포함하지 않았다.

## 적용과 복구

1. 게임 종료 후 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. 검증한 후보 ZIP을 임시 폴더에 풀고 **DLL만 교체**한다. 기존 cfg는 보존한다. ZIP은 기존대로 설정·DLL 두 파일이다.
3. 기존 열기 키(기본 Tab)로 로그를 연다. 새 창 기본값이 필요하면 도구의 **창 위치·크기·글자 기본값 복구**를 사용한다. 1920×1200은 872×960px·본문 20px이다.
4. 문제 시 게임 종료 후 백업 DLL을 복원한다. 저장된 배치까지 되돌리려면 cfg도 복원한다. 공개 alpha.5 DLL로도 복구할 수 있다.

```powershell
Get-FileHash .\DiceMaster-source-candidate.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

## Windows 확인표

모든 항목은 **사용자 확인 대기**다. [기존 Windows 검증표](ISSUE-4-WINDOWS-VALIDATION.md)의 검색·접기 관련 과거 항목은 적용하지 않는다.

| 단계 | 조작 | 기대 결과 |
| --- | --- | --- |
| 1 | 복수 분기가 있는 조건 체크포인트 선택 | 순서 안내와 분기 번호·맥락이 보이고 후보 경계가 분명함 |
| 2 | 한 분기에 여러 비교식·긴 설명·줄바꿈 포함 | 내부 복합 조건은 같은 블록에 남고 다음 후보와 섞이지 않음 |
| 3 | 상세 A·좌우·제목 클릭·터치 후 ↑↓·오른쪽 스틱 | 블록 선택·접기·실행 초점 없이 목록 선택·상세 읽기 가능 |
| 4 | 자동 갱신·직접 스크롤·같은 항목 회복 | 최신 값 갱신, 직접 읽던 위치·같은 유효 선택 보존 |

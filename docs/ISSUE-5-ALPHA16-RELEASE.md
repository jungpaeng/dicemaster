# v1.0.6-alpha.16 — 로그에서도 조건·이벤트 판정과 미충족 표시

상태: **배포 준비 중 · 전체 후보 검사 통과 · 고정 소스 재빌드·게시·공개 파일 검증 대기 · 새 DLL의 실제 Windows·장치 확인 대기**. alpha.15 이후 로그의 이벤트 목록과 조건 상세에서도 팝업과 같은 확정 미충족 회색 표시를 읽도록 정리한다. 현재 공개 시험판은 [v1.0.6-alpha.15](https://github.com/jungpaeng/dicemaster/releases/tag/v1.0.6-alpha.15)이며 이 문서는 아직 새 버전 게시 완료 기록이 아니다.

[현재 공개 시험판 설치 ZIP](https://github.com/jungpaeng/dicemaster/releases/download/v1.0.6-alpha.15/DiceMaster-v1.0.6-alpha.15.zip) · [최신 정식 버전](https://github.com/jungpaeng/dicemaster/releases/latest) · [Windows 확인표](ISSUE-5-WINDOWS-VALIDATION.md#alpha16-로그-판정회색-표시-확인표) · [표시 기준과 구현 경계](ISSUE-5-LOG-JUDGMENT-DISPLAY.md).

## 사용자에게 달라진 점

- 로그의 **이벤트 목록 제목·선택 상세의 조건**, **조건 상세의 개별 분기 제목·전체 조건**에 팝업과 같은 판정을 적용한다. 확정된 조건 미충족·최종 가중치 0·앞 분기 우선만 회색으로 표시한다.
- 조건 목록은 체크포인트당 한 행을 유지하며 체크포인트 전체를 회색 처리하지 않는다. 선택한 체크포인트의 상세에서 분기별 상태와 조건을 읽는다. 앞에서 처음 만족한 분기로 진행하는 순서·기본 분기·다음 실행 횟수 비교를 팝업과 공유한다.
- 이벤트 상세는 **전체 조건 → 예상 결과**로 구분한다. 활성 조건·기본 가중치·조건별 증감·최종 가중치를 읽고 예상 결과의 기존 효과색을 보존한다. 이전의 표시용 난수·조건색과 새로운 엄격 판정이 한 상세에 섞이지 않도록 결과 설명을 따로 가져온다.
- 로그 조건의 난수는 **범위·원래 식·미확정**으로 표시한다. 표시용 예시값을 실제 판정값처럼 쓰거나 그 값으로 미충족 회색을 결정하지 않는다.

| 로그 상태 | 표시와 의미 |
| --- | --- |
| 현재 충족 | 기존 기본색. 해당 판정에서 사용 가능한 것으로 확인한 상태이며 실제 발생 확률이나 미래 결과의 보장은 아님 |
| 확정 미충족·가중치 0·앞 분기 우선 | 제목·조건 회색과 판정 이유. 읽기 가능한 결과의 예약·해제는 기존대로 가능 |
| 난수·미지원·앞 분기 미확정 | 기본색과 `?`·사유. 조건 불만족으로 단정하지 않음 |
| 대상/결과 확인 실패·조건 조회 실패 | `!` 또는 기존 읽기 실패·판정 미확인 상태로 구분. 조건 상세의 조회 실패는 체크포인트 단위의 이전 정상 설명을 보존하며 현재 판정으로 사용하지 않음 |
| 조회 대기·갱신 실패·게시 실패 | 이전 설명을 읽을 수 있어도 기존 회색을 현재 미충족으로 유지하지 않음. 판정 미확인·이전 값과 예약 변경 불가를 표시 |

기준은 **마지막 정상 조회 시점의 현재 상태**다. 현재 Lua에서 찾은 대상 중 열린 탭을 약 0.25초마다 갱신하며 과거 실행 당시 판정이나 실제로 뽑힌 난수 결과를 복원하지 않는다. 횟수 분기는 현재 횟수에 1을 더한 다음 실행으로 판단한다. 로그에서 분기를 회색으로 보더라도 이후 게임 상태 변화와 원래 난수 판정으로 실제 결과가 달라질 수 있다.

## 조작·설정과 기존 기능

회색은 자연 발동 여부의 표시이며 **예약 불가를 뜻하지 않는다**. 최신 대상·결과를 읽을 수 있으면 기존 조건·이벤트 예약을 사용한다. 첫 클릭·터치는 선택만, 선택된 이벤트 행 또는 조건 상세 분기의 새 누름·해제는 예약·해제 한 번이다. A/Enter·분기 탐색·체크포인트 한 행·예약 표시와 우선권을 유지한다. 조회 실패·이전 값에서 오래된 대상을 예약하지 못하는 경계도 유지한다.

팝업의 첫 터치 선택·다음 터치 진행, A/Enter 일반/명시 조건 무시, B/Esc 원래 판정과 하단 텍스트 안내를 바꾸지 않는다. 팝업에서 로그 열기·Tab·설정된 L3/R3 클릭 겹침도 유지한다. 큰 로그가 열린 동안 로그만 입력을 받고 해당 Lua 흐름·예약 소비·팝업 OFF 후 원래 판정은 닫기까지 보류한다. 닫은 뒤 버튼 해제·스틱/트리거 중립을 거쳐 새 입력을 받는다.

`EnableSwitchSelectionPopup=false`·`EnableEventSelectionPopup=true` 기본값과 기존 cfg의 저장값, 상위 `EnableOptionInfo` 계약을 유지한다. 새 설정 키를 추가하지 않는다. 기존 Switch ON은 DLL만 교체해도 ON이며 끄려면 조건 탭 상단 설정을 사용한다. 미션·주사위·읽음 표시와 예약의 일회 적용·수명은 변경하지 않는다.

## 설치·업데이트와 복구

Windows용 활협전과 **BepInEx가 포함된 활협전용 모드 베이스**가 필요하다. alpha.16의 설치 ZIP은 게시 후 이 문서에 연결한다. 현재 alpha.15 설치 링크를 alpha.16 파일로 오인하지 않는다.

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 백업한다.
2. 게시된 대상 버전의 `DiceMaster-v1.0.6-alpha.16.zip`을 받는다. GitHub 자동 `Source code` 압축 파일은 설치용이 아니다.
3. 업데이트는 **`plugins/DiceMaster/DiceMaster.dll`만 교체**해 기존 cfg를 보존한다. 최초 설치는 ZIP의 `config`·`plugins`를 기존 BepInEx 아래에 넣는다.
4. 문제 시 게임 종료 후 백업 DLL과 필요한 cfg를 복원한다. DLL 복원은 이미 진행·저장한 게임 상태를 되돌리지 않는다.

alpha.15로 복구하면 로그의 새 회색 표시·공통 Switch 판정·조건/결과 분리는 사라지고 이전 로그 표시로 돌아간다. alpha.15의 세 줄 팝업·전체 조건·판정 구분과 로그 열기·상세 분기 예약은 유지된다. 기존 Release·태그·자산과 Latest 정식 v1.0.5를 보존할 예정이며 설치 ZIP은 cfg와 DLL 두 파일만 포함하도록 검증한다.

## 검증과 알려진 제한

공통 `SwitchEligibility`는 읽기 전용 평가로 분기 순서·기본 분기·이번 실행 횟수 비교를 계산한다. `SafeDisplayEvaluation`·`PopupConditionText`를 사용하며 게임의 `Check`/`GetValue`/`Execute` 사슬이나 실제 난수·표시용 난수 샘플을 실행하지 않는다. 판정·색상·설명은 예약 또는 직접 선택의 실행 권한을 새로 부여하지 않는다.

팝업 지원 형식은 기존과 같다. 이벤트는 지원하는 비메인 Lua의 직접 리터럴 `checkpointmanager.Position` 호출, 조건은 직접 문자열 리터럴 `Switch`를 지역 변수에 대입한 뒤 바로 정수 동등 비교 `if/elseif/else`로 분기하는 형식이다. 로그는 현재 Lua에서 정적으로 찾은 대상의 현재 상태를 조회한다. 모든 미래 조건·효과를 확정하거나 새 실행 이력을 저장하지 않는다. 회상·조건의 내부 ID 문제 해결과 보류한 구조 정리 3단계는 이번 범위가 아니다.

Windows 개발 환경에 설치·실행하지 않았다. 관리 코드·제공된 게임 API·MoonSharp·모의 Unity 경계 검사와 실제 Windows 화면·XInput·물리 패드·트랙패드·모니터 터치 확인은 별개다. **새 DLL의 실제 Windows·장치 확인과 이슈 #5 완료는 대기**다.

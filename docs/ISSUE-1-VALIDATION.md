## 확인한 문제와 증거의 한계

자동 갱신이 공유 `OptionResult`를 비우면서 `luaOptions`의 파싱 완료 표시를 유지하는 v1.0.2 경로를 수정 대상으로 삼습니다. 실제 Lua 파서와 갱신 본체를 연결하지 않은 기존 모의 검사는 이 회귀를 발견하지 못했습니다.

ZIP SHA-256은 `42F946C26956B61FFE4ACA4C3391BDF0D9EF343FDA6B7B242AA617E9E46BC5CC`입니다. 기존 파일·로그는 Steam appid `1859910`, buildid `26021712`, Unity `2020.3.49f1`, BepInEx `6.0.0-be.692`를 식별합니다. 설치 모드의 메타데이터 버전은 DiceMaster `1.0.0`이지만 DLL SHA-256은 `62ade4b719381fb31bfa7a356ae004299d391f53f13a4f085dc1a39e62cf5179`로 저장소 `e7d6dfe` 기준 DLL과 같습니다. 메타데이터 버전만으로 후보를 구분하지 않습니다.

이 자료는 기존 Windows 파일·정보의 읽기 전용 수집본입니다. 새 Windows 실행이나 호환성 확인 결과가 아니며, 현재 Windows PC의 게임 실행·후보 설치 검증은 승인되지 않았습니다. 완료한 prerelease 파일 게시·다운로드 검증과 구분합니다.

### 실제 API에서 확인한 의미와 후보 변경

`PositionEventData.GetRate`·`StatGroupVariable.GetResult`·`StatCompareItem.Check`의 전이 호출에서 `UnityEngine.Random.Range` 진입과 `ConditionResultData.Execute`의 `_count` 증가를 확인했습니다. 원본 API를 표시 목적으로 반복 실행하는 것과 모드의 표시 보호 깊이를 높이는 것만으로는 게임 상태 비변경을 보장할 수 없습니다.

후보의 `SafeDisplayEvaluation`은 실제 DLL에서 확인한 17개 값 종류·집계·비교·확률 계산을 별도 수행합니다. 난수는 샘플링하거나 임의 값으로 대체하지 않고 해당 행의 실패/이전 값 표시로 처리합니다. 알 수 없는 enum·미지원 `GameStat` 변환·순환 자료는 거부합니다. `ConditionResultItem._items == null`은 잘못된 자료로 실패하며 정상 빈 목록은 false입니다. 알려진 모드 설명 호출은 내러티브 경로의 보호 깊이 0에서도 순수 평가로 연결하고 원본 게임 어셈블리·실제 진행 API는 교체하지 않습니다. `AnimationCurve.Evaluate` 등 native 계산과 실제 리소스·다른 모드의 런타임 패치는 실행 검증하지 않았습니다.

`LifecycleState`와 후킹은 실제 `SaveSystem` 6개 진입점·공통 씬 시작 경계에서 이전 정보와 분석을 지우고 조회를 차단합니다. Lua Prefix의 원문은 임시 보관하며 실제 컴파일 결과가 non-null인 Postfix에서만 활성화합니다. void 로드 반환·씬 코루틴 생성·null Lua·예외·오래된 콜백으로 준비 완료를 선언하지 않습니다. 차단 중 자동·수동·탭 전환의 현재값 조회와 재분석은 0회여야 합니다. 현재 Lua 안의 제자리 복원은 새 Lua를 만들지 않을 수 있으므로 다음 실제 성공 Lua까지 대기할 수 있습니다.

파일 없는 슬롯·빈 `_restoreData`처럼 원본 로더가 무동작으로 반환하는 경우도 진입 시 문맥을 지웁니다. 후속 성공 Lua가 없으면 수동 새로고침으로 대기를 해제할 수 없습니다. 무동작·실패 로드와 제자리 복원 뒤의 즉시 표시 재개는 미구현 한계입니다.

선택지 분석은 공유 `LuaParser.Instance`가, 이벤트 고정 설명은 별도 파서가 소유합니다. 콜드·지연 준비 이벤트도 공유 선택지 분석을 덮어쓰지 않습니다. 실제 관리 코드의 정적 분석·일부 실제 IL 이식 검사와 Unity/Harmony/native 실행 검증은 구분합니다. 세부 서명·IL 근거·남은 한계는 [실제 API 분석](REAL-GAME-API-FINDINGS.md)과 [수명주기 분석](GAME-LIFECYCLE-ANALYSIS.md)에 기록합니다.

## 수용 기준

체크 표시는 자동 검사, 실제 API 분석, 해당 Windows 사용자 확인을 모두 충족한 경우에만 추가합니다. 코드가 존재하거나 일부 모의 검사가 통과한 것만으로 체크하지 않습니다.

- [ ] 실제 파서의 선택지 결과가 콜드·웜 캐시에서 여러 차례 자동 갱신 후 유지되고 수동→자동 결과가 일치합니다.
- [ ] 게임 선택지 옆 요약과 로그 결과가 같은 분석 데이터에 근거하며 `SetFlag`·`AddFlag` 예정값이 유지됩니다.
- [ ] 현재 탭만 0.25초 간격으로 평가하고 정상 행의 재열기·전환 즉시 갱신, 숨김·비활성 탭 평가 중단이 확인됩니다.
- [ ] 첫 행·중간 행·내부 함수 실패를 격리하고 세 상태 문구·마지막 정상 값·5초 재시도·전환 시 대기 유지·수동 즉시 재시도가 확인됩니다.
- [ ] 자동 표시가 공유 분석을 변경하지 않으며 새 Lua·세이브 로드·새 게임에서 이전 행과 실패 상태가 제거됩니다.
- [ ] 실제 API 분석과 Windows 확인으로 게임 상태 비변경·이벤트/미션 예약 보존·반복 대화 기록 방지·예외 후 보호 복구가 확인됩니다.
- [ ] 기존 설정·설치·번역·주사위·패드·네 탭·선택지 요약 계약을 보존합니다.
- [ ] 구조적 성능 기준, 실제 시간·할당량 측정, 오류 최초 1회·복구 1회 로그 정책을 충족합니다.
- [ ] 자동 검사·Windows 검증·문서·릴리스 설명·두 파일 ZIP과 커밋/다운로드 검증이 실제 결과와 일치합니다.

## 성능 측정

아래 게임 측정 절차는 향후 별도 승인을 받은 뒤 검토할 계획입니다. 현재 Windows 실행이나 게임 측정을 요청하지 않으며 실제 게임 성능 기록은 없습니다.

고정 수치 상한은 없습니다. 0.25초는 선택한 갱신 간격이며 실측 통과 기준이 아닙니다. 구조적 기준은 창이 닫힌 동안 표시용 조회 0회, 비활성 탭의 주기 평가 0회, 정상 주기 중 Lua 재분석 0회입니다. 게임 Lua 로딩에 따른 고정 분석은 표시용 조회 횟수와 구분합니다.

측정 때 Windows·CPU·메모리·게임/모드 베이스/BepInEx 버전, 대상 DLL SHA-256, 측정 도구·타이머/할당량 API, 현재 탭과 행 수, 데이터 준비 여부, 워밍업·측정 시간·반복 횟수를 남깁니다. 정상 갱신, 실패 재시도, 수동 새로고침은 각각 측정합니다.

1. 게임 진행 상황을 고정하고 콜드 캐시 첫 표시와 웜 캐시 반복 표시를 분리합니다.
2. 각 탭을 연 상태에서 표시 평가 경계를 측정해 소요 시간의 중앙값·상위 구간·최댓값과 행 수를 기록합니다. 전체 프레임 시간과 구분합니다.
3. 같은 구간의 할당 바이트/갱신과 GC 발생을 측정합니다. 게임 런타임이 지원하는 프로파일러 또는 카운터를 사용하고, 지원되지 않으면 측정 불가 이유를 남깁니다.
4. 창 닫기·비활성 탭·정상 주기 중 조회/재분석 호출 수를 카운터로 확인합니다. 한 행·중간 행 오류와 정상 복구에서 시간·할당량·로그 수도 비교합니다.
5. 모의 환경 수치와 실제 게임 수치를 별도 행으로 기록합니다. 측정용 계측을 넣었다면 최종 DLL과의 차이도 기록합니다.

| 환경 | 탭·행 수·조건 | 시간 | 할당량·GC | 구조적 조회 수 | 결과 |
|---|---|---|---|---|---|
| 독립 엔진·콜드 | 정상 100행, 1회 | 0.908ms | 31,776바이트, GC 0/1/2 각각 0회 | 첫 정상 조회 100회 | 실제 게임 성능 제외 |
| 독립 엔진·웜 | 정상 100행, 워밍업 20회 후 1,000회 | 총 14.292ms, 평균 0.014292ms/회 | 총 28,768,000바이트, 28,768바이트/회, GC 0=3회·1/2=0회 | 조회 100,000회, 발행 100,000행 | 실제 게임 성능 제외 |
| 실제 Windows 게임 | 미기록 | 미측정 | 미측정 | 미기록 | 필수 미완료 |

위 두 수치는 현 소스의 독립 표시 엔진만 측정했으며 순수 평가 getter·수명주기·리플렉션·게임 비용을 포함하지 않습니다. 개발 측정 환경은 macOS 15.5 / Darwin 24.5 / Arm64, .NET 8.0.32, SDK 8.0.426입니다. 실제 게임·Unity·리플렉션 어댑터는 실행하지 않았으며 CPU·메모리 상세는 기록하지 않았습니다. 시간 수치는 이 환경의 단일 실행 결과이고 고정 성능 상한이나 실제 게임의 프레임 비용을 뜻하지 않습니다.

개발 환경에서 엔진만 재현하는 측정 명령은 다음과 같습니다.

```sh
dotnet run --project development/tests/LiveLogArtifactTests/LiveLogArtifactTests.csproj -- --benchmark
```

이 측정은 100개의 미리 만든 정상 쿼리를 사용합니다. 콜드 1회는 엔진 생성부터 첫 표시까지 측정하고, 20회 워밍업 후 GC를 정리한 뒤 0.25초씩 진행시킨 모의 시각으로 1,000회 평가합니다. `Stopwatch`로 경과 시간, `GC.GetAllocatedBytesForCurrentThread`로 같은 스레드의 할당량, `GC.CollectionCount`로 세대별 수집 횟수를 기록합니다. 모의 시각의 250초와 실제 측정 경과 시간은 다릅니다. 정상 행 조회/발행은 각각 100,000회인지 확인합니다.

Unity·게임 API·실제 파서·리플렉션 어댑터·Windows 게임 런타임은 이 측정에 포함하지 않습니다. 모의 환경에서 측정한 숫자를 실제 게임 성능 검증으로 기재하지 않습니다.

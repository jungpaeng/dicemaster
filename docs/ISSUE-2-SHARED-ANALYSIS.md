공유 캐시는 정확히 같은 본문으로 식별하며 이야기 이름이나 해시만으로 동일성을 판단하지 않는다. 64항목 / UTF-16 2,097,152자 / 524,288토큰 LRU가 `PreviewScriptPlan`까지 소유한다. 용량은 기존 1,048,576자/262,144토큰에서 실제 공유 작업 자료 크기를 측정해 조정했으며, 선택지별 추적 한도와 분리한다. 추가 메모는 보유 토큰당 최대 8단위, 보유 원문 문자당 최대 4자의 파생 문자열로 제한한다. 단위는 관리 객체의 바이트 크기가 아니며 실제 상주 메모리 보장은 아니다. 인자·상수·분기 목록을 분석마다 복사하므로 한 선택지의 수정이 다른 선택지나 캐시를 바꾸지 않는다.

읽기 성공/실패·현재 게임값·선택지 효과 결과·추적 작업 큐는 이 공유 캐시에 넣지 않는다. 동일한 본문의 논리 문자·토큰·작업 비용은 캐시가 따뜻해도 그대로 청구한다. 제한된 토큰 접두부는 별도 계획을 사용하므로 캐시의 전체 본문을 통해 경계 밖을 보지 않는다. 캐시는 기존 문맥 초기화에서 함께 해제한다. 자동 표시 갱신 중 재분석 없음과 실제 읽기 실패의 5초 재시도 계약을 유지한다.

## 현재 조건의 의미와 안전 경계

조건 구문만 저장하고 표시 때 현재값을 다시 읽는다. 지원하는 구문은 작은 정수·bool, 비교, `not`/`and`/`or`, 괄호와 정확한 리터럴 `checkpointmanager.Switch/Condition` 읽기 및 문맥 안에서 증명한 단일 대입/별칭이다. Lua의 0은 참이며 `and`/`or`가 피연산자를 반환하는 의미를 보존한다. `elseif`는 앞선 조건이 먼저 선택되는 순서, `else`는 앞선 조건의 부정을 반영한다. 조건 원문·키·세이브는 진단에 출력하지 않는다.

원본 `Switch`·`Condition`·`Execute`는 실행 카운터를 바꿀 수 있으므로 호출하지 않는다. 이미 존재하는 체크포인트 관리자의 필드와 정확한 설정 타입을 읽고, 기존에 감사한 `SafeDisplayEvaluation`의 읽기 전용 의미를 적용한다. 임의 property/싱글턴 초기화 API는 호출하지 않는다. 이름 비교에는 기존 Unity Object의 비가상 이름 읽기만 사용한다. RNG 참조·실행 횟수에 의존하는 `_useCount`·누락된 설정·알 수 없는 타입·순환/과대 자료는 판정 보류한다. 판정 보류는 장식용 힌트의 미지원이며 기존 보상 설명의 읽기 실패나 재시도 상태로 바꾸지 않는다.

한 설명 렌더링은 읽기 세션 하나를 공유해 같은 체크포인트를 다시 탐색하지 않고 전체 읽기 작업을 16,384회로 제한한다. 구문은 최대 4,096자/256토큰, 대입 우변 탐색은 128토큰, 판정 깊이는 64이며 설정 목록·값 그래프·능력치 변환에도 유한 경계를 둔다. 현재값은 렌더링 이후 보관하지 않는다.

선행 상태 변경, 알 수 없는 호출·대입 우변/메타메서드, 메서드 재바인딩·인덱싱, 루프·콜백/함수 경계, 후속 이야기, 입증하지 못한 선택지 바깥 문맥, `SnapshotAllowed=false`는 중립 표시를 유지한다. 기존 추출기의 “표시할 보상 없음” 분류를 런타임 순수 함수 목록으로 오인하지 않는다. 예를 들어 `ToggleSaveButton`, `CloseDialog`, `GetStoryText`, 일반 `tostring`은 새 현재값 판정의 안전한 선행 호출로 취급하지 않는다.

색상이 생겨도 효과의 `Conditional`/`ExecutionUncertain`/`Followup`, 가능한 변화 구분과 center/mental 예상량의 보수적 제한을 바꾸지 않는다. 설명에는 “조건 표시는 현재 상태 기준 · 진행 중 상태가 바뀌면 결과가 달라질 수 있음”을 함께 표시한다. 기존 요약 50자와 전체 로그 설명 경로를 사용한다.

**실제 적용 범위의 제한:** 현재 자료의 선택지 발견은 선택과 결과 사이 생략된 UI 콜백을 입증하지 못해 루트를 `RootConditional`로 보존한다. 최종 보고서에서 매핑 선택지 3,214개와 전체 후보 선택지 3,530개가 모두 `option-context-not-evaluated`를 유지함을 확인했다. 따라서 이 제공 코퍼스의 선택지는 새 현재 조건 힌트를 켜지 않고 중립으로 남는다. 이 경계를 풀어서 새 색상이 실제 선택지 전체에 나타난다고 주장하지 않는다. 안전한 합성 문맥의 현재 조건 표시와 읽기 경계는 검사했지만 실제 설치 게임의 상태·UI에서 표시되는 범위는 미확인이다. 후속 이야기의 현재 충족 색상도 제공하지 않는다.

## 캐시 용량의 근거와 실험

최대 비용 root `ch8_2_5_10_break_start_01`(7선택지·1,465레코드)의 정확한 본문 요청은 99회, 서로 다른 내용은 33개였다. 고유 내용 합은 1,680,299자·294,681토큰이다. 기존 1Mi 문자 캐시는 99회 토큰화·히트 0회·퇴출 81회였고, 새 계획의 부가 비용만 생겨 첫 후보의 이 사례는 약 13.6% 느려졌다. 이 후보를 최종안으로 채택하지 않았다.

같은 자료·관리 IL에서 유한 용량을 비교했다. 2Mi 문자/524,288토큰이면 33개 내용이 들어가 히트 66회·퇴출 0회가 됐다. 4Mi는 같은 히트 수·할당량으로 추가 이득이 없어 더 작은 2Mi를 선택했다. 깊이 8·고유 이야기 32·누적 문자 1,310,720·토큰 262,144·작업 524,288의 논리 추적 정책은 바꾸지 않았다.

12회 순서 교대 실험의 평균 정적 추출 비용:

| 비교 | 시간 | 스레드 누적 할당 |
| --- | ---: | ---: |
| 공개 alpha.4, 토큰 공유 1Mi 문자 | 485.381ms | 166,808,812바이트 |
| 같은 alpha.4, 토큰 공유만 2Mi 문자 | 391.517ms | 107,051,620바이트 |
| 새 구문·상수 계획 공유, 2Mi 문자 | 348.858ms | 66,819,584바이트 |
| 새 공유, 4Mi 문자 | 349.309ms | 같은 할당량 |

공개 기준 대비 이 사례의 시간 약 28.1%·할당 약 59.9% 감소다. 같은 용량의 토큰 공유만과 비교해도 구문·상수 공유가 시간 약 10.9%·할당 약 37.6%를 줄였다. 새 2Mi 계획은 상수 검증 403회 생성/1,062회 재사용, 계획 66회 재사용, 보유 메모 121,340단위/파생 문자 519,484자를 기록했다. 모든 실험의 선택지·효과·설명·논리 예산 해시는 같았다.

이 실험은 별도 대역의 캐시 생성자만 용량을 바꿔 원인을 분리한 결과다. 최종 제품 DLL 자체의 반복 측정은 다음 검사 기록에 별도 연결한다. 입력 SHA 검증·UTF-8 적재는 타이머 밖, 후속 reader는 검증한 메모리 조회다. 한 사례와 Mac .NET 대역의 JIT·리플렉션 포함 비용이며 Unity 프레임·Windows 성능이나 전체 코퍼스 개선률·상주 메모리로 확대하지 않는다. 동기 분석과 남은 지연도 유지되므로 프레임 분할을 구현했다고 주장하지 않는다.

## 검사와 후보

검사와 고정 DLL의 실제 Lua 대조·비용은 아래 결과 및 `artifacts/shared-preview-analysis/`의 비공개 원자료 없는 보고서로 구분한다. 원본 게임 자료는 읽기 전용이며 Lua 해석기·게임 진행 API·Windows는 실행하지 않는다.

전체 소스 빌드 8개 검사 묶음이 통과했다. 미리보기 검사는 1,453개 단언으로, 구문/상수 공유·캐시 소비자 변경 격리·오류 재부착·콜드/웜 논리 예산 동일성·현재 조건 변경 후 재표시·선행 변경/콜백 차단·원본 실행/RNG/카운터 보존을 포함한다. 나머지 기존 로그·수명주기·메타데이터·주사위·패드 검사를 유지한다.

최종 소스 후보는 `artifacts/shared-preview-analysis/final-candidate/`에 분리했다.

최종 DLL 자체를 baseline→candidate→candidate→baseline 순서로 측정한 최대 비용 root의 추출은 평균 **483.784ms → 335.942ms**, 누적 할당은 **166,810,132 → 66,813,912바이트**다. 시간 약 30.56%·할당 약 59.95% 감소이며 네 번의 선택지 의미 해시는 같다. 여전히 약 0.34초의 동기 추출 비용이 남는다.

전체 번체 이야기 2,198개(설명·메타데이터 포함 루트 비용 합)는 alpha.4 **13.045/13.204초 → 최종 12.689/12.395초**, 평균 약 **4.43% 감소**다. 스레드 누적 할당 합은 약 **6.141GB → 5.060GB(17.60% 감소)**이며 이는 상주 메모리가 아니다. root 중앙값은 0.689/0.695ms→0.717/0.705ms로 조금 늘었고 p95는 약 23~24ms로 비슷했다. 최악 root의 개선률을 모든 이야기의 개선률로 일반화하지 않는다.

실제 Lua 고정 DLL 대조는 매핑한 2,198본문/3,214선택지/63,967호출, 매핑하지 않은 후보 2,667본문/3,530선택지/14,728호출을 검사한다. 원본 판정 실행과 RNG 경계는 0회다. 현재 게임 상태가 없는 오프라인 검사는 `SnapshotAllowed=false`로 중립을 유지하므로 실제 상태의 진리나 게임 UI에서의 색상 적용률을 검증한 결과로 쓰지 않는다.

비용을 제외한 효과·분기·이유·설명 해시·논리 예산은 alpha.4와 완전히 같다. 매핑 의미 해시는 `f396aab66807c152d4d2565928479a1f5b7a4301365a8e3bc410f3bdf82ec16c`, 루트 의미 해시는 `2ea72e8164174e097bd9523a9738dd7850c388de651fdf43f88c935e4afe38f3`다. 반복 결과도 같고 추가/누락 호출·변경 선택지는 0개다. 원문에 없는 호출·잘못된 출처·미발견 마커의 독립 대조 실패는 0개지만 임의 실행 경로나 모든 누락 효과를 증명하는 결과로 확대하지 않는다. 기존 한도 영향 54선택지(깊이 46·문자 8)는 그대로이며 무제한 추적으로 바꾸지 않았다. 근거는 `artifacts/shared-preview-analysis/final-audit/{summary,performance-summary}.json`이다. 첫 1Mi 후보의 느려진 측정도 `audit/initial-candidate-deb871f3/`에 남겨 채택 결과와 구분한다. 빌드 명세 내부 `real_lua_comparison=not-run`은 빌드 프로그램의 범위이며 후속 감사 기록으로 보완한다.

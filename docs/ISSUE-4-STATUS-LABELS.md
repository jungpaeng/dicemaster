# PRD #4 후속: 정상 조회 문구 생략

2026-10-19 KST. 네 탭의 항목에서 정상일 때 반복되는 `조회 정상`을 생략한다. 읽음·미독·읽음 정보 없음, 분석 상태와 대기·실패·이전 값 안내는 유지한다. 상단의 항목 수·상태별 집계는 그대로다. 정상 여부 모델, 자동 갱신과 예약 보호는 변경하지 않는다.

## 기존 문구의 의미

| 문구 | 의미와 범위 |
| --- | --- |
| 읽음 | 추출된 대표 이야기 키가 게임 열람 기록에서 모두 확인됨. 연결을 찾지 못한 분기는 집계하지 않으므로 모든 실제 분기를 열람했다는 보장은 아님 |
| 미독 | 연결된 대표 이야기 중 하나 이상을 게임 열람 기록에서 확인하지 못함. 일부만 미독이어도 체크포인트 전체가 미독이며 조건 미충족이나 이벤트 미발생 판정은 아님 |
| 읽음 정보 없음 | 이야기 연결을 찾지 못했거나 읽음 정보가 제공되지 않은 `NoStory/Unknown`. 미독으로 확정하지 않음 |
| 조회 정상 | 조회·갱신에서 오류나 대기가 감지되지 않은 `Healthy`. 조건 충족·이벤트 발생·정보의 완전한 확보를 뜻하지 않음. 이번 후속에서 행 표시를 생략 |

조건 분기의 읽음 정보는 각 분기의 첫 `GetStoryText` 키를 대표로 추출해 게임 `ReadStorySystem` 기록과 대조한다. 현재 이벤트·미션 게시 경로에는 이야기 읽음 정보가 없으므로 `Unknown`의 읽음 배지를 숨긴다. 선택지·조건의 읽음 배지와 조건 색상·분기 설명은 보존한다.

`DescribeSwitchCheckpoint`는 체크포인트를 찾지 못하거나 기존 외부 목록이 없을 때 빈 설명을 정상 반환하는 계약이 있다. 따라서 조회가 `Healthy`여도 모든 조건 데이터의 완전성까지 보증하지 않는다. 이번 후속은 이 읽기·실패 계약을 바꾸지 않는다.

## 구현과 자동 검사

`LogRenderer.RowState`의 정상 상태 문구만 빈 문자열로 바꾼다. `LogBridge`의 조회 상태, `LogItem.CanReserve`와 `TryReserve`의 최신 대상 검증, 게시·갱신 주기와 원본 ID는 변경하지 않는다. 빈 상태일 때 목록의 여분 줄과 상세의 빈 상태 레이블을 만들지 않는 기존 렌더링을 사용한다.

앞선 [시간 제한 없는 L3/R3 겹침 열기](ISSUE-4-PAD-OVERLAP.md)를 포함하며 기존 후보를 덮어쓰지 않는다. [번역 경로 감사](../artifacts/issue-4/translation-audit/audit.json)의 목록·상세 번역 불일치는 점검 기록이며 이번 상태 문구 변경과 별도다.

```sh
python3 build/build-source.py --references '<읽기 전용 참조 루트>' --output-dir artifacts/issue-4/status-labels
```

## 적용·복구

게임 종료 후 기존 DLL과 cfg를 게임 폴더 밖에 백업한다. 새 후보 ZIP에서 `plugins/DiceMaster/DiceMaster.dll`만 꺼내 `BepInEx/plugins/DiceMaster/DiceMaster.dll`에 교체한다. 기존 `BepInEx/config/DiceMaster.cfg`는 보존한다. 설정 키나 값의 변경은 없다.

문제 시 게임 종료 후 백업 DLL을 복원한다. 직전 로컬 [pad-overlap 후보](ISSUE-4-PAD-OVERLAP.md)로 돌아가면 선택지·조건·이벤트의 `조회 정상` 문구가 다시 표시된다. 공개 [alpha.6](ISSUE-4-ALPHA6-RELEASE.md)으로 돌아가면 패드 열기의 300ms 제한도 복구된다.

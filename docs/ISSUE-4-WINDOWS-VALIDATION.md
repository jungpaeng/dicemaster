# PRD #4 Windows 검증표 — 사용자 확인 대기

대상은 [PRD #4](https://github.com/jungpaeng/dicemaster/issues/4)의 **v1.0.5-alpha.1 prerelease 후보**다. 이 문서의 체크되지 않은 항목은 미실행이며 자동 검사나 과거 버전의 사용자 확인으로 대체하지 않는다. 에이전트는 게임 설치·실행을 하지 않았다. 실제 Windows 게임 검증은 유지보수자가 수행한다. 사용자가 후속으로 승인한 prerelease 게시와 실제 게임 확인은 별도다.

## 후보 식별과 적용

최종 DLL·ZIP 경로와 SHA-256은 [구현 기록](ISSUE-4-IMPLEMENTATION.md)의 후보 표와 [prerelease 설명](ISSUE-4-ALPHA1-RELEASE.md)을 따른다. 공개 ZIP 이름은 `DiceMaster-v1.0.5-alpha.1.zip`이며 로컬 후보와 ZIP 내용/해시는 같다. Windows PowerShell에서 `Get-FileHash .\DiceMaster.dll -Algorithm SHA256`와 `Get-FileHash .\DiceMaster-v1.0.5-alpha.1.zip -Algorithm SHA256`으로 대조한다.

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다. 현재 버전과 백업 DLL 해시도 기록한다.
2. 후보 ZIP을 별도 임시 폴더에 푼다. 정확히 `config/DiceMaster.cfg`, `plugins/DiceMaster/DiceMaster.dll` 두 파일이다.
3. **기존 설정을 유지하려면 DLL만** 게임의 같은 경로에 교체한다. 새 창 설정은 다음 시작 때 기존 BepInEx 설정에 추가된다. ZIP 설정 전체를 덮으면 기존 사용자 키/설정을 바꾸므로 새 설치에만 사용한다.
4. 아래 검증을 직접 진행하고 결과·환경·DLL 해시를 기록한다. 탐색 입력이 게임 진행·취소·주사위에 함께 전달되면 해당 재현 순서와 BepInEx 로그를 보관한다.
5. 복구할 때 게임을 종료하고 백업 DLL을 원래 경로에 복원한다. 필요하면 백업 설정도 복원한다. 세이브 형식은 변경하지 않는다. alpha.5 복구 시 PRD #2의 유한 후속 추적·미지원/중립 표시 경계는 유지된다. 더 오래된 버전에는 해당 버전의 알려진 한계가 있다.

시간·할당량은 측정 도구, 항목 수, 콜드/웜, 화면/탭, 측정 구간과 함께 기록한다. macOS 관리 코드 대역의 자동 측정은 Windows Unity 프레임 시간·상주 메모리 수치가 아니다. 오류 재현을 위해 게임 자료/세이브를 수정할 필요는 없다. 확인할 수 없는 경로는 미실행으로 남긴다.

## 결과 전달과 완료 조건

DLL 해시·환경표·실패한 순서·탭/항목 ID·BepInEx의 해당 경계 최초 실패/복구 로그를 전달한다. 전체 Lua·세이브·검색 입력 원문은 진단에 필요하지 않다. 사용자 본인의 패드 탐색·스크롤·버튼 조작 및 주요 회귀 결과를 기록한 뒤 이슈 완료 여부를 결정한다.

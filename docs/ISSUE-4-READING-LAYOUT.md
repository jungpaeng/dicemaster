# PRD #4 후속: 선택지 읽기 화면과 스크롤바

2026-10-19 KST. alpha.5의 실제 테스트 후 요청한 창 기본값, 선택지 표시, 미션 상태 문구와 스크롤바를 다루는 **로컬 후속 후보**다.
공개 [v1.0.5-alpha.5](ISSUE-4-ALPHA5-RELEASE.md)는 이전 파일·해시·검사 결과로 보존한다.
이번 요청에는 커밋·prerelease 게시·이슈 완료를 포함하지 않는다. 게임 설치·실행은 수행하지 않는다.

## 이번 변경

### 1920×1200 기준 기본 배치

기본 창은 1920×1200에서 **872×960px**, 본문은 **20px**이다. 창 너비는 화면 너비에 `872/1920`, 높이는 화면 높이에 `960/1200`을 곱한다.
본문은 화면 높이 `/1200` 배율을 적용하며 기존 0.85~4 배율과 12~64px 제한을 유지한다.
1920×1080에서는 872×864·18px, 2560×1440에서는 1163×1152·24px, 3840×2160에서는 1744×1728·36px이다.

첫 유효한 표시 때 기본 배치를 계산하고 부팅 중 무효 화면으로 설정을 저장하지 않는 보호를 유지한다.
이전 1080 기준 기본값과 60%/70% 기본값은 당시 위치·크기·글자가 모두 일치할 때 새 기본값으로 이행한다.
사용자 지정 배치는 기존 픽셀 값을 유지한다. 도구의 **창 위치·크기·글자 기본값 복구**는 현재 화면의 새 기본값을 적용한다.
첫 표시 후 해상도를 바꿀 때마다 사용자 배치를 강제로 다시 비율 조정하지 않는다. [전체 계산·설정 이행 계약](ISSUE-4-VIEWPORT-1200.md)을 따른다.

### 선택지는 선택 없는 읽기 화면

선택지 탭에는 펼치거나 예약할 별도 동작이 없으므로 제목을 버튼 대신 일반 레이블로 표시한다.
전체 문장·효과·읽음·분석 상태·원본 ID는 계속 공개한다. 헤더 선택·접기·펼침과 선택 강조는 만들지 않는다.
각 항목 사이에 `max(8px, 본문 글자 크기 × 0.6)` 간격을 둔다. 기본 20px 본문에서는 12px이다.

| 입력 | 선택지 본문에서 동작 |
| --- | --- |
| 십자키·왼쪽 스틱·물리 키보드 ↑↓ | 전체 본문 스크롤 |
| 오른쪽 스틱·마우스 휠·터치 스크롤 | 전체 본문 스크롤 |
| A·확인·좌우·제목 누르기 | 항목 선택·접기·상세 진입 없음 |
| LB/RB | 이전/다음 탭 |
| Y / X | 도구 / 누를 때 한 번 새로고침 |
| B | 로그 닫기 |

도구에 들어가면 ↑↓·A는 기존 도구 이동·작동에 사용한다. 조건·이벤트·미션의 유효 항목 선택은 유지한다.
조건의 조작 없는 상세에는 진입하지 않고, 이벤트·미션은 유효한 예약 버튼에만 직접 진입한다.
선택지 본문은 선택을 따라 이동하지 않으며 자동 갱신이 직접 읽던 위치를 되돌리지 않는다. 새 문맥의 선택·입력 취소 경계는 유지한다.

### 미션 정상 문구 생략

미션 정상 행에서 반복되던 `조회 정상`을 생략한다. 이 변경은 표시 문구에 한정하며 정상 상태 판별·자동 갱신·예약 가능 여부를 바꾸지 않는다.
대기·실패·이전 값과 분석 상태, 상단 상태 요약은 유지한다.
실제 값 없는 `미션 정보 / 설명 조회 대기` 같은 상태 안내 행은 계속 목록 최하단에 모으고 비활성화한다.
상태 안내 행의 원본 ID·재조회 설명은 읽을 수 있지만 선택하거나 예약할 수 없다. 실제 값이 남은 대기·실패 미션은 읽을 수 있고 예약만 차단한다.
[상태 안내 행 구분 계약](ISSUE-4-MISSION-STATUS.md)을 따른다.

### 필요한 때에만 스크롤바 표시

공통 `GUILayout.BeginScrollView`의 강제 표시 인수를 가로·세로 모두 `false`로 설정한다.
각 탭 목록·본문·상세와 같은 공통 스크롤 경로에서 내용이 보이는 높이에 들어오면 세로 스크롤바를 강제 표시하지 않는다.
내용이 늘거나 창을 줄이고 글자를 키워 넘치면 필요한 스크롤바를 표시한다.
목록 행은 실제 가용 너비를 채우며, 스크롤바 유무에 따라 제목의 줄바꿈과 높이를 다시 계산한다. 긴 원본 ID가 가로 폭을 강제로 넓히지 않도록 제한한다.
선택을 유지하는 다른 탭의 선택 항목 추종과 직접 스크롤 보호는 유지한다.

실제 Unity의 레이아웃 계산·폰트 줄바꿈·스크롤바 폭에 따른 최종 표시 여부는 Windows 확인 대상이다.
자동 검사 대역이 숨김·표시를 검증하더라도 실제 게임 화면의 결과로 확대하지 않는다.

별도 읽기 전용 검토에서도 현재 입력·패키지·빌드 로그와 실제 후보 DLL의 새 배치·읽기 전용 선택지·자동 스크롤바·미션 문구 연결을 확인했다.
[최종 산출물 검증 영수증](../artifacts/issue-4/reading-layout-evidence/local-verification.json)에 자동 검사와 정적 검토·Windows 미확인을 구분한다.
이전 alpha.5 및 개별 후보의 자동 검사 수나 해시를 이번 결과로 재사용하지 않는다.
설치 ZIP은 `config/DiceMaster.cfg`와 `plugins/DiceMaster/DiceMaster.dll` 두 파일이며 수신 게임 DLL은 포함하지 않는다.

## 적용과 복구

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다.
2. 생성·검증한 후보 ZIP을 임시 폴더에 풀고 **DLL만 교체**한다. 기존 cfg를 보존한다. 전체 cfg 교체는 다른 사용자 설정도 바꾸므로 이번 업데이트에 필요하지 않다.
3. 기존 열기 키(기본 Tab)로 로그를 연다. 새 기본 배치가 필요하면 Y 도구에서 **창 위치·크기·글자 기본값 복구**를 사용한다. 1920×1200에서는 872×960px·본문 20px이다.
4. 문제 시 게임을 종료하고 백업 DLL을 복원한다. 기본값 이행·복구로 저장한 배치까지 되돌리려면 백업 cfg도 복원한다. 공개 alpha.5 DLL로도 복구할 수 있다.

Windows PowerShell에서 생성된 ZIP과 압축을 푼 DLL을 확인한다. 위 표의 최종 SHA-256과 비교한다.

```powershell
Get-FileHash .\DiceMaster-source-candidate.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

모든 항목은 **사용자 확인 대기**다. [기존 Windows 검증표](ISSUE-4-WINDOWS-VALIDATION.md)의 검색·자판·접기 관련 과거 항목 대신 아래 현재 동작을 확인한다.
실제 패드 탐색·스크롤·버튼과 주요 회귀를 확인한 뒤 이슈 #4 완료 여부를 결정한다.

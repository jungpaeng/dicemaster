# 저장 지도 직행의 파일 정의 — alpha.32

2026-10-22 main에서 구현했다. 기준은 `d42be54449bf2a3e8f75365af24d1262a812fd02`, 직전 공개 DLL은 alpha.31 소스 `cc656fc901466aba0c105e2b17c4c508ab672094`다. [alpha.32 게시 기록](ISSUE-6-ALPHA32-RELEASE.md)과 [실제 Windows 확인표](ISSUE-6-WINDOWS-VALIDATION.md#alpha32--저장-지도-직행의-파일-정의-확인-대기)를 구분한다. 새 DLL의 사용자 Windows 확인·PRD #6 전체 완료는 대기다.

## 실제 원인과 변경 범위

전체 게임 복제본의 Unity serialized file을 실행 없이 대조했다. level2=Story의 CheckPointManager가 sharedassets2.assets의 조건 목록511개·분기 목록6개(3,464개 슬롯/3,453개 고유 분기)·이벤트 풀73개를 소유한다. 같은 장면의 StatModifyManager는 실제 대화 초기화 목록12개를 참조한다. Free 지도 장면이 이 공유 파일을 참조하더라도 그 안의 모든 객체를 로드한다는 뜻은 아니다. 새 게임은 Story를 거치지만 지도 저장을 바로 불러오면 이 과정을 생략할 수 있다.

alpha.30/31의 FindObjectsOfTypeAll은 이미 로드된 객체만 찾는다. 필요한 정의가 없는 상태에서5초 재검색을 반복해도 새로 확보하지 못한다. 또한 MapGuideFollowups는 전체 경로에 HasReadFailure가 있으면, 다른 분기의 풀 실패와 무관한 직접 대화도 자동 안내에서 제외했다.

이번 변경은 조건·분기·초기화 정의를 설치 파일에서 확보하는 경로를 더하고 전역 실패의 전파를 줄인다. **이벤트 풀·기회·1회성의 실행 권한을 파일 자료로 대신하지 않는다.** 풀이 필요한 경로는 native 자료가 없으면 미확정으로 남지만, 독립적으로 확인한 직접 인사나 선택 경로까지 함께 숨기지 않는다.

사사형 초회 인사의 실제 Switch는 `_useCount=false`이며 `Talk_Brother4_00 == 0`이라는 플래그 비교다. 사사형 선택의 실제 조건은 `Talk_Brother4 == 1 AND E10005 == 0`이다. 방 진입의 현재 시간 비교와 가상 flag 배정을 별도로 반영한다. 기존 합성 검사의 횟수형 초회 인사 가정을 실제 정의의 증거로 사용하지 않았다. 인물 이름·플래그 예외 목록은 생산 코드에 추가하지 않았다.

## 읽기 전용 자료 경계

- 내장 `DiceMaster.MapDefinitions.index`에는 검토한 파일의 SHA-256·크기, 객체 ID/오프셋/길이/타입과 정의 root만 있다. 게임의 Lua·조건 payload·대사·세이브·게임 DLL은 포함하지 않는다.
- MapDefinitionFileReader는 모든 원본 파일의 크기와 SHA-256을 확인한 뒤 인덱스·PPtr·스키마·끝 위치·깊이/개수/크기 상한을 검증한다. 파일은 Open/Read/ShareRead로 열며 사용자 게임 폴더에 쓰지 않는다. 읽는 동안 원본 파일을 교체/수정하는 핸들과도 공유하지 않는다.
- 파일에서 읽은 조건·분기·그룹은 mod 내부 DisplayDefinition이다. 게임 ScriptableObject를 만들거나 씬을 활성화하지 않는다. Condition/Switch/Execute/Reset·Lua/RNG·게임 초기화·native owner 생성은 실행하지 않는다.
- 파일의 State·실행 count·현재 시간·능력치·아이템 수를 현재 값으로 사용하지 않는다. 등록된 현재 장소의 missions/player와 이미 존재하는 카탈로그를 통해 정확한 타입·자산 이름의 객체 참조만 연결한다. 정적 초기자가 있는 선택적 카탈로그 타입은 초기화를 유발하지 않도록 읽지 않는다. 그 참조의 현재 값은 기존 안전한 reader가 매번 읽는다. 없는 참조·충돌·미지원 입력은 미확정이다.
- 현재 Story owner가 있으면 해당 owner의 정의와 Lua 연결이 우선한다. 손상된 현재 owner를 과거 자료로 우회하지 않는다. 실행 owner 없는 횟수형 Switch는 파일의 count로 판정을 만들지 않는다.
- 파일 정의는 일반 경로의 route reader에만 제공한다. 엄격한 기회/1회성·예약/팝업 실행 판정 reader에는 제공하지 않는다. 밝은 안내를 금색 기회로 승격하지 않는다.

자동 안내의 각 경로는 기존 선택 단계 해금·현재 필수 조건·완료 분기·진입 상태 변경·반복 활동 판정을 그대로 통과해야 한다. 해당 경로의 미확정 선택지나 실행 횟수까지 무시하는 변경이 아니다. 같은 이름의 선택 화면에 대한 기존 범위/해금 보호도 유지한다.

## 지원하는 설치 자료와 실패 처리

이번 파일 대체 경로는 제공받은 전체 복제본의 아래 지문에 한정한다. 공식 게임 버전 번호나 다른 모드 베이스와의 동등성을 해시만으로 추정하지 않는다. 다른 지문에서는 기존 loaded-only 조회를 유지하며 파일 정의는 보류한다. 지원 범위를 자동으로 넓히지 않는다.

ログ → 도구 → 지도 안내 → 지도 조회 성능의 `파일 정의`는 미조회·설치 파일 확인 중·확인·읽기 대기/5초 재시도·지원 자료 불일치/미확인을 구분한다. 기존 `로드된 설정 자산`의 미확인과 파일 대체 경로의 확인은 서로 다른 자료 상태다. 진단을 포맷하기 위해 새 자료 조회를 시작하지 않는다.

일시적인 IO/현재 연결 실패는5초 뒤 다시 확인한다. 파일 지문·인덱스·스키마 불일치는 해당 문맥에서 반복 해시/파싱하지 않는다. 현재 자료를 조작하거나 이전 세이브 값으로 성공 처리하지 않는다. 새 게임/불러오기/장면 전환·두 지도 정보 기능 OFF·종료에서 파일 결과와 연결을 정리한다. 숨김·창 가림·포커스 상실·지도 안내 OFF에서는 진행 중 준비를 취소하고 늦은 결과를 게시하지 않는다.

설정 키·기본값·cfg 바이트·패드/키보드/마우스/터치 조작은 alpha.31과 같다. 파일 조회는 `EnableMapGuide`와 상위 `EnableOptionInfo`를 따른다. `EnableOneShotHints`만 켜져 있어도 엄격한 1회성 기준은 파일 정의를 빌리지 않는다. 상세의 마지막 장소 유지·실제 분기 메모리20건/5초·상점 요약·#5 이벤트/예약·로그 네 탭·주사위는 유지한다.

## 준비와 성능 계약

Unity 이름·기존 참조는 main에서 한정된 현재 카탈로그로 수집한다. 이미 조회한 session의 owner 참조를 재사용하므로 장소마다 같은 owner 필드를 추가로 읽지 않는다. SHA-256과 파일 payload 해석은 취소 가능한 worker에서 수행한다. worker는 Unity/game API를 호출하지 않는다. IO는 청크·객체 사이에서 취소하고 폐기된 작업은 현재 publication에 연결하지 않는다.

성공한 파일 정의는 문맥 내에서 재사용한다. 정상0.25초 갱신은 현재 값만 다시 읽고 파일 전체 해시/파싱이나 warm Lua 읽기/분석을 반복하지 않는다. native 자료가 여전히 없는 풀 등 실패 경로의5초 재시도는 유지한다. 갱신 간격을 늘리지 않았다. 최초 IO/해석·native 이름 수집·관리 GC의 실제 Windows 비용은 따로 확인해야 한다. worker의 처리 시간을 프레임 시간으로 해석하지 않는다.

## 자동 검사와 실제 Windows의 구분

전체21개 자동 검사, 고정 참조16개와 복제본 DLL을 각각 입력으로 한 source/API 연결 검사를 수행한다. 복제본에서는 실제 자산 파일과 SHA 검증한 번체 Lua2,199개를 사용한다. current save/Unity resource availability/입력/UI는 명시적 관리 경계이며 Windows 게임을 실행하지 않는다.

FileDefinitionCases는 Story owner·로드된 config/pool이 없는 상태에서 실제 파일을 읽어 흰색 안내가 복구되는지 검사한다. 완료 flag·확정 false로 제거, 현재 값 복구, warm 파일/Lua 준비 재시작 없음, 엄격한 reader와 횟수형 Switch의 보류, 불명 reset footprint의 보류, 인덱스 손상·지문 불일치·취소·늦은 결과 폐기를 포함한다. 실제 사용자 세이브 값으로 판정을 재현했다고 주장하지 않는다.

실제 후보 IL에는 worker의 Unity/game 호출 없음, 설치 파일의 Read 전용 열기, visibility 취소 연결과 기존 입력/읽기 전용 경계를 검사한다. 새 인덱스 리소스를 명시적으로 허용하면서 기존12개 리소스의 정확한 바이트도 보존한다. 설치 ZIP에는 기존 cfg와 새 DiceMaster.dll 두 파일만 있다.

개발 중 첫 전체 검사는 새 DTO의 test source link 누락, 다음 검사는 추가 리소스를 허용하지 않던 기존 배포 검사에서 중단됐다. DTO 의존성을 연결하고 새 인덱스의 정확한 이름/해시를 추가한 후 전체 검사를 다시 통과시켰다. 진입 시 owner 재조회도 session의 기존 참조를 재사용하도록 정리해 최종 코드로 재검사한다. 이전 실패 로그와 변경 전 성공 로그를 로컬에 보존한다.

최종 단언 수·후보 식별값·성능 표본·커밋 재빌드·공개 다운로드 검증은 [alpha.32 기록](ISSUE-6-ALPHA32-RELEASE.md)에 확정한다. 실제 Windows의 최초 저장 지도·마커/툴팁·파일 지원·지연/FPS·물리 입력 확인은 별도 대기다. #6을 종료하지 않는다.

## 인덱스 재생성

`build/generate-map-definition-index.py`는 UnityPy 1.25.4가 있는 별도 환경에서 사용한다. `--game-root`는 원본 게임, `--output`은 저장소 artifacts 아래 새 index 경로다. 대상 게임 파일은 읽기 전용이며 receipt에 SHA와 파일 불변을 기록한다. 생성물을 자동으로 src에 설치하지 않는다. 현재 root owner의 직렬화 포인터·스키마를 독립 확인하고 index/원본 hash·자료 입력·회귀를 검토한 뒤 리소스를 갱신해야 한다.

제공 복제본과 기존 고정 compiler 참조는 서로 다른 자료다. 기존 release reference-contract를 바꿔 복제본 검사를 통과한 것처럼 처리하지 않는다. 게임 원문 payload·관리 DLL·세이브·내부 추출물을 공개 저장소나 ZIP에 넣지 않는다.

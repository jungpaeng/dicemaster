| 새 A / Enter / Space | 선택된 이벤트·미션 예약/해제. 선택이 없으면 첫 선택 가능한 행만 선택 |

패드 열기는 열기 전용이다. 서로 다른 패드의 클릭이나 겹치지 않는 연속 클릭을 합치지 않는다. `[DiceMaster].EnableGamepadLogOpen=true`의 **게임 창 초점·로그 닫힘**에서는 첫 클릭 중복 전달을 막기 위해 단독 L3/R3도 게임에 보내지 않는다. 원래 클릭 기능이 필요하면 게임 종료 후 `false`로 바꾸고 재시작하며 남은 누름은 해제 후 반환한다. 게임의 실제 L3/R3 바인딩이 미사용이라고 확정하지 않는다. 주사위 패드 옵션과 독립적이다.

조합과 탐색은 전체 버튼 해제·스틱/트리거 중립을 기다리며 홀드로 반복 열기·예약·해제를 만들지 않는다. 소유자 고정·초점/연결/모드 변경·Alt-Tab·닫기·주사위 왕복과 게임 입력 차단 경계를 유지한다. 실제 Windows에서 게임 대화·취소·주사위와 중복되지 않는지는 사용자 확인 대상이다.

정상적으로 읽힌 게임 입력 모드를 우선하며 불명·조회 실패 시 양쪽 입력을 지원한다. 게임 scheme·액션 맵을 강제 변경하지 않고 터치·실제 포인터 조작을 받는다. 패드 열기는 로그 내부의 진입 의도를 보존하는 경로를 사용한다. **Tab으로 열 때의 기존 모드 전환·첫 패드 입력 소비 문제는 별도 미해결 경로**다. 게임의 XInput 폴링·차단 경로를 사용할 수 있을 때 지원하며 미지원 시 기존 키·마우스를 사용한다. native 폴링의 1초 신선도 보호는 두 클릭 사이의 시간 제한과 구분한다. [패드 안내](GAMEPAD.md)를 함께 따른다.

## 예약·해제의 범위

`이벤트 우선 예약`은 다음 해당 판정에 가중치를 주는 기존 일회 예약이며 지정 이벤트의 즉시 발생을 보장하지 않는다. `미션 조건 통과 예약`은 다음 해당 검사에 적용하는 기존 일회 예약이며 즉시 실행·행동 재개를 보장하지 않는다. 해제는 아직 남아 있는 예약을 없애며 이미 소비된 결과·진행된 이야기·미션은 되돌리지 않는다. 선택지·조건 탭은 예약/해제하지 않는다.

현재 선택된 최신 정상 대상에서만 예약과 해제를 허용한다. 대기·실패·이전 값·게시 실패·대상 소멸·같은 ID 객체 교체·새 문맥·실제 게임 데이터에서 빠진 대상은 변경하지 않는다. 새 확인 입력이나 선택된 행의 포인터 누름 때 예약 슬롯·문맥·탭·변경 세대를 캡처한다. 떼는 순간 현재 표시로 동작을 바꾸거나 티켓을 새로 만들지 않는다. 소비·교체·같은 객체 재예약과 조회 실패/회복 후의 오래된 입력을 거부하고 성공·거부·예외 후 권한을 소진한다. 현재 UI 모델·게시 정체성과 실제 게임 멤버십을 최종 검증하며 이를 위해 판정·실행 함수를 호출하지 않는다.

미션 해제는 모드가 직접 주입한 활성 항목의 관리자·사전 객체·키·현재 값이 그대로일 때만 원래 값을 복원하거나 원래 없던 항목을 제거한다. 예약 전부터 정상 활성인 항목은 삭제하지 않는다. 게임이 사전/값을 교체하거나 소비·문맥 전환이 일어나면 소유 기록을 버려 이미 반영된 상태를 되감지 않는다.

같은 문맥에서 마지막으로 명시 해제한 **원본 미션 대상**만 기존 위치 안내의 자동 지정에서 제외한다. 미션 안내 출력은 유지하며 다음 명시적 미션 예약 또는 새 문맥에서 억제를 해제한다. 전체 미션이나 이후 게임 판정을 끄는 기능은 아니다. [예약 표시·토글·미션 복구의 세부 계약](ISSUE-4-RESERVATION-TOGGLE.md)을 따른다.

alpha.9의 입력 153개·생산 소스 63개, 읽기 전용 외부 참조 15개와 ZIP CRC·정확히 두 파일·내부 바이트/해시·독립 감사를 확인했다. Unity·게임 데이터·Win32/XInput 경계는 검사 대역이므로 실제 게임·물리 장치·후킹·화면 검증으로 확대하지 않는다. 게임 소스·DLL을 저장소나 설치 ZIP에 포함하지 않는다. 현재 DiceMaster는 전체 C# 소스를 빌드하며 과거 DLL 패치 산출물을 정식 구현의 기준으로 삼지 않는다.

v1.0.5는 **재빌드·검사 재실행·재압축 없이 alpha.9의 동일 DLL/cfg/ZIP을 승격**한다. 새 정식 태그 소스 커밋의 입력 153개·생산 소스 63개를 Git 스냅샷에서 읽어 alpha.9와 비교한다. 파일의 바이트·크기·SHA-256도 대조해 기존 검증의 출처와 동일성을 확인한다. 기존 빌드 검증기·정책은 수정하지 않는다.

`draft=false`·`prerelease=false`·`make_latest=true`로 게시했다. 공개 페이지·태그 커밋·인증 없는 설치 ZIP의 SHA-256·CRC·내부 바이트와 실제 Latest v1.0.5를 확인했다. 출처 alpha.9·사용자의 게시 지시·원래 검사 기록 재사용·입력/파일 동일성과 게시 메타데이터를 `artifacts/releases/v1.0.5/`의 `promotion-verification.json`과 공개 검증 영수증에 기록했다. 사용자의 게시 지시는 Windows 확인 근거로 쓰지 않는다. 이전 alpha와 정식 Release·태그·자산은 그대로 보존한다. 이 절차는 검증된 배포 파일의 승격·게시 검증이며 새 빌드·새 검사 실행이나 Windows 기능 확인을 뜻하지 않는다.

## 적용·복구

1. 게임을 종료하고 현재 `BepInEx/plugins/DiceMaster/DiceMaster.dll`과 `BepInEx/config/DiceMaster.cfg`를 게임 폴더 밖에 백업한다. 기존 버전과 DLL 해시를 기록한다.
2. Assets의 **`DiceMaster-v1.0.5.zip`**을 임시 폴더에 푼다. GitHub 자동 `Source code` 압축 파일과 구분하고 실제 게시 파일의 SHA-256을 확인한다.
3. **`plugins/DiceMaster/DiceMaster.dll`만** 같은 게임 경로로 교체해 기존 cfg를 보존한다. v1.0.4에서 올라오면 새 로그 설정은 기존 BepInEx cfg에 추가된다. cfg 전체를 덮어써 기존 키·글자·배치를 초기화할 필요는 없다.
4. 문제 시 게임 종료 후 백업 DLL과 필요한 cfg를 복원한다. [alpha.9](ISSUE-4-ALPHA9-RELEASE.md)는 이번 로그 UI·패드·예약 토글을 포함한 이전 비교 기준이다. 정식 [v1.0.4](https://github.com/jungpaeng/dicemaster/releases/tag/v1.0.4)로 복구하면 PRD #2 분석을 포함한 당시 버전으로 돌아가며 이번 로그 GUI·로그 패드 탐색·L3/R3 열기·목록 예약 토글은 제공하지 않는다. 이전 기본 배치까지 되돌리려면 백업 cfg도 복원한다.

```powershell
Get-FileHash .\DiceMaster-v1.0.5.zip -Algorithm SHA256
Get-FileHash .\plugins\DiceMaster\DiceMaster.dll -Algorithm SHA256
```

설치 ZIP에는 `config/DiceMaster.cfg`와 `plugins/DiceMaster/DiceMaster.dll` 두 파일만 둔다. 세이브 형식은 변경하지 않는다.

## 사용자 Windows 확인

다음은 모두 **확인 대기**다. 해상도·배율·패드/Steam Input·게임/로더 환경·DLL SHA-256·항목 ID·재현 순서·BepInEx 로그를 기록한다.

1. cfg 보존 설치·재시작, 기존 사용자 배치 복원과 기본값 복구 시 1920×1200의 872×960·20px, 다른 해상도와 긴/짧은 목록을 확인한다.
2. 네 탭의 최종 구성·한국어·읽음·분기 설명·필요한 스크롤바와 포커스 추적, 마우스·키보드·터치·패드로 도구/닫기를 조작한다.
3. 양쪽 순서로 L3/R3를 겹쳐 한 번 열고, 전체 해제·중립 후 첫 새 방향/A를 확인한다. 기존 설정 키·Tab 진입은 별도로 기록한다.
4. 첫 A·첫 클릭은 선택만 하고 새 A/Enter/Space·선택된 행 재클릭은 예약 → 해제 → 재예약하는지, 다른 행을 읽어도 예약 마커가 남는지 확인한다. 홀드·해제로 반복하지 않아야 한다.
5. 포인터 누름 중 소비·교체·동일 대상 재예약·조회 실패/회복·대상 소멸·새 문맥 뒤 떼어도 이전 입력이 작동하지 않아야 한다. 최신 정상 대상만 변경해야 한다.
6. 미션 정상 활성 항목·직접 주입 항목의 해제, 게임의 소비/사전 변경·문맥 전환, 같은 문맥의 명시 취소 유지와 다음 명시 예약 후 억제 해제를 확인한다. 이미 진행한 게임 상태는 되감지 않아야 한다.
7. A/B·스틱·트리거 홀드 닫기, Alt-Tab·모드 전환·재연결·주사위 왕복에서 해제·중립 뒤 입력을 반환하며 게임 대화·취소·주사위·예약/해제로 중복 전달하지 않아야 한다.
8. [현재 예약·입력 12단계](ISSUE-4-RESERVATION-TOGGLE.md#windows-확인표)를 따른다. [기존 전체 회귀표](ISSUE-4-WINDOWS-VALIDATION.md)의 제거된 검색·자판·접기·상세 예약 버튼·패드 열기 없음·취소 없음 항목은 당시 버전의 기록으로 구분한다.

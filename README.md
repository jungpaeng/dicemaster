# DiceMaster

활협전의 선택지 결과를 미리 확인하고 주사위 판정값을 지정하는 모드입니다. 기존 DiceMaster를 기반으로 한국어 표시와 Windows Xbox/XInput 조작을 보완했습니다.

- 선택지 옆에서 효과 요약을 보고, 로그 창에서 전체 설명과 조건·이벤트·미션 정보를 읽습니다.
- 로그를 마우스·키보드·터치·패드로 탐색하고 이벤트·미션을 일회 예약하거나 해제합니다.
- 주사위 값을 직접 입력하거나 패드로 조정합니다. 음수 지정과 자동 굴림 복귀를 지원합니다.

## 설치와 업데이트

### 처음 설치

1. 게임을 종료하고 활협전용 모드 베이스가 설치되어 있는지 확인합니다.
2. 위 다운로드 또는 [Releases](https://github.com/jungpaeng/dicemaster/releases)의 **Assets**에서 `DiceMaster-vX.Y.Z.zip`을 받습니다. GitHub의 자동 `Source code` 압축 파일은 설치용이 아닙니다.
3. ZIP의 `config`·`plugins` 폴더를 게임의 기존 `BepInEx` 아래에 넣습니다.

```text
게임 설치 폴더/
└── BepInEx/
    ├── config/
    │   └── DiceMaster.cfg
    └── plugins/
        └── DiceMaster/
            └── DiceMaster.dll
```

### 설정을 유지하며 업데이트

게임 종료 후 현재 DLL과 cfg를 백업하고, ZIP의 **`plugins/DiceMaster/DiceMaster.dll`만 교체**합니다. 기존 cfg를 통째로 덮어쓰면 단축키·창 배치·글자 설정이 초기화될 수 있습니다. 새 설정은 실행 시 기존 cfg에 추가되며 버전별 추가 조치는 Release에 안내합니다. **alpha.11에서 이미 저장된 `EnableSwitchSelectionPopup=true`는 새 DLL만 교체해도 ON으로 유지됩니다.** OFF를 원하면 조건 탭 상단에서 변경하세요.

문제가 생기면 게임 종료 후 백업 DLL과 필요한 cfg를 복원하세요. DLL 복원으로 이미 진행하거나 저장한 게임 상태가 되돌아가지는 않습니다. v1.0.2에는 자동 갱신 뒤 선택지 결과가 사라지는 알려진 문제가 있으므로 복구 대상 버전의 Release도 확인하세요.

## 조작 방법

### 로그 창

기본 **Tab** 또는 설정한 `LogMenuToggleKey`로 열고 닫습니다. 패드에서는 **같은 패드의 L3와 R3 클릭이 겹치면** 열립니다. L3/R3는 양쪽 스틱을 아래로 누르는 버튼입니다. 순서·시간 제한 없이 누른 채 다른 쪽을 추가하면 됩니다. 열린 뒤 버튼을 놓고 스틱·트리거를 중립으로 돌린 다음 조작하세요.

| 입력 | 동작 |
| --- | --- |
| LB / RB | 탭 이동 |
| 십자키·왼쪽 스틱·키보드 ↑↓ | 목록 선택. 선택지 탭에서는 본문 스크롤 |
| 오른쪽 스틱 | 선택한 상세 설명 스크롤. 선택이 없으면 목록 스크롤 |
| 새 A / Enter / Space | 선택한 이벤트·미션 예약 또는 해제. 선택이 없으면 첫 항목 선택만 수행 |
| 마우스·터치 | 항목 선택. 선택된 이벤트·미션 행을 다시 누르고 같은 행에서 떼면 예약·해제 |
| X / Y | 새로고침 / 도구 |
| B / Escape | 닫기. 도구에서는 목록으로 복귀 |

선택지는 전체 내용을 읽는 화면이고 조건은 목록과 분기 설명으로 구성됩니다. 이벤트·미션의 상세는 읽기 전용이며 별도 진입이나 버튼 선택이 필요하지 않습니다. 예약된 행에는 **`(예약 중)`**이 표시됩니다. 예약은 다음 해당 판정·검사에 적용하며 즉시 발생·즉시 실행을 보장하지 않습니다. 해제해도 이미 소비된 예약이나 진행된 결과는 되돌리지 않습니다.

창 안의 드래그 가능한 영역을 끌어 위치를 바꿀 수 있습니다. 도구에서 크기·글자 크기를 조정하거나 **창 위치·크기·글자 기본값 복구**를 선택하세요. 기본값은 1920×1200에서 872×960px·본문 20px이며 다른 해상도에 비례해 계산합니다. 사용자 지정값은 보존합니다.

### 주사위 조정

주사위 창에 숫자를 직접 입력하거나 다음 패드 조작을 사용합니다. 게임 창에 초점이 있고 주사위 창이 활성화되어 있어야 합니다.

| 입력 | 동작 |
| --- | --- |
| LB + 십자키·왼쪽 스틱 ← / → | −1 / +1 |
| LB + 십자키·왼쪽 스틱 ↓ / ↑ | −10 / +10 |
| LB + B | 자동 굴림 값인 0으로 복귀 |
| LB 놓기 | 조정 종료, 지정값 유지 |

**0은 게임의 원래 주사위 굴림에 맡기는 값**입니다. 음수와 일반적인 게임 상한을 넘는 값도 지정할 수 있습니다. 방향 입력을 유지하면 반복 조정하며, 주사위 창을 다시 열면 0으로 초기화됩니다. 주사위 조정 중 A·X는 기존 게임 동작을 유지합니다.

## 설정

`BepInEx/config/DiceMaster.cfg`의 **`[DiceMaster]`** 섹션을 사용합니다. 파일에서 설정을 바꿀 때는 게임을 종료하고 수정한 뒤 다시 실행하세요. 로그 도구에서 변경한 창 위치·크기·글자는 바로 반영되고 저장됩니다. 선택·스크롤은 재시작 후 복원하지 않습니다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `EnableDiceController` | `true` | 주사위 수치 지정 |
| `EnableGamepadAdjustment` | `true` | 패드 주사위 조정. 위 설정도 켜져 있어야 함 |
| `EnableOptionInfo` | `true` | 선택지 효과 요약과 로그 정보 |
| `LogMenuToggleKey` | `Tab` | 로그 열기·닫기 키 |
| `EnableGamepadLogOpen` | `true` | L3/R3 겹침으로 로그 열기 |
| `LogWindowX` / `LogWindowY` | `20` / `20` | 창 위치 |
| `LogWindowWidth` / `LogWindowHeight` | `872` / `960` | 기준 해상도의 기본 창 크기 |
| `LogFontSize` | `20` | 기준 해상도의 기본 글자 크기 |

**패드 열기가 켜져 있고 게임 창에 초점이 있으며 로그가 닫혀 있을 때는 단독 L3/R3 클릭도 게임으로 보내지 않습니다.** 원래 스틱 클릭 기능이 필요하면 `EnableGamepadLogOpen=false`로 바꾸세요. 패드 열기와 주사위 조정 옵션은 서로 독립적입니다.

## 표시 읽기와 문제 해결

선택지 옆 요약은 50자까지 표시하며 전체 설명은 로그에서 읽을 수 있습니다. `가능한 변화`·`이후 가능한 변화`는 불확실한 효과를 구분하고, `추가 영향 가능`·`결과는 진행 후 확인`은 해석하지 못한 부분이 있음을 알립니다. 분석 범위 밖의 효과나 실제 미래 판정을 모두 예측하지는 않습니다. [분석 지원 범위](docs/ISSUE-2-STABLE-RELEASE.md#지원-범위)

| 표시 | 의미 |
| --- | --- |
| `읽음` / `미독` | 연결된 대표 이야기의 열람 기록. 조건 충족이나 실제 이벤트 발생 여부와는 별개 |
| `읽음 정보 없음` | 이야기 연결이나 열람 정보를 얻지 못한 상태. 미독으로 확정하지 않음 |
| `게임 데이터 대기 중` | 현재 문맥의 게임 데이터가 아직 준비되지 않음 |
| `읽기 실패` | 첫 조회가 실패해 정상적으로 표시할 값이 없음 |
| `갱신 실패 · 이전 값` | 마지막 정상 값을 표시 중이며 현재 게임 상태와 다를 수 있음 |

- **창이 작거나 배치가 맞지 않을 때:** cfg를 반복 교체하기보다 도구의 기본값 복구를 먼저 사용하세요. 기존 사용자 지정 배치가 유지되고 있을 수 있습니다.
- **Tab으로 연 뒤 첫 패드 입력이 먹지 않을 때:** 입력 모드 전환과 관련된 알려진 경로입니다. 패드의 L3/R3 겹침으로 열어 보세요.
- **로드 뒤 데이터 대기가 계속될 때:** 다음 이야기/Lua 로딩까지 기다릴 수 있습니다. 준비된 문맥에서는 X 또는 도구의 새로고침을 사용합니다.
- **실패·이전 값 상태에서 예약이 안 될 때:** 최신 대상을 확인할 수 있을 때만 예약을 변경합니다. 회복한 정보를 확인하고 새 입력으로 조작하세요.

표시용 난수·색상·확률은 게임의 다음 실제 결과를 보장하지 않습니다. Steam Input 구성·다른 모드와의 조합, 성능은 환경에 따라 달라질 수 있습니다. [입력 지원 범위](docs/GAMEPAD.md) · [읽음·상태 문구 설명](docs/ISSUE-4-STATUS-LABELS.md)

## 시험판의 조건·이벤트 선택

**v1.0.6-alpha.14 게시를 준비 중**입니다. 선택 팝업에서 큰 로그를 열고 닫을 수 있으며, 조건 분기 팝업에는 실제 조건과 미충족 회색 구분을 추가합니다. 조건 목록은 체크포인트당 한 행과 상세 분기 예약을 유지합니다. 이 DLL의 실제 Windows·장치 확인은 [검증표](docs/ISSUE-5-WINDOWS-VALIDATION.md#alpha14-팝업로그-포커스조건-표시-확인표)에서 대기합니다.

### 예약과 설정

조건 목록은 **체크포인트마다 한 행**을 표시합니다. 체크포인트를 고르면 상세에서 **분기 1·분기 2·그 외**의 조건을 모두 읽고 예약할 분기를 선택합니다. 분기 내부의 여러 조건과 분기 우선순위 안내는 각 설명 블록에 유지합니다. 이벤트 탭은 전체 이벤트 목록을 가능한 항목 우선으로 정렬합니다. 이벤트 검색창·발동 가능한 항목만 보기와 관련 도구는 제공하지 않습니다.

조건 상세에서 처음 클릭·터치는 분기를 선택하고, **선택한 분기를 다시 누르고 같은 곳에서 떼면 예약·해제**합니다. 키보드·패드는 체크포인트 선택 후 → 또는 A/Enter로 상세에 들어가고 ↑↓로 분기를 고른 뒤 새 A/Enter로 예약·해제합니다. 상세 진입만으로 예약하지 않으며 ← 또는 B/Esc로 체크포인트 목록으로 돌아옵니다. 목록의 체크포인트 행을 다시 눌러도 예약하지 않습니다.

이벤트·미션은 첫 클릭·터치로 행을 선택하고, 선택된 행을 다시 누르고 같은 행에서 떼면 예약·해제합니다. 키보드 ↑↓·패드로 항목을 선택한 뒤 A/Enter로도 조작합니다. 아무 항목도 선택하지 않았다면 확인 입력은 첫 항목을 고르기만 합니다. 예약한 조건 분기와 해당 체크포인트, 이벤트·미션 행에는 **`(예약 중)`**이 표시됩니다. 조건과 이벤트는 서로 독립적으로 하나씩 예약하며, 같은 탭의 다른 항목을 예약하면 이전 예약을 교체합니다. 읽기 실패·이전 값 상태이거나 실제 대상·결과를 확인할 수 없는 항목은 예약할 수 없습니다.

예약은 **다음 해당 체크포인트 판정에서 결과를 한 번 지정**합니다. 현재 조건 충족 여부와 난수·가중치에 맡기지 않고 고른 결과로 진행하며 능력치·호감도·조건 데이터를 미리 바꾸지 않습니다. Switch는 자체 실행 횟수만 한 번 증가합니다. 즉시 이벤트를 발생시키거나 멈춘 행동을 재개하는 기능은 아니므로 큰 로그를 닫고 게임을 진행해야 할 수 있습니다. 대상·결과·Switch 횟수 등이 달라졌다면 예약을 폐기합니다. 팝업 진입 전에 발견하면 해당 팝업 설정을 따르고, 실제 실행 경계에서 발견하면 원래 판정으로 진행합니다.

유효한 예약은 해당 팝업의 ON/OFF보다 우선합니다. 팝업 대기 중 큰 로그에서 같은 판정을 예약했다면 그 Lua 흐름이 재개될 때 예약을 적용합니다. 예약이 없을 때에는 아래 팝업 설정을 따릅니다. 예약은 일반적인 이야기/Lua 교체에도 유지하지만 로드·새 게임 등 실행 전환에서 해제되며 cfg·세이브에 저장하지 않습니다. 상위 `EnableOptionInfo`가 꺼져 있으면 예약을 적용하지 않습니다. 해제는 이미 소비된 결과나 진행한 게임 상태를 되돌리지 않습니다.

조건·이벤트 탭 상단과 도구에서 각 선택 팝업을 따로 켜고 끄며 변경값은 저장됩니다. 빈 목록에서도 버튼을 사용할 수 있습니다. 목록 맨 위에서 ↑로 설정에 이동하고 A/Enter로 변경하며 ↓로 목록으로 돌아옵니다. 클릭·터치도 지원합니다.

| 시험판의 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `EnableEventSelectionPopup` | `true` | 지원하는 이벤트 판정의 선택 팝업 |
| `EnableSwitchSelectionPopup` | `false` | 지원하는 대화 중 조건 분기의 선택 팝업 |

기존 cfg의 저장값은 보존합니다. **alpha.11에서 이미 저장된 `EnableSwitchSelectionPopup=true`는 자동으로 OFF로 바뀌지 않습니다.** 원하는 경우 조건 탭 상단에서 OFF로 바꾸세요. 새 cfg 또는 해당 키가 없는 cfg에만 새 기본값 `false`를 적용합니다. 두 팝업과 예약 모두 `EnableOptionInfo`가 켜져 있어야 합니다. 예약이 없을 때 설정 OFF는 해당 팝업의 미확정 대기를 해제하고 원래 판정으로 진행합니다. 큰 로그가 열려 있다면 원래 판정의 실행도 로그를 닫을 때까지 기다립니다.

### 선택 팝업의 조작과 지원 범위

팝업 상단의 **로그 열기**를 클릭·터치하거나 기존 `LogMenuToggleKey`(기본 Tab)를 눌러 큰 로그를 엽니다. `EnableGamepadLogOpen=true`이면 팝업 대기 중에도 같은 패드의 **L3/R3 클릭 겹침**으로 열 수 있습니다. 큰 로그가 열린 동안에는 로그만 입력을 받고 대기 중인 선택 판정·예약 소비·설정 OFF 후 원래 판정 실행은 로그를 닫을 때까지 기다립니다. 로그를 닫으면 유효한 팝업 선택·읽던 스크롤 위치로 돌아오고, 닫기에 쓴 B/Esc나 누른 채인 A는 진행에 재사용하지 않습니다. 버튼을 놓고 스틱·트리거를 중립으로 돌린 뒤 새로 조작하세요.

패드 열기를 끄려면 `EnableGamepadLogOpen=false`로 설정합니다. 이 옵션은 로그 열기 조합만 끄며, 열린 로그·대기 팝업의 입력 차단이나 패드 탐색까지 끄는 옵션은 아닙니다. 큰 로그를 여는 것만으로 원래 판정이나 다른 이벤트가 실행되지 않습니다.

팝업은 **처음 클릭·터치한 행을 선택하고, 선택된 행을 다시 눌렀다 같은 행에서 떼면 진행**합니다. ↑↓로 후보를 선택한 뒤 A/Enter/Shift+Enter로 확인할 수도 있습니다. 초기에는 미선택이며 확인키만으로 진행하지 않습니다. 하단은 안내 텍스트이며 실행 버튼은 없습니다. **B/Esc로 원래 게임 판정**을 요청합니다. 이벤트는 원래 추첨, 조건 분기는 원래 조건·난수 판정으로 한 번 진행합니다. 터치만으로 원래 판정에 맡기는 경로는 제공하지 않습니다.

정상 후보는 일반 진행, 미충족·가중치 0·난수/미지원 조건으로 판정 미확인인 후보는 **조건 무시하고 이번만 진행**으로 안내합니다. X는 확정하지 않습니다. 대상·결과를 읽을 수 없는 항목은 실행할 수 없고, 확정 전에 조건이 바뀌면 새로 표시된 진행 방식을 다시 확인해야 합니다.

이벤트 목록은 **굵은 제목·결과 요약의 두 줄**이며 발동 불가 후보의 제목은 회색으로 구분합니다. 조건 분기 목록은 여기에 **조건 요약 한 줄**을 더하고, 선택 상세에는 **전체 분기 조건을 예상 결과보다 먼저** 표시합니다. 긴 조건은 목록에서 줄이고 상세에서 모두 읽습니다. 조건 미충족이나 앞 분기 우선으로 선택되지 않는 분기의 제목·조건은 회색이며, 난수·미지원으로 판정하지 못한 분기는 미충족으로 표시하지 않습니다. 분기 우선순위·기본 분기·실행 횟수 비교 안내를 유지합니다.

요약·상세의 결과 효과색과 읽기 가능한 후보의 명시적인 조건 무시를 유지합니다. 전체 조건·결과는 휠·오른쪽 스틱으로 따로 읽고 ↑↓는 항목 이동입니다. 설명은 정적 분석 범위이며 후속 분기까지 모두 확정하지 않습니다. 회상·조건 설명에 내부 ID가 남을 수 있습니다.

지원하는 Switch 팝업은 비메인 Lua 코루틴에서 직접 문자열 리터럴로 호출하고, 결과를 지역 변수에 대입한 뒤 바로 정수 동등 비교 `if/elseif/else`로 분기하는 형식에 표시됩니다. 강릉 포위전의 **할 일 없이 그늘에서 쉰다** 뒤 대화를 진행해 도달하는 `Ch_3_6_4_002`가 한 예입니다. 선택할 분기가 둘 미만이거나 지원 밖 형식이면 팝업 없이 원래 판정으로 진행합니다. 이벤트 팝업도 지원하는 직접 리터럴 `Position` 호출에만 표시합니다.

**예약 소비는 실제 체크포인트 호출에서 처리**하므로 팝업이 지원하지 않는 Lua 형식·메인 Lua·직접 C# 호출에서도 일치하는 유효 예약이 있으면 적용됩니다. 이는 팝업의 지원 범위를 넓히거나 해당 Lua가 선택한 결과를 반드시 처리한다고 보장하는 것은 아닙니다. 직접 지정은 원래 조건·난수 소비를 건너뛰지만 선택한 결과 이후의 대사·효과는 게임이 실행합니다. 모든 후속 조건을 통과시키는 기능은 아닙니다.

## 오류 제보와 개발 문서

[Issues](https://github.com/jungpaeng/dicemaster/issues)에 사용 버전, 게임·BepInEx 버전, 재현 순서, 패드 종류·Steam Input 사용 여부와 관련 화면·`BepInEx/LogOutput.log`를 남겨 주세요. 가능하면 설치 DLL의 SHA-256과 문제가 난 탭·항목 ID도 적어 주세요. 전체 게임 소스·Lua·세이브는 기본 제보에 필요하지 않습니다.

전체 C# 소스 빌드를 사용합니다. Python 3와 `global.json`에 지정한 .NET SDK, 별도의 읽기 전용 게임·로더 참조를 준비한 뒤 실행합니다.

```sh
python3 build/build-source.py --references '<읽기 전용 참조 루트>'
```

DLL·설치 ZIP·검사 기록은 `artifacts/source-candidate/`에 생성됩니다. 게임 소스·게임 DLL을 저장소나 배포물에 추가하지 않습니다.

# DiceMaster

활협전의 선택지 결과를 미리 확인하고 주사위 판정값을 지정하는 모드입니다. 기존 DiceMaster를 기반으로 한국어 표시와 Windows Xbox/XInput 조작을 보완했습니다.

- 선택지 옆에서 효과 요약을 보고, 로그 창에서 전체 설명과 조건·이벤트·미션 정보를 읽습니다.
- 로그를 마우스·키보드·터치·패드로 탐색하고 조건 분기·이벤트·미션을 일회 예약하거나 해제합니다.
- 이벤트·조건 판정 직전 팝업에서 결과와 조건을 읽고, 이번 결과를 직접 고를 수 있습니다.
- 주사위 값을 직접 입력하거나 패드로 조정합니다. 음수 지정과 자동 굴림 복귀를 지원합니다.

**[정식 버전 다운로드](https://github.com/jungpaeng/dicemaster/releases/latest)** · [설치](#설치와-업데이트) · [조작](#조작-방법) · [변경 이력](CHANGELOG.md) · [오류 제보](https://github.com/jungpaeng/dicemaster/issues)

## 다운로드와 지원 환경

Windows용 활협전과 **BepInEx가 포함된 활협전용 모드 베이스**가 필요합니다. 패드 조작은 Xbox/XInput 기준이며 다른 패드와 Steam Input 구성은 환경에 따라 확인이 필요합니다. ZIP에는 DiceMaster DLL과 설정만 들어 있습니다.

현재 정식 버전은 **[v1.0.6](https://github.com/jungpaeng/dicemaster/releases/tag/v1.0.6)**입니다. **[DiceMaster-v1.0.6.zip](https://github.com/jungpaeng/dicemaster/releases/download/v1.0.6/DiceMaster-v1.0.6.zip)**을 설치하세요. 직전 정식 v1.0.5에 이벤트·조건 선택 팝업, 조건 상세의 분기 예약, 공통 조건 판정·한국어 표시와 클릭·터치 입력 수정을 더했습니다. [변경·파일 확인·검증 기록](docs/ISSUE-5-STABLE-RELEASE.md)

2026-10-21 사용자가 **“v1.0.6 Windows 확인을 완료했고 남은 문제가 없습니다.”**라고 확인했습니다. 이 포괄 확인을 PRD #6의 착수 근거로 기록하며 세부 장치·환경별 시험 결과를 추정하지 않습니다. 아래 기존 조작은 v1.0.6을 기준으로 유지하고, 새 정보 기능은 아래 별도 prerelease에서 제공합니다. [확인 범위](docs/ISSUE-5-STABLE-RELEASE.md#2026-10-21-사용자-windows-후속-확인)

## 정보 기능 시험판

alpha.20은 완료된 초회 진입 대사와 반복 대련 같은 고정 활동 반응이 일반 대화 툴팁에 남는 문제를 보완합니다. 안전하게 확인한 완료 항목을 제외하고 남은 초회 대화·열린 다른 주제는 유지합니다. [설계·범위·검증](docs/ISSUE-6-ENTRY-DIALOGUES.md).

현재 정보 기능 후보는 확인된 기회를 **작은 금색 두루마리**로 표시합니다. 당문 지도는 장소 상단 중앙의 핀과 짧은 연결선, 유학 등 실제 선택 메뉴는 버튼 모서리 배지입니다. 원래 패드·키보드 포커스 또는 마우스 호버 옆에 설명 하나를 띄우며 A/Enter/클릭/터치는 게임의 원래 동작입니다. 두루마리 문양은 요청한 Lucide scroll-text로 교체합니다. [alpha.17 변경·검증·Windows 확인](docs/ISSUE-6-ALPHA17-RELEASE.md).

배지는 **실제 등록된 대기 임무의 해당 선택 실행 연결** 또는 **증명 1회성·현재 조건·경로**를 모두 확인한 항목에 붙입니다. 일반 대화의 진행 가능/경로 설명은 유지하되 배지를 붙이지 않습니다. 유학의 선행 변경·불명 경로는 상세에서 확인하며 모든 유학 이벤트를 탐지하는 것은 아닙니다. 미선택 장소의 Lua를 새로 분석하지 않으므로 배지가 없어도 전체 기회 없음은 아닙니다. [alpha.15에서 확정한 표시 범위](docs/ISSUE-6-ALPHA15-RELEASE.md).

지도 조회 성능 개선 후보는 대기 임무를 먼저 읽고, **1회성 표시 OFF이면 자동 지도에서 Lua 준비를 생략**합니다. 일반 이야기의 숨은 경로 조건과 표시하지 않을 상세 행도 자동 주기에 만들지 않습니다. 로그 → 도구 → 지도 안내의 `지도 조회 성능`에서 최근 64회 시간과 지원되는 런타임의 할당량을 읽습니다. 전체 프레임 시간은 별도 Windows 측정이 필요합니다. [개선 범위·확인표](docs/ISSUE-6-ALPHA13-RELEASE.md).

지도 자동 안내는 **이번 클릭에 실행 가능한, 이미 등록된 대기 임무**와 **1회성 증명·현재 조건·경로를 각각 확인한 항목**을 최대 세 행으로 표시합니다. 행동력·장소 활성·임무 우선순위를 반영하고, 미등록 임무 단계와 일반 대화의 후속 예측은 **로그 → 도구 → 지도 안내**에서만 제공합니다. 상세 조회의 `진행 가능성 있음`을 지도에 자동으로 띄우지 않습니다. 지도에 표시가 없어도 게임 전체에 기회가 없다는 뜻은 아닙니다.

후속 경로의 모든 선택 단계가 해금된 것으로 확인될 때만 툴팁과 기본 상세 목록에 표시합니다. 잠김·해금 미확정 경로는 제외하며, 해금된 선택지 안의 미확정 이야기 분기는 `진행 가능성 있음`으로 구분합니다. 마커에도 같은 해금 확인을 추가하고 기존 대기 임무·1회성 증명·현재 도달 조건을 유지합니다. [구현·검증·한계](docs/ISSUE-6-CHOICE-UNLOCKS.md).

선택 화면에서는 게임이 실제로 만든 현재 메뉴의 활성 선택지를 출발점으로 대화와 필요한 선택 경로를 안내합니다. 비활성·숨김·다른 메뉴의 버튼은 제외합니다. 안전하게 확인한 불가 대화는 자동 툴팁에서 제외합니다. 선택지 해금 미확정은 경로 표시에서 제외하고, 해금이 확인된 선택지 내부의 이야기 조건이 미확정일 때 `진행 가능성 있음`으로 구분합니다. 실제 후속 이야기 발생을 보장하지 않습니다.

준비가 끝나고 자동 안내할 항목이 없으면 지도 패널을 숨깁니다. 전체 임무 정의 색인은 상세 조회에서만 진행하며 빈 장소의 확인 중 문구를 유지시키지 않습니다. 자동 갱신에서는 후속 인물 대화의 조건과 미등록 임무 단계를 읽지 않습니다. 경로·효과의 실제 준비, 분석 제한·읽기 실패·게임 데이터 대기는 상세에서 구분합니다.

상세 조회에서는 개별 이야기와 반복 활동의 고정 반응을 구분하고, 제한된 `현재 필수 조건 표본`으로 원본 조건 키·현재 플래그 값·난수 미추첨·선행 변경 사유를 읽을 수 있습니다. 특정 인물·플래그 예외 목록을 사용하지 않으며 게임 판정·RNG·세이브·능력치·아이템을 변경하지 않습니다. [설계·검사 경계](docs/ISSUE-6-INDEPENDENT-PREPARATION.md).

| 기능 | 게임 화면 | 로그 도구의 상세 |
| --- | --- | --- |
| 지도 안내 | 확인된 기회에 금색 핀·현재 항목 옆 이름/종류/상태 | 미등록 단계·후속 대화 후보·전체 조건·경로·우선순위·현재 입력 표본 |
| 선택 화면 안내 | 대기 임무·증명 1회성의 현재 기회에 금색 배지·일반 대화는 포커스 옆 경로 설명 | 해금 확인 경로·현재 판정·불확실한 사유. 후속 발생 보장은 아님 |
| 1회성 | 안전하게 증명한 항목에만 표식. 지도 자동 안내는 현재 도달 가능성도 필요 | 증명 근거와 현재 조건·경로를 별도로 조회 |
| 실제 분기 | 우측 상단 실제 결과 최신 1건, 5초 | 실행 중 메모리에 최신순 최대 20건과 연결 가능한 조건·효과 |
| 상점 효과 | 짧은 사용 효과 또는 책/비급의 현재·만렙 수치와 성장 방향 | 다음 단계 효과·학습 조건·소모·필요 학습점과 해석 한계 |

정확한 양성 상태의 문구는 초록색이며, 미확정·불가·갱신 실패의 이전 값은 중립색입니다. 1회성 표식은 미독·영구 유일·이번에 반드시 발생한다는 뜻이 아닙니다.

**Tab 또는 L3/R3 겹침 → 버튼 해제·스틱 중립 → Y 도구 → 지도 안내 / 분기 기록 / 상점 효과 조회**로 상세를 읽습니다. ↑↓·왼쪽 스틱은 항목, 오른쪽 스틱은 상세, B/Esc는 복귀, LB/RB는 기존 네 탭입니다. 새 단축키·호버 의존성은 없으며 조회로 예약·선택·구매·사용·학습을 실행하지 않습니다.

네 영구 설정은 기본 ON이며 상위 `EnableOptionInfo`는 시작 시 적용합니다. `EnableMapGuide`가 지도·선택 경로를 함께 제어합니다. 기존 OFF 처리·분기 기록 초기화·정상 0.25초/실패 5초·숨김/OFF 조회 중단·warm Lua 재분석 없음 계약을 유지합니다. [설정](#설정) · [패드](docs/GAMEPAD.md).

이전 공개 후보는 [alpha.11](https://github.com/jungpaeng/dicemaster/releases/tag/v1.0.7-alpha.11), 최신 정식은 v1.0.6입니다. [변경 이력](CHANGELOG.md)과 [Windows 확인표](docs/ISSUE-6-WINDOWS-VALIDATION.md)에서 각 후보의 근거를 구분합니다.

## 설치와 업데이트

### 처음 설치

1. 게임을 종료하고 활협전용 모드 베이스가 설치되어 있는지 확인합니다.
2. 위 다운로드 또는 [Releases](https://github.com/jungpaeng/dicemaster/releases)의 **Assets**에서 `DiceMaster-vX.Y.Z.zip`을 받습니다. GitHub의 자동 `Source code` 압축 파일은 설치용이 아닙니다.
3. ZIP의 `config`·`plugins` 폴더를 게임의 기존 `BepInEx` 아래에 넣습니다.

```text
게임 설치 폴더/
└── BepInEx/
    ├── config/
    │   └── DiceMaster.cfg
    └── plugins/
        └── DiceMaster/
            └── DiceMaster.dll
```

### 설정을 유지하며 업데이트

게임 종료 후 현재 DLL과 cfg를 백업하고, ZIP의 **`plugins/DiceMaster/DiceMaster.dll`만 교체**합니다. 기존 cfg를 통째로 덮어쓰면 단축키·창 배치·글자 설정이 초기화될 수 있습니다. 새 설정은 실행 시 기존 cfg에 추가되며 버전별 추가 조치는 Release에 안내합니다. **조건 팝업의 새 기본값은 OFF지만 기존 cfg에 저장된 ON은 유지됩니다.** OFF를 원하면 조건 탭 상단에서 변경하세요.

문제가 생기면 게임 종료 후 백업 DLL과 필요한 cfg를 복원하세요. DLL 복원으로 이미 진행하거나 저장한 게임 상태가 되돌아가지는 않습니다. v1.0.2에는 자동 갱신 뒤 선택지 결과가 사라지는 알려진 문제가 있으므로 복구 대상 버전의 Release도 확인하세요.

## 조작 방법

### 로그 창

기본 **Tab** 또는 설정한 `LogMenuToggleKey`로 열고 닫습니다. 패드에서는 **같은 패드의 L3와 R3 클릭이 겹치면** 열립니다. L3/R3는 양쪽 스틱을 아래로 누르는 버튼입니다. 순서·시간 제한 없이 누른 채 다른 쪽을 추가하면 됩니다. 열린 뒤 버튼을 놓고 스틱·트리거를 중립으로 돌린 다음 조작하세요.

| 입력 | 동작 |
| --- | --- |
| LB / RB | 탭 이동 |
| 십자키·왼쪽 스틱·키보드 ↑↓ | 목록 선택. 선택지 탭에서는 본문 스크롤 |
| 오른쪽 스틱 | 선택한 상세 설명 스크롤. 선택이 없으면 목록 스크롤 |
| 새 A / Enter / Space | 이벤트·미션 예약·해제. 조건은 선택한 체크포인트의 상세로 이동 |
| 마우스·터치 | 항목 선택. 선택된 이벤트·미션 행을 다시 누르고 같은 행에서 떼면 예약·해제 |
| X / Y | 새로고침 / 도구 |
| B / Escape | 닫기. 도구에서는 목록으로 복귀 |

선택지는 전체 내용을 읽는 화면이고 조건은 체크포인트 목록과 분기 상세로 구성됩니다. 이벤트·미션의 상세는 읽기 전용이며 별도 진입이나 버튼 선택이 필요하지 않습니다. 조건 예약은 아래의 상세 조작을 따릅니다. 도구를 열면 도구만 선택 표시하며 터치 뒤 패드로 돌아와도 현재 화면·선택·읽던 위치를 유지합니다.

창 안의 드래그 가능한 영역을 끌어 위치를 바꿀 수 있습니다. 도구에서 크기·글자 크기를 조정하거나 **창 위치·크기·글자 기본값 복구**를 선택하세요. 기본값은 1920×1200에서 872×960px·본문 20px이며 다른 해상도에 비례해 계산합니다. 사용자 지정값은 보존합니다.

### 조건·이벤트 예약

조건 목록은 **체크포인트마다 한 행**입니다. 체크포인트를 고르면 상세에서 **분기 1·분기 2·그 외**의 전체 조건과 우선순위를 읽고 예약할 분기를 선택합니다. 이벤트 탭은 전체 목록을 가능한 항목 우선으로 정렬하며 검색창·발동 가능한 항목만 보기 기능은 제공하지 않습니다.

| 입력 | 조건 상세 조작 |
| --- | --- |
| 체크포인트 선택 후 → / A / Enter | 상세로 이동. 진입만으로 예약하지 않음 |
| 상세의 ↑↓ | 분기 선택 |
| 선택한 분기의 새 A / Enter | 예약·해제 |
| 클릭·터치 | 처음은 분기 선택, 같은 분기를 다시 누르고 같은 곳에서 떼면 예약·해제 |
| ← / B / Escape | 체크포인트 목록으로 복귀 |

체크포인트 목록 행을 다시 눌러도 예약하지 않습니다. 이벤트·미션은 첫 클릭·터치로 행을 고르고 같은 행을 다시 누르고 떼면 예약·해제합니다. 선택한 이벤트·미션에 새 A/Enter/Space도 사용할 수 있으며 선택이 없으면 첫 항목만 고릅니다. 예약된 분기·체크포인트·이벤트·미션에는 **`(예약 중)`**이 표시됩니다. 조건과 이벤트는 각각 하나씩 독립적으로 예약하고 같은 탭의 다른 예약은 이전 것을 교체합니다. 읽기 실패·이전 값이거나 실제 대상·결과를 확인할 수 없는 항목은 예약할 수 없습니다.

조건·이벤트 예약은 **다음 해당 체크포인트 판정에서 고른 결과를 한 번 지정**합니다. 현재 조건·가중치·난수에 맡기지 않고 고른 결과로 진행하며 능력치·호감도·조건 데이터를 미리 바꾸지 않습니다. Switch 자체 실행 횟수는 한 번 증가합니다. 즉시 이벤트 발생이나 멈춘 행동의 재개는 보장하지 않으므로 로그를 닫고 게임을 진행해야 할 수 있습니다. 대상·결과·Switch 횟수 등이 달라지면 예약을 폐기합니다. 팝업 진입 전에 발견하면 해당 팝업 설정을 따르고 실제 실행 경계에서 발견하면 원래 판정으로 진행합니다.

유효한 예약은 팝업 ON/OFF보다 우선합니다. 팝업 대기 중 로그에서 같은 판정을 예약했다면 Lua 흐름이 재개될 때 적용합니다. 일반 이야기/Lua 교체에는 유지하지만 로드·새 게임 등 실행 전환에서 해제하며 cfg·세이브에 저장하지 않습니다. `EnableOptionInfo=false`이면 적용하지 않습니다. 예약 해제는 이미 소비된 결과나 진행한 게임 상태를 되돌리지 않습니다.

### 선택 팝업

조건·이벤트 탭 상단과 도구에서 각 선택 팝업을 따로 켜고 끕니다. 빈 목록에서도 사용할 수 있고 변경값은 저장됩니다. 클릭·터치하거나 목록 맨 위에서 ↑로 설정에 이동해 A/Enter로 변경하고 ↓로 목록에 돌아옵니다. **조건 팝업은 기본 OFF, 이벤트 팝업은 기본 ON**이며 기존 cfg의 저장값은 보존합니다. 두 팝업은 `EnableOptionInfo`가 켜져 있어야 합니다.

팝업은 **처음 클릭·터치한 행을 선택하고, 선택된 행을 다시 눌렀다 같은 행에서 떼면 진행**합니다. ↑↓·왼쪽 스틱으로 후보를 고른 뒤 A/Enter/Shift+Enter로 확인할 수도 있습니다. 초기에는 미선택이며 확인키만으로 진행하지 않습니다. 정상 후보는 일반 진행, 읽기 가능한 미충족·가중치 0·판정 미확인 후보는 **조건 무시하고 이번만 진행**입니다. X로 확정하지 않으며 대상·결과 읽기 실패는 실행을 막습니다. 확정 전에 진행 방식이 바뀌면 새 상태를 보고 다시 확인해야 합니다.

**B/Esc는 원래 게임 판정으로 한 번 진행**합니다. 이벤트는 원래 추첨, 조건 분기는 원래 조건·난수 판정을 사용합니다. 하단은 텍스트 안내이며 실행 버튼과 별도 무작위 목록 항목은 없습니다. 터치만으로 원래 판정을 요청하는 경로는 제공하지 않습니다. 예약이 없을 때 설정 OFF는 해당 팝업의 미확정 대기를 해제하고 원래 판정으로 진행합니다.

팝업 중에도 **`LogMenuToggleKey`(기본 Tab)** 또는 옵션이 켜진 **같은 패드의 L3/R3 클릭 겹침**으로 큰 로그를 엽니다. 팝업 안에 로그 열기 버튼은 없습니다. 로그가 열린 동안 로그만 입력을 받고 팝업 Lua 흐름·같은 판정의 예약 소비·설정 OFF 뒤 원래 판정은 로그를 닫을 때까지 기다립니다. 닫으면 유효한 팝업 선택·스크롤을 복원하며 닫기 B/Esc나 누른 채인 A를 진행에 재사용하지 않습니다. 버튼 해제·스틱/트리거 중립 뒤 새 입력을 사용하세요.

지원하는 이벤트 팝업은 직접 문자열 리터럴 `Position` 호출을 사용하는 비메인 Lua 코루틴에 표시합니다. 조건 팝업은 직접 리터럴 `Switch` 결과를 지역 변수에 대입한 뒤 바로 정수 동등 비교 `if/elseif/else`로 분기하는 형식입니다. 강릉 포위전에서 **할 일 없이 그늘에서 쉰다** 뒤 대화를 진행해 도달하는 `Ch_3_6_4_002`가 한 예입니다. 조건 분기가 둘 미만이거나 지원 밖 형식이면 팝업 없이 원래 판정으로 진행합니다.

예약은 실제 체크포인트 호출에서 소비하므로 팝업이 지원하지 않는 Lua 형식·메인 Lua·직접 C# 호출에서도 일치하는 유효 예약을 적용할 수 있습니다. 해당 Lua가 고른 결과를 반드시 처리하거나 모든 후속 조건을 통과한다고 보장하지는 않습니다. 직접 지정은 원래 조건·난수를 건너뛰며 선택한 결과 이후 대사·효과·내부 분기는 게임이 실행합니다. [지원·검증 범위](docs/ISSUE-5-STABLE-RELEASE.md)

### 주사위 조정

주사위 창에 숫자를 직접 입력하거나 다음 패드 조작을 사용합니다. 게임 창에 초점이 있고 주사위 창이 활성화되어 있어야 합니다.

| 입력 | 동작 |
| --- | --- |
| LB + 십자키·왼쪽 스틱 ← / → | −1 / +1 |
| LB + 십자키·왼쪽 스틱 ↓ / ↑ | −10 / +10 |
| LB + B | 자동 굴림 값인 0으로 복귀 |
| LB 놓기 | 조정 종료, 지정값 유지 |

**0은 게임의 원래 주사위 굴림에 맡기는 값**입니다. 음수와 일반적인 게임 상한을 넘는 값도 지정할 수 있습니다. 방향 입력을 유지하면 반복 조정하며, 주사위 창을 다시 열면 0으로 초기화됩니다. 주사위 조정 중 A·X는 기존 게임 동작을 유지합니다.

## 설정

`BepInEx/config/DiceMaster.cfg`의 **`[DiceMaster]`** 섹션을 사용합니다. 파일에서 설정을 바꿀 때는 게임을 종료하고 수정한 뒤 다시 실행하세요. 로그 도구에서 변경한 창 위치·크기·글자는 바로 반영되고 저장됩니다. 선택·스크롤은 재시작 후 복원하지 않습니다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `EnableDiceController` | `true` | 주사위 수치 지정 |
| `EnableGamepadAdjustment` | `true` | 패드 주사위 조정. 위 설정도 켜져 있어야 함 |
| `EnableOptionInfo` | `true` | 선택지 효과·로그·예약·팝업과 후보의 네 정보 기능 상위 옵션. 시작 시 적용 |
| `EnableEventSelectionPopup` | `true` | 지원하는 이벤트 판정의 선택 팝업 |
| `EnableSwitchSelectionPopup` | `false` | 지원하는 대화 중 조건 분기의 선택 팝업 |
| `EnableMapGuide` | `true` | 지도에는 실행 가능한 대기 임무·도달 가능성이 확인된 1회성만 최대 세 항목. 선택 화면 경로·지도 로그 상세·현재 필수 조건 표본도 제어 |
| `EnableOneShotHints` | `true` | 증명한 항목만 1회성 표식. OFF이면 자동 지도의 Lua 경로 준비도 생략. 미확인·실패 사유는 상세 |
| `EnableBranchNotices` | `true` | 실제 분기 알림과 메모리 기록 |
| `EnableShopEffectInfo` | `true` | 상점의 짧은 효과 요약. 학습 조건·소모·학습점은 상세, OFF 때 원래 설명 복원 |
| `LogMenuToggleKey` | `Tab` | 로그 열기·닫기 키 |
| `EnableGamepadLogOpen` | `true` | L3/R3 겹침으로 로그 열기 |
| `LogWindowX` / `LogWindowY` | `20` / `20` | 창 위치 |
| `LogWindowWidth` / `LogWindowHeight` | `872` / `960` | 기준 해상도의 기본 창 크기 |
| `LogFontSize` | `20` | 기준 해상도의 기본 글자 크기 |

후보의 네 개별 설정은 `[DiceMaster]`에 기본 ON으로 추가되며 로그 도구에서 각각 즉시 변경·저장합니다. 다른 개별 값·기존 cfg·단축키·배치는 유지합니다. OFF는 해당 표시·수집·스냅샷을 정리하고 분기는 기록까지 지웁니다. ON은 현재 유효 문맥부터 읽으며 지난 알림을 재생하지 않습니다. `EnableOptionInfo=false`로 시작하면 네 저장값을 바꾸지 않고 모두 비활성화합니다. 상위 옵션을 바꾼 뒤에는 기존 규칙대로 재시작하세요. 개별 설정 읽기 실패는 해당 기능만 비활성화하며 최초 키 누락의 기본 ON과 구분합니다.

**패드 열기가 켜져 있고 게임 창에 초점이 있으며 로그가 닫혀 있을 때는 단독 L3/R3 클릭도 게임으로 보내지 않습니다.** 원래 스틱 클릭 기능이 필요하면 `EnableGamepadLogOpen=false`로 바꾸세요. 패드 열기와 주사위 조정 옵션은 서로 독립적입니다.

## 표시 읽기와 문제 해결

선택지 옆 요약은 50자까지 표시하며 전체 설명은 로그에서 읽을 수 있습니다. `가능한 변화`·`이후 가능한 변화`는 불확실한 효과를 구분하고, `추가 영향 가능`·`결과는 진행 후 확인`은 해석하지 못한 부분이 있음을 알립니다. 분석 범위 밖의 효과나 실제 미래 판정을 모두 예측하지는 않습니다. [분석 지원 범위](docs/ISSUE-2-STABLE-RELEASE.md#지원-범위)

로그 이벤트의 제목·상세 조건과 조건 상세의 개별 분기는 팝업과 같은 판정으로 표시합니다. 조건 목록의 체크포인트 자체와 결과 효과색은 유지합니다. 기준은 과거 실행 당시가 아닌 **마지막 정상 조회 시점의 현재 상태**이며 조건 횟수 분기는 다음 실행 횟수로 판단합니다. 로그가 열린 현재 탭은 약 0.25초마다 갱신합니다. 조회 대기·갱신 실패·게시 실패 때 이전 회색을 현재 미충족처럼 표시하지 않습니다.

조건·이벤트 팝업은 **굵은 제목·결과 요약·조건 요약의 고정 세 줄**입니다. 상세는 필요한 짧은 판정 이유 → 전체 조건 → 예상 결과 순서로 읽고 같은 조건식을 중복 표시하지 않습니다. 긴 전체 조건·결과는 휠·오른쪽 스틱으로 따로 읽으며 ↑↓는 후보 이동입니다.

| 판정 표시 | 의미 |
| --- | --- |
| 기본색 | 현재 확인된 일반 진행. 정상 상태 문구는 생략 |
| 회색 제목·조건 | 미충족·최종 가중치 0·앞 분기 우선이 확인됨. 읽기 가능한 결과는 명시 조건 무시·예약 가능 |
| `?`와 이유, 기본색 | 난수·미지원 계산·앞 분기 미확정. 미충족으로 단정하지 않음 |
| `!`와 이유 | 실제 대상·결과 또는 판정 자료를 확인하지 못함. 팝업 실행 차단 |

이벤트는 활성 조건 전체·기본/증감/최종 가중치를, 조건 분기는 앞 분기 우선순위·기본 분기·이번 실행 횟수 비교를 보여줍니다. 가중치는 확률 `%`가 아닙니다. 난수는 **범위·식·미확정**으로 표시하고 조회만으로 RNG·실행 횟수를 진행시키지 않습니다. 이름·날짜·결과에 기존 한국어 번역을 연결하지만 번역 자료가 없는 이름과 식별용 내부 ID는 남을 수 있습니다. 설명 형식화 실패만으로 이미 확인한 실행 자격을 바꾸지 않습니다. [조건·요약 기준](docs/ISSUE-5-POPUP-CONDITION-PARITY.md) · [로그 판정 기준](docs/ISSUE-5-LOG-JUDGMENT-DISPLAY.md)

| 표시 | 의미 |
| --- | --- |
| `읽음` / `미독` | 연결된 대표 이야기의 열람 기록. 조건 충족이나 실제 이벤트 발생 여부와는 별개 |
| `읽음 정보 없음` | 이야기 연결이나 열람 정보를 얻지 못한 상태. 미독으로 확정하지 않음 |
| `게임 데이터 대기 중` | 현재 문맥의 게임 데이터가 아직 준비되지 않음 |
| `읽기 실패` | 첫 조회가 실패해 정상적으로 표시할 값이 없음 |
| `갱신 실패 · 이전 값` | 마지막 정상 값을 표시 중이며 현재 게임 상태와 다를 수 있음 |

- **창이 작거나 배치가 맞지 않을 때:** cfg를 반복 교체하기보다 도구의 기본값 복구를 먼저 사용하세요. 기존 사용자 지정 배치가 유지되고 있을 수 있습니다.
- **Tab으로 연 뒤 첫 패드 입력이 먹지 않을 때:** 입력 모드 전환과 관련된 알려진 경로입니다. 패드의 L3/R3 겹침으로 열어 보세요.
- **새 정보가 확인 불가일 때:** 지원 밖·동적 자료를 효과 없음이나 진행 불가로 단정하지 않습니다. 같은 대상의 갱신 실패는 `이전 값`으로 구분하고 대상·장면·로드가 바뀌면 이전 스냅샷을 버립니다. 실제 게임 화면에서 비교할 대상 ID·버전과 상태를 함께 제보하세요.
- **로드 뒤 데이터 대기가 계속될 때:** 다음 이야기/Lua 로딩까지 기다릴 수 있습니다. 준비된 문맥에서는 X 또는 도구의 새로고침을 사용합니다.
- **실패·이전 값 상태에서 예약이 안 될 때:** 최신 대상을 확인할 수 있을 때만 예약을 변경합니다. 회복한 정보를 확인하고 새 입력으로 조작하세요.

표시용 난수·색상·확률은 게임의 다음 실제 결과를 보장하지 않습니다. Steam Input 구성·다른 모드와의 조합, 성능은 환경에 따라 달라질 수 있습니다. [입력 지원 범위](docs/GAMEPAD.md) · [읽음·상태 문구 설명](docs/ISSUE-4-STATUS-LABELS.md)

## 오류 제보와 개발 문서

[Issues](https://github.com/jungpaeng/dicemaster/issues)에 사용 버전, 게임·BepInEx 버전, 재현 순서, 패드 종류·Steam Input 사용 여부와 관련 화면·`BepInEx/LogOutput.log`를 남겨 주세요. 가능하면 설치 DLL의 SHA-256과 문제가 난 탭·항목 ID도 적어 주세요. 전체 게임 소스·Lua·세이브는 기본 제보에 필요하지 않습니다.

전체 C# 소스 빌드를 사용합니다. Python 3와 `global.json`에 지정한 .NET SDK, 별도의 읽기 전용 게임·로더 참조를 준비한 뒤 실행합니다.

```sh
python3 build/build-source.py --references '<읽기 전용 참조 루트>'
```

DLL·설치 ZIP·검사 기록은 `artifacts/source-candidate/`에 생성됩니다. 게임 소스·게임 DLL을 저장소나 배포물에 추가하지 않습니다.
